## 시작하기 전에

파이썬 기초 트랙에서 숫자 여러 개는 리스트에 담았습니다. 그런데 리스트로 "모든 값을 두 배로" 같은 계산을 하려고 하면 생각과 다르게 움직입니다.

```run
prices = [1200, 3500, 800]
print(prices * 2)
```

값이 두 배가 되지 않고 리스트가 **통째로 두 번 이어 붙었습니다**. 리스트에서 `*`는 "반복해서 붙이기"라는 뜻이기 때문입니다. 값마다 계산하려면 `for`로 하나씩 꺼내야 합니다.

```run
prices = [1200, 3500, 800]
doubled = []
for p in prices:
    doubled.append(p * 2)
print(doubled)
```

값이 3개일 때는 괜찮지만, 센서 기록 100만 개, 사진 한 장의 픽셀 수백만 개를 매번 이렇게 처리하면 코드도 길고 느립니다. 이 불편을 없애려고 만든 도구가 **NumPy**입니다.

## NumPy는 무엇인가

**NumPy**(넘파이)는 **같은 종류의 숫자를 한 덩어리(배열)로 담아, 반복문 없이 한 번에 계산하게 해 주는 라이브러리**입니다. 이름은 **Num**erical **Py**thon(수치 계산용 파이썬)에서 왔습니다.

NumPy가 만드는 배열의 정식 이름은 `ndarray`(n차원 배열)입니다. 줄 하나짜리(1차원)부터 표 모양(2차원), 사진처럼 가로 · 세로 · 색 3겹(3차원)까지 같은 방식으로 다룹니다.

데이터 분석에 쓰는 파이썬 도구들을 한 장의 지도로 그리면 NumPy는 거의 맨 아래, 파이썬 바로 위에 있습니다. pandas · matplotlib · scikit-learn이 모두 NumPy 배열 위에 지어졌습니다.

::figure{src="content/img/libs/lib-map-numpy.svg" alt="파이썬 위에 NumPy가 넓게 깔려 있고, 그 위에 pandas, matplotlib, scikit-learn이, matplotlib 위에 seaborn이 있다. 오른쪽에는 PyTorch가 따로 서 있다. NumPy가 강조되어 있다" caption="데이터 파이썬 지도. NumPy는 pandas · matplotlib · scikit-learn이 함께 딛고 서 있는 바닥입니다."}

NumPy는 파이썬을 설치할 때 함께 들어오지 않는 **외부 라이브러리**라서, 내 컴퓨터에서는 `pip install numpy`로 설치합니다(이 사이트와 Google Colab에는 이미 들어 있습니다. 설치 방법은 [pip: 라이브러리를 설치하고 관리하는 도구](#/l/da-00-1)에서 배웠습니다). 불러올 때는 전 세계 사람들이 똑같이 `np`라는 별명을 씁니다. 다른 사람의 코드를 읽을 때 `np.`이 보이면 NumPy입니다.

같은 계산을 배열로 해 봅니다.

```run
import numpy as np

prices = np.array([1200, 3500, 800])   # 리스트를 배열로 바꾼다
print(prices * 2)
print(prices.shape, prices.dtype)
```

이번에는 `* 2`가 **값마다** 적용되어 `[2400 7000 1600]`이 나왔습니다. 반복문이 없습니다. `shape`의 `(3,)`은 "값이 3개인 1차원 배열", `dtype`의 `int64`(환경에 따라 `int32`)는 "모든 값이 정수"라는 뜻입니다. 배열은 출력할 때 쉼표 없이 보여서 리스트와 구분됩니다.

## 왜 빠를까: 담는 방식이 다르다

리스트와 배열은 겉보기엔 비슷해도 속에서 값을 담는 방식이 다릅니다.

- **리스트**는 칸마다 "값이 메모리 어디에 있는지" 적힌 쪽지만 들고 있습니다. 값은 여기저기 흩어져 있고, 정수 · 글자 · 소수가 섞여 있어도 됩니다. 그래서 계산할 때마다 쪽지를 따라가 "이건 무슨 종류지?"를 확인해야 합니다.
- **배열**은 같은 종류의 값을 **한 줄로 붙여** 담습니다. 컴퓨터는 종류를 한 번만 확인하고 줄을 쭉 훑으며 계산합니다.

::figure{src="content/img/libs/np-list-vs-array.svg" alt="왼쪽 리스트는 칸마다 쪽지가 있어 흩어진 값 상자를 가리킨다. 오른쪽 NumPy 배열은 12, 8, 15, 10, 5가 한 줄로 붙어 있고 dtype int64, shape (5,)라고 적혀 있다" caption="리스트는 흩어진 값을 쪽지로 가리키고, 배열은 같은 종류 값을 한 줄로 붙여 담습니다."}

게다가 배열을 훑는 반복은 파이썬이 아니라 **C 언어로 미리 짜 둔 코드**가 합니다. 우리가 쓴 `* 2` 한 줄이 안쪽에서는 아주 빠른 반복으로 바뀌는 셈입니다. 이렇게 반복문을 쓰지 않고 배열 전체에 계산을 거는 것을 **벡터 연산**(vectorization)이라고 부릅니다.

::figure{src="content/img/libs/np-loop-vs-vector.svg" alt="위: for 반복은 12, 8, 15, 10, 5를 하나씩 꺼내 두 배로 만들기를 다섯 번 한다. 아래: 배열 연산은 배열 전체에 * 2를 한 번 걸어 24, 16, 30, 20, 10을 얻는다" caption="for 반복은 값마다 한 번씩, 벡터 연산은 배열 전체에 한 번. 결과는 같고 코드와 시간이 줄어듭니다."}

얼마나 차이 나는지 직접 재 봅니다. 숫자 100만 개를 두 배로 만드는 데 걸린 시간을 비교합니다.

```run
import time
import numpy as np

nums = list(range(1_000_000))
arr = np.arange(1_000_000)

t0 = time.perf_counter()
doubled = []
for x in nums:
    doubled.append(x * 2)
t1 = time.perf_counter()
for _ in range(10):              # 너무 빨라서 10번 재고 평균
    doubled_arr = arr * 2
t2 = time.perf_counter()

list_sec = t1 - t0
arr_sec = max((t2 - t1) / 10, 1e-6)
print(f"리스트 + for: {list_sec:.4f}초")
print(f"배열 * 2   : {arr_sec:.4f}초")
print(f"배열이 약 {list_sec / arr_sec:.0f}배 빠름")
```

배열 쪽은 너무 빨라서 10번 재고 평균을 냈습니다. 실행할 때마다, 컴퓨터마다 숫자는 조금씩 다르지만 보통 **수십 배 이상** 차이가 납니다. `1_000_000`의 밑줄은 자릿수를 읽기 쉽게 끊은 것으로, 그냥 `1000000`과 같습니다. 숫자를 `10_000_000`(1,000만)으로 바꿔 다시 실행해 보세요. 데이터가 커질수록 차이가 더 벌어집니다.

:::tip 속도보다 더 큰 장점
NumPy의 진짜 장점은 "빠르다"보다 **생각하는 단위가 바뀐다**는 데 있습니다. "값 하나씩 꺼내서…"가 아니라 "이 열 전체에서 평균을 빼고…"처럼 묶음 단위로 생각하게 됩니다. 이 사고방식은 pandas · 머신러닝 · 딥러닝까지 그대로 이어집니다.
:::

## 보이지 않는 곳의 NumPy

**데이터 소개 · 타이타닉 승객 기록** (`titanic.csv`)

1912년 침몰한 여객선 타이타닉의 승객 **891명** 기록입니다. 누가 살아남았는지와 승객 정보가 들어 있어, 생존에 무엇이 영향을 줬는지 분석하는 고전 예제입니다(seaborn 예제 데이터). **한 행 = 승객 한 명**입니다.

| 컬럼 | 뜻 | 자료형 | 예시 |
| --- | --- | --- | --- |
| `survived` | 생존 여부(1 = 생존, 0 = 사망) | 정수 | 0, 1 |
| `pclass` | 객실 등급(1등석이 가장 비쌈) | 정수 | 1, 2, 3 |
| `sex` | 성별 | 글자 | male, female |
| `age` | 나이(세) | 소수 | 22.0 |
| `sibsp` | 함께 탄 형제자매 · 배우자 수 | 정수 | 1 |
| `parch` | 함께 탄 부모 · 자녀 수 | 정수 | 0 |
| `fare` | 요금(파운드) | 소수 | 7.25 |
| `embarked` | 탄 항구 첫 글자 | 글자 | S, C, Q |
| `class` | 객실 등급(글자) | 글자 | First, Second, Third |
| `who` | 남자 · 여자 · 어린이 | 글자 | man, woman, child |
| `adult_male` | 성인 남성인가 | 참/거짓 | True |
| `deck` | 갑판(객실 층) | 글자 | A ~ G |
| `embark_town` | 탄 항구 이름 | 글자 | Southampton |
| `alive` | 생존 여부(글자) | 글자 | yes, no |
| `alone` | 혼자 탔나 | 참/거짓 | False |

`age`는 177명, `deck`은 688명이 비어 있습니다. `class` · `alive` · `embark_town`은 다른 열을 글자로 다시 쓴 것입니다. 전체 생존율은 38.4%입니다.

앞으로 NumPy를 직접 쓰지 않는 순간에도 NumPy는 늘 그 안에 있습니다.

- **pandas 표의 열** 하나하나가 속은 NumPy 배열입니다.
- **사진**은 가로 × 세로 × 색(빨강 · 초록 · 파랑) 숫자가 담긴 3차원 배열입니다.
- **scikit-learn 모델**은 학습할 데이터를 NumPy 배열로 받습니다.

타이타닉 승객 표에서 운임(`fare`) 열을 꺼내 속을 열어 봅니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
fare = df["fare"].to_numpy()   # 표의 열을 NumPy 배열로 꺼내기
print(type(fare))
print(fare[:5])
print(fare.mean().round(2))
```

`type`이 `numpy.ndarray`로 나왔습니다. pandas 표의 열을 꺼내면 바로 NumPy 배열입니다. 승객 891명의 평균 운임 32.2도 반복문 없이 `.mean()` 한 번으로 구했습니다.

## NumPy의 역사

| 해 | 일 |
| --- | --- |
| 1995 | 파이썬으로 큰 숫자 묶음을 계산하려는 첫 시도 **Numeric** 등장 |
| 2001 | 큰 배열에 강한 **Numarray**가 따로 나와, 도구가 둘로 갈라짐 |
| 2006 | **트래비스 올리펀트**(Travis Oliphant)가 둘을 합쳐 **NumPy 1.0** 발표 |
| 2008 | NumPy 배열 위에 **pandas** 개발 시작 |
| 2020 | 과학 학술지 *Nature*에 NumPy 논문 게재. 블랙홀 첫 사진, 중력파 발견 분석에 쓰였다고 소개됨 |
| 2024 | **NumPy 2.0** 발표 |

갈라져 있던 도구가 하나로 합쳐진 덕분에, 이후 나온 라이브러리들이 모두 "NumPy 배열"이라는 같은 그릇을 쓰게 되었습니다. 그래서 pandas 표를 scikit-learn에 넣고, 결과를 matplotlib으로 그리는 일이 자연스럽게 이어집니다.

## 리스트 · 엑셀과 비교하면

| | 파이썬 리스트 | 엑셀 | NumPy 배열 |
| --- | --- | --- | --- |
| 담는 값 | 아무거나 섞어서 | 칸마다 아무거나 | **한 종류로 통일** |
| 전체 계산 | `for`로 하나씩 | 수식을 아래로 끌어 복사 | `arr * 2` 한 줄 |
| 큰 데이터 | 느림 | 약 100만 행이 한계 | 수천만 개도 빠르게 |
| 잘 맞는 일 | 순서 있는 아무 묶음 | 눈으로 보며 고치기 | 숫자 계산 · 통계 · 행렬 |

## 정리

- **NumPy** = 같은 종류 숫자를 한 줄로 붙여 담고(배열), 반복문 없이 한 번에 계산하는 라이브러리. `import numpy as np`
- 리스트의 `* 2`는 반복해서 붙이기, 배열의 `* 2`는 값마다 곱하기
- 빠른 이유: 한 종류 · 붙어 있는 칸 · C로 짠 반복
- pandas 열, 사진, 머신러닝 입력이 모두 NumPy 배열이라서 데이터 파이썬의 바닥 역할을 합니다
