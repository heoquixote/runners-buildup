> **이 레슨의 명령은 내 컴퓨터 터미널에서 칩니다.** 회색 명령 블록은 내 PC에서 따라 하고, ▶ 실행 셀은 여기서 눌러 보세요.

## 시작하기 전에

[pip: 라이브러리를 설치하고 관리하는 도구](#/l/da-00-1)에서 `pip install` 로 설치한 패키지는 파이썬의 `site-packages` 폴더 **한 곳**에 모인다고 했습니다. 그런데 프로젝트가 두 개가 되면 문제가 생깁니다.

```text
프로젝트 A (작년에 만든 보고서 자동화) → pandas 1.x 필요
프로젝트 B (이번에 시작한 분석)       → pandas 2.x 필요
```

파이썬이 하나뿐이면 pandas도 한 버전만 깔 수 있습니다. B를 위해 2.x로 올리면 A가 에러를 내고, A를 위해 1.x로 내리면 B가 에러를 냅니다. 이것을 **버전 충돌**이라고 합니다.

::figure{src="content/img/env/venv-conflict.svg" alt="왼쪽: 프로젝트 A와 B가 파이썬 하나를 같이 써서 pandas 2.x만 설치되고 A가 깨진다. 오른쪽: 프로젝트 A와 B가 각자 venv 폴더를 가져 pandas 1.5.3과 2.2.2를 따로 쓰고 서로 영향이 없다" caption="파이썬 하나를 같이 쓰면 버전이 부딪치고, 가상환경을 나누면 프로젝트마다 다른 버전을 씁니다."}

## 가상환경이란

**가상환경**(virtual environment)은 **프로젝트 폴더 안에 만드는, 그 프로젝트 전용 파이썬 칸**입니다. 칸마다 자기 `site-packages` 폴더를 따로 갖기 때문에, 한 칸에서 설치 · 삭제한 패키지는 다른 칸에 영향을 주지 않습니다.

학교 사물함을 떠올려 보세요. 교실 뒤 공용 책장에 모두의 교과서를 꽂으면 같은 과목 다른 판이 섞여 헷갈립니다. 사물함을 하나씩 나눠 주면 각자 자기 판을 넣어 두고 꺼내 쓰면 됩니다. 가상환경이 프로젝트마다 나눠 주는 사물함입니다.

가상환경을 쓰면

- **프로젝트마다 라이브러리 버전을 따로** 관리할 수 있고
- **팀원끼리 같은 환경**을 맞추기 쉽고(다음 레슨의 requirements.txt)
- 망가지면 **폴더째 지우고 다시 만들면** 되니 실험이 부담 없습니다.

그래서 실무에서는 **프로젝트를 시작하면 가상환경부터** 만드는 것이 거의 필수 습관입니다. 만드는 도구 `venv` 는 파이썬에 들어 있는 표준 라이브러리라 따로 설치할 것이 없습니다.

## 1단계. 파이썬 확인

**어디서**: 명령 프롬프트 · PowerShell(Windows), 터미널(macOS), VS Code 아래쪽 터미널 어디든 됩니다.

```bash
python --version
```

```text
Python 3.12.5
```

버전이 나오면 준비 끝입니다. macOS에서 `python` 이 없다고 나오면 `python3 --version` 을 쓰고, 이 레슨의 `python` 을 모두 `python3` 으로 바꿔 칩니다.

Windows에서 아래처럼 나오면 파이썬을 설치할 때 **PATH**(터미널이 프로그램을 찾아보는 폴더 목록)에 등록하지 않은 것입니다.

```text
'python'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는 배치 파일이 아닙니다.
'python' is not recognized as an internal or external command ...
```

해결법은 [설치 가이드 ③ python.org + VS Code](#/l/pb-00-4)의 "자주 막히는 문제"에 있습니다(설치 파일을 다시 실행해 **Add Python to environment variables** 체크). 환경변수 창에서 직접 등록하는 방법은 [윈도우 10에서 파이썬 환경변수(Path) 설정](https://wxmin.tistory.com/121) 글을 참고하세요.

## 2단계. 가상환경 만들기

**어디서**: **프로젝트 폴더 안**에서 연 터미널. VS Code에서 프로젝트 폴더를 열고 메뉴 **터미널 → 새 터미널**을 누르면 그 폴더에서 열립니다.

```bash
python -m venv venv
```

`venv` 가 두 번 나와서 헷갈리는데 뜻이 다릅니다.

- 앞의 `-m venv`: 파이썬에 들어 있는 **venv 도구를 실행**하라
- 뒤의 `venv`: 만들 **폴더 이름**

폴더 이름은 자유라서 실무에서는 숨김 폴더처럼 보이는 `.venv` 도 많이 씁니다(`python -m venv .venv`). 이 레슨에서는 `venv` 로 통일합니다. 몇 초 뒤 아무 메시지 없이 끝나면 성공이고, 프로젝트 폴더에 `venv/` 폴더가 생깁니다.

::figure{src="content/img/env/venv-folder.svg" alt="my_project 폴더 안에 venv 폴더, app.py, requirements.txt, .gitignore가 있다. venv 안에는 Scripts(macOS·Linux는 bin), Lib/site-packages, pyvenv.cfg가 있다" caption="venv 폴더 안에 이 프로젝트 전용 파이썬 · pip(Scripts 또는 bin)과 패키지 보관함(site-packages)이 들어 있습니다."}

venv 폴더 안을 직접 고칠 일은 없습니다. 패키지는 pip으로 넣고 빼고, 문제가 생기면 폴더를 통째로 지우고 2단계를 다시 하면 됩니다.

## 3단계. 가상환경 켜기 (activate)

만들기만 해서는 아무 일도 일어나지 않습니다. **켜야**(activate) 그 터미널이 venv 안의 파이썬과 pip을 씁니다.

**Windows** (명령 프롬프트 · PowerShell)

```bash
.\venv\Scripts\activate
```

**macOS · Linux**

```bash
source venv/bin/activate
```

켜지면 터미널 줄 맨 앞에 **`(venv)`** 가 붙습니다.

```text
(venv) C:\my_project>
```

이 표시는 "**지금 이 터미널의 파이썬 = 이 프로젝트 전용 파이썬**"이라는 뜻입니다. 앞으로 pip 명령을 치기 전에는 항상 `(venv)` 가 있는지 먼저 봅니다.

> Windows PowerShell에서 "이 시스템에서 스크립트를 실행할 수 없으므로…"라는 빨간 글이 나오면, 보안 설정이 스크립트 실행을 막은 것입니다. PowerShell에 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 를 입력하고 `Y` 를 누른 뒤 다시 activate 하세요.

## 4단계. VS Code 인터프리터 고르기

여기서 많이 놓치는 점이 있습니다. **activate는 그 터미널 창 하나에만 적용됩니다.** VS Code의 ▶ 실행 버튼이나 노트북(.ipynb)은 VS Code가 따로 고른 파이썬(**인터프리터**)을 씁니다. 그래서 VS Code에도 "venv 파이썬을 써라"라고 알려 줘야 합니다.

- **방법 1**: `Ctrl + Shift + P`(macOS `Cmd + Shift + P`) → **Python: Select Interpreter** 입력 → 목록에서 `venv` 가 들어간 파이썬 선택
- **방법 2**: VS Code 오른쪽 아래 상태 표시줄의 파이썬 버전을 클릭 → `venv` 선택

선택 후 상태 표시줄이 `3.12.5 ('venv': venv)` 처럼 바뀌면 됩니다. 노트북을 쓴다면 오른쪽 위 **커널 선택**에서도 같은 venv를 고릅니다. 터미널 · 인터프리터 · 노트북 커널, **세 곳이 같은 환경**을 가리켜야 "설치했는데 없다는" 에러가 안 납니다.

## 5 · 6단계. 패키지 설치하고 확인하기

**어디서**: `(venv)` 가 붙은 터미널.

```bash
python -m pip install pandas numpy matplotlib
pip list
```

`pip list` 에는 방금 설치한 패키지와 그 의존성만 보입니다. 기본 파이썬에 깔려 있던 다른 패키지는 보이지 않습니다. 빈 사물함에서 시작했기 때문입니다.

지금 파이썬이 가상환경 안에서 돌고 있는지는 코드로도 확인할 수 있습니다. 가상환경을 켜면 `sys.prefix`(지금 파이썬의 집)가 venv 폴더로 바뀌고, `sys.base_prefix`(가상환경을 만든 원래 파이썬의 집)는 그대로 남습니다. 둘이 다르면 가상환경 안입니다.

```run
import sys

in_venv = sys.prefix != sys.base_prefix
print("지금 파이썬의 집 :", sys.prefix)
print("원래 파이썬의 집 :", sys.base_prefix)
print("가상환경 안인가요?", in_venv)
```

이 사이트에서는 `False` 가 나옵니다. 브라우저 안 파이썬은 가상환경을 쓰지 않기 때문입니다. 내 PC의 venv 파이썬으로 이 코드를 실행하면 첫 줄이 `...\my_project\venv` 로 바뀌고 `True` 가 나옵니다. VS Code에서 인터프리터를 제대로 골랐는지 확인할 때 쓰기 좋은 코드입니다.

## 7단계. 가상환경 끄기 (deactivate)

작업이 끝났거나 다른 프로젝트로 옮길 때는 끕니다. 운영체제와 관계없이 같습니다.

```bash
deactivate
```

터미널 앞의 `(venv)` 가 사라지면 다시 기본 파이썬으로 돌아온 것입니다. 터미널 창을 닫아도 꺼집니다. 다음에 작업할 때는 2단계(만들기)는 건너뛰고 **3단계(켜기)부터** 하면 됩니다.

## 자주 막히는 문제

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 설치했는데 `ModuleNotFoundError` | `(venv)` 없이 설치해서 기본 파이썬에 깔림, 또는 VS Code 인터프리터 · 노트북 커널이 venv가 아님 | 터미널에 `(venv)` 확인 → `python -m pip install ...` 다시, 인터프리터 · 커널을 venv로 |
| `activate` 에서 "스크립트를 실행할 수 없으므로…" | PowerShell 실행 정책 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 후 다시 |
| `source: command not found` (Windows) | macOS용 명령을 Windows에서 침 | Windows는 `.\venv\Scripts\activate` |
| `No such file or directory: venv/bin/activate` | 프로젝트 폴더가 아닌 곳에서 실행, 또는 아직 안 만듦 | `cd` 로 프로젝트 폴더로 이동하거나 2단계부터 |
| 프로젝트 폴더를 옮겼더니 venv가 이상함 | venv 안에 원래 경로가 적혀 있음 | venv 폴더를 지우고 다시 만든 뒤 requirements.txt로 재설치(다음 레슨) |

## 정리

- **가상환경** = 프로젝트 전용 파이썬 칸. 칸마다 `site-packages` 가 따로라 버전이 부딪치지 않는다.
- 만들기 `python -m venv venv`(뒤의 venv는 폴더 이름) → 켜기 Windows `.\venv\Scripts\activate`, macOS `source venv/bin/activate` → `(venv)` 확인.
- activate는 그 터미널에만 적용된다. **VS Code 인터프리터 · 노트북 커널도 venv로** 맞춘다.
- `(venv)` 가 붙은 터미널에서 `python -m pip install` 로 설치하고, 끝나면 `deactivate`.
- `sys.prefix != sys.base_prefix` 이면 가상환경 안이다.

다음 레슨 [requirements.txt로 환경 저장하고 되살리기](#/l/da-00-3)에서는 이 환경을 파일 한 장으로 저장해 팀원 · 다른 컴퓨터에서 똑같이 되살립니다.
