## 질문 → 차트 → 도구

비교 · 추이 · 분포 · 관계 · 구성 PART에서 질문별 차트를 그리고 읽어 봤습니다. 이 페이지는 그것들을 **하나의 지도**로 정리하고, 어떤 그래프든 같은 순서로 읽는 법을 정리합니다.

그래프를 잘 그리는 사람과 못 그리는 사람의 차이는 코드 실력보다 **순서**에 있습니다. 못 그리는 사람은 "멋진 차트가 뭐가 있지?"부터 고민합니다. 잘 그리는 사람은 이렇게 갑니다.

1. **질문**: 이 그래프로 무엇을 보여 주려고 하나? (한 문장으로)
2. **차트**: 그 질문에 맞는 차트 종류는? (아래 지도)
3. **도구**: matplotlib으로 그릴까, seaborn으로 그릴까?

질문은 대부분 아래 여섯 가지 중 하나입니다.

## 차트 지도

| 질문 | 예시 | 차트 | matplotlib | seaborn |
| --- | --- | --- | --- | --- |
| **비교** 어느 그룹이 큰가 | 요일별 평균 매출 | 막대, 가로 막대, 묶음 막대, 점 | `ax.bar`, `ax.barh` | `barplot`, `countplot`, `pointplot` |
| **추이** 시간에 따라 어떻게 변하나 | 월별 승객 수 | 선, 이동평균, 로그 축, 달력형 히트맵 | `ax.plot`, `ax.set_yscale` | `lineplot`, `relplot` |
| **분포** 값이 어디에 몰려 있나, 이상치는 | 시험 점수 분포, 반별 키 | 히스토그램, 밀도 곡선, 상자, 바이올린 | `ax.hist`, `ax.boxplot` | `histplot`, `kdeplot`, `ecdfplot`, `boxplot`, `violinplot`, `swarmplot` |
| **관계** 두 값이 함께 움직이나 | 공부 시간 vs 점수 | 산점도, 추세선 | `ax.scatter` | `scatterplot`, `regplot`, `lmplot`, `jointplot` |
| **구성** 전체 중 얼마를 차지하나 | 지역별 매출 비중 | 누적 · 100% 막대, 누적 영역, (조각 적으면) 파이 | `ax.pie`, `ax.stackplot`, `crosstab(...).plot.bar(stacked=True)` | `histplot(multiple="fill")` |
| **상관** 여러 값 중 무엇끼리 엮여 있나 | 공정 변수 10개 | 히트맵, pairplot | `ax.imshow` | `heatmap`, `pairplot` |

도구 고르기는 간단합니다.

- **표(DataFrame)가 있고, 그룹별로 묶어 비교·분포를 볼 때** → seaborn (집계·색·범례를 알아서)
- **이미 집계된 숫자 몇 개를 그리거나, 세밀하게 다듬을 때** → matplotlib
- 둘은 섞어 쓰는 것이 기본입니다. seaborn으로 그리고 `ax.set_title`, `ax.axhline`, `ax.annotate`로 다듬습니다.

같은 식당 데이터로 여섯 가지 질문을 하나씩 그려 봅니다. 추이는 시간 순서가 있는 항공 승객 데이터를 씁니다.

```run
import matplotlib.pyplot as plt
import seaborn as sns
import pandas as pd

tips = pd.read_csv("tips.csv")
flights = pd.read_csv("flights.csv")
order = ["Thur", "Fri", "Sat", "Sun"]
fig, axes = plt.subplots(2, 3, figsize=(12, 6.5))
sns.barplot(data=tips, x="day", y="total_bill", order=order, ax=axes[0, 0]).set_title("Compare: avg bill by day")
sns.lineplot(data=flights, x="year", y="passengers", ax=axes[0, 1]).set_title("Trend: passengers by year")
sns.boxplot(data=tips, x="day", y="tip", order=order, ax=axes[0, 2]).set_title("Distribution: tip by day")
sns.scatterplot(data=tips, x="total_bill", y="tip", ax=axes[1, 0]).set_title("Relationship: bill vs tip")
sns.histplot(data=tips, x="day", hue="time", multiple="fill", shrink=0.8, ax=axes[1, 1]).set_title("Composition: lunch/dinner share")
sns.heatmap(tips[["total_bill", "tip", "size"]].corr(), annot=True, cmap="coolwarm", vmin=-1, vmax=1, ax=axes[1, 2]).set_title("Correlation")
fig.tight_layout()
print("질문 6개 → 칸 6개")
```

칸마다 **제목에 질문 종류**를 먼저 적었습니다. 보고서에서도 "이 그래프는 비교다", "이건 분포다"를 스스로 말할 수 있으면 차트 선택에서 거의 실수하지 않습니다. 구성 칸을 보면 목요일은 거의 다 점심, 금요일은 점심이 약 3분의 1, 토·일요일은 전부 저녁입니다.

## 어떤 그래프든: 그래프를 읽는 5단계

질문별 차트 레슨의 해석 틀은 모두 같은 순서를 따랐습니다. 처음 보는 그래프도 이 순서로 읽으면 됩니다.

| 단계 | 질문 | 예 |
| --- | --- | --- |
| 1. 무엇을 그렸나 | 제목, 축 이름, 단위, 점 · 막대 · 선 하나가 무엇인가 | "막대 하나 = 등급 하나, 높이 = 생존율" |
| 2. 큰 그림 | 가장 큰 · 작은 것, 방향, 중심 | "1등실이 가장 높다", "오른쪽 위로 올라간다" |
| 3. 크기 | 차이가 몇 개, 몇 배, 몇 %p인가 | "63% vs 24%, 2.6배" |
| 4. 예외 | 패턴에서 벗어난 점 · 구간 · 그룹 | "이상치 하나", "금요일만 데이터가 적다" |
| 5. 함정 확인 | 축이 잘렸나, 개수 vs 비율, 그룹이 섞였나, 상관 ≠ 원인 | "n=19라 덜 믿을 만하다" |

해석 문장은 **2~4단계를 숫자와 함께** 쓰고, 5단계에서 걸리는 것이 있으면 단서를 붙입니다. "1등실 생존율(63%)이 3등실(24%)의 2.6배다. 다만 등급 안에서도 성별 차이가 커서, 성별을 나눠 보면 차이의 일부는 성별 구성 때문일 수 있다."

## 흔한 실수 ① 막대 축을 0에서 자르기

막대그래프는 **길이**로 비교하는 차트라서, 축이 0이 아닌 곳에서 시작하면 작은 차이가 크게 부풀려집니다. 같은 데이터를 두 가지로 그려 봅니다.

```run
import matplotlib.pyplot as plt

teams = ["A", "B"]
score = [96, 100]
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(7, 3))
ax1.bar(teams, score)
ax1.set_ylim(95, 101)
ax1.set_title("Misleading (starts at 95)")
ax2.bar(teams, score)
ax2.set_title("Honest (starts at 0)")
print("실제 차이:", round((100 - 96) / 96 * 100, 1), "%")
```

실제 차이는 약 4%인데 왼쪽 그림에서는 B가 A의 다섯 배처럼 보입니다. **막대는 0부터**가 원칙입니다. 작은 차이를 꼭 강조해야 한다면 막대 대신 점(`pointplot`)이나 선을 쓰고, 축이 잘렸다는 것을 분명히 적습니다. 선 그래프는 길이가 아니라 **변화의 모양**을 보는 차트라서 0에서 시작하지 않아도 괜찮습니다.

## 흔한 실수 ② 조각 많은 파이

파이 그래프는 조각이 많아지면 크기를 비교하기 어렵습니다. 같은 비율을 파이와 **정렬한 가로 막대**로 나란히 그려 봅니다.

```run
import matplotlib.pyplot as plt
import pandas as pd

df = pd.read_csv("titanic.csv")
share = df["who"].astype(str).str.cat(df["class"], sep="-").value_counts(normalize=True)
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 4))
ax1.pie(share.values, labels=share.index, textprops={"fontsize": 7})
ax2.barh(share.index[::-1], share.values[::-1])
print("조각 수:", len(share), "/ 가장 큰 조각:", share.index[0], round(share.iloc[0], 3))
```

조각이 9개가 되니 파이에서는 `woman-Third`(12.8%)와 `woman-First`(10.2%) 중 무엇이 큰지 알기 어렵지만, 정렬한 막대에서는 바로 보입니다. **조각 5개 이하, 그중 하나가 확실히 클 때만 파이**를 쓰세요.

## 흔한 실수 ③~⑥

| 실수 | 왜 문제인가 | 대안 |
| --- | --- | --- |
| ③ 한 그림에 너무 많이 (선 10개, hue + size + style) | 아무것도 안 읽힌다 | 한 칸에 한 질문. 나머지는 `col=`로 칸 나누기 |
| ④ 두 번째 y축 | 축 범위를 바꾸면 두 선이 얼마든지 "같이 움직이는 것처럼" 보인다 | 칸 두 개로 나누고 x축 공유 |
| ⑤ 정렬하지 않은 막대 | 순위를 읽으려고 눈이 왔다 갔다 한다 | 크기순 정렬(`sort_values`), 순서 있는 범주는 그 순서(`order=`) |
| ⑥ 의미 없는 무지개 색 | 색이 다르면 다른 의미가 있다고 생각하게 된다 | 강조할 것 하나만 색, 나머지는 회색 |

## 마지막으로: 결론을 제목에

보고서용 그래프는 제목에 **차트 이름이 아니라 결론**을 씁니다. "Survival rate by class"보다 "3rd class had the lowest survival rate"가 읽는 사람의 시간을 아껴 줍니다. 강조할 막대 하나만 색을 주고, 나머지는 회색으로 둡니다(실수 ⑥의 대안).

```run
import matplotlib.pyplot as plt
import pandas as pd

df = pd.read_csv("titanic.csv")
rate = df.groupby("class")["survived"].mean().reindex(["First", "Second", "Third"])
fig, ax = plt.subplots(figsize=(6, 3.5))
bars = ax.bar(rate.index, rate.values, color=["lightgray", "lightgray", "crimson"])
ax.bar_label(bars, labels=[f"{v * 100:.0f}%" for v in rate.values])
ax.set_ylim(0, 1)
ax.set_title("3rd class had the lowest survival rate (24%)", loc="left")
ax.set_ylabel("Survival rate")
print((rate * 100).round(0))
```

제목(결론), 축 이름, 0부터 시작하는 막대, 값 표시, 강조 색 하나. 이 다섯 가지가 갖춰지면 읽는 사람이 3초 안에 메시지를 가져갑니다.

- 제목에 결론이 있나?
- 축 이름과 단위가 있나?

- 색은 의미 있는 곳에만 썼나?
- 비교하는 칸끼리 축을 공유했나?
- 상관을 원인처럼 쓰지 않았나?

## 다음 단계

- **plotly**: 마우스를 올리면 값이 뜨고 확대·축소가 되는 **인터랙티브 차트** 도구입니다. 발표·웹 공유·대시보드에 강합니다. 문법은 `px.scatter(df, x=..., y=..., color=...)`로 seaborn과 비슷합니다.
- **자동 EDA 도구**(ydata-profiling, sweetviz 등): 데이터 전체를 요약한 리포트를 자동으로 만들어 줍니다. 처음 데이터를 훑어볼 때 빠르지만, **출발점이지 결론이 아닙니다.** 수치와 그래프가 왜 그렇게 나왔는지는 이 트랙에서 배운 차트로 직접 확인하세요.
