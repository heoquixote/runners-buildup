> **이 레슨의 명령은 내 컴퓨터 터미널에서 칩니다.** 회색 명령 블록은 내 PC에서 따라 하고, ▶ 실행 셀은 여기서 눌러 보세요.

## 시작하기 전에

[가상환경(venv): 프로젝트마다 따로 쓰는 파이썬](#/l/da-00-2)에서 프로젝트 전용 환경을 만들고 pandas · numpy · matplotlib을 설치했습니다. 이제 이런 상황을 생각해 봅니다.

- 팀원에게 내 분석 코드를 보냈더니 "제 컴퓨터에서는 에러가 나요"라는 답이 왔다.
- 노트북을 새로 샀다. 예전 프로젝트를 다시 돌리려는데 무슨 패키지를 몇 버전으로 깔았는지 기억이 안 난다.

코드만 옮기고 **환경**은 옮기지 않았기 때문입니다. 이번 레슨은 환경을 **파일 한 장**으로 저장하고 되살리는 법을 배웁니다.

## 환경을 파일로 저장하기: pip freeze

**어디서**: `(venv)` 가 붙은 터미널.

`pip freeze` 는 지금 환경에 설치된 패키지를 `이름==버전` 모양으로 한 줄씩 출력합니다. 지금 상태를 사진 찍듯 "얼린다"(freeze)는 뜻입니다.

```bash
pip freeze
```

```text
contourpy==1.2.1
matplotlib==3.9.0
numpy==1.26.4
pandas==2.2.2
python-dateutil==2.9.0
...
```

이 출력을 화면 대신 **파일로** 보내려면 `>` 를 붙입니다. `>` 는 pip이 아니라 터미널 기능으로, "앞 명령의 출력을 오른쪽 파일에 써라(있으면 덮어써라)"라는 뜻입니다.

```bash
pip freeze > requirements.txt
```

프로젝트 폴더에 `requirements.txt` 가 생깁니다. 이름은 관례라서 거의 모든 파이썬 프로젝트가 이 이름을 씁니다. 장보기 목록이라고 생각하면 됩니다. 냉장고(venv)를 통째로 들고 갈 수는 없지만, 목록이 있으면 어느 마트에서든 똑같이 채울 수 있습니다.

::figure{src="content/img/env/requirements-flow.svg" alt="내 PC의 venv에서 pip freeze > requirements.txt로 파일을 만들고, 그 파일만 Git으로 공유하고, 팀원 PC의 새 venv에서 pip install -r requirements.txt로 같은 버전을 되살린다" caption="환경은 requirements.txt 로 저장하고, 이 작은 파일만 공유하고, 받는 쪽에서 되살립니다."}

## requirements.txt 들여다보기

requirements.txt는 그냥 **글자 파일**입니다. 파이썬으로 직접 만들고 읽어 볼 수 있습니다. 이 사이트의 파이썬에 파일을 하나 써 봅니다.

```run
lines = ["pandas==2.2.2", "numpy==1.26.4", "matplotlib==3.9.0"]

with open("requirements.txt", "w") as f:
    f.write("\n".join(lines) + "\n")

with open("requirements.txt") as f:
    print(f.read())
```

메모장으로 열어도 똑같이 보이는 세 줄입니다. 한 줄 = 패키지 하나, `==` 왼쪽이 **이름**, 오른쪽이 **버전**입니다.

한 줄을 이름과 버전으로 나눠 봅니다. [문자열 메서드로 데이터 정리하기](#/l/pb-03-1)에서 배운 `split` 으로 충분합니다.

```run
line = "pandas==2.2.2"
name, ver = line.split("==")
print("이름:", name)
print("버전:", ver)
```

`pip install -r` 이 하는 일도 결국 이것입니다. 파일을 한 줄씩 읽어 이름과 버전을 알아내고, 그 버전으로 설치합니다.

이번에는 "목록과 지금 환경이 같은가"를 검사해 봅니다. 목록의 버전과 이 사이트에 실제로 깔린 버전을 나란히 비교합니다. 목록의 버전 숫자를 바꾸거나, `seaborn==0.13.2` 같은 줄을 더해 보세요.

```run
from importlib.metadata import version, PackageNotFoundError

req = """pandas==2.2.2
numpy==1.26.4
matplotlib==3.9.0"""

for line in req.splitlines():
    name, want = line.split("==")
    try:
        have = version(name)
    except PackageNotFoundError:
        have = "(없음)"
    mark = "같음" if have == want else "다름"
    print(f"{name:<11} 목록 {want:<7} 지금 {have:<7} → {mark}")
```

이 사이트는 버전이 목록과 다르게 나올 수 있습니다. 바로 이 "다름"이 팀원 PC에서 에러가 나는 이유입니다. 같은 코드라도 패키지 버전이 다르면 결과나 동작이 달라질 수 있어서, **버전까지 맞춰 주는 것**이 requirements.txt의 역할입니다.

## 다른 컴퓨터에서 되살리기: pip install -r

**어디서**: 팀원 PC(또는 새 노트북)에서, 프로젝트 폴더에 **새로 만든 가상환경을 켠** 터미널.

```bash
pip install -r requirements.txt
```

`-r` 은 "requirements 파일에 적힌 목록대로"라는 뜻입니다. 목록의 모든 패키지가 적힌 버전으로 설치되고, `pip list` 로 확인하면 내 PC와 같은 버전이 보입니다.

두 명령은 방향이 반대라서 헷갈리지 않게 외워 둡니다.

| 명령 | 방향 | 언제 |
| --- | --- | --- |
| `pip freeze > requirements.txt` | 환경 → 파일 (저장) | 패키지를 새로 설치 · 업그레이드했을 때 |
| `pip install -r requirements.txt` | 파일 → 환경 (복원) | 새 PC, 새 팀원, venv를 지우고 다시 만들었을 때 |

> 빈 환경에서 실수로 `pip freeze > requirements.txt` 를 치면, 목록이 텅 빈 파일로 **덮어써집니다**. 받아 온 프로젝트에서는 `install -r` 이 먼저입니다.

## ==와 >=: 버전을 얼마나 꽉 묶을까

requirements.txt에는 `==` 말고도 범위를 적을 수 있습니다.

| 적는 법 | 뜻 | 쓰는 곳 |
| --- | --- | --- |
| `pandas==2.2.2` | 정확히 이 버전 | 분석 결과를 똑같이 재현해야 하는 프로젝트 (freeze 기본값) |
| `pandas>=2.0` | 2.0 이상 아무거나 | 최신 기능만 있으면 되는 개인 스크립트 |
| `pandas>=2.0,<3.0` | 2.x 안에서만 | 주 버전이 바뀌어 깨지는 것만 막고 싶을 때 |
| `pandas` | 버전 상관없이 최신 | 연습용. 나중에 깨질 수 있음 |

[pip: 라이브러리를 설치하고 관리하는 도구](#/l/da-00-1)에서 본 것처럼 **주 버전**이 바뀌면 옛 코드가 안 돌 수 있습니다. 처음에는 freeze가 만들어 주는 `==` 그대로 쓰는 것이 가장 안전합니다.

## .gitignore: venv 폴더는 올리지 않는다

코드를 GitHub 같은 저장소(Git)로 공유할 때, **venv 폴더는 올리지 않습니다.** 대신 requirements.txt를 올립니다.

- **용량이 크다**: pandas · numpy만 깔아도 수백 MB가 됩니다.
- **운영체제마다 다르다**: Windows에서 만든 venv(Scripts, .exe)는 macOS에서 돌지 않고, 반대도 마찬가지입니다. 폴더 안에 내 PC 경로가 적혀 있어 다른 PC에서는 깨집니다.
- **다시 만들 수 있다**: requirements.txt만 있으면 누구나 1분 안에 같은 환경을 만듭니다.

Git에게 "이 파일 · 폴더는 무시해"라고 알려 주는 파일이 **`.gitignore`** 입니다. 프로젝트 폴더 맨 위에 이 이름으로 글자 파일을 만들고 한 줄에 하나씩 적습니다.

```text
venv/
.venv/
__pycache__/
.ipynb_checkpoints/
.env
```

- `venv/`, `.venv/`: 가상환경 폴더 (어느 이름을 써도 빠지게 둘 다)
- `__pycache__/`: 파이썬이 실행 속도를 위해 자동으로 만드는 임시 파일
- `.ipynb_checkpoints/`: 주피터 노트북 자동 저장본
- `.env`: 비밀번호 · API 키를 적어 두는 파일. 올리면 다른 사람이 볼 수 있으니 **반드시** 뺍니다.

::figure{src="content/img/env/gitignore-share.svg" alt="왼쪽 Git에 올리는 것: app.py와 ipynb, requirements.txt, .gitignore, README.md. 오른쪽 .gitignore로 빼는 것: venv, __pycache__, .ipynb_checkpoints, .env" caption="코드와 목록은 올리고, 다시 만들 수 있거나 비밀인 것은 .gitignore 로 뺍니다."}

## 새 팀원이 프로젝트를 받으면

지금까지 배운 것을 한 번에 이으면, 저장소를 막 받은 팀원은 아래 순서대로 하면 됩니다. 이 순서를 프로젝트의 `README.md` 에 적어 두면 팀원이 묻지 않아도 됩니다.

```bash
# 1) 프로젝트 폴더로 이동
cd my_project

# 2) 가상환경 만들기 (처음 한 번)
python -m venv venv

# 3) 켜기  (Windows: .\venv\Scripts\activate)
source venv/bin/activate

# 4) 목록대로 설치
python -m pip install -r requirements.txt

# 5) VS Code에서 인터프리터를 venv로 고른 뒤 코드 실행
```

## PART 정리: 명령 한 장

| 하고 싶은 일 | 명령 |
| --- | --- |
| 파이썬 확인 | `python --version` |
| 가상환경 만들기 | `python -m venv venv` |
| 켜기 | Windows `.\venv\Scripts\activate` · macOS `source venv/bin/activate` |
| 설치 | `python -m pip install pandas` |
| 특정 버전 | `python -m pip install pandas==2.2.2` |
| 업그레이드 · 삭제 | `pip install --upgrade 이름` · `pip uninstall 이름` |
| 확인 | `pip list` · `pip show 이름` |
| 환경 저장 | `pip freeze > requirements.txt` |
| 환경 복원 | `pip install -r requirements.txt` |
| 끄기 | `deactivate` |

## 정리

- `pip freeze` 는 지금 환경을 `이름==버전` 목록으로, `> requirements.txt` 를 붙이면 파일로 저장한다.
- 다른 PC에서는 **새 venv를 켠 뒤** `pip install -r requirements.txt` 로 같은 버전을 되살린다.
- `==` 는 정확히 그 버전, `>=` 는 그 이상. 재현이 중요하면 `==`.
- venv 폴더는 크고 운영체제마다 달라 Git에 올리지 않는다. `.gitignore` 에 `venv/` 와 `.env` 를 꼭 적는다.
