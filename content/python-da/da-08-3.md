센서 데이터는 일정한 간격으로 쌓이도록 설계되지만, 실제로는 통신이 끊겨 기록이 빠지고, 순간적으로 튀는 값이 섞입니다. 이 레슨에서는 10분 간격 온도 기록을 가지고 **빠진 시각을 드러내고, 채우고, 튀는 값을 찾는** 순서를 익힙니다. [시간 순서가 있는 데이터 다루기](#/l/da-08-1)의 `rolling` · `diff`를 실제 센서 정리에 쓰는 레슨입니다.

## 오늘의 데이터: 10분 간격 온도

08:00부터 09:30까지 10분마다 기록되어야 하니 10개여야 하는데, 8개뿐입니다.

```run
import pandas as pd

t = pd.to_datetime(['2026-11-06 08:00', '2026-11-06 08:10', '2026-11-06 08:20',
                    '2026-11-06 08:50', '2026-11-06 09:00', '2026-11-06 09:10',
                    '2026-11-06 09:20', '2026-11-06 09:30'])
temp = pd.Series([201.2, 201.5, 201.9, 203.4, 203.8, 209.6, 204.1, 204.3], index=t)
print(len(temp))
print(temp)
```

목록만 봐서는 08:30, 08:40이 빠졌다는 것을 놓치기 쉽습니다. 빠진 줄은 **아예 행이 없기** 때문에 `isna()`로도 찾을 수 없습니다. 이대로 `rolling(3)`을 쓰면 08:20과 08:50이 바로 이웃처럼 계산됩니다.

## 빠진 시각 드러내기: asfreq

`asfreq('10min')`은 첫 시각부터 끝 시각까지 10분 간격의 **빈틈없는 시간표**를 만들고, 기록이 없는 시각은 NaN으로 채웁니다. 행이 없던 결측이 눈에 보이는 결측이 됩니다.

```run
import pandas as pd

t = pd.to_datetime(['2026-11-06 08:00', '2026-11-06 08:10', '2026-11-06 08:20',
                    '2026-11-06 08:50', '2026-11-06 09:00', '2026-11-06 09:10',
                    '2026-11-06 09:20', '2026-11-06 09:30'])
temp = pd.Series([201.2, 201.5, 201.9, 203.4, 203.8, 209.6, 204.1, 204.3], index=t)

full = temp.asfreq('10min')
print(full)
print(len(full), "행 중", full.isna().sum(), "개 빠짐")
```

| 간격 문자 | 뜻 |
| --- | --- |
| `'10min'` | 10분 |
| `'h'` | 1시간 |
| `'D'` | 1일 |

`asfreq`는 `resample`과 달리 값을 묶지 않고 **정해진 시각의 값만** 가져옵니다. 이제 빠진 칸을 채울 수 있습니다.

## 채우기: ffill과 interpolate

| 방법 | 채우는 값 | 어울리는 데이터 |
| --- | --- | --- |
| `ffill()` | 직전 값을 그대로 | 상태 값 (설비 ON/OFF, 설정값) |
| `interpolate()` | 앞뒤 값을 직선으로 이은 값 | 서서히 변하는 측정값 (온도, 압력) |

```run
import pandas as pd

t = pd.to_datetime(['2026-11-06 08:00', '2026-11-06 08:10', '2026-11-06 08:20',
                    '2026-11-06 08:50', '2026-11-06 09:00', '2026-11-06 09:10',
                    '2026-11-06 09:20', '2026-11-06 09:30'])
full = pd.Series([201.2, 201.5, 201.9, 203.4, 203.8, 209.6, 204.1, 204.3], index=t).asfreq('10min')

compare = pd.DataFrame({'raw': full, 'ffill': full.ffill(), 'interp': full.interpolate()})
print(compare.loc['2026-11-06 08:20':'2026-11-06 08:50'].round(2))
```

08:20(201.9)과 08:50(203.4) 사이가 비어 있습니다. `ffill`은 두 칸을 201.9로 채워서 온도가 30분 동안 멈췄다가 갑자기 1.5도 뛴 모양이 됩니다. `interpolate`는 202.4, 202.9로 고르게 채워서 서서히 오르던 흐름을 살립니다. 온도처럼 연속으로 변하는 값에는 `interpolate`가 자연스럽습니다.

> 너무 긴 공백까지 채우면 없는 데이터를 지어낸 셈이 됩니다. `interpolate(limit=2)`처럼 최대 몇 칸까지만 채울지 정하고, 채운 칸 수를 기록해 두세요.

## 튀는 값 찾기 1: diff

직전 값과의 차이가 갑자기 커지면 튀는 값을 의심합니다. `diff().abs()`로 변화량의 크기를 구하고 기준을 넘는 시각을 고릅니다.

```run
import pandas as pd

t = pd.to_datetime(['2026-11-06 08:00', '2026-11-06 08:10', '2026-11-06 08:20',
                    '2026-11-06 08:50', '2026-11-06 09:00', '2026-11-06 09:10',
                    '2026-11-06 09:20', '2026-11-06 09:30'])
temp = pd.Series([201.2, 201.5, 201.9, 203.4, 203.8, 209.6, 204.1, 204.3], index=t).asfreq('10min').interpolate()

jump = temp.diff().abs()
print(jump.round(2).tolist())
print(jump[jump > 3].round(2))
```

평소 변화량은 0.2~0.5도인데 09:10에 5.8, 09:20에 5.5가 나왔습니다. 그런데 실제로 튄 값은 09:10의 209.6 **하나**입니다. 튀어 올라갈 때 한 번, 제자리로 돌아올 때 한 번, 이렇게 변화량이 두 번 커지기 때문입니다. diff는 "갑자기 바뀐 순간"을 찾는 도구이고, 값이 계단처럼 한 번 바뀌고 유지되는 변화(설정 변경)를 찾을 때 더 잘 맞습니다.

## 튀는 값 찾기 2: 이동 중앙값과 비교

한 점만 튀는 값은 **주변 값들의 중앙값**과 비교하면 정확히 찾습니다. `rolling(3, center=True)`는 자기 자신과 앞뒤 한 칸씩, 세 값으로 창을 만듭니다. 중앙값은 튀는 값 하나에 끌려가지 않습니다.

```run
import pandas as pd

t = pd.to_datetime(['2026-11-06 08:00', '2026-11-06 08:10', '2026-11-06 08:20',
                    '2026-11-06 08:50', '2026-11-06 09:00', '2026-11-06 09:10',
                    '2026-11-06 09:20', '2026-11-06 09:30'])
temp = pd.Series([201.2, 201.5, 201.9, 203.4, 203.8, 209.6, 204.1, 204.3], index=t).asfreq('10min').interpolate()

med = temp.rolling(3, center=True).median()
spike = (temp - med).abs() > 3
print(temp[spike])

clean = temp.where(~spike, med)          # 튄 자리만 중앙값으로 교체
print(clean.loc['2026-11-06 09:00':'2026-11-06 09:20'].tolist())
```

이번에는 09:10 하나만 걸렸습니다. 209.6의 앞뒤 값이 203.8과 204.1이라 세 값의 중앙값은 204.1이고, 차이가 5.5도입니다. 09:20은 창이 (209.6, 204.1, 204.3)이라 중앙값이 204.3이고 자기 값과 0.2밖에 차이 나지 않습니다. [문자열 열 깊게 정리하기](#/l/da-05-2)에서 본 `where`로 튄 자리만 중앙값으로 바꿨습니다.

## 다듬은 뒤 이동평균

튀는 값을 정리한 다음에 이동평균을 내야 추세가 깨끗하게 나옵니다. 튀는 값이 남아 있으면 이동평균이 그 근처 세 칸을 모두 끌어올립니다.

```run
import pandas as pd

t = pd.to_datetime(['2026-11-06 08:00', '2026-11-06 08:10', '2026-11-06 08:20',
                    '2026-11-06 08:50', '2026-11-06 09:00', '2026-11-06 09:10',
                    '2026-11-06 09:20', '2026-11-06 09:30'])
temp = pd.Series([201.2, 201.5, 201.9, 203.4, 203.8, 209.6, 204.1, 204.3], index=t).asfreq('10min').interpolate()
med = temp.rolling(3, center=True).median()
clean = temp.where(~((temp - med).abs() > 3), med)

result = pd.DataFrame({'before': temp.rolling(3).mean(), 'after': clean.rolling(3).mean()}).round(2)
print(result.loc['2026-11-06 09:00':])
```

정리 전 이동평균은 09:10~09:30에 205.6~206.0으로 부풀어 있지만, 정리 후에는 203.8~204.2로 실제 흐름을 따라갑니다.

3. 값의 성격에 맞게 `ffill` 또는 `interpolate`(limit 지정)로 채웁니다
4. 이동 중앙값과 비교해 한 점만 튀는 값을 찾아 처리합니다
