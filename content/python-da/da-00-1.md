> **이 PART의 명령은 내 컴퓨터 터미널에서 칩니다.** 이 사이트의 실행 셀은 브라우저 안의 파이썬이라 `pip` 같은 터미널 명령이 돌지 않습니다. 회색 명령 블록은 읽고 내 PC에서 따라 하고, ▶ 실행 셀은 여기서 바로 눌러 보세요. 내 PC에 아직 파이썬이 없다면 [설치 가이드 ③ python.org + VS Code](#/l/pb-00-4)부터 하고 오세요.

## 시작하기 전에

이 사이트에서는 `import numpy`, `import pandas`가 아무 준비 없이 됩니다. 실제로 몇 버전이 들어 있는지 확인해 봅니다.

```run
import numpy as np
import pandas as pd

print("numpy :", np.__version__)
print("pandas:", pd.__version__)
```

버전 번호가 나왔다면 두 라이브러리가 **이미 설치되어 있다**는 뜻입니다. 이 사이트(와 Google Colab)는 자주 쓰는 라이브러리를 미리 깔아 둔 환경입니다.

그런데 파이썬을 막 설치한 내 컴퓨터에서 같은 코드를 실행하면 이런 에러가 납니다.

```text
ModuleNotFoundError: No module named 'pandas'
```

[모듈과 import: 남이 만든 도구 상자 쓰기](#/l/pb-13-1)에서 배운 것처럼 `math`, `random` 같은 **표준 라이브러리**는 파이썬과 함께 들어오지만, `numpy`, `pandas` 같은 **외부 라이브러리**는 따로 설치해야 합니다. 이 설치를 맡는 도구가 **pip**입니다.

데이터 분석을 하면 거의 모든 일을 외부 라이브러리 위에서 합니다. 그래서 설치 · 버전 · 환경을 다루는 법은 문법만큼 중요한 기본기입니다. 이 PART에서는 세 가지를 배웁니다.

1. **pip**으로 라이브러리를 설치 · 확인 · 업그레이드 · 삭제하기 (이번 레슨)
2. **가상환경**으로 프로젝트마다 따로 쓰는 파이썬 만들기
3. **requirements.txt**로 환경을 저장하고 다른 컴퓨터에서 되살리기

## pip과 PyPI

스마트폰에 앱을 깔 때를 떠올려 보세요. **앱 스토어**라는 창고가 있고, 거기서 앱을 찾아 받아 설치하고, 업데이트하고, 지웁니다.

파이썬에서는

- 창고 = **PyPI**(파이피아이, Python Package Index, [pypi.org](https://pypi.org)). 전 세계 사람들이 만든 파이썬 패키지 수십만 개가 올라와 있습니다.
- 앱 스토어 앱 = **pip**. PyPI에서 패키지를 찾아 받아 **설치 · 업그레이드 · 다운그레이드 · 삭제**합니다.

이름 pip은 **"pip installs packages"**(pip은 패키지를 설치한다)의 줄임말로 알려져 있습니다. 파이썬 3.4부터는 파이썬을 설치하면 pip도 함께 들어옵니다.

::figure{src="content/img/env/pip-pypi.svg" alt="왼쪽 PyPI 창고에 numpy, pandas, matplotlib 같은 패키지가 있고, 가운데 pip이 받아서 오른쪽 내 컴퓨터 파이썬의 site-packages 폴더에 설치한다. 아래에 설치, 업그레이드, 버전 지정, 삭제 명령 네 개가 있다" caption="pip은 PyPI 창고에서 패키지를 받아 내 파이썬의 site-packages 폴더에 넣고 관리합니다."}

설치된 패키지는 파이썬 폴더 안의 **site-packages**라는 폴더에 모입니다. `import pandas`를 하면 파이썬이 이 폴더에서 pandas를 찾습니다. 다음 레슨의 가상환경을 이해할 때 이 폴더가 중요한 열쇠가 됩니다.

## 명령은 어디에 칠까

pip을 처음 쓸 때 가장 많이 하는 실수는 **명령을 엉뚱한 곳에 치는 것**입니다. 화면에 글자를 칠 수 있는 곳이 세 군데 있고, 각자 알아듣는 말이 다릅니다.

::figure{src="content/img/env/pip-where.svg" alt="세 개의 창. 첫째 터미널에서는 pip install pandas가 그대로 된다. 둘째 파이썬 대화형 >>> 에서 pip install pandas를 치면 SyntaxError가 난다. 셋째 노트북 셀에서는 %pip install pandas 또는 !pip install pandas처럼 앞에 기호를 붙인다" caption="pip은 파이썬 코드가 아니라 터미널 명령입니다. 노트북 셀에서는 앞에 %를 붙입니다."}

- **터미널**(Windows의 명령 프롬프트 · PowerShell, macOS의 터미널, VS Code 아래쪽 터미널): 줄 앞에 `C:\project>` 나 `$` 가 보입니다. **pip 명령은 여기에** 칩니다.
- **파이썬 대화형**: 터미널에서 `python` 을 치면 줄 앞이 `>>>` 로 바뀝니다. 여기는 파이썬 코드만 받으므로 pip 명령을 치면 `SyntaxError`가 납니다. `exit()` 로 빠져나와 터미널로 돌아갑니다.
- **노트북 셀**(Jupyter, Colab): 셀은 파이썬 코드 칸입니다. 셀에서 설치하려면 앞에 `%` 를 붙인 `%pip install pandas` 를 씁니다. `%pip` 은 **지금 이 노트북이 쓰는 파이썬**에 설치해 줍니다. Colab에서는 `!pip install` 도 많이 씁니다.

이 레슨의 명령 블록에서는 터미널 줄 앞 표시(`C:\project>`, `$`)를 빼고 **칠 내용만** 적습니다.

## pip 준비하기

터미널을 열고 pip이 있는지, 몇 버전인지 확인합니다.

```bash
pip --version
```

```text
pip 24.2 from C:\Users\me\AppData\Local\Programs\Python\Python312\Lib\site-packages\pip (python 3.12)
```

결과 끝의 `(python 3.12)` 는 **이 pip이 어느 파이썬에 연결돼 있는지**를 알려 줍니다. 컴퓨터에 파이썬이 여러 개 있을 때 이 부분이 중요해집니다(아래 `python -m pip`에서 다시 봅니다).

pip 자신도 가끔 업데이트가 필요합니다. 설치할 때 "A new release of pip is available" 안내가 보이면 아래 명령으로 올립니다.

```bash
python -m pip install --upgrade pip
```

`pip` 명령을 찾을 수 없다고 나오면 pip이 망가졌거나 빠진 경우라, 파이썬에 들어 있는 복구 도구로 다시 깝니다.

```bash
python -m ensurepip --upgrade
```

## 설치하기

패키지 이름을 붙여 `install` 합니다. 이름 여러 개를 띄어 쓰면 한 번에 설치됩니다.

```bash
pip install numpy
pip install pandas matplotlib seaborn
```

```text
Collecting pandas
  Downloading pandas-2.2.2-cp312-cp312-win_amd64.whl (11.5 MB)
Collecting python-dateutil>=2.8.2 (from pandas)
...
Successfully installed pandas-2.2.2 python-dateutil-2.9.0 pytz-2024.1 tzdata-2024.1
```

pandas 하나를 설치했는데 `python-dateutil`, `pytz` 같은 다른 패키지도 같이 깔렸습니다. pandas가 날짜 계산에 이 패키지들을 빌려 쓰기 때문입니다. 이렇게 **한 패키지가 쓰는 다른 패키지**를 **의존성**(dependency)이라고 하고, pip이 알아서 함께 설치합니다.

## 버전 번호 읽기

패키지 이름 뒤의 `2.2.2` 같은 숫자가 **버전**입니다. 보통 점으로 나뉜 세 숫자이고 각 자리의 뜻이 정해져 있습니다.

| 자리 | 예 (`2.2.2`) | 바뀌면 | 비유 |
| --- | --- | --- | --- |
| 주(major) | **2**.2.2 | 사용법이 크게 바뀜. 옛 코드가 안 돌 수 있음 | 교과서 개정판 |
| 부(minor) | 2.**2**.2 | 기능 추가. 옛 코드는 대체로 그대로 돎 | 단원 추가 |
| 수(patch) | 2.2.**2** | 버그 수정 | 오타 수정 |

그래서 "pandas 1.x 코드가 2.x에서 안 돈다"는 말이 나옵니다. 주 버전이 바뀌면 함수 이름이나 기본 동작이 바뀌는 일이 있기 때문입니다.

## 버전 지정 · 업그레이드 · 다운그레이드 · 삭제

**특정 버전으로 설치**하려면 이름 뒤에 `==버전` 을 붙입니다. 이미 다른 버전이 깔려 있으면 지우고 그 버전으로 바꿉니다. 지금보다 낮은 버전이면 **다운그레이드**가 됩니다.

```bash
pip install pandas==2.2.2
```

**최신 버전으로 올리기**(업그레이드)는 `--upgrade`(줄여서 `-U`)입니다.

```bash
pip install --upgrade numpy
```

**삭제**는 `uninstall` 입니다. 정말 지울지 `Proceed (Y/n)?` 하고 물으면 `y` 를 칩니다. 묻지 않고 바로 지우려면 `-y` 를 붙입니다.

```bash
pip uninstall matplotlib
pip uninstall -y matplotlib
```

> 의존성으로 같이 깔린 패키지(`pytz` 등)는 `uninstall` 해도 남아 있습니다. 깨끗하게 처음부터 다시 하고 싶을 때가 바로 다음 레슨의 가상환경이 빛나는 순간입니다. 폴더째 지우고 새로 만들면 되기 때문입니다.

## 무엇이 깔려 있나: list · show

**설치된 패키지 전체 목록**은 `list` 입니다.

```bash
pip list
```

```text
Package         Version
--------------- -------
numpy           1.26.4
pandas          2.2.2
pip             24.2
python-dateutil 2.9.0
...
```

목록이 길면 글자로 거릅니다. 이름에 `py` 가 들어간 것만 보려면 운영체제에 맞게 씁니다. `|`(파이프)는 "앞 명령의 결과를 뒤 명령에 넘긴다"는 뜻입니다.

```bash
pip list | findstr py      # Windows
pip list | grep py         # macOS · Linux
```

**패키지 하나의 자세한 정보**는 `show` 입니다. 버전, 설치 위치, 이 패키지가 필요로 하는 것(Requires), 이 패키지를 필요로 하는 것(Required-by)이 나옵니다.

```bash
pip show pandas
```

```text
Name: pandas
Version: 2.2.2
Summary: Powerful data structures for data analysis, time series, and statistics
Location: C:\Users\me\...\Lib\site-packages
Requires: numpy, python-dateutil, pytz, tzdata
Required-by: seaborn
```

`pip show` 와 같은 정보는 **파이썬 코드 안에서도** 볼 수 있습니다. 표준 라이브러리 `importlib.metadata` 가 설치된 패키지의 정보표를 읽어 줍니다. 이 사이트에 깔린 pandas를 확인해 봅니다.

```run
from importlib.metadata import version, requires

print("pandas 버전:", version("pandas"))
print("pandas가 필요로 하는 것:")
for r in (requires("pandas") or [])[:4]:
    print(" -", r)
```

`requires` 결과 앞부분에 `numpy>=…` 같은 줄이 보입니다. pandas가 NumPy 위에 지어졌다는 것이 설치 정보에도 그대로 적혀 있습니다. 버전 숫자는 환경마다 다르니 내 화면의 숫자를 읽어 보세요.

이번에는 패키지 이름을 바꿔 가며 버전을 확인해 보세요. `"numpy"`, `"matplotlib"` 은 있고, 설치되지 않은 이름을 넣으면 어떻게 되는지도 봅니다.

```run
from importlib.metadata import version, PackageNotFoundError

for name in ["numpy", "matplotlib", "없는패키지"]:   # 이름을 바꿔 보세요
    try:
        print(name, version(name))
    except PackageNotFoundError:
        print(name, "→ 설치되어 있지 않음 (pip install 이 필요)")
```

설치되지 않은 이름은 `PackageNotFoundError` 가 나서 "설치되어 있지 않음"으로 출력됩니다. 내 PC에서 `ModuleNotFoundError` 를 만났을 때 바로 이 상태입니다.

## pip 대신 python -m pip을 쓰는 이유

컴퓨터에 파이썬이 **둘 이상** 있는 경우가 생각보다 흔합니다. python.org에서 하나 깔고, 나중에 Anaconda를 또 깔았다거나, 버전이 다른 파이썬이 남아 있는 경우입니다. 이때 그냥 `pip install` 을 치면 **터미널이 먼저 찾은 pip**이 설치합니다. 그 pip이 내가 코드를 실행하는 파이썬과 다른 파이썬에 연결돼 있으면, 분명히 설치했는데 `ModuleNotFoundError` 가 납니다.

::figure{src="content/img/env/pip-which-python.svg" alt="컴퓨터에 파이썬 A와 파이썬 B가 있다. pip install pandas는 어느 쪽에 설치될지 물음표로 두 갈래 점선 화살표가 간다. python -m pip install pandas는 지금 python으로 실행되는 파이썬 A로 실선 화살표가 간다" caption="python -m pip 은 '지금 python 명령이 가리키는 바로 그 파이썬'의 pip을 씁니다."}

`python -m pip` 은 "**python** 을 실행하되, 그 파이썬에 들어 있는 **pip 모듈**(-m)을 돌려라"라는 뜻입니다. 그래서 **코드를 실행할 파이썬과 설치되는 파이썬이 항상 같습니다**. 명령이 조금 길어도 실무에서는 이 형태를 권합니다(macOS에서 `python` 이 없으면 `python3 -m pip`).

```bash
python -m pip install scikit-learn
```

지금 코드를 실행하는 파이썬이 어디에 있는지는 `sys.executable` 로 확인합니다. 내 PC에서 "설치했는데 import가 안 될 때" 제일 먼저 찍어 보는 줄입니다.

```run
import sys

print("지금 파이썬 위치:", sys.executable or "(브라우저 안 파이썬이라 경로 없음)")
print("파이썬 버전:", sys.version.split()[0])
```

이 사이트는 브라우저 안에서 도는 파이썬이라 위치가 특별하게 나옵니다. 내 PC에서 실행하면 `C:\...\python.exe` 같은 경로가 나오고, 그 경로가 `pip --version` 결과의 경로와 같은 파이썬인지 비교하면 됩니다.

## 명령어 한눈에 보기

| 명령어 | 하는 일 | 예시 |
| --- | --- | --- |
| `pip --version` | pip 버전과 연결된 파이썬 확인 | `pip --version` |
| `pip list` | 설치된 패키지 목록 | `pip list` |
| `pip list \| findstr 글자` | 글자가 들어간 패키지만 (Windows, macOS는 `grep`) | `pip list \| findstr py` |
| `pip show 이름` | 패키지 하나의 자세한 정보 | `pip show pandas` |
| **`pip install 이름`** | 설치 | `pip install numpy` |
| **`pip install 이름==버전`** | 특정 버전 설치 · 다운그레이드 | `pip install pandas==2.2.2` |
| `pip install --upgrade 이름` | 최신 버전으로 업그레이드 | `pip install --upgrade numpy` |
| `pip uninstall 이름` | 삭제 | `pip uninstall matplotlib` |
| `pip freeze` | 설치 목록을 `이름==버전` 모양으로 출력 ([requirements.txt로 환경 저장하고 되살리기](#/l/da-00-3)에서 자세히) | `pip freeze` |
| `pip freeze > requirements.txt` | 그 목록을 파일로 저장 | `pip freeze > requirements.txt` |
| `pip install -r requirements.txt` | 파일 목록대로 설치 | `pip install -r requirements.txt` |
| `pip cache dir` | 내려받은 파일 보관 폴더 위치 | `pip cache dir` |
| `pip cache purge` | 그 보관 폴더 비우기 (디스크가 부족할 때) | `pip cache purge` |
| **`python -m pip install 이름`** | 지금 python 기준으로 설치 (권장) | `python -m pip install scikit-learn` |
| `python -m pip install --upgrade pip` | pip 자신 업그레이드 | |
| `python -m ensurepip --upgrade` | pip 복구 · 다시 설치 | |

> `pip search 이름` 은 예전 자료에 자주 나오지만, 지금은 PyPI 쪽에서 막혀 **에러가 납니다**. 패키지는 [pypi.org](https://pypi.org)에서 검색하세요. 검색 결과 페이지에 설치 명령(`pip install ...`)과 최신 버전이 함께 나옵니다.

## 현업에서는

데이터 분석을 하다 보면 코드보다 **설치 · 버전 충돌 · 환경 문제**에 시간을 더 쓰는 날이 생깁니다. "어제는 되던 코드가 오늘 안 돌아요", "제 컴퓨터에서는 되는데 팀장님 컴퓨터에서는 안 돼요"의 원인 대부분이 여기에 있습니다. 다음 두 레슨의 **가상환경**과 **requirements.txt**가 이 문제를 막는 표준 습관입니다.

## 정리

- 외부 라이브러리는 **pip**으로 **PyPI**에서 받아 설치한다. 설치된 패키지는 파이썬의 `site-packages` 폴더에 모인다.
- pip은 **터미널** 명령이다. 파이썬 `>>>` 에서는 에러, 노트북 셀에서는 `%pip install`.
- 설치 `install`, 버전 지정 `==`, 업그레이드 `--upgrade`, 삭제 `uninstall`, 확인 `list` · `show`.
- 버전 `주.부.수` 에서 **주 버전**이 바뀌면 옛 코드가 안 돌 수 있다.
- 파이썬이 여러 개일 수 있으니 **`python -m pip`** 으로 설치하면 실행할 파이썬과 설치되는 파이썬이 같다.
