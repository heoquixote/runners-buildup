## 시작하기 전에

[시계열을 표로 바꾸기](#/l/ts-08-1)에서 래그, 이동평균, 요일 특성을 만들었습니다. 이제 그 표로 회귀 모델을 학습시키고, 앞에서 만든 예측들과 비교합니다.

이번 레슨의 과제는 **"오늘 밤에 내일 하루의 대여 수 예측하기"** 입니다. 내일의 기온과 강수량은 일기예보로 안다고 가정합니다(하루 앞 예보는 꽤 정확합니다). [SARIMAX: 바깥 변수 넣기](#/l/ts-07-4)에서 본 것처럼, 이 가정이 맞지 않는 먼 미래 예측에는 날씨를 이렇게 쓸 수 없습니다.

## 나누고 학습하기

빈칸이 있는 맨 앞 7행을 빼고, 마지막 28일을 시험용으로 둡니다. 특성은 `lag1`, `lag7`, `roll7`, `dow`, `weekend`, `temp`, `rain` 일곱 개입니다. [선형회귀: 직선 하나로 예측하기](#/l/ml-02-1)와 [랜덤포레스트: 여러 트리의 투표](#/l/ml-04-3)에서 배운 두 모델을 씁니다.

```run
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
day["lag1"] = day["rented"].shift(1)
day["lag7"] = day["rented"].shift(7)
day["roll7"] = day["rented"].shift(1).rolling(7).mean()
day["dow"] = day.index.dayofweek
day["weekend"] = (day["dow"] >= 5).astype(int)
data = day.dropna()
features = ["lag1", "lag7", "roll7", "dow", "weekend", "temp", "rain"]
train, test = data.iloc[:-28], data.iloc[-28:]
print("train:", len(train), "/ test:", len(test))
models = {"linear": LinearRegression(), "forest": RandomForestRegressor(n_estimators=200, random_state=0, n_jobs=1)}
for name, model in models.items():
    pred = model.fit(train[features], train["rented"]).predict(test[features])
    print(f"{name:>6}: MAE = {abs(test['rented'] - pred).mean():.0f}")
```

선형회귀의 MAE는 **2,344**, 랜덤포레스트는 3,054입니다. 이 시험 구간에서는 단순한 선형회귀가 더 좋습니다.

## 무엇이 중요했나

[무엇을 많이 봤나: 피처 중요도와 순열 중요도](#/l/ml-09-1)에서 배운 피처 중요도로 랜덤포레스트가 어떤 특성에 기댔는지 봅니다.

```run
import pandas as pd
from sklearn.ensemble import RandomForestRegressor

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
day["lag1"] = day["rented"].shift(1)
day["lag7"] = day["rented"].shift(7)
day["roll7"] = day["rented"].shift(1).rolling(7).mean()
day["dow"] = day.index.dayofweek
day["weekend"] = (day["dow"] >= 5).astype(int)
data = day.dropna()
features = ["lag1", "lag7", "roll7", "dow", "weekend", "temp", "rain"]
train, test = data.iloc[:-28], data.iloc[-28:]
forest = RandomForestRegressor(n_estimators=200, random_state=0, n_jobs=1).fit(train[features], train["rented"])
for name, score in sorted(zip(features, forest.feature_importances_), key=lambda t: -t[1]):
    print(f"{name:>8}: {score:.3f}")
```

기온(`temp`)이 0.529로 절반을 넘고, 강수량(`rain`) 0.164, 지난 7일 평균(`roll7`) 0.154, 어제 값(`lag1`) 0.106 순입니다. 요일(`dow` 0.009)과 주말 여부(0.002)는 거의 쓰이지 않았습니다.

[어제가 오늘을 말해 준다: 자기상관과 ACF](#/l/ts-03-1)에서 따릉이 일별 데이터의 일주일 주기가 생각보다 약했던 것과 맞아떨어집니다. 이 데이터는 **달력보다 날씨**가 수요를 좌우합니다.

## 날씨 특성을 빼면

날씨 없이 자기 자신의 과거와 달력만으로 예측하면 어떻게 될까요?

```run
import pandas as pd
from sklearn.ensemble import RandomForestRegressor

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
day["lag1"] = day["rented"].shift(1)
day["lag7"] = day["rented"].shift(7)
day["roll7"] = day["rented"].shift(1).rolling(7).mean()
day["dow"] = day.index.dayofweek
day["weekend"] = (day["dow"] >= 5).astype(int)
data = day.dropna()
features = ["lag1", "lag7", "roll7", "dow", "weekend", "temp", "rain"]
train, test = data.iloc[:-28], data.iloc[-28:]
use = ["lag1", "lag7", "roll7", "dow", "weekend"]
forest = RandomForestRegressor(n_estimators=200, random_state=0, n_jobs=1).fit(train[use], train["rented"])
pred = forest.predict(test[use])
print("features:", use)
print("MAE =", round(abs(test["rented"] - pred).mean()))
```

MAE가 3,054에서 **3,548**로 나빠집니다. 날씨 예보를 쓸 수 있는 하루 앞 예측에서는 날씨 특성이 확실히 도움이 됩니다.

아래 셀에서 `use` 목록에 `"temp"`만 더해 보세요. 기온 하나만 넣어도 얼마나 회복되는지 확인할 수 있습니다.

## 여러 원점에서 비교하기

한 구간의 결과만으로 "선형회귀가 낫다"고 결론 내리면 안 됩니다. [시간 순서대로 검증하기: 롤링 원점](#/l/ts-05-3)의 방법으로 다섯 구간에서 비교합니다. 기준 예측으로는 "내일 = 오늘"(`lag1` 그대로)을 둡니다.

```run
import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import TimeSeriesSplit

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
day["lag1"] = day["rented"].shift(1)
day["lag7"] = day["rented"].shift(7)
day["roll7"] = day["rented"].shift(1).rolling(7).mean()
day["dow"] = day.index.dayofweek
day["weekend"] = (day["dow"] >= 5).astype(int)
data = day.dropna()
features = ["lag1", "lag7", "roll7", "dow", "weekend", "temp", "rain"]
train, test = data.iloc[:-28], data.iloc[-28:]
rows = []
for tr, te in TimeSeriesSplit(n_splits=5, test_size=28).split(data):
    a, b = data.iloc[tr], data.iloc[te]
    row = {"start": b.index[0].strftime("%m-%d"), "naive(lag1)": abs(b["rented"] - b["lag1"]).mean()}
    for name, model in [("linear", LinearRegression()), ("forest", RandomForestRegressor(n_estimators=200, random_state=0, n_jobs=1))]:
        row[name] = abs(b["rented"] - model.fit(a[features], a["rented"]).predict(b[features])).mean()
    rows.append(row)
result = pd.DataFrame(rows).set_index("start").round(0)
print(result)
print("mean:", result.mean().round(0).to_dict())
```

| 시험 시작 | naive | 선형회귀 | 랜덤포레스트 |
| --- | --- | --- | --- |
| 7월 14일 | **2,282** | 8,581 | 5,850 |
| 8월 11일 | 5,331 | 4,527 | **2,765** |
| 9월 8일 | 4,374 | 4,602 | **3,991** |
| 10월 6일 | 3,269 | **3,240** | 4,580 |
| 11월 3일 | 3,551 | **2,344** | 3,054 |
| 평균 | **3,761** | 4,659 | 4,048 |

결과가 뜻밖입니다. 평균으로는 **naive가 가장 좋고**, 구간마다 승자가 다릅니다. 특히 7월 14일 구간에서 선형회귀의 MAE가 8,581로 크게 무너졌습니다.

## 선형회귀는 왜 한여름에 무너졌을까

이 데이터는 2017년 12월에 시작합니다. 7월 14일 구간을 예측하는 모델은 12월 ~ 7월 초의 데이터로 학습했습니다. 겨울에서 초여름으로 가는 동안에는 **"기온이 오를수록 대여가 는다"** 는 관계가 한결같았습니다. 선형회귀는 이것을 직선으로 배웠습니다.

그런데 2018년 7월 중순 ~ 8월은 기록적인 폭염이었습니다. 기온이 35도를 넘자 사람들은 자전거를 **덜** 탔습니다. 모델은 처음 보는 높은 기온에 직선을 그대로 연장해 "역대 최다 대여"를 예측했고, 실제는 반대였습니다.

- 선형 모델은 학습 범위 밖에서도 **직선을 그대로 연장**합니다. 관계가 꺾이는 지점을 본 적이 없으면 크게 틀립니다.
- 랜덤포레스트는 학습 범위 밖 값을 만나면 **가장 가까운 경험값 근처**에 머물러서(5,850) 덜 틀렸습니다.
- 한여름을 학습 데이터에 포함한 뒤(8월 11일 구간부터)에는 두 모델 모두 안정됩니다.

이것은 [시계열은 무엇이 다를까](#/l/ts-00-1)에서 말한 "미래는 과거와 비슷하다"는 가정이 깨진 예입니다. **1년이 채 안 되는 데이터로는 사계절을 한 번도 다 보지 못합니다.** 계절이 있는 데이터는 적어도 2 ~ 3주기를 모아야 모델을 믿을 수 있습니다.

## 지금까지의 예측 방법 비교

| | 지수평활 · ARIMA | 머신러닝 회귀 |
| --- | --- | --- |
| 입력 | 시계열 하나 (+ 바깥 변수) | 직접 만든 특성 표 |
| 추세 · 계절성 | 모델이 직접 다룬다 | 특성으로 만들어 줘야 한다 |
| 바깥 변수 여러 개 | 넣을 수 있지만 번거롭다 | 쉽게 넣는다 |
| 복잡한 관계 (폭염에 꺾이는 수요) | 다루기 어렵다 | 트리 모델이 다룬다 (본 적 있는 범위에서) |
| 데이터가 적을 때 | 강하다 | 약하다 |
| 예측 구간 | 기본으로 준다 | 따로 만들어야 한다 |

어느 한쪽이 늘 이기지 않습니다. 시계열이 하나이고 짧으면 지수평활 · ARIMA가, 바깥 변수가 많고 데이터가 길면 머신러닝이 유리한 경우가 많습니다.

## 정리

- 특성 표를 만들면 선형회귀, 랜덤포레스트 등 어떤 회귀 모델이든 쓸 수 있습니다.
- 따릉이 하루 앞 예측에서 가장 중요한 특성은 기온(0.529)이었습니다.
- 다섯 구간으로 평가하자 구간마다 승자가 달랐고, 평균으로는 naive가 가장 좋았습니다.
- 학습 때 보지 못한 상황(폭염)에서 모델은 크게 틀립니다. 계절 데이터는 여러 주기를 모아야 합니다.
