## 시작하기 전에

[이상의 세 종류와 이동 z-점수](#/l/ts-09-1)에서 고정 한계선으로 점 이상을 찾았습니다. 이번 레슨에서는 두 가지를 배웁니다.

1. 고정 한계선으로는 절대 잡을 수 없는 **맥락 이상**을 분해로 찾는 법
2. 경보 규칙이 좋은지 나쁜지를 **정밀도와 재현율로 평가**하는 법

## 한계선으로는 보이지 않는 이상

2018년 6월의 시간별 따릉이 대여 수를 봅니다. 평균과 표준편차로 고정 한계선을 만들 수 있을까요?

```run
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts").loc["2018-06"]
rented = june["rented_bikes"].asfreq("h")
print("mean:", round(rented.mean()), "/ std:", round(rented.std()), "/ mean - 2 std:", round(rented.mean() - 2 * rented.std()))
print("lowest value:", rented.min())
by_hour = rented.groupby(rented.index.hour).mean()
print("usual at 04:00:", round(by_hour[4]), "/ usual at 18:00:", round(by_hour[18]))
print("2018-06-26 18:00:", rented["2018-06-26 18:00"])
```

평균 1,246, 표준편차 769라서 "평균 − 2 × 표준편차"가 **−292**입니다. 대여 수는 0보다 작을 수 없으니 이 한계선은 **절대 울리지 않습니다.** 이 달의 최솟값은 9입니다.

그런데 6월 26일 18시의 대여 수는 **156**입니다. 평소 18시에는 평균 2,494대를 빌립니다. 퇴근 시간에 새벽 4시(평균 241대)보다도 적게 빌린 것입니다. 156이라는 숫자 자체는 새벽마다 나오는 흔한 값이라 한계선에 걸리지 않지만, **"저녁 6시의 156"** 은 분명히 이상합니다. 이것이 맥락 이상입니다.

## 계절성을 빼고 남은 것에서 찾기

맥락 이상을 찾으려면 "이 시각의 평소 값"을 먼저 빼야 합니다. [STL과 여러 겹의 계절성](#/l/ts-02-3)에서 배운 STL로 추세와 하루 주기를 빼고, **남은 잔차에서** 튀는 값을 찾습니다.

여기서 두 가지 장치를 씁니다.

- **`robust=True`**: 이상한 값이 계절 모양 자체를 망가뜨리지 않도록 합니다. 이 옵션이 없으면 폭우가 온 날의 낮은 값이 "평소 18시의 모양"을 끌어내립니다.
- **MAD로 만든 척도**: 잔차의 표준편차 대신 중앙값 절대 편차(MAD)에 1.4826을 곱한 값을 씁니다. 표준편차는 이상한 값 몇 개에 크게 부풀지만, 중앙값으로 만든 MAD는 거의 흔들리지 않습니다. [센서 시계열 다듬기](#/l/da-08-3)에서 평균 대신 이동 중앙값을 쓴 것과 같은 이유입니다.

```run
import matplotlib.pyplot as plt
import pandas as pd
from statsmodels.tsa.seasonal import STL

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts").loc["2018-06"]
rented = june["rented_bikes"].asfreq("h")
resid = STL(rented, period=24, robust=True).fit().resid
scale = 1.4826 * (resid - resid.median()).abs().median()
z = (resid - resid.median()) / scale
fig, ax = plt.subplots(figsize=(10, 3))
ax.plot(z.index, z.values, linewidth=0.7)
ax.axhline(-4, color="crimson", linestyle="--")
print("plain std of residual:", round(resid.std()), "/ robust scale:", round(scale))
print("z at 2018-06-26 18:00:", round(z["2018-06-26 18:00"], 1))
alarm = z < -4
print("alarm hours:", int(alarm.sum()))
```

- 잔차의 보통 표준편차는 435인데, MAD로 만든 척도는 **99**입니다. 이상한 값들이 표준편차를 네 배 넘게 부풀리고 있었습니다. 부풀려진 표준편차로 z-점수를 만들면 진짜 이상도 작게 보입니다.
- 6월 26일 18시의 z-점수는 **−26.1**입니다. 한계선으로는 보이지 않던 값이 잔차에서는 압도적으로 튑니다.
- z가 −4보다 작은 시간은 67시간입니다.

## 경보가 맞는지 확인하기

이 데이터에는 "이상" 라벨이 없습니다. 대신 같은 표에 **강수량과 공휴일 열**이 있으니, 경보가 울린 시간에 실제로 무슨 일이 있었는지 대조할 수 있습니다.

```run
import pandas as pd
from statsmodels.tsa.seasonal import STL

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts").loc["2018-06"]
rented = june["rented_bikes"].asfreq("h")
resid = STL(rented, period=24, robust=True).fit().resid
scale = 1.4826 * (resid - resid.median()).abs().median()
z = (resid - resid.median()) / scale
alarm = z < -4
rain = june["rainfall"] > 0
holiday = june["holiday"] == "Yes"
print("share of rainy hours, whole month :", round(rain.mean(), 2))
print("share of rainy hours, alarm hours :", round(rain[alarm].mean(), 2))
print("alarm hours on the holiday (06-06):", int((alarm & holiday).sum()))
worst = z.nsmallest(5)
print(pd.DataFrame({"z": worst.round(1), "rented": rented[worst.index], "rain_mm": june.loc[worst.index, "rainfall"]}))
```

- 6월 전체에서 비가 온 시간은 7%인데, 경보가 울린 시간 중에서는 **39%** 가 비 오는 시간이었습니다. 경보가 비와 뚜렷하게 연결됩니다.
- 6월 6일 현충일에 7시간 울렸습니다. 공휴일에는 출퇴근 수요가 없어서 평소 평일 패턴보다 낮게 나옵니다.
- 가장 크게 튄 다섯 시간 중 넷은 비가 온 저녁입니다. 나머지 하나인 6월 18일 18시(746대)는 비가 오지 않았습니다. 이 날 저녁에는 러시아 월드컵 한국 대 스웨덴 경기가 있었습니다. 데이터만으로 원인을 단정할 수는 없지만, 경보가 "뭔가 평소와 다른 일이 있었던 시간"을 짚어 낸 것은 분명합니다.

이상 탐지는 여기까지입니다. 경보는 **"평소와 다르다"** 까지만 알려 주고, **"왜 다른가"** 는 사람이 다른 정보와 맞춰 보며 찾아야 합니다.

## 이 방법이 맞지 않는 데이터

같은 방법을 설비 온도에 써도 될까요? 먼저 하루 주기가 있는지부터 확인합니다.

```run
import pandas as pd
from statsmodels.tsa.stattools import acf

m = pd.read_csv("machine_temp.csv", parse_dates=["timestamp"]).set_index("timestamp")["temp"]
hourly = m.resample("h").mean()

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts").loc["2018-06"]
rented = june["rented_bikes"].asfreq("h")
a_bike = acf(rented, nlags=48)
a_machine = acf(hourly, nlags=48)
print("bike    ACF lag 24, 48:", a_bike[[24, 48]].round(2).tolist())
print("machine ACF lag 24, 48:", a_machine[[24, 48]].round(2).tolist())
by_hour = hourly.groupby(hourly.index.hour).mean()
print("machine: highest hourly mean", round(by_hour.max(), 1), "/ lowest", round(by_hour.min(), 1))
```

따릉이는 래그 24, 48의 자기상관이 0.60, 0.67로 하루 주기가 뚜렷합니다. 설비 온도는 래그 24가 0.31, 래그 48이 0.02로 주기가 없습니다. 시각별 평균도 83.6 ~ 87.6으로 거의 같습니다. 설비는 밤낮없이 같은 조건으로 돌아가기 때문입니다.

**뺄 계절성이 없는 데이터에 STL을 쓰면** 있지도 않은 주기를 억지로 만들어 빼게 되어 오히려 잡음이 늘어납니다. 방법은 데이터의 성격에 맞춰 고릅니다.

| 데이터의 성격 | 알맞은 방법 |
| --- | --- |
| 수준이 일정하고 주기가 없다 (연속 가동 설비) | 고정 한계선 |
| 주기가 뚜렷하다 (수요, 트래픽, 전력) | 분해 후 잔차 |
| 수준이 천천히 변한다 | 이동 중앙값 기준, 또는 분해 후 잔차 |

## 경보 규칙 평가하기: 정밀도와 재현율

설비 데이터에는 이상 라벨 네 개가 있으니 경보 규칙을 숫자로 평가할 수 있습니다. [정밀도, 재현율, F1](#/l/ml-03-2)에서 배운 두 지표를 경보에 맞게 다시 정의합니다.

- **재현율**: 실제 이상 4건 중 몇 건을 잡았나. 이상 시점의 48시간 전부터 24시간 후 사이에 경보가 한 번이라도 울리면 잡은 것으로 봅니다.
- **정밀도**: 울린 경보 중 실제 이상 근처에서 울린 비율.

고정 한계선의 한계값을 −3, −2.5, −2, −1.5로 바꿔 가며 비교하고, 앞 레슨의 이동 z-점수도 함께 평가합니다.

```run
import pandas as pd

m = pd.read_csv("machine_temp.csv", parse_dates=["timestamp"]).set_index("timestamp")["temp"]
hourly = m.resample("h").mean()

labels = pd.to_datetime(["2013-12-11 06:00", "2013-12-16 17:00", "2014-01-28 13:00", "2014-02-08 14:00"])
def score(alarm, labels, before="48h", after="24h"):
    in_window = pd.Series(False, index=alarm.index)
    caught = 0
    for t in labels:
        win = (alarm.index >= t - pd.Timedelta(before)) & (alarm.index <= t + pd.Timedelta(after))
        in_window |= win
        caught += int(alarm[win].any())
    total = int(alarm.sum())
    precision = (alarm & in_window).sum() / total if total else 0.0
    false_days = len(set(alarm[alarm & ~in_window].index.date))
    return caught, total, precision, false_days
z = (hourly - hourly.mean()) / hourly.std()
past = hourly.shift(1).rolling(24)
z_roll = (hourly - past.mean()) / past.std()
rules = {"fixed z < -3.0": z < -3, "fixed z < -2.5": z < -2.5, "fixed z < -2.0": z < -2, "fixed z < -1.5": z < -1.5, "rolling |z| > 3": z_roll.abs() > 3}
for name, alarm in rules.items():
    caught, total, precision, false_days = score(alarm, labels)
    print(f"{name:>15}: caught {caught} of 4 | {total:>3} alarm hours | precision {precision:.2f} | false-alarm days {false_days}")
```

| 규칙 | 잡은 이상 | 정밀도 | 헛경보가 울린 날 |
| --- | --- | --- | --- |
| 고정 z < −3.0 | 2 / 4 | 1.00 | 0일 |
| 고정 z < −2.5 | 3 / 4 | 0.87 | 3일 |
| 고정 z < −2.0 | **4 / 4** | 0.74 | 6일 |
| 고정 z < −1.5 | 4 / 4 | 0.70 | 13일 |
| 이동 \|z\| > 3 | 4 / 4 | 0.24 | 36일 |

[임계값: 경보 감도 조절](#/l/ml-03-3)에서 본 줄다리기가 그대로 나타납니다. 한계값을 낮출수록(−3 → −2) 놓치는 이상은 줄지만 헛경보가 늘어납니다. −2에서 4건을 모두 잡았고, 더 낮춰 −1.5로 가면 잡는 것은 그대로인데 헛경보만 13일로 늘어납니다. 이동 z-점수는 4건을 모두 잡긴 했지만 정밀도 0.24, 헛경보 36일로 쓸 수 없는 수준입니다.

## 한계값은 비용으로 정한다

어느 한계값이 정답일까요? 숫자만으로는 정할 수 없고, **현장의 비용**을 따져야 합니다.

- 이상을 놓쳤을 때의 비용: 설비가 고장 나서 라인이 멈춘다. 매우 크다.
- 헛경보의 비용: 작업자가 가서 점검한다. 작지만, 너무 잦으면 경보 자체를 무시하게 된다.

80일 동안 헛경보 6일(−2.0)은 2주에 한 번꼴입니다. 고장 한 번의 피해가 점검 수십 번의 비용보다 크다면 충분히 받아들일 만합니다.

경보가 **얼마나 일찍** 울리는지도 중요합니다. 한계값 −2로 각 이상에 대해 첫 경보 시각을 봅니다.

```run
import pandas as pd

m = pd.read_csv("machine_temp.csv", parse_dates=["timestamp"]).set_index("timestamp")["temp"]
hourly = m.resample("h").mean()

labels = pd.to_datetime(["2013-12-11 06:00", "2013-12-16 17:00", "2014-01-28 13:00", "2014-02-08 14:00"])
z = (hourly - hourly.mean()) / hourly.std()
alarm = z < -2
for t in labels:
    near = alarm[t - pd.Timedelta("48h"): t + pd.Timedelta("24h")]
    first = near[near].index.min()
    print(f"event {t:%m-%d %H:%M}: first alarm {first:%m-%d %H:%M}")
```

2월 8일 14시의 고장에 대해 첫 경보가 **2월 7일 14시**, 하루 전에 울렸습니다. 12월 11일의 정지도 하루 전(10일 4시)에 울렸습니다. 고장 하루 전에 알 수 있다면 설비를 미리 세우고 점검할 시간을 벌 수 있습니다.

## 정리

- 맥락 이상은 값 자체가 흔해서 고정 한계선으로는 잡을 수 없습니다. 계절성을 뺀 잔차에서 찾습니다.
- 잔차의 척도는 이상한 값에 덜 흔들리는 MAD로 잡고, STL에는 `robust=True`를 씁니다.
- 주기가 없는 데이터에는 분해를 쓰지 않습니다. 방법은 데이터의 성격에 맞춥니다.
- 경보 규칙은 재현율(몇 건 잡았나)과 정밀도(헛경보가 얼마나 적나)로 평가하고, 한계값은 놓쳤을 때와 헛경보의 비용을 따져 정합니다.
