## 시작하기 전에

[시계열을 이루는 세 가지](#/l/ts-02-1)에서는 추세, 계절성, 잔차를 **더해서** 원래 값이 된다고 보았습니다. 이산화탄소 농도는 그렇게 잘 나뉘었습니다.

그런데 모든 시계열이 덧셈으로 나뉘지는 않습니다. 이번 레슨에서는 계절 물결의 **높이가 점점 커지는** 데이터를 다루는 법을 배웁니다.

## "50명 더"와 "20% 더"

놀이공원 입장객이 여름마다 늘어난다고 해 봅시다. 늘어나는 방식은 두 가지일 수 있습니다.

- **덧셈형**: 여름에는 평소보다 **5,000명** 더 온다. 평소 입장객이 1만 명이든 10만 명이든 늘 5,000명입니다.
- **곱셈형**: 여름에는 평소보다 **20%** 더 온다. 평소 1만 명일 때는 2,000명, 10만 명일 때는 2만 명이 늘어납니다.

::figure{src="content/img/ts/ts02-add-mul.svg" alt="덧셈형은 추세가 올라가도 물결 높이가 일정하고, 곱셈형은 추세가 올라갈수록 물결 높이가 함께 커진다" caption="그래프에서 물결의 높이가 일정하면 덧셈형, 수준이 높아질수록 커지면 곱셈형입니다."}

| | 덧셈 분해 | 곱셈 분해 |
| --- | --- | --- |
| 식 | 값 = 추세 + 계절 + 잔차 | 값 = 추세 × 계절 × 잔차 |
| 계절 성분의 단위 | 원래 단위 (+50명) | 배율 (×1.2) |
| 그래프 모양 | 물결 높이가 일정 | 수준이 오를수록 물결이 커짐 |
| 흔한 예 | 기온, 이산화탄소 농도 | 매출, 승객 수, 방문자 수 |

사람이나 돈과 관련된 숫자는 대부분 곱셈형입니다. 회사가 두 배로 크면 성수기 매출 증가분도 두 배가 되기 때문입니다.

## 항공 승객은 어느 쪽일까

연도별로 가장 적은 달과 가장 많은 달을 뽑아, 그 차이(`swing`)와 비율(`ratio`)을 봅니다.

```run
import pandas as pd

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
by_year = y.groupby(y.index.year).agg(["min", "max", "mean"])
by_year["swing"] = by_year["max"] - by_year["min"]
by_year["ratio"] = (by_year["max"] / by_year["min"]).round(2)
print(by_year.loc[[1949, 1952, 1956, 1960]].round(1))
```

한 해 안의 차이는 1949년 44천 명에서 1960년 232천 명으로 **다섯 배** 넘게 커졌습니다. 반면 비율은 1.4 ~ 1.6으로 비슷합니다. "여름에는 몇 명 더"가 아니라 "여름에는 몇 배"로 움직이는 **곱셈형**입니다.

## 덧셈 분해를 하면 생기는 일

`seasonal_decompose`는 앞 레슨에서 손으로 했던 일(이동평균으로 추세 → 같은 달 평균으로 계절성 → 나머지가 잔차)을 한 번에 해 줍니다. 먼저 일부러 `model="additive"`(덧셈)로 분해합니다. `period=12`는 주기가 12개월이라는 뜻입니다.

```run
import matplotlib.pyplot as plt
import pandas as pd
from statsmodels.tsa.seasonal import seasonal_decompose

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
res = seasonal_decompose(y, model="additive", period=12)
res.plot()
print("seasonal (Jan~Dec):", res.seasonal[:12].round(1).tolist())
july = res.resid[res.resid.index.month == 7].dropna()
print("July residual by year:", july.round(0).astype(int).tolist())
```

계절 성분은 7월 +63.8, 11월 −53.6입니다. "7월에는 추세보다 63.8천 명 많다"는 **고정된 숫자 하나**입니다.

문제는 잔차에서 드러납니다. 7월의 잔차를 연도순으로 보면 −43, −35, −36 …으로 시작해서 … 32, 45, 53으로 끝납니다. 초반에는 +63.8이 너무 커서 실제가 그보다 한참 낮고, 후반에는 +63.8이 너무 작아서 실제가 그보다 높습니다. **잔차에 뚜렷한 패턴이 남았다**는 것은 분해가 데이터의 구조를 제대로 잡지 못했다는 신호입니다.

## 곱셈 분해

같은 데이터를 `model="multiplicative"`로 분해합니다.

```run
import matplotlib.pyplot as plt
import pandas as pd
from statsmodels.tsa.seasonal import seasonal_decompose

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
res = seasonal_decompose(y, model="multiplicative", period=12)
res.plot()
print("seasonal (Jan~Dec):", res.seasonal[:12].round(2).tolist())
july = res.resid[res.resid.index.month == 7].dropna()
print("July residual by year:", july.round(2).tolist())
```

계절 성분이 배율로 나옵니다. 7월은 1.23(추세의 123%), 11월은 0.80(추세의 80%)입니다. 곱셈 분해의 잔차는 1을 중심으로 움직이는데, 7월 잔차가 0.95 ~ 1.05 사이에 머뭅니다. 덧셈 분해에서 −43 ~ +53으로 벌어지던 것에 비하면 훨씬 고릅니다.

다만 여기서도 앞쪽은 1보다 조금 작고 뒤쪽은 1보다 조금 큽니다. 계절 배율 자체가 12년 동안 조금씩 커졌기 때문인데, 이 문제는 다음 레슨의 STL이 해결합니다.

## 로그를 씌우면 곱셈이 덧셈이 된다

곱셈형을 다루는 또 하나의 방법은 **로그 변환**입니다. 로그에는 곱셈을 덧셈으로 바꾸는 성질이 있습니다.

log(추세 × 계절 × 잔차) = log(추세) + log(계절) + log(잔차)

그래서 값에 로그를 씌운 다음 덧셈 분해를 하면 곱셈 분해와 같은 일을 하게 됩니다.

```run
import numpy as np
import pandas as pd
from statsmodels.tsa.seasonal import seasonal_decompose

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
log_y = np.log(y)
by_year = log_y.groupby(log_y.index.year).agg(["min", "max"])
print((by_year["max"] - by_year["min"]).loc[[1949, 1952, 1956, 1960]].round(2).to_dict())
res = seasonal_decompose(log_y, model="additive", period=12)
print("exp(seasonal) Jul:", round(float(np.exp(res.seasonal.iloc[6])), 2), "/ Nov:", round(float(np.exp(res.seasonal.iloc[10])), 2))
```

로그를 씌우자 한 해 안의 차이가 0.35 ~ 0.47로 비슷해졌습니다. 다섯 배씩 벌어지던 물결 높이가 거의 일정해진 것입니다. 로그 값으로 덧셈 분해한 계절 성분을 `exp`로 되돌리면 7월 1.23, 11월 0.81로, 곱셈 분해의 결과(1.23, 0.80)와 거의 같습니다.

로그 변환은 앞으로도 계속 나옵니다. 많은 시계열 모델이 덧셈 구조를 가정하기 때문에, 곱셈형 데이터는 **먼저 로그를 씌우고 모델에 넣은 뒤, 예측값을 `exp`로 되돌리는** 방식을 자주 씁니다.

## 어느 쪽을 고를까

1. 그래프를 그려 물결 높이가 수준과 함께 커지는지 봅니다.
2. 커지면 곱셈 분해를 하거나 로그를 씌웁니다. 일정하면 덧셈 분해를 합니다.
3. 분해한 뒤 **잔차에 패턴이 남았는지** 확인합니다. 깔때기처럼 벌어지거나 한쪽으로 쏠려 있으면 다른 쪽을 시도합니다.

값에 0이나 음수가 있으면 곱셈 분해와 로그를 쓸 수 없습니다. 그럴 때는 덧셈 분해를 씁니다.

## 정리

- 계절 효과가 일정한 양이면 덧셈형, 일정한 비율이면 곱셈형입니다.
- 항공 승객은 한 해 안의 차이가 44에서 232로 커지지만 비율은 1.4 ~ 1.6으로 일정한 곱셈형입니다.
- 잘못된 방식으로 분해하면 잔차에 패턴이 남습니다.
- 로그를 씌우면 곱셈형이 덧셈형으로 바뀝니다.
