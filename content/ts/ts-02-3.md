## 시작하기 전에

[덧셈 분해와 곱셈 분해](#/l/ts-02-2)에서 쓴 `seasonal_decompose`는 간단하지만 아쉬운 점이 두 가지 있었습니다.

1. 추세의 **양 끝이 비어** 있습니다. 가장 궁금한 "최근"의 추세를 알 수 없습니다.
2. 계절 모양을 **전 기간에 하나**로 고정합니다. 7월 효과가 해마다 조금씩 커져도 따라가지 못합니다.

이번 레슨에서는 이 두 가지를 해결한 분해 방법인 **STL**을 배우고, 하루 주기와 일주일 주기가 겹친 데이터를 분해해 봅니다.

## STL: 계절 모양이 천천히 변해도 따라간다

STL은 Seasonal-Trend decomposition using LOESS의 줄임말입니다. LOESS는 "가까운 값일수록 크게 반영해서 부드러운 곡선을 그리는 방법"입니다. 이름은 어렵지만 쓰는 법은 `seasonal_decompose`와 거의 같습니다.

STL은 덧셈 분해만 하므로, 곱셈형인 항공 승객은 로그를 씌워서 넣습니다. 두 방법으로 분해해 비교합니다.

```run
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from statsmodels.tsa.seasonal import STL, seasonal_decompose

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
log_y = np.log(y)
classic = seasonal_decompose(log_y, period=12)
stl = STL(log_y, period=12).fit()
stl.plot()
print("classic trend missing:", classic.trend.isna().sum(), "/ STL trend missing:", stl.trend.isna().sum())
july = stl.seasonal[stl.seasonal.index.month == 7]
print("July effect 1949:", round(float(np.exp(july.iloc[0])), 3), "/ 1960:", round(float(np.exp(july.iloc[-1])), 3))
```

- 기존 분해는 추세가 양 끝 12칸에서 비어 있지만, STL은 **빈칸이 0개**입니다. 마지막 달까지 추세를 알 수 있습니다.
- STL이 구한 7월 효과는 1949년 1.188배에서 1960년 1.312배로 **해마다 조금씩 커집니다.** 기존 분해는 12년 내내 1.23 하나로 고정했었습니다. 앞 레슨에서 곱셈 분해의 7월 잔차가 앞쪽은 1보다 작고 뒤쪽은 1보다 컸던 이유가 이것입니다.

| | `seasonal_decompose` | `STL` |
| --- | --- | --- |
| 추세 양 끝 | 비어 있음 | 채워짐 |
| 계절 모양 | 전 기간 하나로 고정 | 천천히 변할 수 있음 |
| 곱셈형 | `model="multiplicative"` | 로그를 씌워서 넣음 |
| 튀는 값 | 영향을 크게 받음 | `robust=True`로 줄일 수 있음 |

실무에서는 대부분 STL을 씁니다.

## period는 "한 바퀴가 몇 칸인가"

분해할 때 가장 중요한 설정은 `period`입니다. **계절 한 바퀴가 데이터 몇 칸인지** 적습니다.

| 데이터 간격 | 되풀이되는 주기 | period |
| --- | --- | --- |
| 월별 | 1년 | 12 |
| 주별 | 1년 | 52 |
| 일별 | 일주일 | 7 |
| 시간별 | 하루 | 24 |
| 시간별 | 일주일 | 168 (= 24 × 7) |

## 하루 주기 분해: 시간별 따릉이

2018년 6월 한 달의 **시간별** 따릉이 대여 수를 분해합니다. 날짜와 시각 열을 합쳐 시간 단위 인덱스를 만들고 `period=24`로 분해합니다.

```run
import matplotlib.pyplot as plt
import pandas as pd
from statsmodels.tsa.seasonal import STL

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts")["rented_bikes"]["2018-06"].asfreq("h")
stl = STL(june, period=24).fit()
stl.plot()
day = stl.seasonal["2018-06-05"]
print("peak hour:", day.idxmax().hour, round(day.max()), "/ lowest hour:", day.idxmin().hour, round(day.min()))
```

계절 성분(하루 주기)이 가장 높은 시각은 **18시**(평균보다 약 1,560대 많음), 가장 낮은 시각은 **새벽 4시**(약 1,103대 적음)입니다. 퇴근 시간에 가장 많이 빌리고 새벽에 가장 적게 빌린다는 뜻입니다.

## period를 바꿔 보기

`period`를 잘못 주면 어떻게 될까요? 12, 24, 168로 바꿔 가며 잔차의 표준편차를 비교합니다. 잔차가 작을수록 추세와 계절성이 데이터를 잘 설명한 것입니다.

```run
import pandas as pd
from statsmodels.tsa.seasonal import STL

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts")["rented_bikes"]["2018-06"].asfreq("h")
for period in [12, 24, 168]:
    stl = STL(june, period=period).fit()
    print(f"period {period:>3}: residual std = {stl.resid.std():.0f}")
```

- 12(반나절): 잔차 표준편차 370. 실제 주기와 맞지 않아 패턴을 제대로 떼어 내지 못했습니다.
- 24(하루): 296.
- 168(일주일): 250. 가장 작습니다.

168이 24보다 더 잘 맞는 이유는 다음에 나옵니다.

## 두 겹의 계절성

`period=24`로 분해한 잔차에서 **아침 8시** 값만 골라 요일별로 평균 냅니다. 0은 월요일, 6은 일요일입니다.

```run
import pandas as pd
from statsmodels.tsa.seasonal import STL

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
bike["ts"] = bike["date"] + pd.to_timedelta(bike["hour"], unit="h")
june = bike.set_index("ts")["rented_bikes"]["2018-06"].asfreq("h")
stl = STL(june, period=24).fit()
at8 = stl.resid[stl.resid.index.hour == 8]
print(at8.groupby(at8.index.dayofweek).mean().round(0).to_dict())
```

토요일(5)은 −545, 일요일(6)은 −752로 크게 낮고, 월요일(0)과 금요일(4)은 +750, +652로 높습니다. 하루 주기를 빼고도 **요일에 따른 패턴이 잔차에 남아** 있는 것입니다. 평일 아침 8시에는 출근하는 사람들이 자전거를 빌리지만 주말 아침에는 그렇지 않으니까요.

수요일(2)이 −359로 낮은 것이 이상해 보일 수 있습니다. 2018년 6월에는 6일(현충일)과 13일(지방선거일)이 모두 수요일 공휴일이었습니다. 수요일 네 번 중 두 번이 쉬는 날이었으니 평균이 낮게 나온 것입니다. 잔차를 들여다보면 이렇게 달력에 숨은 사정까지 드러납니다.

::figure{src="content/img/ts/ts02-two-seasons.svg" alt="하루 주기의 작은 물결이 일주일 주기의 큰 물결 위에 얹혀 있다. 평일에는 물결이 높고 주말에는 낮다" caption="시간별 데이터에는 하루 주기와 일주일 주기가 겹쳐 있는 경우가 많습니다."}

시간별 데이터에는 이렇게 **하루 주기와 일주일 주기가 겹쳐** 있는 경우가 많습니다. 다루는 방법은 세 가지입니다.

1. **더 긴 주기로 분해**: `period=168`로 주면 "월요일 8시", "토요일 8시"를 따로 봅니다. 대신 일주일이 여러 번 들어 있을 만큼 데이터가 길어야 합니다.
2. **단위를 묶어서 한 겹 없애기**: 하루 합계로 묶으면 하루 주기는 사라지고 일주일 주기(`period=7`)만 남습니다. 이 트랙에서 따릉이를 주로 일별로 쓰는 이유입니다.
3. **요일을 특성으로 넣기**: 머신러닝 모델에 요일 열을 넣어 주는 방법입니다. [시계열을 표로 바꾸기](#/l/ts-08-1)에서 다룹니다.

## 정리

- STL은 추세의 양 끝이 비지 않고, 계절 모양이 천천히 변하는 것도 따라갑니다.
- `period`는 계절 한 바퀴가 데이터 몇 칸인지입니다. 월별 12, 일별 7, 시간별 24.
- 분해 후에는 잔차에 패턴이 남았는지 확인합니다. 남아 있으면 주기가 한 겹 더 있다는 신호입니다.
- 두 겹의 계절성은 더 긴 주기로 분해하거나, 단위를 묶거나, 요일을 특성으로 넣어 다룹니다.
