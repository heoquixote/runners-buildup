## 시작하기 전에

여기부터는 미래를 **예측**합니다. 그런데 모델을 만들기 전에 먼저 정해야 할 것이 있습니다. "얼마나 잘 맞혀야 잘한 것인가"의 기준입니다.

[기준 모델과 누수](#/l/ml-01-5)에서 "항상 가장 흔한 답만 찍는 모델"을 먼저 만들어 두고, 진짜 모델이 그것보다 나은지 확인했습니다. 시계열에도 똑같은 역할을 하는 **기준 예측** 네 가지가 있습니다. 계산은 한두 줄이지만, 복잡한 모델이 이 기준을 넘지 못하는 일이 실제로 흔합니다.

## 예측할 구간 떼어 놓기

[시간 순서가 있는 데이터 나누기](#/l/ml-05-4)에서 배운 대로, 시계열은 섞지 않고 **뒤쪽을 시험용**으로 떼어 놓습니다. 항공 승객 144개월 중 마지막 24개월을 시험용으로 둡니다.

```run
import pandas as pd

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
train, test = y.iloc[:-24], y.iloc[-24:]
print("train:", train.index[0].date(), "~", train.index[-1].date(), len(train))
print("test :", test.index[0].date(), "~", test.index[-1].date(), len(test))
print("last train value:", train.iloc[-1], "/ train mean:", round(train.mean(), 1))
```

학습용은 1949 ~ 1958년 120개월, 시험용은 1959 ~ 1960년 24개월입니다. 학습용의 마지막 값(1958년 12월)은 337, 학습용 전체 평균은 245.9입니다. 우리는 1958년 12월에 서 있고, 앞으로 24개월을 예측해야 하는 상황입니다.

## 기준 예측 네 가지

| 이름 | 예측 방법 | 말로 하면 |
| --- | --- | --- |
| naive (단순) | 마지막 값을 그대로 | "다음 달도 이번 달과 같을 것이다" |
| mean (평균) | 지금까지의 평균 | "늘 평균쯤일 것이다" |
| seasonal naive (계절 단순) | 한 주기 전 같은 시기의 값 | "내년 7월은 올해 7월과 같을 것이다" |
| drift (표류) | 처음과 끝을 이은 직선을 연장 | "지금까지 오른 속도로 계속 오를 것이다" |

::figure{src="content/img/ts/ts05-baselines.svg" alt="과거 시계열 끝에서 뻗어 나가는 네 가지 예측선. naive는 마지막 값에서 수평선, mean은 전체 평균 높이의 수평선, seasonal naive는 마지막 한 주기를 그대로 복사한 물결, drift는 첫 값과 끝 값을 이은 직선의 연장" caption="기준 예측 네 가지. 모델이라기보다 '아무것도 안 했을 때의 예측'입니다."}

네 가지를 모두 만들어 실제 값과 비교합니다. 오차는 [오차 재기: MAE · RMSE · R²](#/l/ml-02-2)에서 배운 MAE(평균 절대 오차)로 잽니다.

```run
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
train, test = y.iloc[:-24], y.iloc[-24:]
h = len(test)
naive = pd.Series(train.iloc[-1], index=test.index)
mean_fc = pd.Series(train.mean(), index=test.index)
snaive = pd.Series(np.tile(train.iloc[-12:].values, 2), index=test.index)
slope = (train.iloc[-1] - train.iloc[0]) / (len(train) - 1)
drift = pd.Series(train.iloc[-1] + slope * np.arange(1, h + 1), index=test.index)
fig, ax = plt.subplots(figsize=(9, 3.5))
ax.plot(train.index[-36:], train.values[-36:], color="gray", label="train")
ax.plot(test.index, test.values, color="black", label="actual")
for name, fc in [("naive", naive), ("mean", mean_fc), ("seasonal naive", snaive), ("drift", drift)]:
    ax.plot(fc.index, fc.values, linestyle="--", label=name)
    print(f"{name:>14}: first 3 = {fc.iloc[:3].round(1).tolist()}, MAE = {(test - fc).abs().mean():.1f}")
ax.legend(fontsize=8)
```

- **naive**: 24개월 내내 337입니다. MAE 115.2.
- **mean**: 24개월 내내 245.9입니다. MAE 206.3으로 가장 나쁩니다. 승객이 계속 늘어 온 데이터에서 12년 전 값까지 섞은 평균은 한참 낮습니다.
- **seasonal naive**: 1958년 1월(340), 2월(318), 3월(362) …을 그대로 가져옵니다. MAE **71.2**로 가장 좋습니다. 계절 모양을 그대로 살렸기 때문입니다.
- **drift**: 338.9, 340.8, 342.7 …로 조금씩 올라갑니다. MAE 91.6. 추세는 따라가지만 계절 물결이 없습니다.

## drift는 어떻게 계산할까

drift는 첫 값과 마지막 값을 직선으로 잇고 그 기울기대로 뻗어 나갑니다.

```run
import pandas as pd

df = pd.read_csv("flights.csv")
df["date"] = pd.to_datetime(df["year"].astype(str) + "-" + df["month"], format="%Y-%B")
y = df.set_index("date")["passengers"].asfreq("MS")
train, test = y.iloc[:-24], y.iloc[-24:]
slope = (train.iloc[-1] - train.iloc[0]) / (len(train) - 1)
print("first:", train.iloc[0], "/ last:", train.iloc[-1], "/ steps:", len(train) - 1)
print("slope per month:", round(slope, 2))
print("drift forecast 1, 12, 24 months ahead:", [round(float(train.iloc[-1] + slope * k), 1) for k in (1, 12, 24)])
```

120개월 동안 112에서 337로 올랐으니, 한 달에 평균 (337 − 112) ÷ 119 = 1.89씩 오른 셈입니다. 그래서 1개월 뒤는 337 + 1.89 = 338.9, 12개월 뒤는 359.7, 24개월 뒤는 382.4로 예측합니다.

## 데이터에 따라 가장 좋은 기준이 다르다

같은 방법을 따릉이 일별 대여 수에 써 봅니다. 마지막 28일을 시험용으로 두고, 계절 주기는 일주일(7)로 잡습니다.

```run
import numpy as np
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
daily = bike.groupby("date")["rented_bikes"].sum().asfreq("D")
bike_ok = bike.groupby("date")["functioning_day"].apply(lambda s: (s == "Yes").any())
daily = daily.where(bike_ok).interpolate()
h = 28
train, test = daily.iloc[:-h], daily.iloc[-h:]
naive = pd.Series(train.iloc[-1], index=test.index)
snaive = pd.Series(np.tile(train.iloc[-7:].values, h // 7), index=test.index)
mean_fc = pd.Series(train.mean(), index=test.index)
for name, fc in [("naive", naive), ("seasonal naive (7)", snaive), ("mean", mean_fc)]:
    print(f"{name:>18}: MAE = {(test - fc).abs().mean():.0f}")
print("test mean:", round(test.mean()))
```

이번에는 **mean이 가장 좋고**(MAE 3,615) naive가 가장 나쁩니다(7,254). 항공 승객과 순위가 정반대입니다.

이유는 이렇습니다. 일별 대여 수는 날씨에 따라 하루하루 크게 출렁입니다. naive는 마지막 하루 값 하나에 28일을 모두 겁니다. 하필 그날이 비 오는 날이었다면 28일 치 예측이 모두 낮아집니다. 평균은 여러 날을 섞으니 이런 운에 덜 흔들립니다.

| 데이터의 성격 | 잘 맞는 기준 예측 |
| --- | --- |
| 추세가 강하고 잡음이 작다 | naive, drift |
| 계절성이 뚜렷하다 | seasonal naive |
| 추세가 없고 잡음이 크다 | mean |

아래 셀에서 `h = 28`을 `7`로 바꿔 실행해 보세요. 예측 기간이 달라지면 순위가 또 달라질 수 있습니다.

## 기준 예측을 왜 꼭 먼저 만들까

- **모델이 쓸모 있는지 판단하는 잣대**입니다. 항공 승객에서 어떤 모델의 MAE가 80이라면, seasonal naive(71.2)보다 못하니 쓸 이유가 없습니다.
- **오차의 크기에 감을 줍니다.** "MAE 71"이 큰지 작은지는 비교 대상이 있어야 알 수 있습니다.
- **실수를 잡아 줍니다.** 복잡한 모델이 naive보다 훨씬 나쁘면 코드 어딘가가 잘못됐을 가능성이 큽니다.

실제 예측 대회에서도 seasonal naive를 넘지 못하는 모델이 적지 않습니다. 기준 예측은 "쉬운 출발점"이 아니라 **넘어야 할 문턱**입니다.

## 정리

- 기준 예측은 naive(마지막 값), mean(평균), seasonal naive(한 주기 전 값), drift(직선 연장) 네 가지입니다.
- 항공 승객에서는 seasonal naive가 MAE 71.2로 가장 좋았고, 따릉이에서는 mean이 가장 좋았습니다.
- 어떤 기준이 좋은지는 추세, 계절성, 잡음의 크기에 따라 달라집니다.
- 모델을 만들면 반드시 기준 예측과 같은 시험 구간에서 비교합니다.
