## 시작하기 전에

지금까지 배운 도구를 하나의 흐름으로 엮어 볼 차례입니다. 실제 예측 프로젝트는 모델 하나를 고르는 일이 아니라, **질문을 정하는 것부터 운영하며 점검하는 것까지** 이어지는 여러 단계입니다.

이번 레슨에서는 "따릉이 운영팀이 다음 주 자전거 재배치 계획을 세운다"는 상황으로 처음부터 끝까지 한 바퀴 돕니다.

::figure{src="content/img/ts/ts10-workflow.svg" alt="예측 프로젝트의 여덟 단계. 질문 정하기, 데이터 준비, 살펴보기, 기준 예측, 후보 모델, 롤링 원점 검증, 구간과 함께 예측, 운영하며 점검" caption="예측 프로젝트의 여덟 단계. 앞 단계가 부실하면 뒤 단계의 모델이 아무리 좋아도 소용이 없습니다."}

## 1단계: 질문 정하기

모델보다 먼저 정할 것 세 가지입니다.

| 정할 것 | 이번 프로젝트 | 이유 |
| --- | --- | --- |
| 무엇을 | 하루 총 대여 수 | 재배치 인력은 하루 단위로 짠다 |
| 얼마나 멀리 (지평) | 1 ~ 7일 뒤 | 다음 주 계획을 금요일에 세운다 |
| 어떤 지표로 | MAE | 대여 수가 0에 가까운 날이 없고, 단위(대)로 말하는 것이 현장에 쉽다 |

지평이 7일이라는 점이 중요합니다. [SARIMAX: 바깥 변수 넣기](#/l/ts-07-4)에서 봤듯이 7일 뒤의 날씨는 정확히 알 수 없습니다. 그래서 **날씨 변수는 쓰지 않기로** 합니다.

## 2단계: 데이터 준비

[일정한 간격 만들기: 날짜 인덱스와 빈도](#/l/ts-01-1)와 [시간 단위 바꾸기: 합칠까, 평균 낼까](#/l/ts-01-2)에서 배운 대로 준비합니다. 시간별 대여 수를 하루 합계로 묶고, 빈도를 붙이고, 운영하지 않은 날은 보간합니다.

```run
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
s = day["rented"].where(day["open"]).interpolate()
print("rows:", len(s), "/ freq:", s.index.freq, "/ closed days interpolated:", int((~day["open"]).sum()))
print("missing after fill:", int(s.isna().sum()))
```

365일이 빠짐없이 있고 빈도는 하루입니다. 운영하지 않은 12일은 보간했고 빈칸은 남지 않았습니다.

## 3단계: 살펴보기

모델을 고르기 전에 이 시계열에 무엇이 들어 있는지 봅니다. [STL과 여러 겹의 계절성](#/l/ts-02-3)의 분해와 [어제가 오늘을 말해 준다: 자기상관과 ACF](#/l/ts-03-1)의 자기상관을 씁니다.

```run
import pandas as pd
from statsmodels.tsa.seasonal import STL
from statsmodels.tsa.stattools import acf

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
s = day["rented"].where(day["open"]).interpolate()
stl = STL(s, period=7, robust=True).fit()
print("std - original:", round(s.std()), "/ trend:", round(stl.trend.std()), "/ weekly:", round(stl.seasonal.std()), "/ residual:", round(stl.resid.std()))
print("ACF lag 1, 7:", acf(s, nlags=7)[[1, 7]].round(2).tolist())
```

- 추세 성분의 표준편차가 9,406으로 가장 큽니다. 겨울에 적고 여름에 많은 느린 오르내림입니다.
- 잔차가 5,147로 그다음입니다. 하루하루의 날씨 때문에 생기는 큰 출렁임입니다.
- 일주일 주기는 2,153으로 가장 작습니다.

여기서 전략이 나옵니다. 일주일 주기가 약하니 seasonal naive는 기대하기 어렵고, 잔차가 크니 **마지막 하루에 기대는 naive는 위험**합니다. 최근 며칠을 평균 내는 방법이 유리할 것으로 짐작할 수 있습니다.

## 4 ~ 6단계: 기준 예측, 후보 모델, 롤링 원점 검증

기준 예측 세 가지와 모델 두 가지를 같은 조건에서 비교합니다.

- 기준: naive, 최근 7일 평균(`week_mean`), seasonal naive
- 모델: [단순 지수평활: 최근일수록 크게](#/l/ts-06-1), [Holt-Winters: 계절까지](#/l/ts-06-3)(감쇠 추세 + 덧셈 계절)

[시간 순서대로 검증하기: 롤링 원점](#/l/ts-05-3)의 방법으로, 원점을 일주일씩 옮겨 가며 **7일 예측을 여덟 번** 시험합니다.

```run
import numpy as np
import pandas as pd
import warnings
from sklearn.model_selection import TimeSeriesSplit
from statsmodels.tsa.holtwinters import ExponentialSmoothing, SimpleExpSmoothing

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
s = day["rented"].where(day["open"]).interpolate()
warnings.filterwarnings("ignore")
h = 7
rows = []
for tr, te in TimeSeriesSplit(n_splits=8, test_size=h).split(s):
    train, test = s.iloc[tr], s.iloc[te]
    forecasts = {
        "naive": np.repeat(train.iloc[-1], h),
        "week_mean": np.repeat(train.iloc[-7:].mean(), h),
        "snaive": train.iloc[-7:].values,
        "ses": SimpleExpSmoothing(train, initialization_method="estimated").fit().forecast(h).values,
        "holt_winters": ExponentialSmoothing(train, trend="add", damped_trend=True, seasonal="add", seasonal_periods=7, initialization_method="estimated").fit().forecast(h).values,
    }
    rows.append({name: np.abs(test.values - fc).mean() for name, fc in forecasts.items()})
result = pd.DataFrame(rows)
print(result.round(0).to_string())
print("mean MAE:", result.mean().round(0).to_dict())
```

| 방법 | 평균 MAE |
| --- | --- |
| naive | 7,012 |
| seasonal naive | 5,302 |
| Holt-Winters | 4,151 |
| 단순 지수평활 | 3,902 |
| **최근 7일 평균** | **3,365** |

3단계의 짐작대로입니다. 가장 좋은 것은 **최근 7일 평균**이고, 그다음이 단순 지수평활입니다. 둘 다 "최근 며칠을 평균 낸다"는 같은 생각입니다. 더 정교한 Holt-Winters는 그보다 못했습니다. 첫 번째 구간에서 naive가 20,488이나 틀린 것도 보입니다. 마지막 날이 하필 유난히 대여가 적은 날이었던 것입니다.

"가장 단순한 방법이 이겼다"는 결과는 실망스러워 보일 수 있지만, 실무에서는 **좋은 소식**입니다. 설명하기 쉽고, 고장 날 것이 없고, 누구나 점검할 수 있기 때문입니다. 복잡한 모델은 단순한 방법보다 **확실히** 나을 때만 씁니다.

## 7단계: 구간과 함께 예측하기

최종 예측을 냅니다. 여기서는 단순 지수평활을 씁니다. 성능이 최근 7일 평균과 비슷하고, `simulate`로 예측 구간을 바로 얻을 수 있기 때문입니다. [Holt-Winters: 계절까지](#/l/ts-06-3)에서 한 것처럼 가상의 미래 500개를 만들어 80% 구간을 구합니다.

```run
import matplotlib.pyplot as plt
import pandas as pd
import warnings
from statsmodels.tsa.holtwinters import SimpleExpSmoothing

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
s = day["rented"].where(day["open"]).interpolate()
warnings.filterwarnings("ignore")
train, test = s.iloc[:-7], s.iloc[-7:]
fit = SimpleExpSmoothing(train, initialization_method="estimated").fit()
fc = fit.forecast(7)
sims = fit.simulate(7, repetitions=500, random_state=0)
low, high = sims.quantile(0.1, axis=1), sims.quantile(0.9, axis=1)
fig, ax = plt.subplots(figsize=(9, 3.5))
ax.plot(train.index[-28:], train.values[-28:], color="gray", label="history")
ax.plot(test.index, test.values, color="black", marker="o", label="actual")
ax.plot(fc.index, fc.values, color="crimson", linestyle="--", label="forecast")
ax.fill_between(fc.index, low, high, color="crimson", alpha=0.2, label="80% interval")
ax.legend(fontsize=8)
print(pd.DataFrame({"actual": test.round(0), "forecast": fc.round(0), "low": low.round(0), "high": high.round(0)}))
print("MAE:", round((test - fc).abs().mean()), "/ inside interval:", int(((test >= low) & (test <= high)).sum()), "of 7")
```

- 예측은 7일 내내 17,146대입니다. 수평선입니다.
- 80% 구간은 대략 9,000 ~ 24,500대입니다. 폭이 넓습니다. 하루하루의 날씨를 모르는 상태에서 솔직하게 말할 수 있는 범위가 이 정도라는 뜻입니다.
- 실제 값 7개 중 6개가 구간 안에 들었습니다. 벗어난 하루는 11월 24일(6,477대)입니다. 이 날 서울에는 첫눈이 많이 내렸습니다.
- 11월 26 ~ 30일 평일 닷새는 실제 값이 16,282 ~ 17,162로 예측과 거의 같습니다.

운영팀에는 이렇게 전합니다. **"다음 주 하루 대여는 17,000대 안팎으로 예상합니다. 날씨에 따라 9,000 ~ 24,500대까지 달라질 수 있으니, 전날 예보에서 비나 눈이 있으면 낮은 쪽으로 준비하세요."** 숫자 하나보다 훨씬 쓸모 있는 정보입니다.

## 8단계: 운영하며 점검하기

모델을 배포하면 끝이 아닙니다. 세상이 변하면 모델은 조용히 틀리기 시작합니다. 그래서 예측 오차를 계속 기록하고 지켜봅니다.

마지막 60일 동안 매일 하루 앞을 예측했다고 가정하고, 오차(실제 − 예측)를 앞 30일과 뒤 30일로 나눠 봅니다.

```run
import numpy as np
import pandas as pd
import warnings
from statsmodels.tsa.holtwinters import SimpleExpSmoothing

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
s = day["rented"].where(day["open"]).interpolate()
warnings.filterwarnings("ignore")
errors = []
for origin in range(len(s) - 60, len(s)):
    fit = SimpleExpSmoothing(s.iloc[:origin], initialization_method="estimated").fit()
    errors.append(s.iloc[origin] - fit.forecast(1).iloc[0])
errors = pd.Series(errors, index=s.index[-60:])
print("first 30 days  - mean error:", round(errors.iloc[:30].mean()), "/ MAE:", round(errors.iloc[:30].abs().mean()))
print("last 30 days   - mean error:", round(errors.iloc[30:].mean()), "/ MAE:", round(errors.iloc[30:].abs().mean()))
```

MAE는 3,751과 3,541로 비슷합니다. 그런데 **평균 오차**가 −1,095, −606으로 계속 음수입니다. 예측이 실제보다 꾸준히 높다는 뜻입니다. 가을에서 겨울로 가면서 대여가 줄어드는데, 지수평활은 과거 평균에 무게를 두니 한 발씩 늦게 따라가는 것입니다.

점검할 때는 두 가지를 봅니다.

- **오차의 크기**(MAE)가 갑자기 커졌는가 → 패턴이 깨졌다는 신호
- **오차의 평균**(편향)이 한쪽으로 쏠려 있는가 → 모델이 체계적으로 높게 또는 낮게 예측한다는 신호

오차 자체도 시계열입니다. [변화점: 수준이 바뀌는 순간](#/l/ts-09-3)의 CUSUM을 예측 오차에 걸어 두면, 모델이 틀어지기 시작하는 시점을 자동으로 알 수 있습니다.

## 이 프로젝트의 한계와 다음에 할 일

- **데이터가 1년뿐**입니다. 작년 같은 시기와 비교할 수 없어서 1년 주기의 계절성을 모델에 넣지 못했습니다. 2 ~ 3년 치가 모이면 "작년 11월 넷째 주"를 쓸 수 있습니다.
- **달력 정보**(공휴일)는 미래 값을 확실히 아는 변수이니 넣어 볼 만합니다.
- **하루 앞 예측**이라면 일기예보를 쓸 수 있어 [회귀 모델로 예측하고 비교하기](#/l/ts-08-2)의 방법이 유리합니다. 지평에 따라 다른 모델을 쓰는 것도 흔한 설계입니다.

## 정리

- 예측 프로젝트는 질문 정하기 → 준비 → 살펴보기 → 기준 예측 → 후보 모델 → 롤링 원점 검증 → 구간 예측 → 점검 순서로 갑니다.
- 지평을 먼저 정해야 어떤 정보를 쓸 수 있는지가 정해집니다.
- 따릉이 7일 예측에서는 최근 7일 평균(MAE 3,365)이 가장 좋았습니다. 단순한 방법이 이기면 단순한 방법을 씁니다.
- 예측은 구간과 함께 전하고, 배포 뒤에는 오차의 크기와 편향을 계속 지켜봅니다.
