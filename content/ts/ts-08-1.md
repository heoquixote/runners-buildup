## 시작하기 전에

지수평활과 ARIMA는 시계열 전용 모델입니다. 그런데 [머신러닝 트랙](#/l/ml-00-1)에서 배운 선형회귀나 랜덤포레스트로도 시계열을 예측할 수 있습니다. 단, 그 모델들은 "한 행 = 특성 여러 개 + 정답 하나"인 **표**를 입력으로 받습니다. 시계열은 값이 한 줄로 늘어선 모양이라 그대로는 넣을 수 없습니다.

이번 레슨에서는 시계열을 머신러닝이 받을 수 있는 표로 바꾸는 법을 배웁니다. [시간 순서가 있는 데이터 나누기](#/l/ml-05-4)에서 래그와 이동평균 특성을 한 번 만들어 봤는데, 여기서는 그것을 체계적으로 정리하고 달력 특성까지 더합니다.

## 한 행 = "그날 아침에 알고 있는 것" + "그날의 정답"

표로 바꾸는 원칙은 하나입니다.

**각 행의 특성 칸에는, 그 날을 예측하는 순간에 이미 알고 있는 것만 넣는다.**

내일의 대여 수를 오늘 밤에 예측한다고 하면, 알고 있는 것은 오늘까지의 대여 수, 내일의 요일, 내일의 일기예보입니다. 내일의 실제 대여 수는 당연히 모릅니다.

::figure{src="content/img/ts/ts08-to-table.svg" alt="한 줄로 늘어선 시계열을, 각 행에 하루 전 값, 일주일 전 값, 지난 7일 평균, 요일을 특성으로 두고 그날 값을 정답으로 둔 표로 바꾸는 그림" caption="시계열을 '특성 여러 개 + 정답 하나'인 표로 바꾸면 어떤 회귀 모델이든 쓸 수 있습니다."}

특성은 크게 세 종류입니다.

| 종류 | 예 | 만드는 법 |
| --- | --- | --- |
| 래그 특성 | 어제 값, 일주일 전 값 | `shift(1)`, `shift(7)` |
| 이동 통계 특성 | 지난 7일 평균, 지난 7일 최대 | `shift(1).rolling(7).mean()` |
| 달력 특성 | 요일, 주말 여부, 공휴일, 월 | `index.dayofweek` |

## 특성 만들기

따릉이 일별 표에 특성을 붙입니다.

```run
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
day["lag1"] = day["rented"].shift(1)
day["lag7"] = day["rented"].shift(7)
day["roll7"] = day["rented"].shift(1).rolling(7).mean()
day["dow"] = day.index.dayofweek
day["weekend"] = (day["dow"] >= 5).astype(int)
print(day[["rented", "lag1", "lag7", "roll7", "dow", "weekend"]].iloc[6:10].round(0))
print("rows with empty cells:", int(day[["lag1", "lag7", "roll7"]].isna().any(axis=1).sum()))
```

12월 8일 행을 보면, `lag1`은 전날인 7일의 대여 수 8,549, `lag7`은 일주일 전인 1일의 9,539, `roll7`은 1 ~ 7일의 평균 8,220입니다. `dow`는 요일(0 = 월요일, 4 = 금요일)입니다.

12월 7일 행은 `lag7`과 `roll7`이 비어 있습니다. 일주일 전 기록이 없기 때문입니다. 이렇게 빈칸이 있는 맨 앞 7행은 학습에서 뺍니다. 래그를 길게 잡을수록 버리는 행이 늘어납니다.

## 가장 흔한 실수: 오늘 값이 섞인 이동평균

이동평균 특성을 만들 때 `shift(1)`을 빠뜨리면 **정답이 특성에 섞입니다.** 두 방식을 나란히 놓고 봅니다.

```run
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
wrong = day["rented"].rolling(7).mean()
right = day["rented"].shift(1).rolling(7).mean()
view = pd.DataFrame({"rented": day["rented"], "wrong": wrong, "right": right})
print(view.loc["2018-06-25":"2018-06-28"].round(0))
print("corr with target - wrong:", round(day["rented"].corr(wrong), 3), "/ right:", round(day["rented"].corr(right), 3))
```

6월 26일은 비가 많이 와서 대여가 5,200건으로 뚝 떨어진 날입니다.

- `wrong`(shift 없음): 26일의 값이 28,603으로, 전날(32,910)보다 **이미 내려가 있습니다.** 26일의 5,200이 평균에 들어갔기 때문입니다. 모델은 이 열을 보고 "오늘 대여가 적다"는 것을 미리 알게 됩니다.
- `right`(shift 후): 26일의 값은 32,910으로, 25일까지의 평균입니다. 26일에 일어날 일을 전혀 모릅니다. 폭락은 하루 뒤인 27일 값(28,603)에 가서야 반영됩니다.

정답과의 상관계수도 `wrong`이 0.860, `right`가 0.804입니다. 잘못 만든 특성이 더 "좋아 보이는" 것이 누수의 특징입니다. 학습 · 시험 점수는 좋게 나오지만 실전에서는 그 성능이 나오지 않습니다.

## 달력 특성

요일과 공휴일은 **미래 값을 확실히 아는** 특성이라 가장 안전합니다. 요일별, 공휴일 여부별 평균 대여 수를 봅니다.

```run
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
day["dow"] = day.index.dayofweek
holiday = bike.groupby("date")["holiday"].first().eq("Yes")
day["holiday"] = holiday.astype(int)
print(day.groupby("dow")["rented"].mean().round(0).to_dict())
print("holiday mean:", round(day.loc[day["holiday"] == 1, "rented"].mean()), "/ other days:", round(day.loc[day["holiday"] == 0, "rented"].mean()), "/ holidays:", int(day["holiday"].sum()))
```

일요일(6)이 15,574건으로 가장 적고, 금요일(4)이 18,708건으로 가장 많습니다. 공휴일 18일의 평균은 13,488건으로 다른 날(17,891건)보다 25%쯤 적습니다.

요일 번호(0 ~ 6)를 그대로 넣을 때는 주의할 점이 있습니다. [인코딩: 글자를 숫자로](#/l/ml-01-3)에서 배웠듯이, 선형 모델은 숫자의 크기를 그대로 믿어서 "일요일(6)은 월요일(0)보다 6만큼 크다"고 읽습니다. 선형 모델에는 원-핫 인코딩을 하거나 `weekend`처럼 0/1 열을 따로 만들어 줍니다. 트리 모델은 번호 그대로 넣어도 괜찮습니다.

## 누수 점검표

특성 열 하나하나에 대해 이렇게 묻습니다. **"예측하는 순간에 이 값을 알 수 있는가?"**

| 특성 | 내일을 예측할 때 | 판정 |
| --- | --- | --- |
| 어제 대여 수 (`shift(1)`) | 안다 | 사용 가능 |
| 지난 7일 평균 (`shift(1)` 후 `rolling`) | 안다 | 사용 가능 |
| `rolling(7).mean()` (shift 없음) | 내일 값이 섞여 있다 | **누수** |
| 내일의 요일 · 공휴일 | 안다 | 사용 가능 |
| 내일의 실제 기온 | 모른다 (예보만 안다) | 예보값으로 바꿔야 함 |
| 내일의 실제 강수량 | 모른다 | 예보값으로 바꿔야 함 |

또 하나 주의할 것은 **예측 지평**입니다. 7일 뒤를 예측하는 모델이라면 "어제 값"도 알 수 없습니다. 7일 뒤의 어제는 아직 오지 않은 6일 뒤입니다. 그때는 `shift(7)` 이상의 래그만 쓸 수 있습니다. 이 문제는 [여러 걸음 앞 예측과 트리의 한계](#/l/ts-08-3)에서 다룹니다.

## 정리

- 시계열을 "특성 + 정답" 표로 바꾸면 회귀 모델을 쓸 수 있습니다.
- 특성은 래그, 이동 통계, 달력 세 종류입니다.
- 이동 통계는 반드시 `shift(1)`을 한 뒤 계산합니다. 빠뜨리면 정답이 섞입니다.
- 특성마다 "예측하는 순간에 알 수 있는가"를 확인합니다.
