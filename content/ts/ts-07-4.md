## 시작하기 전에

지금까지의 모델은 모두 **자기 자신의 과거**만 보고 예측했습니다. 그런데 따릉이 대여 수는 과거 대여 수만으로 정해지지 않습니다. 비가 오면 줄고 날이 따뜻하면 늡니다.

이번 레슨에서는 SARIMA에 날씨 같은 **바깥 변수**를 넣는 SARIMAX를 배웁니다. 끝의 X는 eXogenous(외생), 곧 "시계열 바깥에서 온 변수"라는 뜻입니다. 그리고 바깥 변수를 쓸 때 꼭 조심해야 하는 함정도 봅니다.

## 날씨와 대여 수

따릉이 데이터를 하루 단위로 묶습니다. [시간 단위 바꾸기: 합칠까, 평균 낼까](#/l/ts-01-2)에서 배운 대로 대여 수와 강수량은 합계, 기온은 평균으로 묶고, 운영하지 않은 날은 보간합니다. 그런 다음 세 변수의 상관계수를 봅니다.

```run
import pandas as pd

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
print(day[["rented", "temp", "rain"]].corr().round(2))
print("rainy days (>= 10mm):", int((day["rain"] >= 10).sum()), "/ mean rented:", round(day.loc[day["rain"] >= 10, "rented"].mean()), "vs dry days:", round(day.loc[day["rain"] == 0, "rented"].mean()))
```

- 대여 수와 기온의 상관계수는 **0.75**입니다. 따뜻할수록 많이 빌립니다.
- 대여 수와 강수량은 −0.24입니다. 비가 10mm 이상 온 33일의 평균 대여는 10,954건, 비가 전혀 안 온 날은 18,931건입니다. 거의 절반입니다.

날씨는 분명히 쓸 만한 정보입니다.

## 바깥 변수 넣기

마지막 28일을 시험용으로 두고, 바깥 변수 없는 SARIMA와 기온 · 강수량을 넣은 SARIMAX를 비교합니다. 일별 데이터이므로 계절 주기는 7입니다.

바깥 변수는 `exog=`에 넣습니다. 중요한 점은 **예측할 때도 `exog`를 줘야 한다**는 것입니다. 모델이 "기온이 1도 오르면 대여가 몇 건 는다"를 배웠으니, 예측하려는 날의 기온을 알아야 계산할 수 있습니다.

```run
import pandas as pd
import warnings
from statsmodels.tsa.statespace.sarimax import SARIMAX

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
warnings.filterwarnings("ignore")
mae = lambda fc: round(float((test["rented"] - fc).abs().mean()))
plain = SARIMAX(train["rented"], order=(1, 0, 1), seasonal_order=(1, 0, 1, 7), trend="c").fit(disp=False)
print("SARIMA  MAE:", mae(plain.forecast(28)))
withx = SARIMAX(train["rented"], exog=train[["temp", "rain"]], order=(1, 0, 1), seasonal_order=(1, 0, 1, 7), trend="c").fit(disp=False)
print("SARIMAX MAE:", mae(withx.forecast(28, exog=test[["temp", "rain"]])))
print("coef temp:", round(withx.params["temp"]), "/ coef rain:", round(withx.params["rain"]))
print("naive MAE:", mae(train["rented"].iloc[-1]), "/ mean MAE:", mae(train["rented"].mean()))
```

- SARIMA의 MAE는 4,295입니다. [기준 예측 네 가지](#/l/ts-05-1)에서 본 mean(3,615)보다도 나쁩니다.
- SARIMAX의 MAE는 **2,617**입니다. 날씨를 넣자 오차가 40% 가까이 줄었고, 처음으로 모든 기준 예측을 넘었습니다.
- 기온의 계수는 443입니다. 다른 조건이 같을 때 평균 기온이 1°C 오르면 하루 대여가 약 443건 는다는 뜻입니다. 강수량의 계수는 −432로, 비가 1mm 더 오면 약 432건 줄어듭니다.

이 데이터에서는 자기 자신의 과거보다 **날씨가 훨씬 중요한 정보**였습니다.

## 함정: 미래의 날씨는 누가 알려 주나

방금 예측에서 `exog=test[["temp", "rain"]]`을 넣었습니다. 시험 구간 28일의 **실제 기온과 실제 강수량**입니다.

그런데 생각해 봅시다. 10월 말에 서서 11월 한 달의 대여 수를 예측한다면, 11월 20일의 실제 기온을 알 수 있을까요? 알 수 없습니다. 쓸 수 있는 것은 **일기예보**뿐이고, 28일 뒤의 예보는 거의 맞지 않습니다.

미래의 실제 날씨를 넣어 평가한 2,617은 **실전에서는 얻을 수 없는 점수**입니다. [기준 모델과 누수](#/l/ml-01-5)에서 배운 누수의 한 종류입니다. 예측하는 시점에 알 수 없는 정보를 쓴 것입니다.

현실에 가깝게, 미래 날씨를 "학습 구간 마지막 주의 평균 기온이 계속되고 비는 안 온다"고 가정해서 넣어 봅니다.

```run
import pandas as pd
import warnings
from statsmodels.tsa.statespace.sarimax import SARIMAX

bike = pd.read_csv("seoul_bike.csv", parse_dates=["date"])
day = bike.groupby("date").agg(rented=("rented_bikes", "sum"), temp=("temp", "mean"), rain=("rainfall", "sum"), open=("functioning_day", lambda s: (s == "Yes").any()))
day = day.asfreq("D")
day["rented"] = day["rented"].where(day["open"]).interpolate()
train, test = day.iloc[:-28], day.iloc[-28:]
warnings.filterwarnings("ignore")
mae = lambda fc: round(float((test["rented"] - fc).abs().mean()))
withx = SARIMAX(train["rented"], exog=train[["temp", "rain"]], order=(1, 0, 1), seasonal_order=(1, 0, 1, 7), trend="c").fit(disp=False)
last_week = pd.DataFrame({"temp": train["temp"].iloc[-7:].mean(), "rain": 0.0}, index=test.index)
print("with actual weather       :", mae(withx.forecast(28, exog=test[["temp", "rain"]])))
print("with last week's mean temp:", mae(withx.forecast(28, exog=last_week)))
print("temp last week of train:", round(train["temp"].iloc[-7:].mean(), 1), "/ test period:", round(test["temp"].mean(), 1))
```

MAE가 2,617에서 **4,330**으로 올라갑니다. 바깥 변수가 없는 SARIMA(4,295)와 거의 같아졌습니다. 날씨 정보의 이점이 모두 사라진 것입니다.

마지막 주 평균 기온(8.1°C)과 시험 기간 평균 기온(7.7°C)은 비슷합니다. 평균은 맞혔는데도 성능이 떨어진 이유는, 대여 수를 크게 움직이는 것이 **어느 날 비가 오고 어느 날 유난히 추운가** 하는 하루하루의 변화이기 때문입니다.

## 바깥 변수를 쓸 때 묻는 질문

바깥 변수를 넣기 전에 **"예측하는 시점에 이 변수의 미래 값을 알 수 있는가"** 를 먼저 묻습니다.

| 바깥 변수 | 미래 값을 아는가 | 쓰는 법 |
| --- | --- | --- |
| 요일, 공휴일, 방학 | 확실히 안다 | 그대로 쓴다 |
| 계획된 행사, 할인 일정, 정기 보수 | 우리가 정한다 | 그대로 쓴다 |
| 내일 · 모레 날씨 | 예보로 꽤 정확히 안다 | 예보값을 넣는다. 평가할 때도 실제 값이 아닌 **그때의 예보값**을 쓴다 |
| 한 달 뒤 날씨, 환율, 경쟁사 가격 | 모른다 | 쓰지 않거나, 그 변수부터 예측해야 한다 |

가장 안전하고 효과적인 바깥 변수는 **달력 정보**입니다. 미래 값을 확실히 알기 때문입니다. 날씨는 하루 이틀 앞의 짧은 예측에서 쓸모가 큽니다.

## 정리

- SARIMAX는 SARIMA에 바깥 변수(`exog`)를 더한 모델입니다. 예측할 때도 바깥 변수의 미래 값을 넣어야 합니다.
- 따릉이 28일 예측에서 기온과 강수량을 넣으면 MAE가 4,295에서 2,617로 줄었습니다.
- 하지만 실제 미래 날씨를 넣은 평가는 실전에서 얻을 수 없는 점수입니다. 현실적인 가정을 넣자 4,330으로 돌아갔습니다.
- 바깥 변수는 예측 시점에 미래 값을 알 수 있는 것만 씁니다.
