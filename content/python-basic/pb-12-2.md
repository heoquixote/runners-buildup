pb-12-1에서는 파이썬이 낸 에러를 `try`/`except`로 **잡는** 법을 배웠습니다. 이번에는 반대 방향입니다. 값이 문법적으로는 멀쩡해도 **업무 규칙에 맞지 않으면**, 함수가 직접 에러를 **내서** 알려야 할 때가 있습니다. 측정값이 음수이거나, 검사 수가 0이거나, 등급 코드가 정해진 값이 아닐 때입니다. 이때 쓰는 것이 `raise`입니다.

### 조용히 틀린 값을 돌려주는 함수가 가장 위험합니다

```run
def defect_rate(defects, qty):
    return defects / qty

print(defect_rate(18, 1250))
print(defect_rate(30, 20))     # 불량이 검사 수보다 많다?
print(defect_rate(-5, 100))    # 음수 불량?
```

1.5(150%)와 -0.05가 아무 경고 없이 계산됩니다. 이 값이 보고서까지 흘러가면 나중에 원인을 찾기 어렵습니다. **잘못된 입력은 들어온 자리에서 바로 멈추게** 하는 것이 좋습니다.

### raise: 직접 에러 내기

`raise 에러이름("설명")`을 실행하면 그 자리에서 에러가 납니다. 파이썬이 내는 에러와 똑같이 동작해서, 아무도 잡지 않으면 프로그램이 멈추고 메시지가 보입니다.

```python
def defect_rate(defects, qty):
    if qty <= 0:
        raise ValueError(f"검사 수는 1 이상이어야 합니다: {qty}")
    if not 0 <= defects <= qty:
        raise ValueError(f"불량 수가 범위를 벗어났습니다: {defects}/{qty}")
    return defects / qty

defect_rate(30, 20)
```

```
ValueError: 불량 수가 범위를 벗어났습니다: 30/20
```

어떤 에러 이름을 쓸지는 pb-05-3의 표를 따릅니다. 자료형은 맞는데 값이 규칙에 안 맞으면 `ValueError`, 자료형 자체가 틀리면 `TypeError`가 보통입니다. 메시지에는 **문제가 된 값**을 꼭 넣습니다.

### 내가 낸 에러도 똑같이 잡을 수 있습니다

함수를 쓰는 쪽에서는 `try`/`except`로 잡아서 처리합니다. `as e`로 받은 에러를 출력하면 `raise`에 쓴 메시지가 나옵니다.

```run
def defect_rate(defects, qty):
    if qty <= 0:
        raise ValueError(f"검사 수는 1 이상이어야 합니다: {qty}")
    if not 0 <= defects <= qty:
        raise ValueError(f"불량 수가 범위를 벗어났습니다: {defects}/{qty}")
    return defects / qty

for d, q in [(18, 1250), (30, 20), (5, 0)]:
    try:
        print(f"{defect_rate(d, q):.2%}")
    except ValueError as e:
        print("입력 오류:", e)
```

정상 입력은 1.44%, 나머지 둘은 각자의 메시지와 함께 "입력 오류"로 처리됐고, 반복은 끝까지 돌았습니다. **함수는 규칙을 검사해 에러를 내고, 함수를 쓰는 쪽이 그 에러를 어떻게 처리할지 정합니다.** 역할이 나뉘어 있어 같은 함수를 보고서용(건너뛰기)과 입력 화면용(다시 입력 받기)에 함께 쓸 수 있습니다.

### 실행 순서 다시 보기

pb-12-1의 `else`, `finally`까지 합치면 실행 순서는 다음과 같습니다.

| 블록 | 에러가 안 났을 때 | 에러가 났을 때 |
| --- | --- | --- |
| `try` | 끝까지 실행 | 에러 난 줄에서 멈춤 |
| `except` | 건너뜀 | 실행 |
| `else` | 실행 | 건너뜀 |
| `finally` | 실행 | 실행 |

```run
def check_grade(g):
    if g not in ("A", "B", "X"):
        raise ValueError(f"알 수 없는 등급: {g}")
    return g

for g in ["A", "Z"]:            # 다른 등급을 넣어 보세요
    try:
        check_grade(g)
    except ValueError as e:
        print("except:", e)
    else:
        print("else: 등급", g, "통과")
    finally:
        print("finally: 검사 기록 남김")
```

"A"는 try → else → finally, "Z"는 try → except → finally 순서로 지나갑니다. `else`에는 **에러가 나지 않았을 때만 할 일**(통과 처리)을 두면, try 안에는 에러가 날 수 있는 줄만 남아 무엇을 감시하는지 분명해집니다.

### 잡았다가 다시 올려 보내기

에러를 잡아서 기록만 남기고, 처리는 위쪽에 맡기고 싶을 때는 `except` 안에서 `raise`만 씁니다. 잡은 에러를 그대로 다시 냅니다.

```run
def read_value(text):
    try:
        return float(text)
    except ValueError:
        print("로그: 변환 실패", repr(text))
        raise

try:
    read_value("N/A")
except ValueError:
    print("상위에서 처리: 이 값은 결측으로 표시")
```

로그가 먼저 찍히고, 같은 에러가 바깥 `try`로 올라가 처리됐습니다.

### 정리

- 문법은 맞지만 **업무 규칙에 안 맞는 값**은 `raise ValueError("설명과 값")`으로 바로 알린다.
- 검사는 함수 안에서, 처리 방법은 함수를 쓰는 쪽에서 정한다.
- `else`에는 성공했을 때만 할 일, `finally`에는 항상 할 일(기록, 정리).
- `except` 안의 `raise` 한 단어는 잡은 에러를 그대로 다시 올려 보낸다.
