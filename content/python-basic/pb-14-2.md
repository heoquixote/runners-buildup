### 시작하기 전에

[객체: 값과 기능을 함께 가진 것](#/l/pb-14-1)에서 모든 값은 객체이고, 객체의 종류(설계도)가 클래스라는 것을 봤습니다. `str`, `list`, `datetime`은 남이 만들어 둔 클래스였습니다. 이번 레슨에서는 **내가 쓸 클래스를 직접** 만듭니다.

지금까지 로트 기록은 딕셔너리로 담고, 불량률은 따로 만든 함수로 계산했습니다([딕셔너리로 기록 다루기](#/l/pb-06-2)).

```run
def defect_rate(lot):
    return round(lot["defects"] / lot["qty"] * 100, 2)

a = {"lot_id": "A0915", "qty": 1250, "defects": 18}
print(defect_rate(a))
```

잘 동작합니다. 하지만 값(딕셔너리)과 기능(함수)이 따로 떨어져 있어서, 로트를 다루는 함수가 늘어날수록 "이 함수에는 어떤 모양의 딕셔너리를 넣어야 하지?"를 매번 확인해야 합니다. 클래스는 **값과 그 값을 다루는 기능을 한 묶음**으로 만듭니다.

### 클래스는 설계도, 객체는 찍어 낸 물건

**클래스(class)**는 붕어빵 틀, **객체(object)**는 그 틀로 찍어 낸 붕어빵입니다. 틀은 하나지만 붕어빵은 여러 개 찍을 수 있고, 붕어빵마다 속(팥, 슈크림)이 다를 수 있습니다. 클래스로 만든 객체를 그 클래스의 **인스턴스(instance)**라고도 부릅니다.

::figure{src="content/img/py/py-class-instance.svg" alt="왼쪽에 Lot 클래스 설계도가 있고 속성 lot_id, qty, defects와 메서드 rate()가 적혀 있다. 화살표가 오른쪽 객체 세 개로 이어지며 각각 A0915 1250 18, A0916 980 7, A0917 1100 25라는 서로 다른 값을 가진다" caption="설계도(클래스) 하나로 값이 다른 객체를 여러 개 만듭니다. 모든 객체가 같은 메서드 rate()를 가집니다."}

가장 작은 클래스부터 만들어 봅시다. `class 이름:` 아래에 내용을 들여 씁니다. 아직 내용이 없으면 `pass`를 씁니다.

```run
class Lot:
    pass

a = Lot()          # 설계도로 객체 하나 찍어 내기
print(type(a))
```

`<class '__main__.Lot'>`이 나옵니다. `'str'` 자리에 우리가 만든 `Lot`이 나왔습니다. `__main__`은 "지금 실행 중인 이 파일에서 만든"이라는 뜻입니다. 클래스 이름은 `Lot`, `DecisionTreeClassifier`처럼 **단어 첫 글자를 대문자로** 쓰는 것이 관례입니다(변수 · 함수 이름은 소문자와 밑줄).

### __init__: 만들 때 속성을 채우는 메서드

로트마다 번호 · 검사 수 · 불량 수를 가지게 하려면 `__init__` 메서드를 씁니다. 이름 앞뒤로 **밑줄이 두 개씩** 있습니다. `Lot(...)`으로 객체를 만들 때 **파이썬이 자동으로 한 번 실행**해서, 넣은 값을 객체의 속성으로 저장합니다.

```run
class Lot:
    def __init__(self, lot_id, qty, defects):
        self.lot_id = lot_id
        self.qty = qty
        self.defects = defects

a = Lot("A0915", 1250, 18)
print(a.lot_id, a.qty, a.defects)
```

`Lot("A0915", 1250, 18)`의 세 값이 `lot_id`, `qty`, `defects`로 들어가고, `self.lot_id = lot_id`가 그 값을 **객체 안에** 저장합니다. 그래서 밖에서 `a.lot_id`로 꺼낼 수 있습니다.

### self: "지금 이 객체"

`self`는 처음 보면 가장 낯선 부분입니다. `self`는 **지금 만들어지고 있는(또는 지금 쓰이고 있는) 바로 그 객체**를 가리키는 이름입니다. 붕어빵 틀이 "이 붕어빵의 속은 팥"이라고 적을 때 "이 붕어빵"이 `self`입니다.

`a = Lot("A0915", 1250, 18)`을 실행하면 파이썬은 이렇게 움직입니다.

1. 빈 `Lot` 객체를 하나 만든다.
2. `__init__(방금 만든 객체, "A0915", 1250, 18)`을 호출한다. 첫 번째 칸 `self`에 그 객체가 자동으로 들어간다.
3. `self.lot_id = "A0915"`는 "**그 객체의** lot_id는 A0915"라는 뜻이 된다.
4. 다 채운 객체를 `a`에 담는다.

그래서 정의할 때는 매개변수가 4개(`self, lot_id, qty, defects`)인데, 부를 때는 값을 3개만 넣습니다. `self`는 파이썬이 채워 줍니다.

### 메서드: 클래스 안의 함수

이제 불량률 계산을 클래스 안으로 옮깁니다. 클래스 안에 `def`로 만든 함수가 **메서드**입니다. 메서드도 첫 매개변수는 `self`이고, `self.qty`처럼 자기 속성을 꺼내 씁니다.

```run
class Lot:
    def __init__(self, lot_id, qty, defects):
        self.lot_id = lot_id
        self.qty = qty
        self.defects = defects

    def rate(self):
        return round(self.defects / self.qty * 100, 2)

a = Lot("A0915", 1250, 18)
print(a.rate())
```

`1.44`입니다. 앞에서 함수에 딕셔너리를 넣던 것과 달리, `a.rate()`는 괄호 안이 비어 있습니다. 필요한 값은 이미 `a` 안에 있기 때문입니다.

`a.rate()`는 사실 파이썬이 `Lot.rate(a)`로 바꿔 실행하는 것입니다. 점 앞의 객체가 `self` 자리에 들어갑니다.

::figure{src="content/img/py/py-self-call.svg" alt="위 줄에 a.rate()가 있고, 화살표를 따라 아래 줄 Lot.rate(a)로 바뀐다. 점 앞의 a가 괄호 안 첫 칸으로 이동하며 그 칸에 self라는 이름표가 붙어 있다. 메서드 안에서 self.qty는 a.qty, self.defects는 a.defects를 뜻한다" caption="a.rate() = Lot.rate(a). 점 앞의 객체가 self 자리에 들어가므로, 메서드 안의 self.qty는 곧 a.qty입니다."}

```run
class Lot:
    def __init__(self, lot_id, qty, defects):
        self.lot_id = lot_id
        self.qty = qty
        self.defects = defects

    def rate(self):
        return round(self.defects / self.qty * 100, 2)

a = Lot("A0915", 1250, 18)
print(a.rate(), Lot.rate(a))
```

두 결과가 같습니다. 실제로는 항상 `a.rate()` 모양으로 씁니다. 원리를 확인하려고 한 번 풀어 써 본 것입니다.

### 객체 여러 개 다루기

설계도가 하나 있으면 객체는 얼마든지 만들 수 있습니다. 리스트에 담아 반복문으로 돌면, 객체마다 **자기 값으로** 계산합니다.

```run
class Lot:
    def __init__(self, lot_id, qty, defects):
        self.lot_id = lot_id
        self.qty = qty
        self.defects = defects

    def rate(self):
        return round(self.defects / self.qty * 100, 2)

lots = [Lot("A0915", 1250, 18), Lot("A0916", 980, 7), Lot("A0917", 1100, 25)]
for lot in lots:
    print(lot.lot_id, lot.rate())
```

`A0915 1.44`, `A0916 0.71`, `A0917 2.27`입니다. 같은 `rate()`인데 결과가 다른 이유는, 메서드가 `self`(각자 자기 객체)의 값을 쓰기 때문입니다.

객체 리스트에도 [lambda와 key: 정렬 기준 고르기](#/l/pb-11-3)에서 배운 `key`를 그대로 쓸 수 있습니다.

```run
class Lot:
    def __init__(self, lot_id, qty, defects):
        self.lot_id = lot_id
        self.qty = qty
        self.defects = defects

    def rate(self):
        return round(self.defects / self.qty * 100, 2)

lots = [Lot("A0915", 1250, 18), Lot("A0916", 980, 7), Lot("A0917", 1100, 25)]
worst = max(lots, key=lambda lot: lot.rate())
print(worst.lot_id)
```

불량률이 가장 높은 `A0917`이 나옵니다.

### 상태를 바꾸는 메서드

메서드는 계산만 하는 것이 아니라 **객체의 속성을 바꿀** 수도 있습니다. 같은 로트를 하루에 여러 번 검사해서 결과를 누적한다고 해 봅시다.

```run
class Lot:
    def __init__(self, lot_id):
        self.lot_id = lot_id
        self.qty = 0          # 처음에는 0에서 시작
        self.defects = 0

    def add(self, qty, defects):
        self.qty += qty
        self.defects += defects

    def rate(self):
        return round(self.defects / self.qty * 100, 2)

a = Lot("A0915")
a.add(500, 6)
a.add(750, 12)
print(a.qty, a.defects, a.rate())
```

`1250 18 1.44`입니다. `add`를 부를 때마다 `a` 안의 값이 쌓였습니다. 이렇게 객체가 **지금까지의 상태를 기억**하고, 메서드가 그 상태를 바꾸거나 쓰는 것이 클래스의 가장 큰 쓸모입니다. [객체: 값과 기능을 함께 가진 것](#/l/pb-14-1)에서 본 리스트의 `append`도 이런 "상태를 바꾸는 메서드"입니다. `add`는 `return`이 없으니 `None`을 돌려주는 것까지 똑같습니다.

:::tip 알아 두면 좋아요 · print(객체)를 보기 좋게: __repr__
객체를 그냥 `print`하면 `<__main__.Lot object at 0x7f...>`처럼 알아보기 힘든 글자가 나옵니다. `__repr__` 메서드를 만들어 문자열을 돌려주면 그 모양으로 보입니다.

```run
class Lot:
    def __init__(self, lot_id, qty, defects):
        self.lot_id = lot_id
        self.qty = qty
        self.defects = defects

    def __repr__(self):
        return f"Lot({self.lot_id}, {self.qty}, {self.defects})"

print(Lot("A0915", 1250, 18))
```

`__init__`, `__repr__`처럼 앞뒤 밑줄 두 개인 메서드는 파이썬이 정해진 때에 알아서 부르는 특별한 메서드입니다. pandas 표가 `print(df)`로 깔끔하게 보이는 것도 이 덕분입니다.
:::

### 딕셔너리와 클래스, 언제 무엇을

모든 것을 클래스로 만들 필요는 없습니다. 원칙은 간단합니다.

| 상황 | 고르기 | 예 |
| --- | --- | --- |
| 값을 한 번 계산하고 끝 | **함수** | 불량률 한 번 계산 |
| 값 몇 개를 잠깐 묶어 두기 | **딕셔너리 · 튜플** | CSV에서 읽은 한 행 |
| 값과 기능이 **함께 다니고**, 상태가 **계속 바뀜** | **클래스** | 검사가 쌓이는 로트, 학습하고 예측하는 모델 |

실무 데이터 분석에서는 클래스를 직접 만드는 일보다 **남이 만든 클래스(DataFrame, 모델)를 쓰는 일**이 훨씬 많습니다. 직접 만들어 보는 이유는, 그 객체들이 속에서 어떻게 움직이는지 이해하기 위해서입니다.

### 자주 하는 실수

```python
class Lot:
    def __init__(self, lot_id):
        self.lot_id = lot_id

    def show():                  # self를 빠뜨림
        print("로트")

a = Lot("A0915")
a.show()
```

```
TypeError: Lot.show() takes 0 positional arguments but 1 was given
```

"값을 0개 받는 메서드인데 1개가 들어왔다"는 뜻입니다. 우리는 아무것도 안 넣었지만, 파이썬이 `a`를 `self` 자리에 자동으로 넣었기 때문입니다. 메서드의 첫 매개변수는 항상 `self`입니다.

| 실수 | 결과 | 고치기 |
| --- | --- | --- |
| 메서드에 `self`를 빠뜨림 | `TypeError: ... takes 0 positional arguments but 1 was given` | 첫 매개변수로 `self` |
| 메서드 안에서 `self.` 없이 `qty` | `NameError: name 'qty' is not defined` | 속성은 `self.qty` |
| `__init__`에서 `self.qty = qty` 대신 `qty = qty` | 나중에 `AttributeError: 'Lot' object has no attribute 'qty'` | 객체에 저장하려면 `self.` |
| `_init_`(밑줄 하나) | 만들 때 실행되지 않아 `TypeError: Lot() takes no arguments` | 앞뒤 밑줄 두 개 `__init__` |
| `a = Lot` (괄호 없음) | 객체가 아니라 설계도 자체가 담김 | `a = Lot(...)` |

### 정리

- `class 이름:`으로 설계도를 만들고, `이름(값, ...)`으로 객체(인스턴스)를 찍어 낸다. 클래스 이름은 첫 글자 대문자.
- `__init__(self, ...)`는 객체를 만들 때 자동 실행되어 `self.속성 = 값`으로 속성을 채운다.
- `self`는 "지금 이 객체". 메서드의 첫 매개변수로 쓰고, 부를 때는 파이썬이 채워 준다(`a.rate()` = `Lot.rate(a)`).
- 메서드 안에서 속성은 `self.이름`으로 읽고 바꾼다. 객체는 상태를 기억한다.
- 한 번 계산하고 끝나면 함수, 값과 기능이 함께 다니며 상태가 바뀌면 클래스.
