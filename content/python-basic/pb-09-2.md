pb-09-1에서 "함수 안의 변수는 함수 안에서만 산다"는 규칙을 봤습니다. 이 규칙을 정확히 알면 두 가지 버그를 피할 수 있습니다. 함수 밖 값이 왜 안 바뀌는지 헷갈리는 버그, 그리고 반대로 **함수에 넘긴 리스트가 몰래 바뀌는** 버그입니다. 이 레슨에서는 함수를 부를 때 무슨 일이 일어나는지 순서대로 따라가 봅니다.

### 호출하면 새 작업 공간이 생깁니다

함수를 호출하면 파이썬은 그 함수만 쓰는 **작업 공간**을 새로 만들고, 매개변수와 함수 안에서 만든 변수를 거기에 둡니다. `return`을 만나면 값을 들고 호출한 곳으로 돌아가고, 작업 공간은 사라집니다.

```run
def rate(defects, qty):
    print("  rate 시작:", defects, qty)
    r = defects / qty
    print("  rate 끝, 돌려줄 값:", r)
    return r

def report(lot, defects, qty):
    print(" report 시작:", lot)
    r = rate(defects, qty)
    print(" report 끝")
    return f"{lot} {r:.2%}"

print("시작")
print(report("A0915", 18, 1250))
print("끝")
```

출력의 들여쓰기를 따라가면 `report` 안에서 `rate`가 불리고, `rate`가 먼저 끝나야 `report`가 이어서 끝나는 순서가 보입니다. 함수 안에서 또 함수를 부르면 작업 공간이 **위로 쌓이고**, 끝난 것부터 치워집니다. 접시를 쌓고 맨 위부터 꺼내는 모양이라 **호출 스택**이라고 부릅니다.

### 지역 변수와 전역 변수

| 구분 | 만드는 곳 | 보이는 곳 |
| --- | --- | --- |
| 지역 변수 | 함수 안 | 그 함수 안에서만 |
| 전역 변수 | 함수 밖 (파일 맨 바깥) | 어디서나 읽을 수 있음 |

함수 안에서 전역 변수를 **읽는 것**은 됩니다.

```run
LIMIT = 10.5                 # 전역 변수: 규격 상한

def over(value):
    return value > LIMIT     # 함수 안에서 읽기

print(over(10.8), over(10.2))
```

True, False입니다. 바뀌지 않는 기준값은 이렇게 대문자 이름의 전역 변수로 두는 경우가 많습니다.

### 같은 이름이면 안쪽이 이깁니다

함수 안에서 **같은 이름에 값을 대입하면**, 바깥 변수를 바꾸는 게 아니라 그 이름의 **지역 변수가 새로 생깁니다.**

```run
total = 0

def add_shift(qty):
    total = qty              # 바깥 total 이 아니라 새 지역 변수
    return total

add_shift(120)
print(total)
```

바깥 `total`은 0 그대로입니다. 함수 안의 `total`은 함수가 끝나면서 사라졌습니다. 바깥 값을 바꾸고 싶으면 `global` 키워드를 쓸 수도 있지만, 어디서 값이 바뀌는지 추적하기 어려워져서 권하지 않습니다. **return으로 돌려받아 다시 담는 것**이 정석입니다.

```run
def add_shift(total, qty):
    return total + qty

total = 0
total = add_shift(total, 120)
total = add_shift(total, 135)
print(total)
```

255입니다. 값이 어디서 들어와 어디로 나가는지가 코드에 그대로 보입니다.

### 리스트를 넘기면 원본이 바뀝니다

pb-04-3에서 `b = a`는 같은 리스트에 이름표를 하나 더 붙인다고 했습니다. 함수에 리스트를 넘길 때도 **똑같습니다.** 매개변수는 원본 리스트에 붙은 또 하나의 이름표입니다.

```run
def drop_outliers(values):
    values.remove(max(values))     # 넘겨받은 리스트를 직접 고친다
    return values

raw = [23.1, 23.4, 99.9, 22.8]
clean = drop_outliers(raw)
print(clean)
print(raw)
```

`raw`에서도 99.9가 사라졌습니다. 원본 측정값을 잃어버린 것입니다. 숫자나 문자열을 넘길 때는 이런 일이 없습니다(고칠 수 없는 값이라서). **리스트·딕셔너리를 받아 고치는 함수**만 조심하면 됩니다.

### 원본을 지키는 두 가지 방법

함수 안에서 복사본을 만들어 고치거나, 아예 새 리스트를 만들어 돌려줍니다.

```run
def drop_outliers(values):
    out = values.copy()           # 방법 1: 복사본을 고친다
    out.remove(max(out))
    return out

def below(values, limit):
    out = []                      # 방법 2: 새 리스트에 모은다
    for v in values:
        if v <= limit:
            out.append(v)
    return out

raw = [23.1, 23.4, 99.9, 22.8]
print(drop_outliers(raw), below(raw, 50))
print(raw)
```

이번에는 `raw`가 그대로입니다. 함수 이름과 설명에 "원본을 고친다"고 밝힌 경우가 아니라면, **입력은 건드리지 않고 결과를 새로 만들어 돌려주는 함수**가 쓰기 안전합니다.

### 정리

- 호출할 때마다 새 작업 공간이 생기고, return 하면 사라진다.
- 함수 안에서 바깥 변수를 **읽는 것**은 되지만, 대입하면 같은 이름의 지역 변수가 새로 생긴다.
- 바깥 값을 바꾸려면 `global` 대신 **return 값을 다시 담는다.**
- 리스트·딕셔너리를 넘기면 원본이 바뀔 수 있다. 복사본을 고치거나 새로 만들어 돌려준다.
