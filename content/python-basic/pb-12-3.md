현장 데이터는 깨끗하지 않습니다. 센서가 `"ERR"`을 남기고, 사람이 칸을 비워 두고, 수량에 쉼표를 넣습니다. 1,000행 중 3행이 이상하다고 전체 처리가 멈추면 안 되고, 그렇다고 이상한 행을 조용히 버려서도 안 됩니다. 이 레슨에서는 **반복 안에서 예외를 처리해 끝까지 돌리고, 무엇을 왜 건너뛰었는지 기록하는** 정제 패턴을 만듭니다.

### 문제 데이터

검사 기록 6행입니다. 일부러 문제를 섞었습니다.

```run
rows = [
    {"lot": "A0915", "qty": "1250", "defects": "18"},
    {"lot": "A0916", "qty": "980", "defects": "ERR"},
    {"lot": "A0917", "qty": "1,100", "defects": "25"},
    {"lot": "A0918", "qty": "0", "defects": "0"},
    {"lot": "A0919", "qty": "1310"},
    {"lot": "A0920", "qty": "1200", "defects": "9"},
]
print(len(rows), "행")
```

CSV를 `DictReader`로 읽으면(pb-10-2) 값이 모두 문자열인 이런 모양이 됩니다. 문제는 네 가지입니다. `"ERR"`(숫자 아님), `"1,100"`(쉼표), 검사 수 0(나누기 불가), `defects` 칸 없음.

### try를 반복 밖에 두면 첫 에러에서 끝납니다

```python
try:
    for row in rows:
        rate = int(row["defects"]) / int(row["qty"])
        print(row["lot"], rate)
except ValueError:
    print("에러")
```

A0915만 처리하고 A0916의 `"ERR"`에서 반복 전체가 끝납니다. 뒤의 멀쩡한 A0920까지 처리되지 않습니다. **한 행의 실패가 다른 행에 번지지 않게** 하려면 `try`를 반복 **안**에 둡니다.

### 반복 안의 try: 한 행씩 따로

```run
rows = [
    {"lot": "A0915", "qty": "1250", "defects": "18"},
    {"lot": "A0916", "qty": "980", "defects": "ERR"},
    {"lot": "A0917", "qty": "1,100", "defects": "25"},
    {"lot": "A0918", "qty": "0", "defects": "0"},
    {"lot": "A0919", "qty": "1310"},
    {"lot": "A0920", "qty": "1200", "defects": "9"},
]
for row in rows:
    try:
        rate = int(row["defects"]) / int(row["qty"])
        print(row["lot"], f"{rate:.2%}")
    except (ValueError, ZeroDivisionError, KeyError) as e:
        print(row["lot"], "건너뜀:", type(e).__name__)
```

6행 모두 처리됐습니다. 정상 2행(A0915, A0920)은 불량률이 나오고, 나머지 4행은 에러 이름과 함께 건너뛰었습니다. 에러 여러 개를 같은 방법으로 처리할 때는 괄호로 묶어 `except (A, B, C)`로 씁니다. `type(e).__name__`은 잡은 에러의 이름입니다.

### 고칠 수 있는 건 고치고, 안 되는 건 기록한다

쉼표가 든 `"1,100"`은 데이터가 틀린 게 아니라 **표기 문제**라 고칠 수 있습니다. 변환 함수를 따로 만들어 고칠 수 있는 것은 고치고, 정상 결과와 실패 목록을 **둘 다** 모읍니다.

```run
rows = [
    {"lot": "A0915", "qty": "1250", "defects": "18"},
    {"lot": "A0916", "qty": "980", "defects": "ERR"},
    {"lot": "A0917", "qty": "1,100", "defects": "25"},
    {"lot": "A0918", "qty": "0", "defects": "0"},
    {"lot": "A0919", "qty": "1310"},
    {"lot": "A0920", "qty": "1200", "defects": "9"},
]

def to_int(text):
    return int(text.replace(",", "").strip())

good, failed = [], []
for row in rows:
    try:
        qty = to_int(row["qty"])
        defects = to_int(row["defects"])
        rate = defects / qty
    except KeyError as e:
        failed.append((row["lot"], f"칸 없음 {e}"))
    except ValueError:
        failed.append((row["lot"], f"숫자 아님 {row.get('defects')}"))
    except ZeroDivisionError:
        failed.append((row["lot"], "검사 수 0"))
    else:
        good.append((row["lot"], rate))

print("정상", len(good), "건")
for lot, r in good:
    print(" ", lot, f"{r:.2%}")
print("실패", len(failed), "건")
for lot, why in failed:
    print(" ", lot, why)
```

A0917이 쉼표를 지우고 살아나 정상이 3건(A0915, A0917, A0920)이 됐고, 실패 3건은 이유와 함께 남았습니다. 실패 목록은 보고서 끝에 붙이거나 파일로 저장해 **현장에 다시 확인을 요청하는 근거**가 됩니다. "데이터 1,000건 중 997건 처리, 3건은 아래 사유로 제외"라고 쓸 수 있어야 분석 결과를 믿을 수 있습니다.

### 미리 검사할까, 일단 시도할까

에러를 피하는 방법은 두 가지입니다.

| 방법 | 모양 | 잘 맞는 경우 |
| --- | --- | --- |
| 미리 검사 | `if "defects" in row:`, `row.get("defects")` | 확인이 쉽고 흔히 생기는 상황 (칸 없음, 0) |
| 일단 시도 | `try: int(text)` / `except ValueError:` | 미리 검사하기 어려운 경우 (숫자 모양인지, 파일이 열리는지) |

```run
row = {"lot": "A0919", "qty": "1310"}
print(row.get("defects", "0"))         # 미리 검사: 없으면 기본값

text = "12.5e1"
try:                                    # 일단 시도: 숫자 모양 규칙은 복잡하다
    print(float(text))
except ValueError:
    print("숫자 아님")
```

`"12.5e1"`은 125.0으로 읽힙니다(지수 표기). `isdigit()`(pb-03-2)으로 미리 검사했다면 숫자가 아니라고 잘못 판단했을 값입니다. 숫자인지 판단은 `float()`에 맡기고 실패를 잡는 쪽이 정확합니다.

다만 `get()`의 기본값은 신중하게 정합니다. 위 예처럼 빈 불량 칸을 `"0"`으로 채우면 "불량 0개"로 집계되어 실제보다 좋아 보이게 됩니다. **모르는 값은 0이 아니라 실패로 남기는 것**이 품질 데이터에서는 더 안전합니다.

### 정리

- `try`는 반복 **안**에 두어 한 행의 실패가 전체를 멈추지 않게 한다.
- 고칠 수 있는 표기 문제(쉼표, 공백)는 변환 함수에서 고친다.
- 정상 결과와 **실패 목록(행 + 이유)**을 함께 모아 보고한다.
- 칸 없음·0 같은 흔한 경우는 `if`/`get`으로, 숫자 모양 판단은 `try`로.
- 모르는 값을 0으로 채우지 않는다.
