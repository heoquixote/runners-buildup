윈도우 함수의 모양은 `함수() OVER (PARTITION BY 묶을 열 ORDER BY 정렬 열)`입니다. `OVER (…)` 괄호가 "어떤 창으로 내다볼지"를 정합니다.

```sqlrun
SELECT ename_ko, deptno, sal,
       AVG(sal) OVER (PARTITION BY deptno) AS dept_avg
FROM emp
ORDER BY deptno, sal DESC;
```

14줄이 그대로 있고, 줄마다 자기 부서의 평균이 붙었습니다. 이제 "내 연봉 − 부서 평균"처럼 **개인과 그룹을 한 줄에서 비교**할 수 있습니다.

## 순위 매기기: ROW_NUMBER · RANK · DENSE_RANK

순위 함수는 `OVER (ORDER BY …)`의 순서대로 번호를 붙입니다. 세 가지는 **동점 처리**만 다릅니다.

```sqlrun
SELECT ename_ko, sal,
       ROW_NUMBER() OVER (ORDER BY sal DESC) AS row_num,
       RANK()       OVER (ORDER BY sal DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY sal DESC) AS dense
FROM emp;
```

연봉 6000인 정성구와 이주영을 보세요.

| 함수 | 6000인 두 사람 | 그다음 사람(5500) | 쓰임 |
| --- | --- | --- | --- |
| `ROW_NUMBER` | 9, 10 (동점이어도 다른 번호) | 11 | 줄마다 하나뿐인 번호가 필요할 때 |
| `RANK` | 9, 9 | **11** (10을 건너뜀) | 올림픽 순위처럼 |
| `DENSE_RANK` | 9, 9 | **10** (건너뛰지 않음) | 등급 · 단계처럼 빈 번호가 없어야 할 때 |

## PARTITION BY: 그룹 안에서 따로 세기

`PARTITION BY`를 붙이면 그룹마다 순위를 **1부터 다시** 셉니다. 직급 안에서의 연봉 순위입니다.

```sqlrun
SELECT joblv, ename_ko, sal,
       DENSE_RANK() OVER (PARTITION BY joblv ORDER BY sal DESC) AS rank_in_job
FROM emp
ORDER BY joblv, rank_in_job;
```

부장 3명은 김낙수 1, 최재혁 2, 도진우 3이고, 대리 3명도 정성구 1부터 다시 셉니다.

## 그룹별 1등만 뽑기

"부서마다 연봉 1등"은 실무에서 아주 자주 나오는 질문입니다(카테고리별 베스트 상품, 고객별 최근 주문 …). 순위를 매긴 뒤 **1위만 남기면** 됩니다. 그런데 윈도우 함수는 SELECT 단계에서 계산되므로 같은 쿼리의 WHERE에서는 쓸 수 없습니다(Day 04의 실행 순서). 그래서 Day 07의 **CTE로 한 단계 감싼 뒤** 거릅니다.

```sqlrun
WITH ranked AS (
    SELECT deptno, ename_ko, sal,
           ROW_NUMBER() OVER (PARTITION BY deptno ORDER BY sal DESC) AS rn
    FROM emp
    WHERE deptno IS NOT NULL
)
SELECT deptno, ename_ko, sal
FROM ranked
WHERE rn = 1
ORDER BY deptno;
```

부서 5곳의 1등이 한 줄씩 나왔습니다. 공동 1등을 모두 남기고 싶으면 `ROW_NUMBER` 대신 `RANK`를 씁니다.

## 누적합: SUM() OVER (ORDER BY)

`OVER` 안에 `ORDER BY`를 쓰면 창이 **처음부터 지금 줄까지**로 정해집니다. 그래서 `SUM`은 누적합이 됩니다. 쇼핑몰의 월별 매출과 누적 매출을 구해 봅니다. 월별 매출은 CTE로 먼저 만들어 둡니다.

```sqlrun
WITH monthly AS (
    SELECT strftime('%Y-%m', order_date) AS ym, SUM(amount) AS revenue
    FROM orders GROUP BY ym
)
SELECT ym, revenue,
       SUM(revenue) OVER (ORDER BY ym) AS cum_revenue
FROM monthly;
```

2월의 누적은 1월 + 2월 = 3,635,600원, 7월의 누적은 7개월 전체 매출 21,008,000원입니다. 목표 매출까지 얼마나 왔는지 볼 때 쓰는 숫자입니다.

## LAG · LEAD: 이전 줄 · 다음 줄 값

`LAG(열)`은 **바로 앞 줄**의 값, `LEAD(열)`은 **바로 다음 줄**의 값을 가져옵니다. 지난달 매출을 옆에 붙이면 전월 대비 증감을 계산할 수 있습니다.

```sqlrun
WITH monthly AS (
    SELECT strftime('%Y-%m', order_date) AS ym, SUM(amount) AS revenue
    FROM orders GROUP BY ym
)
SELECT ym, revenue,
       LAG(revenue) OVER (ORDER BY ym) AS prev_revenue,
       revenue - LAG(revenue) OVER (ORDER BY ym) AS diff
FROM monthly;
```

1월은 앞 줄이 없어서 NULL입니다. 4월에 547,000원 줄었다가 5월 · 6월에 다시 늘고, 7월에는 2,646,500원이 크게 줄었습니다.

사원 데이터에서는 입사 순서대로 앞 사람 · 뒷사람의 연봉을 나란히 볼 수 있습니다.

```sqlrun
SELECT ename_ko, hiredate, sal,
       LAG(sal)  OVER (ORDER BY hiredate) AS prev_sal,
       LEAD(sal) OVER (ORDER BY hiredate) AS next_sal
FROM emp;
```

## 이동평균: 창의 크기 정하기

월별 숫자는 오르락내리락이 심해 흐름이 잘 안 보입니다. 최근 3개월 평균(**이동평균**)을 내면 흐름이 부드럽게 보입니다. `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`는 "앞 2줄부터 지금 줄까지", 즉 3줄짜리 창입니다.

```sqlrun
WITH monthly AS (
    SELECT strftime('%Y-%m', order_date) AS ym, SUM(amount) AS revenue
    FROM orders GROUP BY ym
)
SELECT ym, revenue,
       ROUND(AVG(revenue) OVER (ORDER BY ym ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)) AS ma3
FROM monthly;
```

4월 매출은 3월보다 줄었지만, 3개월 이동평균(`ma3`)은 1월부터 6월까지 계속 올라갑니다. 한 달의 출렁임보다 큰 흐름은 성장 중이었다는 뜻입니다.

> 직접 해보기: `2 PRECEDING`을 `1 PRECEDING`(2개월 평균)이나 `5 PRECEDING`(6개월 평균)으로 바꿔 보세요. 창이 클수록 선이 더 부드러워지는 대신, 최근 변화(7월 감소)를 늦게 반영합니다.

## 정리

| 하고 싶은 일 | 쓰는 문법 |
| --- | --- |
| 줄은 그대로, 그룹 값 붙이기 | `AVG(열) OVER (PARTITION BY 그룹)` |
| 순위 | `ROW_NUMBER` (모두 다른 번호) · `RANK` (동점 후 건너뜀) · `DENSE_RANK` (건너뛰지 않음) |
| 그룹 안에서 순위 | `… OVER (PARTITION BY 그룹 ORDER BY 기준)` |
| 그룹별 1등 | CTE로 순위를 매긴 뒤 `WHERE rn = 1` |
| 누적합 | `SUM(열) OVER (ORDER BY 순서)` |
| 앞 · 뒤 줄 값 | `LAG(열)` · `LEAD(열)` |
| 이동평균 | `AVG(열) OVER (ORDER BY … ROWS BETWEEN n PRECEDING AND CURRENT ROW)` |
