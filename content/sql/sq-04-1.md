## 왜 표를 나눠 두었을까

`emp` 테이블에는 부서 **번호**만 있고 부서 **이름**은 `dept`에 따로 있습니다. 한 표에 다 적으면 편할 텐데 왜 나눴을까요?

사원 14명 줄마다 "ACT 영업1팀, 서울"을 적어 두었다고 해 봅시다. 영업1팀 이름이 "ACT 국내영업팀"으로 바뀌면 5줄을 모두 고쳐야 하고, 하나라도 빠뜨리면 같은 부서가 두 이름으로 남습니다. 표를 나눠 두면 `dept`의 **한 줄**만 고치면 끝입니다. 그래서 회사 DB는 주제별로 표를 잘게 나눠 두고, 볼 때 **키로 다시 이어 붙입니다**. 이어 붙이는 문법이 `JOIN`입니다.

## JOIN … ON: 키가 같은 행끼리 잇기

```sqlrun
SELECT e.ename_ko, e.deptno, d.dname
FROM emp e
JOIN dept d ON e.deptno = d.deptno;
```

- `FROM emp e`: `emp` 테이블을 짧게 `e`라고 부르겠다는 **테이블 별칭**입니다.
- `JOIN dept d ON e.deptno = d.deptno`: `dept`(별칭 `d`)를 붙이되, 두 표의 `deptno`가 같은 행끼리 잇습니다.
- `e.ename_ko`처럼 **별칭.열** 로 어느 표의 열인지 밝힙니다. `deptno`는 두 표에 다 있어서, 별칭 없이 쓰면 `ambiguous column name`(어느 표 것인지 모호함) 오류가 납니다.

결과를 보면 **13행**입니다. 사원은 14명인데 한 명이 빠졌습니다. 부서가 NULL인 김대표입니다. 그냥 `JOIN`은 **양쪽 모두에 짝이 있는 행만** 남기는 **INNER JOIN**이기 때문입니다. (`INNER JOIN`이라고 써도 똑같습니다.)

## LEFT JOIN: 왼쪽 표는 하나도 빼지 않기

"모든 사원과 부서 이름"이 필요하다면 짝이 없는 사원도 남겨야 합니다. `LEFT JOIN`은 **왼쪽(FROM에 쓴) 표의 행을 모두 남기고**, 오른쪽에 짝이 없으면 그 칸을 NULL로 채웁니다.

```sqlrun
SELECT e.ename_ko, e.deptno, d.dname, d.location
FROM emp e
LEFT JOIN dept d ON e.deptno = d.deptno;
```

14행이 모두 나왔고, 김대표 줄의 부서 이름 · 위치가 NULL입니다.

> `RIGHT JOIN`은 오른쪽 표를 모두 남기는 것인데, 표 순서만 바꾸면 LEFT JOIN과 같아서 실무에서는 거의 LEFT JOIN으로 통일합니다. 양쪽을 모두 남기는 `FULL OUTER JOIN`도 있습니다.

## LEFT JOIN으로 "없는 것" 찾기

LEFT JOIN의 진짜 쓸모는 **짝이 없는 행 찾기**입니다. 쇼핑몰에서 "가입만 하고 한 번도 주문하지 않은 고객"을 찾아봅니다. 고객(`users`)을 왼쪽에 두고 주문(`orders`)을 붙인 뒤, 주문 쪽이 NULL인 행만 남깁니다.

```sqlrun
SELECT u.user_id, u.signup_date, u.channel
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
WHERE o.order_id IS NULL;
```

고객 256명 중 **64명**이 한 번도 사지 않았습니다. 이 명단은 "첫 구매 쿠폰"을 보낼 대상이 됩니다. INNER JOIN으로는 절대 찾을 수 없는 사람들입니다.

## LEFT JOIN 뒤에 셀 때: COUNT(*) vs COUNT(열)

고객별 주문 수를 세어 봅니다. 두 가지 방법을 나란히 둡니다.

```sqlrun
SELECT u.user_id, COUNT(*) AS count_star, COUNT(o.order_id) AS order_count
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
GROUP BY u.user_id
ORDER BY u.user_id
LIMIT 8;
```

1번 · 3번 고객은 주문이 없는데 `COUNT(*)`는 1, `COUNT(o.order_id)`는 0입니다. LEFT JOIN이 주문 칸을 NULL로 채운 **행 1개**를 남겼고, `COUNT(*)`는 그 행까지 세기 때문입니다. Day 04에서 배운 대로 `COUNT(열)`은 NULL을 세지 않으니, LEFT JOIN 뒤에는 **오른쪽 표의 열로 셉니다**.

## 키가 여러 번 나오면 행이 불어난다

JOIN은 짝이 되는 행마다 한 줄씩 만듭니다. 그래서 양쪽에 같은 키가 여러 번 나오면 **곱한 만큼** 행이 생깁니다. 7번 고객의 주문(4건)과 방문 기록(3건)을 고객 번호로 이어 봅니다.

```sqlrun
SELECT o.order_id, o.amount, v.step
FROM orders o
JOIN events v ON o.user_id = v.user_id
WHERE o.user_id = 7;
```

4 × 3 = **12행**이 됐습니다. 주문 하나가 방문 기록 수만큼 복사됐습니다. 이 상태로 매출을 더하면 어떻게 될까요?

```sqlrun
SELECT SUM(amount) AS real_revenue FROM orders;
SELECT SUM(o.amount) AS wrong_revenue
FROM orders o JOIN events v ON o.user_id = v.user_id;
```

실제 매출은 21,008,000원인데, 잘못 이은 쪽은 56,127,900원으로 두 배 넘게 부풀었습니다. 오류 메시지 없이 숫자만 틀리기 때문에 실무에서 가장 흔하고 위험한 실수입니다. JOIN 전후로 **행 수를 세어 보는 습관**이 이 실수를 막아 줍니다.

> 한 셀에 SQL 문장을 여러 개 쓰면 결과 표도 문장마다 하나씩 나옵니다.

## 자기 자신과 잇기: SELF JOIN

`emp.mgr`는 같은 `emp` 표의 `empno`를 가리킵니다. 같은 표를 별칭 두 개(`e`는 사원, `b`는 상사)로 불러 이으면 사원과 상사 이름을 나란히 볼 수 있습니다.

```sqlrun
SELECT e.ename_ko AS employee, b.ename_ko AS boss
FROM emp e
LEFT JOIN emp b ON e.mgr = b.empno;
```

LEFT JOIN을 썼기 때문에 상사가 없는 김대표와 이주영도 boss가 NULL인 채로 남았습니다.

## 범위로 잇기: 급여 등급

ON 뒤에는 `=`만이 아니라 어떤 조건이든 쓸 수 있습니다. 총급여가 `salgrade`의 `losal ~ hisal` 사이에 드는 등급을 붙입니다.

```sqlrun
SELECT e.ename_ko, e.sal + e.comm AS total_pay, g.grade
FROM emp e
JOIN salgrade g ON e.sal + e.comm BETWEEN g.losal AND g.hisal
ORDER BY total_pay DESC;
```

## UNION: 위아래로 붙이기

JOIN이 표를 **옆으로** 붙인다면, `UNION`은 두 SELECT 결과를 **위아래로** 붙입니다. 두 결과의 열 개수와 순서가 같아야 합니다.

```sqlrun
SELECT empno, ename_ko, deptno FROM emp WHERE deptno = 11
UNION ALL
SELECT empno, ename_ko, deptno FROM emp WHERE deptno = 12;
```

- `UNION ALL`: 그대로 이어 붙입니다.
- `UNION`: 붙인 뒤 **중복 행을 지웁니다**(그만큼 느립니다).

```sqlrun
SELECT joblv FROM emp WHERE deptno = 11
UNION
SELECT joblv FROM emp WHERE deptno = 12;
```

두 부서의 직급을 그냥 이으면 9줄이지만, `UNION`은 중복을 지워 5종류만 남깁니다.

## 정리

| 하고 싶은 일 | 쓰는 문법 |
| --- | --- |
| 양쪽에 짝이 있는 행만 | `JOIN` (= `INNER JOIN`) |
| 왼쪽 표는 모두 남기기 | `LEFT JOIN`, 짝 없으면 NULL |
| 짝이 없는 행 찾기 | `LEFT JOIN … WHERE 오른쪽.키 IS NULL` |
| LEFT JOIN 뒤 개수 세기 | `COUNT(오른쪽 표의 열)` |
| 같은 표끼리 | SELF JOIN (별칭 두 개) |
| 위아래로 붙이기 | `UNION ALL` (그대로) · `UNION` (중복 제거) |

JOIN 뒤에는 항상 **행 수가 예상과 같은지** 확인하세요. 줄었다면 INNER가 짝 없는 행을 버렸고, 늘었다면 키가 중복됐습니다.
