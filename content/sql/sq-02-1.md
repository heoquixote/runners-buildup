## ORDER BY: 줄 세우기

체육 시간에 "키 순서대로 서!" 하면 작은 사람부터 줄을 섭니다. SQL에서 결과를 줄 세우는 말이 `ORDER BY 열`입니다. 연봉이 높은 사람부터 보려면 `DESC`(내림차순)를 붙입니다.

```sqlrun
SELECT ename_ko, joblv, sal FROM emp ORDER BY sal DESC;
```

`ASC`(오름차순)는 작은 값부터이고, 아무것도 안 붙이면 ASC입니다. 글자는 가나다 · ABC 순, 날짜는 오래된 날부터입니다.

```sqlrun
SELECT ename_ko, hiredate FROM emp ORDER BY hiredate;
```

> ORDER BY는 **보여 주는 순서만** 바꿉니다. 테이블에 저장된 데이터는 그대로입니다.

## 기준을 여러 개 쓰기

위 결과에서 정성구와 이주영은 연봉이 6000으로 같습니다. 이렇게 동점이 있을 때 다음 기준을 쉼표로 이어 적습니다. 먼저 부서 번호 순, 같은 부서 안에서는 연봉 높은 순으로 세워 봅니다.

```sqlrun
SELECT ename_ko, deptno, sal FROM emp ORDER BY deptno, sal DESC;
```

`deptno`에는 아무것도 안 붙였으니 오름차순, `sal`에는 DESC를 붙였으니 내림차순입니다. **방향은 열마다 따로** 붙입니다. 맨 위의 김대표는 부서가 NULL이라 가장 앞에 왔습니다. SQLite와 MySQL은 오름차순에서 NULL을 맨 앞에 둡니다.

## 별칭으로 정렬하기

SELECT에서 계산해 만든 열도 별칭으로 정렬할 수 있습니다. 총급여(연봉 + 성과급)가 높은 순입니다.

```sqlrun
SELECT ename_ko, sal + comm AS total_pay FROM emp ORDER BY total_pay DESC;
```

연봉 순으로는 5등이던 도진우(12000 + 7000 = 19000)가 총급여로는 4등으로 올라섰습니다. 무엇을 기준으로 줄 세우느냐에 따라 순위가 달라집니다.

```sqlrun
SELECT ename_ko, sal FROM emp ORDER BY sal DESC LIMIT 3;
```

`OFFSET N`을 붙이면 앞의 N개를 건너뛰고 가져옵니다. 4등부터 3명입니다.

```sqlrun
SELECT ename_ko, sal FROM emp ORDER BY sal DESC LIMIT 3 OFFSET 3;
```

ORDER BY 없이 LIMIT만 쓰면 어떻게 될까요?

```sqlrun
SELECT ename_ko, sal FROM emp WHERE sal >= 5000 LIMIT 3;
```

> 직접 해보기: 결과가 김대표 · 최재혁 · 남궁민수입니다. 연봉 순이 아니라 **저장된 순서**(여기서는 사번 순)대로 앞의 3개가 나왔을 뿐입니다. DB는 ORDER BY가 없으면 순서를 약속하지 않습니다. 위 셀에 `ORDER BY sal DESC`를 넣어 결과를 비교해 보세요. "상위 N개"에는 반드시 ORDER BY가 함께 있어야 합니다.

## 계산 열과 정수 나눗셈의 함정

연봉을 12로 나눠 월급을 계산해 봅니다.

```sqlrun
SELECT ename_ko, sal, sal / 12 AS monthly FROM emp ORDER BY sal DESC LIMIT 5;
```

김대표의 월급이 6666으로 나왔습니다. 80000 ÷ 12 = 6666.66…인데 소수점 아래가 사라졌습니다. SQLite는 **정수 ÷ 정수의 결과도 정수(몫)** 로 계산하기 때문입니다.

```sqlrun
SELECT 7 / 2, 7 / 2.0, 7 * 1.0 / 2, 7 % 2;
```

`7 / 2`는 3, 어느 한쪽이라도 소수(`2.0`, `* 1.0`)가 섞이면 3.5입니다. `%`는 나머지입니다.

> MySQL에서는 `7 / 2`가 3.5로 나옵니다. 데이터베이스마다 다르니, 비율을 계산할 때는 `* 1.0`이나 `100.0`을 섞어 두는 습관이 안전합니다.

이 함정은 비율 계산에서 특히 위험합니다. 성과급이 연봉의 몇 %인지 두 가지로 계산해 봅니다.

```sqlrun
SELECT ename_ko, sal, comm,
       comm / sal * 100 AS wrong_pct,
       comm * 100.0 / sal AS bonus_pct
FROM emp WHERE comm != 0 ORDER BY bonus_pct DESC;
```

`wrong_pct`는 모두 0입니다. `7000 / 12000`이 정수 나눗셈으로 먼저 0이 되고, 0 × 100 = 0이 됐기 때문입니다. `100.0`을 먼저 곱한 `bonus_pct`는 도진우 58.33…%처럼 제대로 나옵니다. 에러 없이 **틀린 숫자가 조용히 나오는** 실수라서 더 조심해야 합니다.

> SQL은 한 문장을 여러 줄에 나눠 써도 됩니다. 길어지면 열마다 줄을 바꾸는 편이 읽기 쉽습니다.

## 숫자 함수: 반올림 · 버림 · 절댓값

| 함수 | 하는 일 | 예 → 결과 |
| --- | --- | --- |
| `ROUND(x, n)` | 소수 n자리로 반올림 (n 생략 시 정수) | `ROUND(3.14159, 2)` → 3.14 |
| `CAST(x AS INTEGER)` | 소수점 아래 버림 | `CAST(3.6 AS INTEGER)` → 3 |
| `ABS(x)` | 절댓값 | `ABS(-10)` → 10 |
| `x % y` | 나머지 | `7 % 2` → 1 |

```sqlrun
SELECT ROUND(3.14159, 2), ROUND(3.6), CAST(3.6 AS INTEGER), ABS(-10);
```

보너스 비율을 소수 둘째 자리까지 반올림하고, 월급은 소수 첫째 자리까지 보여 줍니다.

```sqlrun
SELECT ename_ko,
       ROUND(comm * 100.0 / sal, 2) AS bonus_pct,
       ROUND(sal / 12.0, 1) AS monthly
FROM emp WHERE comm != 0 ORDER BY bonus_pct DESC;
```

> MySQL의 `TRUNCATE(x, 0)`(버림)은 SQLite에서 `CAST(x AS INTEGER)`로 씁니다.

## 쇼핑몰: 가장 큰 주문 TOP 5

결제 금액(`amount`)이 가장 큰 주문 5건입니다. "매출 상위 N건"은 실무 보고서에서 가장 자주 만드는 표입니다.

```sqlrun
SELECT order_id, order_date, category, amount FROM orders ORDER BY amount DESC LIMIT 5;
```

5건 모두 전자 제품이고, 1위는 6월 1일의 389,400원 주문입니다.

## NULL은 어디에 줄 설까

부서 번호 순으로 사원을 세우면 이상한 일이 생깁니다.

```sqlrun
SELECT ename_ko, deptno FROM emp ORDER BY deptno LIMIT 3;
```

부서가 없는(NULL) 김대표가 맨 앞에 옵니다. SQLite는 **오름차순에서 NULL을 가장 작은 값처럼** 맨 앞에 둡니다. 부서가 있는 사원만 보려면 NULL을 먼저 걸러 냅니다.

```sqlrun
SELECT ename_ko, deptno FROM emp WHERE deptno IS NOT NULL ORDER BY deptno LIMIT 3;
```

> DB마다 NULL의 자리가 다릅니다. MySQL · SQLite는 오름차순에서 맨 앞, Oracle · PostgreSQL은 맨 뒤입니다. 결과를 다른 DB로 옮길 때 순서가 바뀌는 흔한 이유입니다.

## 정리

- `ORDER BY 열 [ASC | DESC]`: 정렬. 기준을 여러 개 쓸 수 있고 방향은 열마다 따로.
- `LIMIT N OFFSET M`: M개 건너뛰고 N개. **ORDER BY와 짝**으로 써야 "상위 N개"가 됩니다.
- 정수 ÷ 정수 = 정수(몫). 비율은 `* 100.0`처럼 소수를 섞어 계산합니다.
- `ROUND` 반올림, `CAST(… AS INTEGER)` 버림, `ABS` 절댓값.
- 오름차순 정렬에서 NULL은 맨 앞. 필요하면 `IS NOT NULL`로 먼저 거릅니다.
