- **DDL** (Data Definition Language, 정의어): 표 자체를 만들고 바꾸고 지웁니다. 이번 레슨.

- **DCL** (Data Control Language, 제어어): "분석팀은 주문 표를 읽기만 가능" 같은 권한을 줍니다(`GRANT SELECT ON orders TO analyst;`). 이 사이트의 SQLite는 혼자 쓰는 파일 DB라 권한 개념이 없어서 실습은 하지 않습니다. 회사 DB에서 "permission denied" 오류를 보면 DCL로 권한을 받아야 한다는 뜻입니다.
- **TCL** (Transaction Control Language): 여러 변경을 하나로 묶어 확정하거나 되돌립니다. [모두 되거나, 모두 안 되거나: 트랜잭션](#/l/sq-12-1)에서 배웁니다.

## CREATE TABLE: 표 만들기

동아리 표를 만들어 봅니다. 괄호 안에 `열 이름 자료형 제약조건`을 쉼표로 이어 적습니다.

```sqlrun
CREATE TABLE club (
  club_id INTEGER PRIMARY KEY,
  name    TEXT NOT NULL UNIQUE,
  room    TEXT
);
INSERT INTO club VALUES (1, '축구부', '체육관'), (2, '밴드', '음악실'), (3, '코딩', NULL);
SELECT * FROM club;
```

- `club_id INTEGER PRIMARY KEY`: 정수 열, 기본키.
- `name TEXT NOT NULL UNIQUE`: 글자 열, 비면 안 되고(NOT NULL) 겹치면 안 됨(UNIQUE).
- `room TEXT`: 제약 없음. 그래서 코딩 동아리의 방은 NULL이 들어갔습니다.

처음 만드는 표는 비어 있으니, `INSERT`로 행을 넣은 뒤에야 SELECT에 무언가 보입니다.

## 자료형: 열에 담을 값의 종류

열마다 어떤 종류의 값을 담을지 정합니다. 물리 모델에서 가장 먼저 정하는 것입니다.

| 담을 값 | SQLite | MySQL | 예 |
| --- | --- | --- | --- |
| 정수 | `INTEGER` | `INT`, `BIGINT` | 학번, 수량 |
| 소수 | `REAL` | `DOUBLE`, `DECIMAL(10,2)` | 키, 환율 |
| 글자 | `TEXT` | `VARCHAR(50)`, `TEXT` | 이름, 주소 |
| 날짜 · 시각 | `TEXT`('2025-07-31') | `DATE`, `DATETIME` | 가입일 |
| 참 · 거짓 | `INTEGER`(0 · 1) | `BOOLEAN`(TINYINT) | 재직 여부 |

> 돈은 MySQL에서 `DOUBLE`보다 `DECIMAL`로 저장합니다. 소수 자료형은 0.1 + 0.2가 0.30000000000000004가 되는 것처럼 아주 작은 오차가 생기는데, 금액에서는 1원 오차도 문제가 되기 때문입니다.

SQLite는 자료형에 아주 너그럽습니다. 정수 열에 글자를 넣어도 받아 줍니다.

```sqlrun
CREATE TABLE score_box (n INTEGER, d TEXT);
INSERT INTO score_box VALUES ('abc', 2025);
SELECT n, typeof(n) AS n_type, d, typeof(d) AS d_type FROM score_box;
```

`INTEGER` 열 `n`에 글자 'abc'가 그대로(`text`) 들어갔습니다. SQLite는 자료형을 "되도록 이 종류로 바꿔 저장한다"는 **선호(타입 친화성)**로만 다루기 때문입니다. MySQL · PostgreSQL은 이런 값을 거절합니다. SQLite에서도 표 끝에 `STRICT`를 붙이면 엄격하게 검사합니다.

```sqlrun
-- 오류 예시
CREATE TABLE score_box (n INTEGER) STRICT;
INSERT INTO score_box VALUES ('abc');
```

## 제약조건: 표 앞의 문지기

자료형이 "어떤 종류의 값"을 정한다면, **제약조건**은 "어떤 값은 절대 들어오면 안 된다"는 규칙입니다. 표 앞에 문지기를 세워 두는 것과 같습니다. 규칙을 어긴 행은 문지기가 돌려보내고(오류), 표에는 들어가지 않습니다.

| 제약조건 | 막는 것 | 예 |
| --- | --- | --- |
| `NOT NULL` | 빈 값 | 회원 이름은 꼭 있어야 |
| `UNIQUE` | 중복 | 동아리 이름 · 이메일은 겹치면 안 됨 |
| `PRIMARY KEY` | 빈 값 + 중복 | 학번 |
| `FOREIGN KEY` | 없는 대상을 가리키기 | 없는 동아리 번호 |
| `CHECK` | 규칙 밖의 값 | 학년은 1~3, 금액은 0 이상 |
| `DEFAULT` | (막지는 않고) 값을 안 주면 채울 기본값 | 상태 = '활동' |

하나씩 어겨 봅니다. 먼저 **NOT NULL**: 이름 없는 회원을 넣습니다.

```sqlrun
-- 오류 예시
CREATE TABLE member (member_id INTEGER PRIMARY KEY, name TEXT NOT NULL);
INSERT INTO member (member_id) VALUES (1);
```

`NOT NULL constraint failed: member.name`. 어느 표의 어느 열이 막았는지까지 알려 줍니다.

**UNIQUE**: 같은 이름의 동아리를 두 번 만듭니다.

```sqlrun
-- 오류 예시
CREATE TABLE club (club_id INTEGER PRIMARY KEY, name TEXT UNIQUE);
INSERT INTO club VALUES (1, '밴드');
INSERT INTO club VALUES (2, '밴드');
```

첫 번째 INSERT는 성공하고, 두 번째에서 `UNIQUE constraint failed`가 납니다. 기본키도 같은 이유로 중복을 막습니다(`club_id`를 1로 두 번 넣어 보세요).

**CHECK**: 학년은 1~3이어야 합니다.

```sqlrun
-- 오류 예시
CREATE TABLE member (member_id INTEGER PRIMARY KEY, name TEXT,
                     grade INTEGER CHECK (grade BETWEEN 1 AND 3));
INSERT INTO member VALUES (1, '민준', 4);
```

CHECK 안에는 WHERE에 쓰는 조건식을 그대로 씁니다. `amount >= 0`, `status IN ('활동', '휴면')`처럼 업무 규칙을 표에 새겨 둘 수 있습니다.

**DEFAULT**는 오류를 내지 않고, 값을 주지 않은 열을 기본값으로 채웁니다.

```sqlrun
CREATE TABLE member (member_id INTEGER PRIMARY KEY, name TEXT NOT NULL,
                     status TEXT DEFAULT '활동');
INSERT INTO member (member_id, name) VALUES (1, '민준');
INSERT INTO member VALUES (2, '서연', '휴면');
SELECT * FROM member;
```

민준은 상태를 주지 않아 '활동'으로 채워졌고, 서연은 준 값 '휴면'이 그대로 들어갔습니다.

## 외래키: 없는 것을 가리키지 못하게

**FOREIGN KEY**(`REFERENCES 표(열)`)는 "이 열의 값은 저 표에 실제로 있는 값이어야 한다"는 규칙입니다. 9번 동아리는 없는데 회원을 9번 동아리에 넣어 봅니다.

```sqlrun
-- 오류 예시
PRAGMA foreign_keys = ON;
CREATE TABLE club (club_id INTEGER PRIMARY KEY, name TEXT);
CREATE TABLE member (member_id INTEGER PRIMARY KEY, name TEXT,
                     club_id INTEGER REFERENCES club(club_id));
INSERT INTO club VALUES (1, '축구부');
INSERT INTO member VALUES (1, '민준', 1);
INSERT INTO member VALUES (2, '서연', 9);
```

민준(1번 동아리)은 들어가고, 서연(없는 9번)에서 `FOREIGN KEY constraint failed`가 납니다. 외래키가 없으면 "주인 없는 주문", "없는 부서의 사원" 같은 고아 데이터가 쌓이고, JOIN할 때 조용히 사라져 숫자가 틀어집니다.

> SQLite는 옛날 프로그램과의 호환 때문에 외래키 검사가 **기본으로 꺼져** 있어서, 맨 위의 `PRAGMA foreign_keys = ON;`으로 켜야 합니다. MySQL(InnoDB)은 기본으로 검사합니다.

반대 방향도 막습니다. 회원이 있는 동아리를 지우려고 하면?

```sqlrun
-- 오류 예시
PRAGMA foreign_keys = ON;
CREATE TABLE club (club_id INTEGER PRIMARY KEY, name TEXT);
CREATE TABLE member (member_id INTEGER PRIMARY KEY, name TEXT,
                     club_id INTEGER REFERENCES club(club_id));
INSERT INTO club VALUES (1, '축구부');
INSERT INTO member VALUES (1, '민준', 1);
DELETE FROM club WHERE club_id = 1;
```

지우면 민준이 없는 동아리를 가리키게 되니 막힙니다. 동아리를 없앨 때 회원도 함께 지우고 싶다면, 외래키에 `ON DELETE CASCADE`(따라서 지우기)를 붙입니다.

```sqlrun
PRAGMA foreign_keys = ON;
CREATE TABLE club (club_id INTEGER PRIMARY KEY, name TEXT);
CREATE TABLE member (member_id INTEGER PRIMARY KEY, name TEXT,
                     club_id INTEGER REFERENCES club(club_id) ON DELETE CASCADE);
INSERT INTO club VALUES (1, '축구부'), (2, '밴드');
INSERT INTO member VALUES (1, '민준', 1), (2, '서연', 2), (3, '도윤', 1);
DELETE FROM club WHERE club_id = 1;
SELECT * FROM member;
```

축구부를 지웠더니 축구부 회원 민준 · 도윤도 함께 지워지고 서연만 남았습니다. 편하지만 한 번에 많은 데이터가 연쇄로 사라질 수 있어 조심해서 씁니다. 그 밖에 `ON DELETE SET NULL`(가리키던 값을 NULL로)도 있습니다.

- **개체 무결성**: 기본키는 NULL도 중복도 안 된다. → PRIMARY KEY
- **참조 무결성**: 외래키는 참조하는 표에 실제 있는 값이거나 NULL이어야 한다. → FOREIGN KEY
- **도메인 무결성**: 열 값은 정해진 종류와 범위 안이어야 한다. → 자료형 · CHECK · NOT NULL

규칙을 프로그램 코드에만 적어 두면, 다른 프로그램이나 사람이 직접 넣은 데이터는 검사를 피해 갑니다. **DB 표에 새겨 둔 제약조건은 누가 어떤 경로로 넣든 반드시 지켜집니다.** 이것이 데이터를 믿을 수 있게 만드는 가장 확실한 방법입니다.

## ALTER TABLE · DROP TABLE: 구조 바꾸기 · 표 지우기

이미 만든 표의 구조를 바꿀 때는 `ALTER TABLE`을 씁니다.

```sqlrun
CREATE TABLE club (club_id INTEGER PRIMARY KEY, name TEXT);
INSERT INTO club VALUES (1, '축구부'), (2, '밴드');

ALTER TABLE club ADD COLUMN room TEXT DEFAULT '미정';
ALTER TABLE club RENAME COLUMN name TO club_name;

SELECT * FROM club;
```

`room` 열이 새로 생겼고, 이미 있던 행은 기본값 '미정'으로 채워졌습니다. `name` 열 이름은 `club_name`으로 바뀌었습니다. 표 이름은 `ALTER TABLE club RENAME TO clubs;`로 바꿉니다.

`DROP TABLE club;`은 표를 **구조와 데이터 모두** 지웁니다. 되돌릴 수 없으니 실무에서는 가장 조심하는 명령입니다. `CREATE TABLE IF NOT EXISTS`, `DROP TABLE IF EXISTS`처럼 쓰면 "이미 있음 · 없음" 오류 없이 넘어갑니다.

> 실무 DB의 표 구조 변경은 그 표를 쓰는 모든 프로그램 · 대시보드에 영향을 줍니다. 열 이름 하나 바꿔도 그 열을 쓰는 쿼리가 모두 깨지므로, 보통은 DBA나 개발팀과 협의해서 진행합니다.

## 정리

| 명령 · 제약 | 하는 일 |
| --- | --- |
| `CREATE TABLE 표 (열 자료형 제약, …)` | 표 만들기 (DDL) |
| `ALTER TABLE 표 ADD COLUMN · RENAME …` | 구조 바꾸기 |
| `DROP TABLE 표` | 표 지우기 (되돌릴 수 없음) |
| `NOT NULL` · `UNIQUE` · `PRIMARY KEY` | 빈 값 · 중복 막기 |
| `FOREIGN KEY` (`REFERENCES`) | 없는 대상 가리키기 막기, `ON DELETE CASCADE` |
| `CHECK (조건)` · `DEFAULT 값` | 규칙 밖의 값 막기 · 기본값 |
