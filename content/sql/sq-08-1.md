## 분석가는 SQL로 무엇을 할까

지금까지 배운 SELECT · WHERE · GROUP BY · CASE · JOIN · CTE · 윈도우 함수는 실무에서 따로 쓰이지 않고 **한 쿼리 안에서 함께** 쓰입니다. 이번 레슨에서는 데이터 분석가가 실제로 매주 만드는 세 가지 표를 처음부터 끝까지 만들어 봅니다.

1. **월별 핵심 지표(KPI)**: 매출은 늘고 있나?
2. **퍼널**: 방문한 사람 중 몇 %가 구매까지 가나? 어디서 가장 많이 빠지나?
3. **리텐션(코호트)**: 가입한 고객이 다음 달에도 다시 사나?

데이터는 Day 01에서 소개한 **가상 쇼핑몰**입니다. 2025년 1~6월에 가입한 고객 256명(`users`), 1~7월의 주문 372건(`orders`), 7월 한 달의 방문 기록(`events`)이 있습니다. 실제 회사 데이터가 아니라 연습용으로 만든 데이터입니다.

```sqlrun
SELECT * FROM users LIMIT 3;
SELECT * FROM orders LIMIT 3;
SELECT * FROM events WHERE session_id <= 3;
```

`events`는 방문(세션) 한 번에 거친 단계가 한 줄씩 적혀 있습니다. 방문(`visit`) → 상품 보기(`view`) → 장바구니(`cart`) → 구매(`purchase`) 순서입니다.

## 1. 월별 핵심 지표

지표를 계산하기 전에 **정의**부터 정합니다. 같은 "고객 수"라도 정의가 다르면 숫자가 달라지고, 회의에서 숫자끼리 싸우게 됩니다.

| 지표 | 정의 | SQL |
| --- | --- | --- |
| 매출 | 결제 금액의 합 | `SUM(amount)` |
| 주문 수 | 주문 건수 | `COUNT(*)` |
| 구매자 수 | 그 달에 한 번이라도 산 **서로 다른** 고객 수 | `COUNT(DISTINCT user_id)` |
| 객단가 | 주문 한 건의 평균 금액 | 매출 ÷ 주문 수 |

`COUNT(DISTINCT 열)`은 중복을 빼고 셉니다. 한 고객이 한 달에 두 번 사면 주문 수는 2, 구매자 수는 1입니다.

```sqlrun
SELECT strftime('%Y-%m', order_date) AS ym,
       SUM(amount) AS revenue,
       COUNT(*) AS orders,
       COUNT(DISTINCT user_id) AS buyers,
       ROUND(SUM(amount) * 1.0 / COUNT(*)) AS aov
FROM orders
GROUP BY ym;
```

주문 수와 구매자 수는 6월까지 꾸준히 늘었고(매출은 4월에 한 번 주춤), 7월에는 매출이 6월의 절반 아래로 떨어졌습니다. 객단가(`aov`)는 4만~6만 원대로 크게 변하지 않았으니, 매출이 준 것은 **사는 사람이 줄었기** 때문입니다. 가입 쪽도 확인해 봅니다.

```sqlrun
SELECT strftime('%Y-%m', signup_date) AS ym, COUNT(*) AS new_users
FROM users GROUP BY ym;
```

1~6월에는 매달 40명 안팎이 가입했는데 7월 줄이 아예 없습니다. 7월에 **신규 가입이 0명**이었던 것입니다. 기존 고객만 다시 사 준 셈이니 매출이 반토막 난 이유가 설명됩니다. 이렇게 지표 하나가 움직이면 "왜?"를 다른 표로 확인하는 것이 분석입니다.

Day 08의 `LAG`로 전월 대비 증감률도 붙여 둡니다.

```sqlrun
WITH monthly AS (
    SELECT strftime('%Y-%m', order_date) AS ym, SUM(amount) AS revenue
    FROM orders GROUP BY ym
)
SELECT ym, revenue,
       ROUND((revenue - LAG(revenue) OVER (ORDER BY ym)) * 100.0
             / LAG(revenue) OVER (ORDER BY ym), 1) AS mom_pct
FROM monthly;
```

`mom_pct`(Month over Month)는 7월이 −56.3%입니다. 4월도 −15.4%로 한 번 줄었던 달입니다.

## 2. 퍼널: 어디서 빠져나가나

먼저 단계별로 몇 번의 방문(세션)이 도달했는지 셉니다.

```sqlrun
SELECT step, COUNT(DISTINCT session_id) AS sessions
FROM events
GROUP BY step
ORDER BY sessions DESC;
```

단계를 가로로 펼쳐 놓아야 단계끼리 나눌 수 있습니다. Day 05의 `CASE`를 `COUNT` 안에 넣으면 "이 단계일 때만 세기"가 됩니다. 이 기법을 **조건부 집계**라고 하고, 행을 열로 펼치는(피벗) 데 두루 씁니다.

```sqlrun
WITH f AS (
    SELECT COUNT(DISTINCT CASE WHEN step = 'visit'    THEN session_id END) AS visit,
           COUNT(DISTINCT CASE WHEN step = 'view'     THEN session_id END) AS view,
           COUNT(DISTINCT CASE WHEN step = 'cart'     THEN session_id END) AS cart,
           COUNT(DISTINCT CASE WHEN step = 'purchase' THEN session_id END) AS purchase
    FROM events
)
SELECT visit, view, cart, purchase,
       ROUND(view * 100.0 / visit, 1)     AS visit_to_view,
       ROUND(cart * 100.0 / view, 1)      AS view_to_cart,
       ROUND(purchase * 100.0 / cart, 1)  AS cart_to_buy,
       ROUND(purchase * 100.0 / visit, 1) AS overall
FROM f;
```

`CASE WHEN step = 'view' THEN session_id END`는 view 단계가 아니면 NULL이 되고, `COUNT`는 NULL을 세지 않으니 view 단계 세션만 세어집니다.

결과를 읽어 봅니다. 방문의 55%가 상품을 보고, 그중 **30.8%만 장바구니에 담고**, 담은 사람의 44.8%가 삽니다. 전체로는 방문 100번에 7.6번 구매입니다. 가장 많이 새는 곳은 "상품 보기 → 장바구니"이므로, 상품 상세 페이지(가격 · 리뷰 · 배송 정보)를 먼저 개선해 볼 만하다는 결론이 나옵니다.

> 전환율은 **분모가 무엇인지**가 핵심입니다. "장바구니 → 구매 44.8%"와 "방문 → 구매 7.6%"는 둘 다 맞는 숫자지만 뜻이 전혀 다릅니다. 보고할 때는 항상 "무엇 대비"인지 함께 적으세요.

## 3. 재구매율

한 번 산 고객 중 **두 번 이상** 산 고객은 몇 %일까요? 고객별 주문 수를 CTE로 먼저 만들고, 그 표를 다시 요약합니다.

```sqlrun
WITH per_user AS (
    SELECT user_id, COUNT(*) AS n FROM orders GROUP BY user_id
)
SELECT COUNT(*) AS buyers,
       SUM(CASE WHEN n >= 2 THEN 1 ELSE 0 END) AS repeaters,
       ROUND(AVG(CASE WHEN n >= 2 THEN 1.0 ELSE 0 END), 3) AS repeat_rate
FROM per_user;
```

구매자 192명 중 102명(53.1%)이 다시 샀습니다. Day 04의 "0/1의 평균 = 비율"을 CASE로 0/1 열을 만들어 응용했습니다.

가입 경로(채널)별로 나눠 보면 어떨까요? 주문이 없는 고객도 넣어야 하므로 Day 06의 `LEFT JOIN`과 `COUNT(o.order_id)`를 씁니다.

```sqlrun
WITH per_user AS (
    SELECT u.user_id, u.channel, COUNT(o.order_id) AS n
    FROM users u LEFT JOIN orders o ON u.user_id = o.user_id
    GROUP BY u.user_id, u.channel
)
SELECT channel, COUNT(*) AS users,
       ROUND(AVG(CASE WHEN n >= 1 THEN 1.0 ELSE 0 END), 2) AS buy_rate,
       ROUND(AVG(CASE WHEN n >= 2 THEN 1.0 ELSE 0 END), 2) AS repeat_rate,
       ROUND(AVG(n), 2) AS orders_per_user
FROM per_user
GROUP BY channel
ORDER BY repeat_rate DESC;
```

**추천**으로 가입한 고객은 49명으로 가장 적지만, 84%가 구매하고 57%가 재구매해 1인당 2.27건을 샀습니다. SNS 고객(1인당 1.16건)의 두 배입니다. 고객 수만 보면 검색이 1등이지만, 고객 한 명의 가치는 추천이 1등입니다. 이런 결과는 "추천 이벤트에 예산을 더 쓰자"는 결정으로 이어집니다.

단계를 CTE로 나눠 쌓습니다. 먼저 고객마다 가입 월과, 주문한 달이 **가입 후 몇 개월째**인지 구합니다. 월 차이는 "연 × 12 + 월"로 바꾼 숫자끼리 빼면 됩니다(SQLite는 `'2025'` 같은 숫자 모양 글자를 계산에 쓰면 숫자로 바꿔 줍니다).

```sqlrun
WITH cohort AS (
    SELECT user_id, strftime('%Y-%m', signup_date) AS cohort_ym,
           strftime('%Y', signup_date) * 12 + strftime('%m', signup_date) AS cohort_idx
    FROM users
),
activity AS (
    SELECT DISTINCT c.user_id, c.cohort_ym,
           strftime('%Y', o.order_date) * 12 + strftime('%m', o.order_date) - c.cohort_idx AS month_no
    FROM cohort c JOIN orders o ON c.user_id = o.user_id
)
SELECT cohort_ym, month_no, COUNT(*) AS active_users
FROM activity
GROUP BY cohort_ym, month_no
ORDER BY cohort_ym, month_no;
```

`DISTINCT`는 한 고객이 같은 달에 두 번 사도 한 명으로 세기 위해 넣었습니다. 결과는 "코호트 × 경과 월"마다 한 줄인 **세로로 긴 표**입니다. 3월 코호트는 가입한 달에 32명, 1개월째 19명, 2개월째 15명이 주문했습니다.

이제 퍼널에서 쓴 조건부 집계로 경과 월을 가로로 펼치고, 코호트 인원으로 나눠 비율로 만듭니다. 마지막 관측 달(2025-07)을 넘는 칸은 0이 아니라 NULL로 둡니다.

```sqlrun
WITH cohort AS (
    SELECT user_id, strftime('%Y-%m', signup_date) AS cohort_ym,
           strftime('%Y', signup_date) * 12 + strftime('%m', signup_date) AS cohort_idx
    FROM users
),
activity AS (
    SELECT DISTINCT c.user_id, c.cohort_ym,
           strftime('%Y', o.order_date) * 12 + strftime('%m', o.order_date) - c.cohort_idx AS month_no
    FROM cohort c JOIN orders o ON c.user_id = o.user_id
),
size AS (
    SELECT cohort_ym, cohort_idx, COUNT(*) AS users FROM cohort GROUP BY cohort_ym, cohort_idx
)
SELECT s.cohort_ym, s.users,
       ROUND(COUNT(DISTINCT CASE WHEN a.month_no = 0 THEN a.user_id END) * 1.0 / s.users, 2) AS m0,
       ROUND(COUNT(DISTINCT CASE WHEN a.month_no = 1 THEN a.user_id END) * 1.0 / s.users, 2) AS m1,
       CASE WHEN s.cohort_idx + 2 <= 2025 * 12 + 7
            THEN ROUND(COUNT(DISTINCT CASE WHEN a.month_no = 2 THEN a.user_id END) * 1.0 / s.users, 2) END AS m2,
       CASE WHEN s.cohort_idx + 3 <= 2025 * 12 + 7
            THEN ROUND(COUNT(DISTINCT CASE WHEN a.month_no = 3 THEN a.user_id END) * 1.0 / s.users, 2) END AS m3
FROM size s
LEFT JOIN activity a ON s.cohort_ym = a.cohort_ym
GROUP BY s.cohort_ym, s.users, s.cohort_idx
ORDER BY s.cohort_ym;
```

읽는 법은 그림과 같습니다.

- **가로(한 코호트)**: 3월 코호트는 가입한 달 71% → 1개월째 42% → 2개월째 33% → 3개월째 18%. 시간이 지날수록 다시 사는 고객이 줄어드는 전형적인 모양입니다.
- **세로(같은 경과 월끼리)**: 1개월째(`m1`)는 모든 코호트가 36~43% 사이로 비슷합니다. 최근 코호트라고 특별히 나빠지지는 않았습니다. 반면 2개월째(`m2`)는 3월 코호트 33%에서 5월 코호트 13%로 떨어졌는데, 코호트가 작아(40명 안팎) 우연일 수도 있으니 몇 달 더 지켜봐야 합니다.
- **NULL 칸**: 6월 코호트의 2개월째는 8월이라 아직 데이터가 없습니다. 이 칸을 0으로 채우면 "6월 가입자는 아무도 다시 안 샀다"는 틀린 결론이 나옵니다.

## 정리: 분석 쿼리를 짜는 순서

1. **질문을 지표로 바꾼다**: "잘 되고 있나?" → 매출 · 구매자 수 · 전환율 · 리텐션 중 무엇인지, 정의는 무엇인지.
2. **단위를 정한다**: 한 줄이 무엇인가(월, 세션, 고객, 코호트 × 경과 월).
3. **CTE로 단계를 쌓는다**: 고객별 요약 → 그룹별 요약 → 비율. 단계마다 `SELECT * FROM 단계이름`으로 중간 결과를 확인한다.
4. **분모와 빈칸을 점검한다**: 무엇 대비 비율인지, 0과 NULL(아직 모름)을 구분했는지, JOIN 뒤 행 수가 맞는지.
5. **숫자가 움직이면 "왜?"를 다른 표로 확인한다**: 7월 매출 감소 → 신규 가입 0명.
