## 시작하기 전에

[테이블 만들기: 자료형과 제약조건](#/l/sq-11-1)에서 표의 뼈대(DDL)를 만들었습니다. 이번에는 표 안의 데이터를 바꾸는 DML 세 가지를 배웁니다.

- `INSERT`: 행 넣기 (한 줄, 여러 줄, 다른 표에서 골라 넣기)
- `UPDATE`: 값 고치기
- `DELETE`: 행 지우기
- WHERE를 빠뜨리는 사고와, 그것을 막는 습관

> 이 사이트의 셀은 실행할 때마다 실습 데이터를 **새로** 불러옵니다. 셀에서 사원 연봉을 0으로 만들어도 다음 실행에는 원래대로 돌아오니 마음껏 실험하세요. 회사 DB에서는 그렇지 않다는 것만 기억하면 됩니다.

## INSERT: 행 넣기

새 부서 '데이터팀'을 만듭니다. `INSERT INTO 표 (열, …) VALUES (값, …)`로 씁니다.

```sqlrun
INSERT INTO dept (deptno, dname, location)
VALUES (90, 'ACT 데이터팀', '판교');

SELECT * FROM dept;
```

맨 아래에 90번 부서가 생겼습니다. 결과 위의 "실행 완료 · 1행 변경"은 INSERT가 행 하나를 넣었다는 뜻입니다.

열 이름 목록은 생략할 수도 있지만(`INSERT INTO dept VALUES (90, …)`), 그러면 **표에 열이 만들어진 순서**대로 값을 다 줘야 합니다. 나중에 누군가 열을 하나 추가하면 그 쿼리는 깨지므로, 열 이름을 적는 습관이 안전합니다. 열 이름을 적으면 일부 열만 넣을 수도 있습니다.

```sqlrun
INSERT INTO dept (deptno, dname)
VALUES (91, 'ACT 품질팀'),
       (92, 'ACT 연구소');

SELECT * FROM dept WHERE deptno >= 90;
```

괄호 묶음을 쉼표로 이으면 **여러 행을 한 번에** 넣습니다. 값을 주지 않은 `location`은 NULL이 되었습니다(DEFAULT가 있었다면 기본값으로 채워졌겠죠).

### INSERT … SELECT: 다른 표에서 골라 넣기

VALUES 대신 SELECT를 쓰면, 조회 결과를 통째로 다른 표에 넣습니다. 퇴사자(`employed = 0`)를 보관용 표로 옮겨 봅니다.

```sqlrun
CREATE TABLE emp_archive (empno INTEGER PRIMARY KEY, ename_ko TEXT, hiredate TEXT);

INSERT INTO emp_archive (empno, ename_ko, hiredate)
SELECT empno, ename_ko, hiredate
FROM emp
WHERE employed = 0;

SELECT * FROM emp_archive;
```

퇴사자 허태환이 보관 표로 들어갔습니다. 백업용 표, 분석용 요약 표를 만들 때 자주 씁니다. [일부러 합치기: 반정규화와 분석용 테이블](#/l/sq-10-2)에서 쓴 `CREATE TABLE … AS SELECT`는 표 만들기와 넣기를 한 번에 하는 줄임말입니다.

## UPDATE: 값 고치기

11번 부서(영업1팀) 연봉을 10% 올립니다. `UPDATE 표 SET 열 = 새 값 WHERE 조건`으로 씁니다.

```sqlrun
UPDATE emp
SET sal = ROUND(sal * 1.1)
WHERE deptno = 11;

SELECT ename_ko, sal FROM emp WHERE deptno = 11;
```

"5행 변경"과 함께 김낙수 15000 → 16500처럼 다섯 명의 연봉이 올랐습니다. `SET sal = sal * 1.1`처럼 **지금 값으로 계산**해서 고칠 수 있습니다. 여러 열을 한 번에 고칠 때는 `SET sal = …, joblv = '부장'`처럼 쉼표로 잇습니다.

## WHERE를 빠뜨리면

UPDATE와 DELETE에서 가장 무서운 실수는 **WHERE를 빠뜨리는 것**입니다. 조건이 없으면 "모든 행"이 대상이 됩니다.

```sqlrun
UPDATE emp SET sal = 0;

SELECT ename_ko, sal FROM emp;
```

"14행 변경". 회사 전 직원의 연봉이 0이 되었습니다. 실제 회사 DB였다면 백업에서 복구하는 큰 사고입니다. 이런 일을 막는 습관은 간단합니다.

1. 같은 WHERE로 **먼저 SELECT**해서 대상 행과 행 수를 눈으로 확인합니다.
2. `SELECT … FROM`만 `UPDATE … SET` 또는 `DELETE FROM`으로 바꾸고 WHERE는 그대로 둡니다.
3. "n행 변경"이 1번의 행 수와 같은지 봅니다. 다르면 되돌립니다. 되돌리는 방법은 [모두 되거나, 모두 안 되거나: 트랜잭션](#/l/sq-12-1)에서 배웁니다.

> MySQL Workbench는 기본으로 **안전 모드**(safe update)가 켜져 있어서, 기본키 조건 없는 UPDATE · DELETE를 아예 실행하지 않습니다. 귀찮다고 끄기 전에 왜 있는지 기억하세요.

## DELETE: 행 지우기

퇴사자를 사원 표에서 지웁니다. `DELETE FROM 표 WHERE 조건`입니다. 열을 고르지 않는 이유는 DELETE가 **행 전체**를 지우기 때문입니다.

```sqlrun
SELECT COUNT(*) AS before_n FROM emp;

DELETE FROM emp WHERE employed = 0;

SELECT COUNT(*) AS after_n FROM emp;
```

결과 표가 두 개 나옵니다. 14명에서 13명이 되었습니다. 지우기 전에 `INSERT … SELECT`로 보관 표에 옮겨 두는 것이 실무의 흔한 순서입니다. 아예 지우지 않고 `employed` 같은 **상태 열만 바꾸는**(UPDATE) 방식도 많이 씁니다. 이것을 "논리 삭제(soft delete)"라고 하는데, 실수로 지워도 되살릴 수 있고 과거 분석도 할 수 있어서입니다. 실습 데이터의 `employed` 열이 바로 그 방식입니다.

외래키가 걸린 표라면 DELETE가 막히거나(다른 행이 가리키고 있을 때) 연쇄로 지워질 수 있다는 것도 [테이블 만들기: 자료형과 제약조건](#/l/sq-11-1)에서 보았습니다.

## DELETE · TRUNCATE · DROP

셋 다 "지운다"지만 지우는 범위가 다릅니다. 시험에도 자주 나옵니다.

| 명령 | 가족 | 지우는 것 | 표 구조 | 되돌리기(ROLLBACK) |
| --- | --- | --- | --- | --- |
| `DELETE FROM 표 WHERE …` | DML | 조건에 맞는 행 (WHERE 없으면 전부) | 남음 | 가능 |
| `TRUNCATE TABLE 표` | DDL | 모든 행 (조건 불가) | 남음 | 대부분 DBMS에서 불가 |
| `DROP TABLE 표` | DDL | 표 자체 (구조 + 데이터) | 없어짐 | 불가 |

`TRUNCATE`는 한 줄씩 지우지 않고 표를 비워 버려서 아주 빠르지만, 조건을 걸 수 없고 되돌리기 어렵습니다. 서랍 속 물건을 하나씩 꺼내는 것이 DELETE, 서랍을 통째로 비우는 것이 TRUNCATE, 서랍장을 버리는 것이 DROP입니다.

> SQLite에는 TRUNCATE가 없습니다. 조건 없는 `DELETE FROM 표;`가 같은 일을 합니다.

## 정리

| 하고 싶은 일 | 문법 |
| --- | --- |
| 한 행 넣기 | `INSERT INTO 표 (열1, 열2) VALUES (값1, 값2);` |
| 여러 행 넣기 | `VALUES (…), (…), (…)` |
| 조회 결과 넣기 | `INSERT INTO 표 (열…) SELECT …;` |
| 값 고치기 | `UPDATE 표 SET 열 = 값 WHERE 조건;` |
| 행 지우기 | `DELETE FROM 표 WHERE 조건;` |

- INSERT는 열 이름을 적는 습관을, UPDATE · DELETE는 **같은 WHERE로 먼저 SELECT**하는 습관을.
- WHERE가 없으면 모든 행이 바뀐다.
- DELETE(행, 되돌리기 가능) · TRUNCATE(전체 비우기) · DROP(표 자체 삭제).
