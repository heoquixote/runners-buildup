## SELECT ~ FROM: 열 고르기

기본 모양은 `SELECT 열 이름 FROM 테이블 이름;` 입니다. "어느 표(FROM)에서 어떤 열(SELECT)을 보여 줘"라고 읽습니다. `*`를 쓰면 모든 열을 가져옵니다.

```sqlrun
SELECT * FROM emp;
```

필요한 열만 쉼표로 이어 적으면 그 열만, 적은 순서대로 나옵니다.

```sqlrun
SELECT ename_ko, joblv, sal FROM emp;
```

> SQL 단어(`SELECT`, `FROM`)는 대문자 · 소문자를 가리지 않습니다. 이 트랙에서는 읽기 쉽게 SQL 단어는 대문자, 테이블 · 열 이름은 소문자로 씁니다.

## AS: 결과에 붙이는 별칭

`AS 새이름`을 붙이면 결과 표의 열 제목이 바뀝니다. 이것을 **별칭(alias)** 이라고 합니다. 실제 테이블의 열 이름은 그대로이고, 이번 결과 화면에서만 바뀝니다.

```sqlrun
SELECT empno AS 사번, ename_ko AS 이름, joblv AS 직급 FROM emp;
```

## 계산한 값도 열이 된다

SELECT에는 열 이름만이 아니라 **계산식**도 쓸 수 있습니다. 연봉(`sal`)과 성과급(`comm`)을 더한 총급여를 새 열로 만들어 봅니다.

```sqlrun
SELECT ename_ko, sal, comm, sal + comm AS total_pay FROM emp;
```

김대표는 80000 + 0 = 80000, 백정태는 20000 + 10000 = 30000입니다. 원래 테이블에는 `total_pay`라는 열이 없지만, 결과에는 계산된 열이 생겼습니다.

## DISTINCT: 중복을 빼고 종류만

직급에 어떤 종류가 있는지 알고 싶으면 `DISTINCT`를 붙입니다. 같은 값이 여러 번 나와도 한 번씩만 보여 줍니다.

```sqlrun
SELECT DISTINCT joblv FROM emp;
```

사원은 14명이지만 직급은 8종류입니다. 부장이 3명, 대리가 3명이라 중복이 빠졌습니다.

## WHERE: 조건에 맞는 행만

`WHERE 조건`을 FROM 뒤에 붙이면 조건이 참인 행만 남습니다. 연봉이 10000 이상인 사원만 봅니다.

```sqlrun
SELECT ename_ko, joblv, sal FROM emp WHERE sal >= 10000;
```

6명이 남았습니다. 쓸 수 있는 비교 연산자는 다음과 같습니다.

| 연산자 | 뜻 | 예 |
| --- | --- | --- |
| `=` | 같다 | `deptno = 11` |
| `!=` 또는 `<>` | 같지 않다 | `deptno != 11` |
| `>` · `<` | 크다 · 작다 | `sal > 6000` |
| `>=` · `<=` | 이상 · 이하 | `sal >= 6000` |

SQL에서 "같다"는 `=` 하나로 씁니다. 글자와 날짜는 **작은따옴표**로 감쌉니다.

```sqlrun
SELECT ename_ko, joblv FROM emp WHERE joblv = '부장';
```

## AND · OR: 조건 여러 개

- `AND`: 두 조건이 **모두** 참인 행
- `OR`: 둘 중 **하나라도** 참인 행

11번 부서이면서 연봉이 7000 이상인 사원입니다.

```sqlrun
SELECT ename_ko, deptno, sal FROM emp WHERE deptno = 11 AND sal >= 7000;
```

AND와 OR를 섞을 때는 조심해야 합니다. SQL은 **AND를 먼저** 계산합니다(곱셈을 덧셈보다 먼저 하는 것과 같습니다). "11번 또는 12번 부서의 대리"를 괄호 없이 쓰면 이렇게 됩니다.

```sqlrun
SELECT ename_ko, deptno, joblv FROM emp WHERE deptno = 11 OR deptno = 12 AND joblv = '대리';
```

부장 · 과장 · 사원까지 6명이 나왔습니다. `deptno = 12 AND joblv = '대리'`가 먼저 묶여서 "11번 부서 전체 **또는** 12번 부서 대리"가 됐기 때문입니다. 괄호로 의도를 분명히 하면 대리 2명만 남습니다.

```sqlrun
SELECT ename_ko, deptno, joblv FROM emp WHERE (deptno = 11 OR deptno = 12) AND joblv = '대리';
```

> 직접 해보기: 위 셀의 괄호를 지웠다 다시 붙이며 결과 행 수가 6 ↔ 2로 바뀌는 것을 확인해 보세요. AND와 OR를 같이 쓸 때는 **항상 괄호**를 치는 습관을 들이세요.

## IN · BETWEEN: 목록과 범위

`IN (값, 값, …)`은 "목록 중 하나와 같다"입니다. OR를 여러 번 쓰는 것보다 짧고 읽기 쉽습니다.

```sqlrun
SELECT ename_ko, joblv FROM emp WHERE joblv IN ('과장', '대리');
```

`BETWEEN A AND B`는 "A 이상 B 이하"입니다. **양 끝을 포함**한다는 점을 기억하세요. 연봉이 정확히 5000인 남궁민수와 6000인 두 사람도 결과에 들어갑니다.

```sqlrun
SELECT ename_ko, sal FROM emp WHERE sal BETWEEN 5000 AND 6000;
```

## LIKE: 글자 패턴으로 찾기

이름이 "김"으로 시작하는 사람처럼 **일부만 아는 글자**를 찾을 때는 `LIKE`와 기호 두 개를 씁니다.

| 패턴 | 뜻 | 맞는 예 |
| --- | --- | --- |
| `'김%'` | 김으로 시작 | 김대표, 김낙수 |
| `'%수'` | 수로 끝남 | 김낙수, 남궁민수 |
| `'%영%'` | 영이 들어감 | 이주영 |
| `'_정%'` | 두 번째 글자가 정 | 백정태 |

`%`는 "아무 글자가 몇 개든(0개 포함)", `_`는 "아무 글자 딱 1개"입니다.

```sqlrun
SELECT ename_ko FROM emp WHERE ename_ko LIKE '김%';
```

```sqlrun
SELECT ename_ko FROM emp WHERE ename_ko LIKE '_정%';
```

## NULL은 = 로 찾을 수 없다

NULL은 "값이 없음 · 모름"입니다. 모르는 값과 무엇을 비교해도 결과는 참도 거짓도 아닌 "모름"이 되어 버립니다. 그래서 `= NULL`로 찾으면 **아무 행도 나오지 않습니다**.

```sqlrun
SELECT ename_ko, mgr FROM emp WHERE mgr = NULL;
```

0행입니다. NULL인지 확인할 때는 반드시 `IS NULL`(또는 반대로 `IS NOT NULL`)을 씁니다.

```sqlrun
SELECT ename_ko, joblv, mgr FROM emp WHERE mgr IS NULL;
```

상사가 없는 사람은 김대표와 아산공장의 이주영 작업반장, 2명입니다.

> 주의: NULL과 0은 다릅니다. 이 회사 데이터에서 성과급이 없는 사람은 `comm`이 NULL이 아니라 **0**으로 적혀 있습니다. 그래서 "성과급 없는 사원"은 `comm IS NULL`이 아니라 `comm = 0`으로 찾아야 합니다. 데이터에서 "없음"을 어떻게 적었는지 먼저 확인하는 습관이 중요합니다.

## 행이 많은 표에서 쓰기: 쇼핑몰

조건 거르기는 행이 많을수록 힘을 발휘합니다. 쇼핑몰 방문 기록 1,113건 중 로그인하지 않은(고객 번호가 없는) 방문을 찾아봅니다.

```sqlrun
SELECT session_id, event_date, step FROM events WHERE user_id IS NULL;
```

표 위에 **488행**이라고 나옵니다. 방문 기록의 절반 가까이는 누가 왔는지 모릅니다. 실제 데이터에는 이렇게 빈 값이 흔하고, 분석하기 전에 반드시 확인해야 합니다.

조건 여러 개를 섞어 "전자 제품 주문 중 30만 원 이상"도 바로 뽑을 수 있습니다.

```sqlrun
SELECT order_id, user_id, order_date, amount FROM orders WHERE category = '전자' AND amount >= 300000;
```

372건 중 8건이 남았습니다. 눈으로 표를 훑어서는 찾기 어려운 행을 조건 한 줄로 골라냈습니다.

## 정리

| 하고 싶은 일 | 쓰는 문법 |
| --- | --- |
| 열 고르기 · 계산 열 만들기 | `SELECT 열, 계산식 AS 별칭 FROM 표` |
| 종류만 보기 | `SELECT DISTINCT 열` |
| 조건에 맞는 행만 | `WHERE 조건` (`=`, `!=`, `>`, `>=` …) |
| 조건 여러 개 | `AND` · `OR`, 섞을 때는 괄호 |
| 목록 · 범위 | `IN (…)`, `BETWEEN A AND B` (양 끝 포함) |
| 글자 패턴 | `LIKE '김%'`, `'_정%'` |
| 빈 값 | `IS NULL` · `IS NOT NULL` (절대 `= NULL` 아님) |
