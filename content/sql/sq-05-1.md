## 두 번 물어야 답이 나오는 질문

"회사 평균보다 연봉을 많이 받는 사람은 누구야?" 이 질문은 한 번에 답할 수 없습니다. **먼저** 평균을 알아야, **그다음** 평균보다 큰 사람을 고를 수 있습니다. Day 04에서 `WHERE sal > AVG(sal)`이 오류가 났던 것도 이 때문이었습니다.

첫 번째 질문부터 해 봅니다.

```sqlrun
SELECT AVG(sal) FROM emp;
```

평균은 약 14057입니다. 이 숫자를 손으로 옮겨 적어 두 번째 쿼리를 쓸 수도 있지만, 데이터가 바뀌면 평균도 바뀌니 매번 고쳐야 합니다. 대신 **쿼리 안에 쿼리**를 넣습니다. 괄호 안에 넣은 쿼리를 **서브쿼리**라고 합니다.

```sqlrun
SELECT ename_ko, joblv, sal
FROM emp
WHERE sal > (SELECT AVG(sal) FROM emp);
```

서브쿼리는 놓는 **자리**에 따라 이름과 쓰임이 다릅니다. WHERE 안, SELECT 안, FROM 안. 차례로 봅니다.

## 값이 여러 개면 IN

서울에 있는 부서의 사원을 찾아봅니다. 서울 부서는 하나가 아니라 4개(10, 11, 12, 80)라서 서브쿼리 결과도 **여러 행**입니다. 여러 값 중 하나와 같은지는 `IN`으로 비교합니다.

```sqlrun
SELECT ename_ko, deptno
FROM emp
WHERE deptno IN (SELECT deptno FROM dept WHERE location = '서울');
```

12명입니다. 여기서 `IN` 대신 `=`를 쓰면 어떻게 될까요?

```sqlrun
SELECT ename_ko, deptno
FROM emp
WHERE deptno = (SELECT deptno FROM dept WHERE location = '서울');
```

백정태 1명만 나옵니다. SQLite는 서브쿼리 결과 4행 중 **첫 행(10)만** 몰래 쓰기 때문입니다. MySQL은 `Subquery returns more than 1 row` 오류를 냅니다. 어느 쪽이든 의도와 다르니, **결과가 여러 행일 수 있는 서브쿼리에는 `IN`** 을 씁니다.

## SELECT 안의 서브쿼리: 행마다 값 하나

SELECT에 넣은 서브쿼리는 **열 하나**처럼 동작합니다. 그래서 결과가 꼭 1행 1열이어야 하고, 이것을 **스칼라 서브쿼리**라고 부릅니다. 사원마다 부서 이름과 그 부서의 평균 연봉을 붙여 봅니다.

```sqlrun
SELECT e.ename_ko, e.sal, e.deptno,
       (SELECT d.dname FROM dept d WHERE d.deptno = e.deptno) AS dname,
       (SELECT ROUND(AVG(x.sal)) FROM emp x WHERE x.deptno = e.deptno) AS dept_avg
FROM emp e;
```

안쪽 쿼리가 바깥의 `e.deptno`를 쓰고 있습니다. 바깥 행이 바뀔 때마다 안쪽이 다시 계산되는데, 이런 서브쿼리를 **상관 서브쿼리**라고 합니다. 김낙수 줄에서는 11번 부서 평균(8160), 도진우 줄에서는 12번 부서 평균(8000)이 계산됐습니다.

같은 방식으로 WHERE에서 "**자기 부서** 평균보다 많이 받는 사원"도 찾을 수 있습니다.

```sqlrun
SELECT e.ename_ko, e.deptno, e.sal
FROM emp e
WHERE e.sal > (SELECT AVG(x.sal) FROM emp x WHERE x.deptno = e.deptno);
```

회사 전체 평균으로는 3명이었지만, 부서별 평균으로 보면 최재혁 · 김낙수 · 도진우 · 신준섭 4명입니다. "평균"을 어느 범위로 잡느냐에 따라 답이 달라집니다.

> 상관 서브쿼리는 행마다 다시 계산하므로 표가 크면 느려집니다. 같은 일을 아래의 JOIN이나 CTE로 바꿔 쓰는 경우가 많습니다.

## FROM 안의 서브쿼리: 임시 표 (인라인 뷰)

FROM에는 테이블 이름 대신 **쿼리 결과**를 둘 수도 있습니다. 결과가 그 자리에서 임시 표가 되므로 **인라인 뷰**라고 부르고, 반드시 별칭(`AS x`)을 붙입니다. 재직자만 먼저 골라 낸 표에 부서 이름을 붙여 봅니다.

```sqlrun
SELECT x.empno, x.ename_ko, d.dname
FROM (SELECT empno, ename_ko, deptno FROM emp WHERE employed = 1) AS x
LEFT JOIN dept d ON x.deptno = d.deptno;
```

퇴사한 허태환이 빠진 13행입니다. 인라인 뷰는 "먼저 거르거나 집계한 결과를 다시 JOIN"할 때 실무에서 가장 많이 쓰는 서브쿼리입니다.

## WITH (CTE): 중간 결과에 이름 붙이기

서브쿼리가 겹겹이 들어가면 괄호 속 괄호가 되어 읽기 어렵습니다. `WITH 이름 AS (쿼리)`로 중간 결과에 **이름을 붙여 맨 앞에 꺼내 두면**, 뒤에서는 그 이름을 표처럼 씁니다. 이것을 **CTE**(Common Table Expression)라고 합니다.

앞의 "자기 부서 평균보다 많이 받는 사원"을 CTE로 다시 써 봅니다. 상관 서브쿼리 대신 **부서별 평균 표를 한 번만 만들어** JOIN합니다.

```sqlrun
WITH dept_avg AS (
    SELECT deptno, AVG(sal) AS avg_sal FROM emp GROUP BY deptno
)
SELECT e.ename_ko, e.deptno, e.sal, ROUND(a.avg_sal) AS dept_avg
FROM emp e
JOIN dept_avg a ON e.deptno = a.deptno
WHERE e.sal > a.avg_sal;
```

결과는 같은 4명이지만, "① 부서별 평균을 만든다 ② 사원과 잇는다 ③ 평균보다 큰 사람만 남긴다"는 흐름이 위에서 아래로 그대로 읽힙니다.

계산 열을 먼저 만들어 두는 데도 좋습니다. 총급여를 CTE에서 한 번 계산하고, 뒤에서는 이름(`total_pay`)으로만 씁니다.

```sqlrun
WITH emp_pay AS (
    SELECT empno, ename_ko, deptno, sal + comm AS total_pay FROM emp
)
SELECT p.ename_ko, p.total_pay, d.dname
FROM emp_pay p
JOIN dept d ON p.deptno = d.deptno
ORDER BY p.total_pay DESC;
```

## 단계를 여러 개 잇기: 쇼핑몰

CTE는 쉼표로 여러 개를 이을 수 있습니다. "구매 고객 1명당 구매액이 전체 평균보다 큰 지역은?"을 단계로 나눠 풉니다. ① 지역별 구매 고객 수와 매출, ② 전체 1인당 구매액, ③ 둘을 비교.

```sqlrun
WITH by_city AS (
    SELECT u.city, COUNT(DISTINCT o.user_id) AS buyers, SUM(o.amount) AS revenue
    FROM orders o JOIN users u ON o.user_id = u.user_id
    GROUP BY u.city
),
overall AS (
    SELECT SUM(amount) * 1.0 / COUNT(DISTINCT user_id) AS per_buyer FROM orders
)
SELECT city, buyers, revenue, ROUND(revenue * 1.0 / buyers) AS per_buyer
FROM by_city
WHERE revenue * 1.0 / buyers > (SELECT per_buyer FROM overall);
```

전체 1인당 구매액(약 109,417원)을 넘는 지역은 광주 · 대구 · 서울 세 곳입니다. 광주(17명)와 대구(14명)는 구매 고객이 적어서, 몇 명의 큰 주문만으로도 평균이 크게 움직인다는 점도 함께 봐야 합니다. `COUNT(DISTINCT 열)`은 겹치는 값을 한 번만 세서 "주문 건수"가 아니라 "주문한 사람 수"를 셉니다.

> 직접 해보기: 위 쿼리의 마지막 SELECT를 `SELECT * FROM by_city;`로 바꿔 실행해 보세요. CTE는 단계 이름만 바꿔 넣으면 **중간 결과를 바로 확인**할 수 있어서, 긴 쿼리를 디버깅할 때 특히 편합니다.

## 정리

| 놓는 자리 | 이름 | 결과 모양 | 예 |
| --- | --- | --- | --- |
| WHERE | 서브쿼리 | 값 하나 → `>` `=` / 여러 행 → `IN` | 평균보다 큰 사원 |
| SELECT | 스칼라 서브쿼리 | 반드시 1행 1열 | 사원마다 부서 평균 |
| FROM | 인라인 뷰 | 표 (별칭 필수) | 재직자만 걸러 JOIN |
| 맨 앞 `WITH` | CTE | 이름 붙인 표 | 단계별 분석 |

복잡한 질문은 "먼저 무엇을 알아야 하지?"를 묻고, 그 답을 한 단계씩 CTE로 쌓아 가면 됩니다.
