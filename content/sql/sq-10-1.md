## 시작하기 전에

[ERD 읽기: 관계 · 카디널리티 · 키](#/l/sq-09-2)에서 관계의 모양과 키를 배웠습니다. 이번 레슨은 논리 모델링의 핵심인 **정규화**입니다. 정규화는 "표를 어떻게 나눌지" 정하는 규칙인데, 규칙부터 외우면 어렵습니다. 그래서 **나누지 않은 표가 어떤 사고를 내는지** 먼저 직접 보고, 그 사고를 막는 방법으로 정규화를 배웁니다.

- 중복이 만드는 세 가지 사고: 삽입 · 갱신 · 삭제 이상
- 함수 종속: "이걸 알면 저게 정해진다"
- 1NF · 2NF · 3NF로 표 나누기, 그리고 다시 JOIN으로 붙이기

## 엑셀 한 장에 다 적은 수강 명단

조교가 수강 명단을 엑셀 한 장에 정리했다고 해 봅시다. 한 줄에 "누가 어떤 과목을 들었는지"와 함께 학생 정보, 학과 사무실, 과목 정보, 담당 교수까지 다 적었습니다. 보기에는 편합니다.

```sqlrun
CREATE TABLE enroll_raw (
  student_id INTEGER NOT NULL, name TEXT, major TEXT, office TEXT,
  course_id TEXT NOT NULL, title TEXT, professor TEXT, score INTEGER,
  PRIMARY KEY (student_id, course_id)
);
INSERT INTO enroll_raw VALUES
(1, '민준', '통계학과', 'B동 301', 'DB', '데이터베이스', '김교수', 90),
(1, '민준', '통계학과', 'B동 301', 'ST', '통계', '이교수', 85),
(2, '서연', '컴퓨터공학과', 'A동 201', 'DB', '데이터베이스', '김교수', 78),
(3, '도윤', '통계학과', 'B동 301', 'DB', '데이터베이스', '김교수', 88),
(3, '도윤', '통계학과', 'B동 301', 'PY', '파이썬', '박교수', 92);
SELECT * FROM enroll_raw;
```

5줄밖에 안 되는데도 같은 글자가 계속 반복됩니다. '민준 · 통계학과 · B동 301'이 두 번, '데이터베이스 · 김교수'가 세 번, '통계학과 · B동 301'이 네 번입니다. 기본키는 (학번, 과목 코드) 쌍입니다. 이 반복이 왜 문제인지 세 가지 사고로 확인해 봅니다.

## 사고 1. 갱신 이상: 고쳤는데 둘이 됐다

데이터베이스 과목 담당이 최교수로 바뀌었습니다. 조교가 첫 줄만 고치고 나머지를 깜빡했습니다.

```sqlrun
CREATE TABLE enroll_raw (student_id INTEGER, name TEXT, course_id TEXT, title TEXT, professor TEXT, score INTEGER);
INSERT INTO enroll_raw VALUES
(1, '민준', 'DB', '데이터베이스', '김교수', 90), (1, '민준', 'ST', '통계', '이교수', 85),
(2, '서연', 'DB', '데이터베이스', '김교수', 78), (3, '도윤', 'DB', '데이터베이스', '김교수', 88),
(3, '도윤', 'PY', '파이썬', '박교수', 92);

UPDATE enroll_raw SET professor = '최교수'
WHERE student_id = 1 AND course_id = 'DB';

SELECT DISTINCT course_id, title, professor
FROM enroll_raw
WHERE course_id = 'DB';
```

데이터베이스 과목 하나에 교수가 **둘**(최교수, 김교수)이 되었습니다. 이제 이 표만 봐서는 누가 진짜 담당인지 알 수 없습니다. 같은 사실을 여러 곳에 적어 두면, 고칠 때 한 곳이라도 빠뜨리는 순간 데이터가 서로 모순됩니다. 이것이 **갱신 이상**(Update Anomaly)입니다.

## 사고 2. 삽입 이상: 넣고 싶은데 못 넣는다

다음 학기에 '머신러닝(ML) · 정교수' 과목이 새로 열립니다. 아직 수강생은 없습니다. 이 과목 정보를 표에 넣어 보겠습니다.

```sqlrun
-- 오류 예시
CREATE TABLE enroll_raw (student_id INTEGER NOT NULL, name TEXT, course_id TEXT NOT NULL, title TEXT, professor TEXT, score INTEGER,
                         PRIMARY KEY (student_id, course_id));
INSERT INTO enroll_raw VALUES (1, '민준', 'DB', '데이터베이스', '김교수', 90);

INSERT INTO enroll_raw (course_id, title, professor)
VALUES ('ML', '머신러닝', '정교수');
```

`NOT NULL constraint failed` 오류가 납니다. 이 표의 한 줄은 "누가 무엇을 들었다"라서 기본키인 학번이 꼭 있어야 하는데, 수강생이 없으니 학번을 채울 수가 없습니다. **수강생이 생기기 전에는 과목을 등록할 수조차 없는** 것입니다. 이것이 **삽입 이상**(Insertion Anomaly)입니다. 가짜 학번을 넣어 우회하면 "학생 수"를 셀 때마다 가짜가 섞입니다.

## 사고 3. 삭제 이상: 지웠더니 다른 것도 사라졌다

민준이 통계(ST) 수강을 취소했습니다. 그 줄을 지웁니다. 통계는 민준 혼자 듣던 과목이었습니다.

```sqlrun
CREATE TABLE enroll_raw (student_id INTEGER, name TEXT, course_id TEXT, title TEXT, professor TEXT, score INTEGER);
INSERT INTO enroll_raw VALUES
(1, '민준', 'DB', '데이터베이스', '김교수', 90), (1, '민준', 'ST', '통계', '이교수', 85),
(2, '서연', 'DB', '데이터베이스', '김교수', 78), (3, '도윤', 'PY', '파이썬', '박교수', 92);

DELETE FROM enroll_raw WHERE student_id = 1 AND course_id = 'ST';

SELECT * FROM enroll_raw WHERE course_id = 'ST';
```

0행입니다. 수강 기록 하나를 지웠을 뿐인데 **"통계 과목이 있고, 이교수가 가르친다"는 사실까지 통째로 사라졌습니다.** 이것이 **삭제 이상**(Deletion Anomaly)입니다.

세 사고의 원인은 하나입니다. 한 줄에 **서로 다른 사실**(학생 정보, 학과 사무실, 과목 정보, 성적)을 섞어 적었기 때문입니다. 해결책도 하나입니다. **하나의 사실은 한 곳에만** 적도록 표를 나누는 것, 이것이 **정규화**(Normalization)입니다.

## 함수 종속: 이걸 알면 저게 정해진다

어떻게 나눌지 정하려면 열끼리의 관계를 봐야 합니다. **A를 알면 B가 하나로 정해질 때**, "B는 A에 **함수 종속**한다"고 하고 `A → B`로 씁니다. A를 결정자, B를 종속자라고 합니다.

- 학번 → 이름, 학과 (학번 1번이면 이름은 무조건 민준)
- 학과 → 사무실 (통계학과면 사무실은 무조건 B동 301)
- 과목 코드 → 과목명, 교수
- (학번, 과목 코드) → 성적 (둘 다 알아야 성적이 정해짐)

반대로 이름 → 학번은 성립하지 않습니다. 동명이인이 있을 수 있으니까요.

이 그림이 정규화의 지도입니다. 키 **전체**에 기대는 열만 그 표에 남기고, 다른 곳에 기대는 열은 떼어 냅니다. 단계별로 보겠습니다.

## 1NF: 한 칸에 값 하나

**제1정규형(1NF)**은 모든 칸에 값이 **하나씩만** 들어 있는 상태입니다. 엑셀에서는 한 칸에 "DB, ST"처럼 여러 값을 적는 일이 흔합니다. 그러면 어떤 일이 생길까요? 희망 과목에 데이터베이스(DB)를 적은 학생을 찾아봅니다.

```sqlrun
CREATE TABLE wish (name TEXT, courses TEXT);
INSERT INTO wish VALUES ('민준', 'DB, ST'), ('서연', 'DB'), ('도윤', 'PY, ADB');
SELECT name, courses FROM wish WHERE courses LIKE '%DB%';
```

3명이 나오지만 도윤은 DB가 아니라 **ADB**(고급 데이터베이스)를 적었습니다. 글자 일부로 찾다 보니 엉뚱한 사람이 섞였습니다. "DB 희망자 수", "과목별 희망자 수"도 깔끔하게 셀 수 없습니다. 해결은 **한 줄에 한 과목**으로 행을 나누는 것입니다. 앞의 `enroll_raw`처럼 (민준, DB), (민준, ST)를 따로 적으면 `WHERE course_id = 'DB'`로 정확하게 찾고 `GROUP BY`로 셀 수 있습니다.

> 같은 이유로 `과목1`, `과목2`, `과목3`처럼 같은 종류의 열을 번호 붙여 늘어놓는 것(반복 그룹)도 1NF 위반으로 봅니다. 네 번째 과목을 들으면 열을 새로 만들어야 하니까요.

## 2NF: 키의 일부에만 기대는 열 떼어 내기

**제2정규형(2NF)**은 1NF이면서, 키가 아닌 모든 열이 **기본키 전체**에 기대는 상태입니다. 키의 **일부**에만 기대는 것을 **부분 종속**이라 하고, 이것을 떼어 냅니다.

`enroll_raw`의 기본키는 (학번, 과목 코드)인데,

- 이름 · 학과 · 사무실은 **학번만** 알면 정해집니다 → 학생 표로
- 과목명 · 교수는 **과목 코드만** 알면 정해집니다 → 과목 표로
- 성적만 (학번, 과목 코드) **둘 다** 있어야 정해집니다 → 수강 표에 남김

```text
학생(학번 PK, 이름, 학과, 사무실)
과목(과목 코드 PK, 과목명, 교수)
수강(학번 FK, 과목 코드 FK, 성적)   ← 기본키 (학번, 과목 코드)
```

삽입 이상이 이 단계에서 해결됩니다. 새 과목은 과목 표에 학생 없이 넣으면 되니까요. 참고로 기본키가 열 **하나**인 표는 "키의 일부"가 없으므로, 1NF이기만 하면 자동으로 2NF입니다.

## 3NF: 키가 아닌 열에 기대는 열 떼어 내기

2NF로 나눈 학생 표를 다시 봅니다. 사무실은 학번에 직접 기대는 게 아니라 **학과**를 거쳐서 정해집니다(학번 → 학과 → 사무실). 이렇게 키가 아닌 열을 징검다리 삼아 기대는 것을 **이행 종속**이라고 합니다. 통계학과 학생이 100명이면 'B동 301'이 100번 적히고, 사무실이 옮기면 100줄을 고쳐야 합니다.

**제3정규형(3NF)**은 2NF이면서 이행 종속이 없는 상태입니다. 학과 → 사무실을 학과 표로 떼어 냅니다.

```text
학생(학번 PK, 이름, 학과 FK)
학과(학과 PK, 사무실)
과목(과목 코드 PK, 과목명, 교수)
수강(학번 FK, 과목 코드 FK, 성적)
```

## 나눈 표를 다시 붙이면 원래대로

표를 나누면 정보가 사라지지 않을까요? 나눈 네 표를 만들고, JOIN으로 붙여 원래 명단을 다시 만들어 봅니다.

```sqlrun
CREATE TABLE major   (major TEXT PRIMARY KEY, office TEXT);
CREATE TABLE student (student_id INTEGER PRIMARY KEY, name TEXT, major TEXT);
CREATE TABLE course  (course_id TEXT PRIMARY KEY, title TEXT, professor TEXT);
CREATE TABLE enroll  (student_id INTEGER, course_id TEXT, score INTEGER, PRIMARY KEY (student_id, course_id));
INSERT INTO major   VALUES ('통계학과', 'B동 301'), ('컴퓨터공학과', 'A동 201');
INSERT INTO student VALUES (1, '민준', '통계학과'), (2, '서연', '컴퓨터공학과'), (3, '도윤', '통계학과');
INSERT INTO course  VALUES ('DB', '데이터베이스', '김교수'), ('ST', '통계', '이교수'), ('PY', '파이썬', '박교수');
INSERT INTO enroll  VALUES (1, 'DB', 90), (1, 'ST', 85), (2, 'DB', 78), (3, 'PY', 92), (3, 'DB', 88);

SELECT s.student_id, s.name, s.major, m.office, c.course_id, c.title, c.professor, e.score
FROM enroll e
JOIN student s ON e.student_id = s.student_id
JOIN major m   ON s.major = m.major
JOIN course c  ON e.course_id = c.course_id
ORDER BY s.student_id, c.course_id;
```

처음 엑셀 명단과 똑같은 5줄이 나옵니다. 이처럼 나눈 표를 JOIN하면 원래 표가 그대로 돌아오는 분해를 **무손실 분해**라고 합니다. 정규화는 정보를 버리는 게 아니라 **보관하는 방식**을 바꾸는 것입니다.

이제 세 사고가 어떻게 되는지 한 번에 확인합니다.

```sqlrun
CREATE TABLE course (course_id TEXT PRIMARY KEY, title TEXT, professor TEXT);
CREATE TABLE enroll (student_id INTEGER, course_id TEXT, score INTEGER, PRIMARY KEY (student_id, course_id));
INSERT INTO course VALUES ('DB', '데이터베이스', '김교수'), ('ST', '통계', '이교수'), ('PY', '파이썬', '박교수');
INSERT INTO enroll VALUES (1, 'DB', 90), (1, 'ST', 85), (2, 'DB', 78), (3, 'PY', 92), (3, 'DB', 88);

UPDATE course SET professor = '최교수' WHERE course_id = 'DB';           -- 갱신: 한 줄만
INSERT INTO course VALUES ('ML', '머신러닝', '정교수');                  -- 삽입: 수강생 없이도
DELETE FROM enroll WHERE student_id = 1 AND course_id = 'ST';          -- 삭제: 수강 기록만

SELECT * FROM course;
```

- 교수 변경은 과목 표 **한 줄**만 고치면 끝이고, 모순이 생길 수 없습니다.
- 수강생이 없는 머신러닝 과목도 문제없이 들어갑니다.
- 민준의 통계 수강을 지워도 통계 과목과 이교수 정보는 그대로 남아 있습니다.

## 그다음 단계: BCNF

3NF 다음에는 **BCNF**(보이스-코드 정규형)가 있습니다. "결정자(→의 왼쪽)는 모두 후보키여야 한다"는 조건입니다. 예를 들어 "교수 한 명은 한 과목만 가르친다"는 규칙이 있는 특강 표 (학번, 과목, 교수)에서는 교수 → 과목이 성립하는데, 교수는 후보키가 아닙니다. 이런 드문 경우를 한 번 더 나누는 단계입니다. 실무 설계는 대부분 **3NF**를 목표로 하고, 그 뒤 4NF · 5NF는 시험 범위에서 이름 정도만 알아 두면 됩니다.

| 정규형 | 없애는 것 | 확인 질문 | 수강 예 |
| --- | --- | --- | --- |
| 1NF | 한 칸에 여러 값, 반복 열 | 모든 칸에 값이 하나인가? | 'DB, ST' → 두 줄로 |
| 2NF | 부분 종속 | 키의 **일부**에만 기대는 열이 있나? | 이름 → 학생 표, 교수 → 과목 표 |
| 3NF | 이행 종속 | 키가 **아닌 열**에 기대는 열이 있나? | 사무실 → 학과 표 |
| BCNF | 후보키가 아닌 결정자 | 모든 결정자가 후보키인가? | 교수 → 과목 분리 |

## 정리

- 서로 다른 사실을 한 줄에 섞으면 **갱신 · 삽입 · 삭제 이상**이 생긴다 (시험에서는 "삽갱삭").
- 함수 종속 `A → B`: A를 알면 B가 하나로 정해진다.
- 1NF 한 칸에 값 하나 → 2NF 부분 종속 제거 → 3NF 이행 종속 제거. 실무 목표는 보통 3NF.
- 나눈 표는 JOIN으로 원래대로 붙일 수 있다(무손실 분해).
- 정규화의 한 줄 요약: **하나의 사실은 한 곳에.**

그런데 표를 이렇게 잘게 나누면 질문 하나에 JOIN을 네 번씩 해야 합니다. 다음 레슨에서는 반대로 **일부러 합치는** 반정규화를 배웁니다.
