## 시작하기 전에

[계수와 부분 의존도](#/l/ml-09-2)까지의 방법은 모두 "모델이 **전체적으로** 무엇을 중요하게 보나"였습니다. 하지만 현장에서 가장 많이 받는 질문은 "**이 설비**는 왜 고장 위험 93%로 나왔어요?"입니다. 이번 레슨에서는 예측 하나를 열마다 나눠서 설명하는 **SHAP 값**을, 라이브러리 없이 원리대로 **직접 계산**해 봅니다.

## 공동 과제 점수를 공정하게 나누기

SHAP은 게임 이론의 **샤플리 값**에서 왔습니다. 팀이 함께 얻은 점수를 팀원에게 공정하게 나누는 방법입니다.

민수와 지아가 과제를 했습니다. 누가 참여했느냐에 따라 점수가 이렇게 나온다고 해 봅시다.

| 참여한 사람 | 점수 |
| --- | --- |
| 아무도 안 함 | 50 (기본 점수) |
| 민수만 | 70 |
| 지아만 | 60 |
| 둘 다 | 90 |

둘이 함께 기본 점수보다 **40점**을 더 얻었습니다. 이 40점을 어떻게 나눌까요? 샤플리 값은 "**팀원이 들어오는 순서를 모두 따져서, 각자 들어올 때 늘어난 점수를 평균**"합니다.

- 순서 민수 → 지아: 민수가 들어올 때 50 → 70 (**+20**), 지아가 들어올 때 70 → 90 (**+20**)
- 순서 지아 → 민수: 지아가 들어올 때 50 → 60 (**+10**), 민수가 들어올 때 60 → 90 (**+30**)

민수 = (20 + 30) / 2 = **25**, 지아 = (20 + 10) / 2 = **15**. 합하면 25 + 15 = 40으로 늘어난 점수와 **정확히 같습니다.** 이것이 샤플리 값의 가장 좋은 성질입니다. 같은 계산을 코드로 해 봅니다.

```run
from itertools import permutations

score = {(): 50, ("minsu",): 70, ("jia",): 60, ("jia", "minsu"): 90}
def value(team):
    return score[tuple(sorted(team))]

players = ["minsu", "jia"]
share = {p: 0 for p in players}
orders = list(permutations(players))
for order in orders:
    team = []
    for p in order:
        before = value(team)
        team.append(p)
        share[p] += value(team) - before
print({p: s / len(orders) for p, s in share.items()})
```

손으로 계산한 25와 15가 그대로 나옵니다.

## 모델 예측에 적용하기

이제 팀원을 **열**로, 점수를 **모델의 예측 확률**로 바꿉니다.

| 공동 과제 | 모델 설명 |
| --- | --- |
| 팀원 | 특성(열): 공기 온도, 공정 온도, 회전수, 토크, 공구 마모 |
| 팀원이 참여한다 | 그 열의 **실제 값**을 모델에 알려 준다 |
| 팀원이 빠진다 | 그 열의 값을 **모른다**: 배경 데이터 200대의 값을 대신 넣고 예측을 평균 낸다 |
| 기본 점수 | 아무 열도 모를 때의 예측 = 배경 데이터의 평균 예측 |
| 각자의 몫 | 그 열의 **SHAP 값** |

열이 5개면 들어오는 순서는 5 × 4 × 3 × 2 × 1 = **120가지**입니다. 120가지 순서마다 열을 하나씩 알려 주며 예측이 얼마나 변하는지 재고 평균을 냅니다. 같은 조합은 한 번만 계산하도록 저장해 두면(`cache`) 브라우저에서도 금방 끝납니다.

설비 2761번은 토크 65.1, 공구 마모 212분인 설비입니다. 랜덤포레스트는 이 설비의 고장 확률을 얼마로 보고, 그 이유는 무엇일까요?

```run
from itertools import permutations
import pandas as pd
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
rf = RandomForestClassifier(n_estimators=100, min_samples_leaf=5, random_state=0, n_jobs=1).fit(df[features], df["failure"])
background = df[features].sample(200, random_state=0)

def shap_values(x):
    cache = {}
    def value(known):                       # average prediction when only `known` columns are revealed
        key = frozenset(known)
        if key not in cache:
            X = background.copy()
            for col in known:
                X[col] = x[col]
            cache[key] = rf.predict_proba(X)[:, 1].mean()
        return cache[key]
    share = dict.fromkeys(features, 0.0)
    orders = list(permutations(features))
    for order in orders:
        known = []
        for col in order:
            before = value(known)
            known.append(col)
            share[col] += value(known) - before
    return {col: s / len(orders) for col, s in share.items()}, value([]), value(features)

x = df.loc[2761, features]
shap, base, pred = shap_values(x)
print(x.to_dict())
print("base (average prediction):", round(base, 3))
for col, s in sorted(shap.items(), key=lambda kv: -abs(kv[1])):
    print(f"{col:>12}: {s:+.3f}")
print("base + sum of SHAP:", round(base + sum(shap.values()), 3), "/ model prediction:", round(pred, 3))
```

읽는 법:

- **기본값 0.043**: 아무 정보도 없을 때 평균 고장 확률(약 4%)에서 출발합니다.
- **토크 +0.672**: 토크 65.1이라는 값 하나가 고장 확률을 67%p 올렸습니다. 가장 큰 이유입니다.
- **공구 마모 +0.186**: 212분 닳은 공구가 19%p를 더했습니다.
- 회전수 +0.041, 공정 온도 +0.012는 조금 올렸고, 공기 온도 −0.026은 오히려 조금 내렸습니다.
- 모두 더하면 0.043 + 0.672 + 0.186 + 0.041 + 0.012 − 0.026 = **0.928**로 모델 예측과 정확히 같습니다.

::figure{src="content/img/ml/ml09-shap-waterfall.svg" alt="기본값 0.043에서 시작해 토크가 0.672, 공구 마모가 0.186, 회전수가 0.041, 공정 온도가 0.012를 올리고 공기 온도가 0.026을 내려 최종 0.928이 된다" caption="설비 2761번의 SHAP 폭포 그림. 막대를 차례로 쌓으면 기본값에서 최종 예측까지 갑니다."}

"토크가 높고 공구가 많이 닳아서 위험"이라는 설명은 이 데이터의 실제 고장 유형(과부하 고장: 토크 × 마모가 너무 큼)과 맞아떨어집니다.

### 직접 해보기: 다른 설비 설명하기

번호를 77, 603, 4988로 바꿔 보세요. 같은 모델이라도 **설비마다 이유가 다릅니다.**

```run
from itertools import permutations
import pandas as pd
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
rf = RandomForestClassifier(n_estimators=100, min_samples_leaf=5, random_state=0, n_jobs=1).fit(df[features], df["failure"])
background = df[features].sample(200, random_state=0)

def shap_values(x):
    cache = {}
    def value(known):
        key = frozenset(known)
        if key not in cache:
            X = background.copy()
            for col in known:
                X[col] = x[col]
            cache[key] = rf.predict_proba(X)[:, 1].mean()
        return cache[key]
    share = dict.fromkeys(features, 0.0)
    orders = list(permutations(features))
    for order in orders:
        known = []
        for col in order:
            before = value(known)
            known.append(col)
            share[col] += value(known) - before
    return {col: round(float(s) / len(orders), 3) for col, s in share.items()}, round(float(value(features)), 3)

machine = 77   # <- change me (77, 603, 4988)
shap, pred = shap_values(df.loc[machine, features])
print(df.loc[machine, features].to_dict(), "failure:", df.loc[machine, "failure"])
print("prediction:", pred, shap)
```

| 설비 | 예측 | 가장 큰 이유 | 해석 |
| --- | --- | --- | --- |
| 2761 | 0.928 | 토크 +0.672, 마모 +0.186 | 힘도 세고 공구도 닳음 |
| 603 | 0.929 | 토크 +0.838 | 공구는 새것(31분)인데 토크가 71.6으로 매우 큼 |
| 77 | 0.177 | 마모 +0.127 | 토크는 평범, 공구가 208분 닳은 것만 문제 |
| 4988 | 0.544 | 회전수 +0.246, 토크 +0.243 | 아주 빨리 돌면서 힘이 거의 없음 (동력 이상) |

전체 중요도(순열 중요도)만 보면 "토크와 회전수가 중요하다"로 끝나지만, SHAP을 보면 설비마다 **점검할 곳**이 다르다는 것을 알 수 있습니다. 77번은 공구 교체, 603번은 부하 점검, 4988번은 구동계 점검처럼요.

## 실무에서는: shap 라이브러리

열이 5개면 순서가 120가지지만, 20개면 약 243경(2.4 × 10¹⁸) 가지라서 직접 계산할 수 없습니다. 실무에서는 **shap 라이브러리**가 트리 모델의 구조를 이용해 같은 값을 빠르게 계산합니다(TreeSHAP). 이 사이트의 브라우저 파이썬에는 설치할 수 없어서, 아래 코드는 내 컴퓨터나 Colab에서 실행해 보세요.

```python
import pandas as pd
import shap
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
rf = RandomForestClassifier(n_estimators=100, min_samples_leaf=5, random_state=0).fit(df[features], df["failure"])

explainer = shap.TreeExplainer(rf)
sv = explainer(df[features].iloc[:500])
shap.plots.waterfall(sv[0, :, 1])     # one machine, class 1 (failure)
shap.plots.beeswarm(sv[:, :, 1])      # all 500 machines at once
```

`beeswarm` 그림은 설비 수백 대의 SHAP 값을 한 번에 점으로 찍어서, "토크가 높은 설비(빨간 점)는 대부분 오른쪽(위험 증가)"처럼 **전체 경향과 한 건 설명을 함께** 보여 줍니다.

## 주의할 점

- **SHAP 값은 "모델이 그렇게 계산했다"는 뜻이지 원인이 아닙니다.** 토크를 낮추면 고장이 줄어드는지는 현장 실험으로 확인해야 합니다.
- **배경 데이터에 따라 값이 달라집니다.** "모른다"를 무엇으로 채우느냐(어느 기간, 어느 설비)가 기본값과 몫을 바꿉니다.
- **서로 겹치는 열**(공기 온도·공정 온도)은 몫을 나눠 갖거나 이상하게 나눌 수 있습니다. [다중공선성](#/l/ml-06-6)에서 본 문제와 같습니다.

## 정리

- **SHAP 값** = 예측을 열마다 나눈 몫. 들어오는 순서를 모두 따져 각 열이 더한 값을 평균냅니다.
- **기본값 + SHAP 값의 합 = 모델 예측**이 항상 성립합니다(0.043 + … = 0.928).
- 같은 모델도 설비마다 이유가 다릅니다. 전체 중요도는 "무엇이 중요한가", SHAP은 "**이 건은 왜**"에 답합니다.
- 열이 많으면 shap 라이브러리(TreeSHAP)로 계산합니다. 원인이 아니라 모델의 판단 근거라는 점은 같습니다.
