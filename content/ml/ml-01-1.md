## 시작하기 전에

앞 레슨(ml-00)에서 머신러닝은 **예시와 정답을 잔뜩 보여 주고 컴퓨터가 스스로 규칙을 찾게 하는 방법**이라고 배웠습니다. 이번 레슨에서는 실제로 모델을 만들기 **전에** 꼭 해야 하는 준비 과정을 순서대로 해 봅니다.

1. 데이터를 X(특성)와 y(정답)로 나누기
2. 빈칸(결측치)과 글자(범주)를 숫자로 손질하기
3. 학습용과 시험용으로 나누기
4. "찍어도 이 정도"인 기준 점수 알기
5. 시험지를 미리 보는 실수(누수) 피하기

## 데이터, 특성(X), 정답(y)

머신러닝에서 데이터는 보통 **표**입니다. 엑셀 시트를 떠올리면 됩니다.

- **행(가로 한 줄)**: 사례 하나. 승객 한 명, 설비 기록 한 건
- **특성(feature, X)**: 예측에 쓰는 정보. 나이, 성별, 객실 등급…
- **정답(target, label, y)**: 맞히고 싶은 값. 생존했나(1) 못 했나(0)

::figure{src="content/img/ml/ml01-table-xy.svg" alt="타이타닉 표에서 pclass·sex·age·fare 열은 특성 X, survived 열은 정답 y, 가로 한 줄은 승객 한 명" caption="표의 가로 한 줄이 사례 하나, 예측에 쓰는 열이 X, 맞히고 싶은 열이 y입니다."}

먼저 이 강의에서 계속 쓸 **타이타닉 승객 데이터**를 불러와 봅니다. 1912년 타이타닉호 승객 891명의 실제 기록입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print(df.shape)          # (rows, columns)
print(df[["survived", "pclass", "sex", "age", "fare"]].head())
```

`survived`가 정답(y)이고, 나머지 열 중에서 골라 특성(X)으로 씁니다. 실행 결과의 `NaN`은 값이 비어 있다는 뜻입니다(나이를 모르는 승객).

## 데이터를 먼저 들여다보기

모델을 만들기 전에 사람이 먼저 데이터를 봐야 합니다. 어떤 특성이 정답과 관련 있어 보이는지 감을 잡는 단계입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print("overall survival rate:", round(df["survived"].mean(), 3))
print(df.groupby("sex")["survived"].mean().round(3))
print(df.groupby("pclass")["survived"].mean().round(3))
```

전체 생존율은 약 38%인데, 여성은 74%, 남성은 19%입니다. 1등실은 63%, 3등실은 24%입니다. "여성과 어린이 먼저", "상층 객실이 구명보트에 가까웠다"는 역사적 사실이 데이터에 그대로 보입니다. 모델도 이런 패턴을 찾아내는 것입니다.

> `0`과 `1`로 된 열의 평균은 `1`의 비율과 같습니다. 생존율을 `mean()`으로 구할 수 있는 이유입니다.

## 모델은 숫자만 받는다

scikit-learn(파이썬 머신러닝 도구)의 모델은 속으로 덧셈·곱셈 같은 **계산**을 해서 답을 냅니다. 그래서 X에는 **숫자만**, 그리고 **빈칸 없이** 들어가야 합니다. 그런데 타이타닉 표에는 두 가지 문제가 있습니다.

| 문제 | 예 | 해결 | 이 레슨에서 |
| --- | --- | --- | --- |
| 값이 비어 있다 | 나이를 모르는 승객 | **결측치 처리** (지우거나 채우기) | 바로 아래 |
| 값이 글자다 | `male` / `female`, `S` / `C` / `Q` | **인코딩** (글자를 숫자로 바꾸기) | 그다음 |

하나씩 쪼개서 해 봅니다.

## 결측치: 비어 있는 칸

**결측치(missing value)**는 값이 기록되지 않은 칸입니다. 나이를 모르는 승객, 객실 번호가 남아 있지 않은 승객처럼 현실 데이터에는 빈칸이 꼭 있습니다. pandas는 빈칸을 **`NaN`**(Not a Number, "숫자가 아님")으로 표시합니다.

### 1단계: 빈칸이 어디에 몇 개 있나 세기

`df.isna()`는 칸마다 "비어 있나?"를 True/False로 바꿔 주고, 여기에 `.sum()`을 붙이면 열마다 True의 개수, 즉 **빈칸 개수**가 나옵니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print(df.isna().sum())
```

`age` 177칸, `deck`(갑판) 688칸, `embarked`(탑승 항구) 2칸이 비어 있습니다. 개수보다 **비율**로 보면 판단하기 더 쉽습니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
ratio = df.isna().mean().round(3)
print(ratio[ratio > 0])
```

`isna()`의 평균은 "비어 있는 비율"입니다(True=1, False=0이라서). `deck`은 77%가 비어 있고, `age`는 20%, `embarked`는 0.2%뿐입니다.

### 2단계: 빈칸을 그냥 두면?

빈칸이 있는 채로 모델에 넣으면 어떻게 되는지 직접 확인해 봅니다.

```run
import pandas as pd
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("titanic.csv")
try:
    LogisticRegression().fit(df[["age"]], df["survived"])
except ValueError as e:
    print("error:", str(e).splitlines()[0])
```

`Input X contains NaN`이라는 에러가 납니다. 빈칸은 반드시 처리해야 합니다. 방법은 크게 두 가지, **지우기**와 **채우기**입니다.

### 방법 1: 지우기

`dropna()`는 빈칸이 하나라도 있는 행을 지웁니다. 간단하지만, 얼마나 지워지는지 꼭 확인해야 합니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print("original rows         :", len(df))
print("dropna() on all columns:", len(df.dropna()))
print("dropna(subset=['age']) :", len(df.dropna(subset=["age"])))
```

모든 열 기준으로 지우면 891명 중 **182명만** 남습니다. `deck`이 거의 다 비어 있어서입니다. 나이 기준으로만 지워도 177명(20%)을 잃습니다. 데이터를 이렇게 많이 버리면 배울 거리가 줄어듭니다.

그래서 보통 이렇게 판단합니다.

| 상황 | 처리 |
| --- | --- |
| 빈칸이 **아주 적다** (`embarked` 2칸) | 그 행을 지워도 괜찮음 |
| 빈칸이 **너무 많은 열** (`deck` 77%) | 행 대신 **열을 통째로** 빼기 (`df.drop(columns=["deck"])`) |
| 빈칸이 **꽤 있지만 중요한 열** (`age` 20%) | 지우지 말고 **채우기** |

### 방법 2: 채우기 — 평균? 중앙값? 최빈값?

빈칸에 "그럴듯한 값"을 넣는 방법입니다. 대표값 세 가지가 있습니다.

| 대표값 | 뜻 | 어울리는 열 |
| --- | --- | --- |
| 평균 (`mean`) | 모두 더해서 개수로 나눈 값 | 고르게 퍼진 숫자 |
| 중앙값 (`median`) | 작은 순서로 줄 세웠을 때 **가운데** 값 | 아주 큰 값(이상치)이 섞인 숫자 |
| 최빈값 (`mode`) | 가장 **많이 나온** 값 | 글자(범주) 열 |

왜 중앙값을 자주 쓸까요? 반 친구 30명의 용돈 평균을 내는데, 한 명이 한 달에 1,000만 원을 받는다고 해 봅시다. 평균은 확 올라가서 "보통 학생의 용돈"과 동떨어지지만, 중앙값(가운데 학생)은 거의 그대로입니다. 운임(`fare`)이 딱 그런 열입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print("fare  mean:", round(df["fare"].mean(), 1), "  median:", df["fare"].median(), "  max:", df["fare"].max())
print("age   mean:", round(df["age"].mean(), 1), "  median:", df["age"].median())
print("embarked mode:", df["embarked"].mode()[0])
```

운임은 최고 512파운드 같은 아주 비싼 표 때문에 평균(32.2)이 중앙값(14.5)의 2배가 넘습니다. 나이는 평균 29.7, 중앙값 28로 비슷합니다. 이렇게 차이가 크지 않을 때는 둘 다 괜찮지만, **튀는 값에 흔들리지 않는 중앙값**을 기본으로 쓰는 경우가 많습니다. 탑승 항구처럼 글자인 열은 평균을 낼 수 없으니 가장 많이 나온 `S`(최빈값)로 채웁니다.

이제 실제로 채워 봅니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
df["age"] = df["age"].fillna(df["age"].median())
df["embarked"] = df["embarked"].fillna(df["embarked"].mode()[0])
df = df.drop(columns=["deck"])
print(df[["age", "embarked"]].isna().sum())
print("columns left:", df.shape[1])
```

빈칸이 모두 0개가 되었습니다.

> 채운 값은 **진짜 값이 아니라 추측**입니다. 나이를 모르던 177명이 모두 28살이 되었으니 실제와 다릅니다. 그래서 "원래 비어 있었는지"를 따로 `age_missing` 같은 0/1 열로 남겨 두기도 합니다. 나이 기록이 없다는 사실 자체가 정보(예: 3등실 승객일수록 기록이 없음)일 수 있기 때문입니다.
>
> 그리고 엄밀하게는 이 중앙값도 **학습용 데이터로만** 계산해야 합니다. 이유는 아래 "누수"에서 배우고, ml-06에서 이 과정을 자동으로 처리하는 도구(`SimpleImputer`, Pipeline)를 배웁니다.

## 인코딩: 글자를 숫자로 바꾸기

**인코딩(encoding)**은 글자로 된 범주를 모델이 계산할 수 있는 숫자로 바꾸는 일입니다. 범주가 몇 종류인지, 순서가 있는지에 따라 방법이 다릅니다.

### 값이 두 종류일 때: 0과 1로

성별처럼 값이 두 가지뿐이면 한쪽을 1, 다른 쪽을 0으로 바꾸면 됩니다. 두 가지 방법이 있고 결과는 같습니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)         # way 1: True/False -> 1/0
df["sex_num"] = df["sex"].map({"male": 0, "female": 1})   # way 2: a lookup table
print(df[["sex", "female", "sex_num"]].head())
```

- 방법 1: `df["sex"] == "female"`은 여성이면 True, 아니면 False입니다. `.astype(int)`로 True → 1, False → 0이 됩니다.
- 방법 2: `map({...})`은 "이 글자는 이 숫자로" 바꾸는 **대응표**를 직접 줍니다.

열 이름을 `female`처럼 지어 두면 "1이면 여성"이라는 뜻이 바로 읽혀서 좋습니다.

### 값이 여러 종류일 때: 번호를 매기면 생기는 문제

탑승 항구 `embarked`는 `S`(사우샘프턴), `C`(셰르부르), `Q`(퀸스타운) 세 가지입니다. 똑같이 대응표로 0, 1, 2를 매겨 볼까요? 이것을 **라벨 인코딩(label encoding)**이라고 합니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
df["embarked_num"] = df["embarked"].map({"S": 0, "C": 1, "Q": 2})
print(df[["embarked", "embarked_num"]].dropna().drop_duplicates().astype({"embarked_num": int}))
```

문제는 모델이 이 숫자를 **크기**로 읽는다는 것입니다. "Q(2)는 C(1)의 두 배", "S와 Q의 평균은 C" 같은, 현실에는 없는 관계가 생깁니다. 항구 사이에는 순서도 크기도 없는데 말입니다.

반대로 **진짜 순서가 있는** 범주라면 번호가 자연스럽습니다. 객실 등급 `pclass`(1등실 < 2등실 < 3등실)가 처음부터 1, 2, 3 숫자로 들어 있는 이유입니다. 이렇게 순서를 지켜 번호를 매기는 것을 **순서 인코딩(ordinal encoding)**이라고 합니다.

### 순서가 없을 때: 원-핫 인코딩

순서 없는 범주는 **종류마다 0/1 열을 하나씩** 만듭니다. 이것이 **원-핫 인코딩(one-hot encoding)**입니다. "hot"은 켜졌다는 뜻으로, 여러 칸 중 **딱 한 칸만 1(켜짐)**이 됩니다. 출석부에서 해당하는 칸에만 동그라미를 치는 것과 같습니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
onehot = pd.get_dummies(df["embarked"], prefix="embarked", dtype=int)
print(pd.concat([df["embarked"], onehot], axis=1).head())
```

`embarked_C`, `embarked_Q`, `embarked_S` 세 열이 생기고, 승객마다 자기 항구 칸만 1입니다. 이제 숫자 사이에 가짜 크기 관계가 없습니다.

### 언제 무엇을 쓸까

| 범주의 모양 | 예 | 방법 | 코드 |
| --- | --- | --- | --- |
| 두 종류 | 성별, 합격/불합격 | 0/1로 바꾸기 | `(df["sex"] == "female").astype(int)` |
| 여러 종류, **순서 있음** | 객실 등급, 학년, 제품 등급 L<M<H | 순서대로 번호 | `map({"L": 0, "M": 1, "H": 2})` |
| 여러 종류, **순서 없음** | 탑승 항구, 혈액형, 색깔 | 원-핫 | `pd.get_dummies(...)` |
| 종류가 아주 많음 | 우편번호, 상품 ID | 원-핫을 하면 열이 수백 개 → 자주 나오는 것만 남기는 등 따로 고민 | |

## 모델에 넣을 X와 y 만들기

이제 손질한 열을 모아 X와 y를 만듭니다. 빈칸 채우기 → 0/1 바꾸기 → 원-핫 → 열 고르기 순서입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
df["age"] = df["age"].fillna(df["age"].median())
df["embarked"] = df["embarked"].fillna(df["embarked"].mode()[0])
df["female"] = (df["sex"] == "female").astype(int)
df = pd.concat([df, pd.get_dummies(df["embarked"], prefix="embarked", dtype=int)], axis=1)

features = ["pclass", "female", "age", "fare", "embarked_C", "embarked_Q", "embarked_S"]
X = df[features].values
y = df["survived"].values
print("X shape:", X.shape)      # 891 passengers, 7 features
print("first passenger:", X[0], "-> survived?", y[0])
```

891명, 특성 7개짜리 숫자 표가 완성되었습니다. 첫 승객은 3등실, 남성(0), 22살, 운임 7.25, 사우샘프턴 탑승(`embarked_S`=1)이고 생존하지 못했습니다(0). 이제 모델이 먹을 수 있는 모양이 되었습니다.

## 왜 데이터를 나눌까: 시험 문제 비유

학생에게 문제집을 풀게 한 뒤, **같은 문제**로 시험을 보면 100점이 나와도 실력이라고 할 수 없습니다. 답을 외웠을 수도 있으니까요.

모델도 똑같습니다. 그래서 데이터를 두 묶음으로 나눕니다.

| 묶음 | 비유 | 하는 일 |
| --- | --- | --- |
| 학습용 (train) | 문제집 | 모델이 보고 규칙을 배움 |
| 시험용 (test) | 처음 보는 시험지 | 배운 모델이 얼마나 잘 맞히는지 확인 |

::figure{src="content/img/ml/ml01-split.svg" alt="891명을 학습용 75퍼센트와 시험용 25퍼센트로 나누기" caption="학습용으로 배우고, 한 번도 보지 않은 시험용으로 실력을 잽니다."}

`train_test_split`이 이 일을 해 줍니다. `test_size=0.25`는 25%를 시험용으로 떼라는 뜻이고, `random_state=0`은 매번 같은 방식으로 섞으라는 뜻(재현용)입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
X = df[["pclass", "female", "fare"]].values
y = df["survived"].values
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0)
print("train:", X_train.shape, " test:", X_test.shape)
```

### 직접 해보기

아래 셀에서 `test_size` 값을 0.2, 0.3, 0.5로 바꿔 실행해 보세요. 시험용이 커질수록 학습용은 줄어듭니다. 보통은 0.2~0.3을 씁니다. 학습용이 너무 적으면 배울 거리가 부족하고, 시험용이 너무 적으면 점수가 운에 크게 흔들리기 때문입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split

df = pd.read_csv("titanic.csv")
X = df[["pclass", "fare"]].values
y = df["survived"].values

test_size = 0.25   # <- change me
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=test_size, random_state=0)
print("train rows:", len(X_train), " test rows:", len(X_test))
```

### 검증용(validation)까지 세 덩어리로

모델을 여러 개 만들어 비교하거나 설정을 이리저리 바꿔 볼 때, 시험용 점수를 보면서 고르면 어떻게 될까요? 시험지를 여러 번 보면서 공부한 셈이라, 결국 그 시험지에만 잘 맞는 모델이 됩니다. 그래서 실제로는 세 덩어리로 나눕니다.

| 덩어리 | 비유 | 언제 쓰나 |
| --- | --- | --- |
| 학습용 (train) | 문제집 | 모델이 규칙을 배울 때 |
| 검증용 (validation) | 모의고사 | 어떤 모델·설정이 나은지 고를 때 (여러 번 봐도 됨) |
| 시험용 (test) | 수능 | 모든 결정이 끝난 뒤 **딱 한 번** 최종 점수 확인 |

검증용을 따로 떼는 대신 학습용을 돌려 가며 쓰는 방법(교차검증)은 ml-05에서 배웁니다.

> 날짜가 있는 데이터(매출, 수요 등)는 무작위로 섞어 나누면 안 됩니다. 과거로 학습하고 **미래로 시험**해야 실제 상황과 같습니다. 또 한 사람의 기록이 여러 줄이면, 같은 사람이 학습용과 시험용에 동시에 들어가지 않게 **사람 단위로** 나눠야 합니다.

## stratify: 정답 비율을 똑같이

설비 고장처럼 정답 1이 드문 데이터에서는 그냥 나누면 시험용에 고장이 거의 안 들어갈 수도 있습니다. `stratify=y`를 주면 학습용과 시험용의 1 비율이 원래 데이터와 같게 맞춰집니다.

여기서는 두 번째 실제 데이터인 **AI4I 2020 설비 고장 데이터**(UCI 공개, 1만 건)를 씁니다. 회전수·토크·공구 사용 시간 같은 센서 값과 고장 여부(`failure`)가 들어 있고, 고장은 약 3.4%뿐입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]].values
y = df["failure"].values
print("failure rate (all):", round(y.mean(), 4))
for strat in [None, y]:
    _, _, y_tr, y_te = train_test_split(X, y, test_size=0.02, random_state=3, stratify=strat)
    print("stratify" if strat is not None else "no stratify", "-> test failure rate", round(y_te.mean(), 4))
```

시험용을 작게(2%) 떼어 보면 차이가 분명합니다. stratify 없이는 시험용의 고장 비율이 원래(3.4%)와 꽤 달라질 수 있습니다.

## 기준 모델: 넘어야 할 최소선

"아무 생각 없이 찍어도 이 정도는 나온다"는 점수를 먼저 알아야 내 모델이 잘한 건지 알 수 있습니다. 가장 많은 답만 계속 말하는 모델을 **기준 모델(baseline)**이라고 합니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyClassifier
from sklearn.metrics import recall_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]].values
y = df["failure"].values
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
base = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
pred = base.predict(X_test)
print("accuracy:", round(base.score(X_test, y_test), 3))
print("failures caught (recall):", recall_score(y_test, pred))
```

전부 "정상"이라고만 답했는데 정확도가 96.6%입니다. 하지만 고장은 **하나도** 못 잡았습니다(재현율 0). 고장이 드문 데이터에서 "정확도 97%"는 자랑이 아닐 수 있다는 뜻입니다. 이런 지표는 평가지표 코스(ml-03)에서 자세히 다룹니다.

## 누수: 시험지를 미리 본 것

**누수(leakage)**는 **실제로 예측하는 순간에는 알 수 없는 정보**가 학습에 몰래 섞여 들어가는 것입니다. 시험 전에 시험지를 슬쩍 본 것과 같아서 점수는 아주 좋게 나오지만, 실제로 쓰면 그대로 무너집니다. 과적합은 "너무 외운" 문제라면, 누수는 **평가 자체가 무효**가 되는 더 심각한 문제입니다.

대표적인 누수는 세 가지입니다.

1. **정답을 다르게 쓴 열**: 정답과 사실상 같은 열이 특성에 들어간 경우. 예: 생존 예측에 "구조 완료 여부"
2. **미래 정보**: 예측 시점 이후에야 생기는 정보. 예: 고장 예측에 "수리 완료 날짜"
3. **전처리 누수**: 평균·표준편차 같은 기준을 시험용까지 포함한 전체 데이터로 계산한 경우

타이타닉 데이터에는 1번의 좋은 예가 들어 있습니다. `alive` 열은 `survived`를 yes/no로 다시 쓴 열입니다. 이걸 특성으로 넣으면 어떻게 되는지 봅시다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["alive_yes"] = (df["alive"] == "yes").astype(int)
y = df["survived"]
for cols in [["pclass", "female"], ["pclass", "female", "alive_yes"]]:
    X_train, X_test, y_train, y_test = train_test_split(df[cols], y, test_size=0.25, random_state=0, stratify=y)
    acc = DecisionTreeClassifier(max_depth=3, random_state=0).fit(X_train, y_train).score(X_test, y_test)
    print(cols, "-> test accuracy", round(acc, 3))
```

`alive_yes`를 넣자 정확도가 1.0(100%)이 됩니다. 모델이 똑똑해진 게 아니라 **정답을 그대로 읽은** 것입니다. 실제로 새 승객의 생존을 예측하는 순간에는 `alive` 값을 알 수 없으니 이 모델은 쓸모가 없습니다.

> 점수가 갑자기 "너무 좋게" 나오면 먼저 누수를 의심하세요. 열 이름에 `final`, `result`, `completed`, `after`, `status` 같은 말이 들어 있으면 "이 값은 사건이 일어난 뒤에 채워지는가?"를 꼭 확인합니다.

3번 전처리 누수의 흔한 실수는 "평균으로 숫자 크기를 맞추는" 표준화를 **전체 데이터로** 하는 것입니다. 평균·표준편차 같은 기준은 **학습용으로만** 정하고(fit), 시험용에는 그 기준을 적용(transform)만 해야 합니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("titanic.csv")
X = df[["fare"]].values
X_train, X_test = train_test_split(X, test_size=0.25, random_state=0)
scaler = StandardScaler().fit(X_train)          # learn mean/std from train only
print("mean learned from train:", scaler.mean_.round(2))
print("test after transform, mean:", scaler.transform(X_test).mean().round(3), "(not exactly 0 - that's normal)")
```

시험용의 평균이 딱 0이 아닌 것이 정상입니다. 실제 서비스에서 새 데이터가 들어올 때도 학습 때 정한 기준을 그대로 쓰기 때문입니다.

## 정리: 머신러닝 작업 순서

1. **문제 정하기**: 무엇을 예측하나 (생존? 고장?)
2. **데이터 살펴보기**: 표 모양, 빈 값, 정답 비율
3. **특성 점검**: 예측하는 순간에 알 수 있는 정보인가? (누수 확인)
4. **나누기**: 학습용 / (검증용) / 시험용 (드문 정답이면 `stratify=y`)
5. **기준 모델** 점수 확인
6. **학습**: 학습용 데이터로만 (전처리 기준도 학습용으로)
7. **평가**: 시험용으로 딱 한 번
