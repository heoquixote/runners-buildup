## 시작하기 전에

앞 레슨의 랜덤포레스트는 트리들을 **동시에, 따로따로** 만들어 투표했습니다. 이번에는 트리를 **차례로** 만들어 앞 트리의 실수를 고쳐 가는 **부스팅**을 배우고, 트리 모델이 어떤 정보를 많이 썼는지 보여 주는 **피처 중요도**를 살펴봅니다.

## 부스팅: 앞 트리의 실수를 고쳐 가기

트리를 여러 개 쓰는 방법은 하나 더 있습니다. 랜덤포레스트가 트리들을 **따로따로 만들어 투표**한다면, **부스팅(Gradient Boosting)**은 트리를 **하나씩 차례로** 만듭니다. 새 트리는 앞 트리들이 **틀린 부분을 고치는 데** 집중합니다. 오답 노트를 보며 틀린 문제만 다시 공부하는 학생과 비슷합니다.

| | 랜덤포레스트 (배깅) | 부스팅 |
| --- | --- | --- |
| 트리 만드는 순서 | 동시에, 서로 독립 | 차례로, 앞 트리의 실수를 보완 |
| 합치는 방법 | 다수결 | 차례로 더하기 |
| 특징 | 설정을 대충 해도 안정적 | 잘 맞추면 성능이 더 좋지만 설정에 민감 |

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
for name, m in [("random forest", RandomForestClassifier(n_estimators=100, random_state=0)),
                ("boosting", GradientBoostingClassifier(n_estimators=100, learning_rate=0.1, max_depth=3, random_state=0))]:
    m.fit(X_train, y_train)
    print(f"{name:>13}: test {m.score(X_test, y_test):.3f}")
```

부스팅이 0.834로 랜덤포레스트(0.807)보다 조금 높게 나왔습니다. 다만 이 정도 차이는 데이터를 어떻게 나누느냐에 따라 뒤집히기도 해서, [교차검증과 하이퍼파라미터](#/l/ml-05-1)에서 배울 방법으로 여러 번 확인해야 믿을 수 있습니다. 성능이 비슷하면 더 단순하고 안정적인 쪽을 고르는 것도 좋은 판단입니다. 실무에서 많이 쓰는 XGBoost, LightGBM, CatBoost가 모두 이 부스팅 계열입니다.

### 실무용 부스팅: HistGradientBoosting

`GradientBoostingClassifier`는 원리를 배우기 좋지만, 데이터가 수만 행을 넘으면 느립니다. 실무에서는 같은 부스팅을 훨씬 빠르게 만든 **XGBoost, LightGBM, CatBoost**를 주로 씁니다. 사이킷런에도 LightGBM과 같은 방식으로 만든 `HistGradientBoostingClassifier`가 들어 있습니다. 숫자를 수백 개 구간으로 묶어(히스토그램) 기준값 후보를 줄이기 때문에 빠릅니다.

또 하나 편한 점이 있습니다. **빈칸(NaN)이 있어도 그대로 학습합니다.** 타이타닉의 `age`에는 빈칸이 177개 있는데, 채우지 않고 넣어 봅니다.

```run
import pandas as pd
from sklearn.model_selection import cross_val_score
from sklearn.ensemble import HistGradientBoostingClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]    # age still has NaN
print("empty age cells:", X["age"].isna().sum())
model = HistGradientBoostingClassifier(random_state=0)
print("cv accuracy:", round(cross_val_score(model, X, df["survived"], cv=5).mean(), 3))
```

빈칸 177개를 그대로 두고도 에러 없이 교차검증 정확도 0.827이 나옵니다. 나무가 기준을 정할 때 "빈칸은 왼쪽과 오른쪽 중 어느 쪽으로 보내는 게 나은가"까지 함께 배우기 때문입니다. 나이를 모른다는 사실 자체가 정보일 수도 있으니(나이가 빈칸인 승객의 생존율은 29.4%로, 나이가 적힌 승객 40.6%보다 낮습니다), 무작정 채우는 것보다 나을 때도 있습니다.

| 도구 | 특징 |
| --- | --- |
| `GradientBoostingClassifier` | 원리 학습용, 작은 데이터 |
| `HistGradientBoostingClassifier` | 사이킷런 내장, 빠름, 빈칸 그대로 |
| XGBoost · LightGBM · CatBoost | 별도 설치, 대회·실무 표준. CatBoost는 범주형 열 처리가 특히 편함 |

## 피처 중요도 맛보기: 어떤 정보를 많이 썼나

트리 모델은 각 특성이 예측에 얼마나 쓰였는지를 `feature_importances_`로 알려 줍니다. 합은 1입니다. 설비 데이터로 고장 예측에 중요한 센서를 찾아봅니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X_train, X_test, y_train, y_test = train_test_split(df[features], df["failure"], test_size=0.25, random_state=0, stratify=df["failure"])
forest = RandomForestClassifier(n_estimators=50, random_state=0).fit(X_train, y_train)
print(pd.Series(forest.feature_importances_, index=features).sort_values(ascending=False).round(3))
```

토크와 회전수가 가장 중요하게 쓰였습니다. 실제로 이 데이터의 고장 원인에는 "힘(토크 × 회전수)이 너무 크거나 작음", "토크가 큰데 공구가 많이 닳음" 같은 조건이 들어 있습니다.

> 트리는 "값이 어떤 기준보다 큰가?"만 묻기 때문에 숫자 크기를 맞추는 표준화가 필요 없습니다. 대신 `random_state`를 고정해야 매번 같은 결과가 나옵니다.

## 정리

| | 랜덤포레스트 (배깅) | 부스팅 |
| --- | --- | --- |
| 만드는 방식 | 독립된 트리들의 다수결 | 앞 트리의 실수를 차례로 보완 |
| 대표 도구 | `RandomForestClassifier` | `GradientBoostingClassifier`, `HistGradientBoostingClassifier`, XGBoost, LightGBM |
| 장점 | 설정을 대충 해도 안정적 | 잘 맞추면 성능이 더 좋음 |

- `feature_importances_`로 트리 모델이 많이 쓴 특성을 확인합니다(합 = 1).
- 트리는 크기 비교만 하므로 표준화가 필요 없습니다.
- 피처 중요도의 약점과 더 믿을 만한 방법은 [모델 해석](#/l/ml-09-1)에서 배웁니다.
