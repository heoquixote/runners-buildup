## 시작하기 전에

앞 레슨에서 혼동행렬의 네 칸(TP, FN, FP, TN)을 셌습니다. 이번 레슨에서는 네 칸으로 두 가지 핵심 점수 **정밀도**와 **재현율**을 만들고, 둘을 하나로 합친 **F1**까지 배웁니다.

## 정밀도와 재현율

네 칸으로 두 가지 중요한 점수를 만듭니다.

- **정밀도(precision)** = TP / (TP + FP): "1이라고 한 것 중 진짜 1의 비율". 경보가 울렸을 때 진짜 불일 확률. **헛경보가 적을수록** 높음
- **재현율(recall)** = TP / (TP + FN): "진짜 1 중에서 잡아낸 비율". 실제 불 중 경보가 울린 비율. **놓친 게 적을수록** 높음

::figure{src="content/img/ml/ml03-precision-recall.svg" alt="정밀도는 예측 1 열(TP와 FP) 안에서, 재현율은 실제 1 행(TP와 FN) 안에서 비율을 잰다" caption="두 점수 모두 분자는 TP입니다. 정밀도는 '울린 것' 칸 안에서, 재현율은 '진짜 불' 칸 안에서 셉니다."}

어느 쪽이 더 중요한지는 상황이 정합니다.

| 상황 | 더 아픈 실수 | 중요한 지표 |
| --- | --- | --- |
| 설비 고장 탐지, 암 검진 | 놓침(FN) | 재현율 |
| 스팸 필터 (정상 메일을 스팸함으로) | 헛경보(FP) | 정밀도 |

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, f1_score, accuracy_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
pred = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict(X_test)
print("accuracy :", round(accuracy_score(y_test, pred), 3))
print("precision:", round(precision_score(y_test, pred), 3))
print("recall   :", round(recall_score(y_test, pred), 3))
print("f1       :", round(f1_score(y_test, pred), 3))
```

설비 데이터에서 정확도는 97%로 높지만 재현율은 약 0.28입니다. 실제 고장 10건 중 7건 이상을 놓친다는 뜻이라, 현장에서 쓰기에는 부족한 모델입니다.

### 손으로 계산해 보기

앞 레슨의 AI4I 네 칸(TP=24, FN=61, FP=5, TN=2,410)으로 직접 계산하면 위 결과와 같아집니다.

- 정밀도 = 24 / (24 + 5) ≈ **0.83**: "고장"이라고 울린 29번 중 24번은 진짜 고장
- 재현율 = 24 / (24 + 61) ≈ **0.28**: 진짜 고장 85건 중 24건만 잡음

정밀도는 좋지만 재현율이 나쁩니다. 이 모델은 **아주 확실할 때만 "고장"이라고 말하는 소심한 경보기**입니다. 울리면 대부분 맞지만, 대부분의 고장에는 울리지 않습니다.

## F1: 정밀도와 재현율을 하나로

두 점수를 따로 보면 "모델 A는 정밀도가, 모델 B는 재현율이 높은데 어느 게 낫지?"처럼 비교가 어렵습니다. 그래서 둘을 하나로 합친 **F1** 점수를 씁니다.

`F1 = 2 × 정밀도 × 재현율 / (정밀도 + 재현율)` (조화평균)

그냥 평균을 내면 안 될까요? 아래 표를 보면 이유가 보입니다.

| 정밀도 | 재현율 | 그냥 평균 | F1 |
| --- | --- | --- | --- |
| 0.9 | 0.9 | 0.90 | 0.90 |
| 0.9 | 0.5 | 0.70 | 0.64 |
| 0.9 | 0.1 | 0.50 | 0.18 |
| 1.0 | 0.02 | 0.51 | 0.04 |

마지막 줄은 "확실한 1건만 고장이라고 말하고 나머지는 다 놓친" 모델입니다. 그냥 평균은 0.51로 그럴듯하지만, F1은 0.04로 **낮은 쪽을 따라갑니다.** 둘 중 하나라도 나쁘면 F1도 나쁘게 나오므로, "둘 다 괜찮은가"를 한 숫자로 볼 수 있습니다.

## 한 번에 보기: classification_report

`classification_report`는 클래스별 정밀도·재현율·F1을 표 하나로 보여 줍니다. [혼동행렬: 맞힘과 틀림을 네 칸으로](#/l/ml-03-1)의 타이타닉 모델로 확인해 봅니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
pred = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict(X_test)
print(classification_report(y_test, pred, digits=3))
```

- `1`(생존) 줄: 정밀도 0.773 = 58/75, 재현율 0.674 = 58/86, F1 0.720. 앞 레슨의 네 칸으로 손으로 계산한 값과 같습니다.
- `0`(사망) 줄: 사망을 "찾을 대상"으로 봤을 때의 점수입니다.
- `support`: 실제 개수(사망 137명, 생존 86명)
- `macro avg`: 두 클래스 점수의 단순 평균, `weighted avg`: 개수로 가중한 평균

## F-beta: 한쪽에 무게를 더 주기

F1은 정밀도와 재현율을 **똑같이** 중요하게 봅니다. 그런데 설비 고장처럼 놓침이 훨씬 아픈 문제라면 재현율에 무게를 더 주고 싶습니다. 이때 쓰는 것이 **F-beta** 점수입니다. beta는 "재현율을 정밀도보다 몇 배 중요하게 볼까"입니다.

- **F2** (beta = 2): 재현율을 더 중요하게. 고장 탐지, 암 1차 검진
- **F1** (beta = 1): 둘을 똑같이
- **F0.5** (beta = 0.5): 정밀도를 더 중요하게. 스팸 필터, 추천

설비 모델의 판정 기준선을 0.5(기본)와 0.1(더 쉽게 경보) 두 가지로 놓고 점수를 비교해 봅니다. 기준선은 [임계값: 경보 감도 조절](#/l/ml-03-3)에서 자세히 배웁니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, f1_score, fbeta_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict_proba(X_test)[:, 1]
for t in [0.5, 0.1]:
    pred = (proba >= t).astype(int)
    print(f"threshold {t}: precision {precision_score(y_test, pred):.3f}, recall {recall_score(y_test, pred):.3f}, "
          f"F1 {f1_score(y_test, pred):.3f}, F2 {fbeta_score(y_test, pred, beta=2):.3f}, F0.5 {fbeta_score(y_test, pred, beta=0.5):.3f}")
```

| 기준선 | 정밀도 | 재현율 | F1 | F2 | F0.5 |
| --- | --- | --- | --- | --- | --- |
| 0.5 | 0.828 | 0.282 | **0.421** | 0.325 | **0.597** |
| 0.1 | 0.268 | 0.612 | 0.373 | **0.487** | 0.302 |

F1과 F0.5로 보면 기준선 0.5가 낫지만, **F2로 보면 0.1이 낫습니다.** 어떤 점수로 고르느냐에 따라 "좋은 모델"이 바뀝니다. 그래서 지표는 모델을 만들기 **전에** 문제에 맞춰 정해 둡니다. 놓침이 아픈 고장 탐지라면 F2가 현장의 판단과 더 가깝습니다.

## 평균 두 가지가 크게 다를 때

AI4I 모델로 `classification_report`를 보면 `macro avg`와 `weighted avg`의 차이가 아주 큽니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
pred = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict(X_test)
print(classification_report(y_test, pred, digits=3))
```

- `weighted avg` F1은 0.967입니다. 개수로 가중하니 정상(2,415개)의 점수 0.986이 거의 그대로 반영됩니다.
- `macro avg` F1은 0.704입니다. 정상(0.986)과 고장(0.421)을 **똑같은 무게**로 평균 낸 값이라, 고장을 못 찾는 약점이 드러납니다.

그래서 드문 것을 찾는 문제에서 "weighted F1 0.97"이라고 보고하면 듣는 사람이 오해하기 쉽습니다. **찾고 싶은 클래스(1)의 줄**을 먼저 보고, 평균을 쓴다면 macro를 쓰는 것이 정직합니다.

### 자주 하는 실수

| 실수 | 무슨 일이 생기나 | 바로잡기 |
| --- | --- | --- |
| 어느 쪽이 1인지 확인 안 함 | 정답이 `"yes"/"no"` 같은 글자면 sklearn이 알파벳순으로 정해서, "no"의 재현율을 보고 있을 수 있음 | 0/1로 바꾸거나 `pos_label="yes"` 지정 |
| `precision_score(y_pred, y_test)`처럼 순서를 바꿔 넣음 | 정밀도와 재현율이 **서로 뒤바뀌어** 나옴 | 항상 `(정답, 예측)` 순서 |
| weighted 평균만 보고 보고 | 정상 클래스가 점수를 부풀림 | 찾는 클래스의 줄, macro 평균 |

## 정리

- **정밀도** = TP / (TP + FP): 1이라고 한 것 중 진짜 비율 (헛경보가 적을수록 ↑)
- **재현율** = TP / (TP + FN): 진짜 1 중 잡아낸 비율 (놓침이 적을수록 ↑)
- **F1**은 두 점수의 조화평균으로, 낮은 쪽을 따라갑니다.
- 놓침이 아프면 재현율, 헛경보가 아프면 정밀도를 우선합니다.
- 한쪽에 무게를 더 주려면 **F-beta**: F2는 재현율, F0.5는 정밀도를 더 중요하게 봅니다. 지표는 모델을 만들기 전에 정합니다.
- 드문 것을 찾을 때는 weighted 평균(0.967)이 아니라 찾는 클래스의 줄과 macro 평균(0.704)을 봅니다.
