## 시작하기 전에

앞 레슨의 class_weight는 모델을 **다시 학습**해서 기울기를 바꿨습니다. 이번에는 모델은 그대로 두고, 확률을 판정으로 바꾸는 **기준선(임계값)** 만 움직입니다. [임계값: 경보 감도 조절](#/l/ml-03-3)에서 배운 임계값을 이번에는 **비용**으로 정합니다.

## 방법 2: 판정 기준선 내리기 (임계값)

[평가지표](#/l/ml-03-1)에서 배운 **임계값**(경보 감도)을 다시 꺼냅니다. `predict()`는 고장 확률이 0.5 이상일 때만 "고장"이라고 답하는데, 불균형 데이터에서는 이 0.5가 너무 높은 경우가 많습니다. 이번에는 "얼마나 낮출까"를 **돈(비용)으로** 정하는 방법을 배웁니다.

`predict_proba()`로 확률을 직접 받아서, 기준선을 바꿔 가며 비교해 봅시다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_tr, y_tr)
proba = model.predict_proba(X_te)[:, 1]
for t in [0.5, 0.3, 0.2, 0.1]:
    pred = (proba >= t).astype(int)
    print(f"threshold {t}: recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}  alarms {pred.sum()}")
```

기준선을 0.5 → 0.2로 내리면 재현율이 0.26 → 0.56으로 오르고, 정밀도는 0.48로 아직 절반 가까이 유지됩니다. `balanced`처럼 한 번에 크게 넘어가지 않고 **원하는 만큼 조금씩 조절**할 수 있다는 것이 임계값의 장점입니다. 그럼 어디가 정답일까요? **비용**으로 정합니다.

::figure{src="content/img/ml/ml08-cost.svg" alt="저울 왼쪽에는 무거운 놓침 1건(라인 정지와 수리비), 오른쪽에는 가벼운 헛경보 1건(점검 10분)" caption="놓침 1건과 헛경보 1건의 비용을 저울에 달아 보고 기준선을 정합니다."}

- 고장 하나를 놓치면 라인이 멈추고 수리비가 크게 든다 → 기준선을 낮춰 재현율을 높인다.
- 헛경보 하나에 사람이 가서 설비를 세우고 점검해야 하고, 그 비용이 크다 → 기준선을 너무 낮추지 않는다.

### 직접 해보기: 총비용이 가장 적은 기준선 찾기

놓침 1건의 비용(`cost_fn`)과 헛경보 1건의 비용(`cost_fp`)을 정해 두면, 기준선마다 **총비용 = 놓침 수 × cost_fn + 헛경보 수 × cost_fp**를 계산할 수 있습니다. 두 비용을 바꿔 가며 가장 싼 기준선이 어떻게 움직이는지 보세요. 놓침이 비쌀수록 기준선이 내려갑니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_tr, y_tr).predict_proba(X_te)[:, 1]

cost_fn = 100   # <- missing one failure (e.g. 100만 원)
cost_fp = 5     # <- one false alarm (e.g. 5만 원)
best = None
for t in [0.5, 0.4, 0.3, 0.2, 0.1, 0.05]:
    pred = (proba >= t).astype(int)
    fn = int(((pred == 0) & (y_te == 1)).sum())
    fp = int(((pred == 1) & (y_te == 0)).sum())
    total = fn * cost_fn + fp * cost_fp
    print(f"threshold {t:<4}: missed {fn:3d}  false alarms {fp:4d}  total cost {total}")
    if best is None or total < best[1]:
        best = (t, total)
print("cheapest threshold:", best[0])
```

처음 값(놓침 100, 헛경보 5)으로 돌리면 기준선 0.05가 가장 쌉니다. 헛경보를 373건이나 울려도, 놓침 한 건이 헛경보 20건 값이라 놓침을 줄이는 쪽이 이득이기 때문입니다. `cost_fp`를 10이나 30으로 올려 보세요. 가장 싼 기준선이 0.2로 올라갑니다. 헛경보가 비싸질수록 경보를 아껴야 하기 때문입니다.

> 기준선을 고를 때는 **테스트 데이터를 보면서 고르면 안 됩니다.** 시험 문제를 보고 답을 맞춰 놓는 것과 같아서 점수가 실제보다 좋게 나옵니다. 학습 데이터를 다시 나눈 검증용 데이터(또는 교차검증)로 고르고, 테스트는 마지막 확인에만 씁니다.

## 확률을 믿어도 될까: 보정

기준선을 정하는 것과 별개로, 현장에서는 확률 숫자 자체를 쓰기도 합니다. "이 설비 고장 확률 80%"라고 보고하면 듣는 사람은 **10대 중 8대는 고장 난다**고 받아들입니다. 그런데 정말 그럴까요? 예측 확률이 실제 비율과 맞는 정도를 **보정**(calibration)이라고 합니다.

[class_weight](#/l/ml-08-2)로 고장을 더 혼낸 모델은 고장 쪽으로 기울어져 있으니, 확률도 부풀려졌을 수 있습니다. 예측 확률을 구간으로 나눠 실제 고장률과 비교해 봅니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.calibration import CalibratedClassifierCV

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
models = {
    "plain": make_pipeline(StandardScaler(), LogisticRegression()),
    "balanced": make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced")),
    "balanced + calibrated": CalibratedClassifierCV(make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced")), method="sigmoid", cv=5),
}
print("actual failure rate:", round(y_te.mean(), 3))
for name, m in models.items():
    p = m.fit(X_tr, y_tr).predict_proba(X_te)[:, 1]
    high = p >= 0.7
    print(f"{name:>22}: mean predicted {p.mean():.3f} | said >= 0.7 for {high.sum():>3} machines, actually failed {y_te[high].mean():.3f}")
```

- 보통 모델(`plain`): 평균 예측 0.035, 실제 고장률 0.034로 잘 맞습니다. "70% 이상"이라고 한 16대 중 93.8%가 실제 고장이었습니다.
- `class_weight="balanced"` 모델: 평균 예측이 **0.267**로 실제(0.034)의 8배입니다. "70% 이상"이라고 한 256대 중 실제 고장은 **21.9%** 뿐입니다. 이 모델의 "80%"는 믿으면 안 되는 숫자입니다.
- `CalibratedClassifierCV`로 보정하면 평균 예측이 0.035로 돌아오고, "70% 이상" 13대 중 92.3%가 실제 고장입니다.

> class_weight나 오버샘플링은 **판정(기준선 근처의 순서)**을 개선하는 도구이지, 확률을 정확하게 만드는 도구가 아닙니다. 확률 숫자를 사람에게 보여 주거나 비용 계산에 그대로 쓸 거라면 보정 상태를 확인하고, 필요하면 `CalibratedClassifierCV`로 보정합니다. 보정도 학습 데이터 안에서(교차검증) 합니다.

## 정리

- 임계값은 다시 학습하지 않고 원하는 만큼 조금씩 조절할 수 있습니다(0.5 → 0.2: 재현율 0.26 → 0.56, 정밀도 0.48).
- 기준선은 **총비용 = 놓침 × 놓침 비용 + 헛경보 × 헛경보 비용**이 가장 작은 곳으로 정합니다.
- 놓침이 비쌀수록 기준선은 내려갑니다. 고를 때는 검증 데이터로, 테스트는 마지막에 한 번.
- 확률 숫자 자체를 쓸 거라면 **보정**을 확인합니다. class_weight 모델은 확률이 부풀려집니다(평균 0.267 vs 실제 0.034) → `CalibratedClassifierCV`.
