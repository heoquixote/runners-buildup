## 시작하기 전에

지금까지 벌점(class_weight)과 기준선(임계값)을 바꿨습니다. 마지막 방법은 **데이터 자체**를 바꾸는 것입니다. 드문 고장 사례를 늘려 정상과 개수를 맞춥니다.

## 방법 3: 드문 쪽 데이터 늘리기 (오버샘플링)

고장 사례가 적으니, 학습 데이터 속 고장 행을 **복사해서 늘려** 정상과 개수를 비슷하게 맞추는 방법입니다. `sklearn.utils.resample`로 복원 추출(같은 행을 여러 번 뽑을 수 있게)을 합니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.utils import resample
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

X_min, X_maj = X_tr[y_tr == 1], X_tr[y_tr == 0]
X_up = resample(X_min, n_samples=len(X_maj), replace=True, random_state=0)
X_bal = np.vstack([X_maj, X_up])
y_bal = np.array([0] * len(X_maj) + [1] * len(X_up))
print("before:", np.bincount(y_tr), " after:", np.bincount(y_bal))

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_bal, y_bal)
pred = model.predict(X_te)
print(f"recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}")
```

고장 행 237개를 6,763개로 늘려 정상과 개수를 맞췄습니다. 결과(재현율 0.85, 정밀도 0.14)는 `class_weight="balanced"`와 거의 같습니다. 사실 둘은 같은 생각("드문 쪽을 더 중요하게")을 다른 방식으로 구현한 것입니다.

::figure{src="content/img/ml/ml08-oversample.svg" alt="올바른 순서는 나누기 다음 학습용 고장 행만 복사, 잘못된 순서는 복사 후 나누기라 같은 행의 복사본이 학습용과 시험용 양쪽에 들어간다" caption="나누기 전에 복사하면 같은 행의 복사본이 시험지에 섞여 점수가 부풀려집니다."}

가장 중요한 규칙은 **반드시 나눈 뒤, 학습 데이터에만** 늘린다는 것입니다. 나누기 전에 복사하면 같은 고장 행의 복사본이 학습용과 테스트용에 동시에 들어갑니다. 그러면 모델은 테스트에서 "이미 본 문제"를 맞히게 되어 점수가 부풀려집니다.

### 다른 리샘플링 방법들

| 방법 | 하는 일 | 장점 | 주의 |
| --- | --- | --- | --- |
| 오버샘플링 | 드문 쪽 행을 복사해 늘림 | 간단 | 같은 행을 반복해 보며 외울 수 있음 |
| 언더샘플링 | 많은 쪽 행을 버려 줄임 | 학습이 빨라짐 | 정상 데이터의 정보를 버림 |
| SMOTE | 드문 쪽 점들 **사이에** 새 점을 만들어 늘림 | 단순 복사보다 덜 외움 | 진짜로는 없을 수도 있는 점을 만듦 |

어떤 방법이든 규칙은 같습니다. **나눈 뒤 학습용에만**, 교차검증을 할 때는 **조각마다 따로** 적용합니다(`imbalanced-learn` 라이브러리의 파이프라인이 이 일을 해 줍니다). 그리고 가장 먼저 할 일은 리샘플링이 아니라, [평가지표](#/l/ml-03-1)에서 배운 지표로 **현재 모델이 얼마나 놓치는지 확인하는 것**입니다.

## 정리

| 상황 | 할 일 |
| --- | --- |
| 정답 한쪽이 아주 드물다 | 정확도 대신 재현율 · 정밀도 · F1을 본다 |
| 데이터 나누기 | `stratify=y`로 비율을 맞춰 나눈다 |
| 드문 쪽을 놓친다 | `class_weight="balanced"` 또는 임계값 낮추기 또는 오버샘플링 |
| 기준선 고르기 | 놓침 비용 vs 헛경보 비용으로, 검증 데이터에서 정한다 |
| 오버샘플링 | 반드시 train/test로 나눈 **뒤** 학습 데이터에만 |

| 방법 | 바꾸는 것 | 다시 학습? |
| --- | --- | --- |
| class_weight ([드문 쪽을 더 혼내기: class_weight](#/l/ml-08-2)) | 틀렸을 때의 벌점 | 예 |
| 임계값 ([판정 기준선 내리기: 임계값과 비용](#/l/ml-08-3)) | 확률 → 판정 기준선 | 아니오 |
| 오버샘플링 ([드문 쪽 데이터 늘리기: 오버샘플링](#/l/ml-08-4)) | 학습 데이터의 개수 | 예 |
