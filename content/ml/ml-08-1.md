## 고장은 드물다

AI4I 설비 데이터 10,000건 중 고장은 몇 건일까요? 직접 세어 봅시다.

```run
import pandas as pd

df = pd.read_csv("ai4i2020.csv")
print(df["failure"].value_counts())
print("failure rate:", round(df["failure"].mean(), 4))
```

10,000건 중 339건, 약 **3.4%**입니다. 나머지 96.6%는 정상입니다. 이렇게 한쪽 정답이 다른 쪽보다 훨씬 드문 데이터를 **불균형 데이터**라고 합니다. 제조 불량, 카드 부정 결제, 희귀 질병 진단처럼 **우리가 정말 찾고 싶은 것은 대부분 드뭅니다.**

::figure{src="content/img/ml/ml08-imbalance.svg" alt="점 100개 중 빨간 고장 점은 3개뿐인 그림" caption="100건 중 고장은 3~4건. 모델이 볼 고장 사례가 아주 적습니다."}

## 정확도의 함정

시험 문제 100개 중 97개의 답이 "O"라고 해 봅시다. 문제를 읽지도 않고 전부 "O"라고 찍으면 97점입니다. 점수는 높지만 실력은 0입니다.

머신러닝도 똑같습니다. 아무것도 배우지 않고 **"전부 정상"이라고만 답하는 모델**을 만들어 보겠습니다. sklearn의 `DummyClassifier`가 바로 이런 "찍기" 모델입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyClassifier
from sklearn.metrics import accuracy_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

dummy = DummyClassifier(strategy="most_frequent").fit(X_tr, y_tr)
pred = dummy.predict(X_te)
print("accuracy:", round(accuracy_score(y_te, pred), 3))
print("recall  :", recall_score(y_te, pred))
```

정확도는 0.966인데 **재현율은 0**입니다. 고장을 단 하나도 잡지 못했습니다. 그래서 불균형 데이터에서는 정확도 대신 ml-03에서 배운 지표들을 봅니다. 한 번 더 짚어 보면 이렇습니다.

- **재현율(recall)**: 실제 고장 중에서 모델이 잡아낸 비율. "놓치지 않았나?"
- **정밀도(precision)**: 모델이 고장이라고 한 것 중 진짜 고장의 비율. "괜히 울리지 않았나?"
- **F1**: 둘을 함께 보는 점수(조화평균). 둘 중 하나라도 낮으면 낮게 나옵니다.

> `stratify=y`는 학습용과 테스트용에 고장 비율을 똑같이(3.4%) 맞춰 나눠 줍니다. 고장이 드물면 그냥 무작위로 나눴을 때 테스트에 고장이 너무 적게 들어갈 수 있어서, 불균형 데이터에서는 꼭 넣습니다.

## 진짜 모델은 어떨까

이번에는 로지스틱 회귀로 제대로 학습해 봅니다. 숫자 크기가 다른 열들이라 표준화를 함께 묶었습니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, precision_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_tr, y_tr)
pred = model.predict(X_te)
print("accuracy :", round(accuracy_score(y_te, pred), 3))
print("recall   :", round(recall_score(y_te, pred), 3))
print("precision:", round(precision_score(y_te, pred), 3))
print("real failures in test:", y_te.sum(), " caught:", ((pred == 1) & (y_te == 1)).sum())
```

정확도는 0.973으로 찍기 모델(0.966)과 거의 같습니다. 재현율을 보면 테스트의 실제 고장 102건 중 27건, 약 26%만 잡았습니다. 대신 고장이라고 한 34건 중 27건은 진짜라서 정밀도(0.79)는 높습니다. 모델 입장에서는 정상이 압도적으로 많으니 "애매하면 정상"이라고 답하는 쪽이 손해가 적기 때문입니다. 이제 이 문제를 고치는 방법 세 가지를 하나씩 해 봅니다.

## 방법 1: 드문 쪽을 틀리면 더 혼내기 (class_weight)

모델은 학습할 때 틀린 만큼 벌점(손실)을 받으며 고쳐 갑니다. 기본 설정에서는 정상 하나를 틀리든 고장 하나를 틀리든 벌점이 같습니다. `class_weight="balanced"`를 주면 **드문 클래스를 틀렸을 때 벌점을 그만큼 크게** 줍니다. 고장이 정상보다 약 28배 드물면, 고장 하나를 틀릴 때 약 28배 벌점을 받는 식입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, f1_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

for cw in [None, "balanced"]:
    model = make_pipeline(StandardScaler(), LogisticRegression(class_weight=cw)).fit(X_tr, y_tr)
    pred = model.predict(X_te)
    print(f"class_weight={cw}: recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}  f1 {f1_score(y_te, pred):.2f}  alarms {pred.sum()}")
```

`balanced`로 바꾸자 재현율이 0.26 → 0.85로 크게 올랐습니다. 대신 경보(`alarms`, 고장이라고 예측한 건수)가 34건 → 614건으로 늘고 정밀도는 0.14로 떨어졌습니다. 경보 7건 중 6건이 헛경보라는 뜻입니다. **놓침을 줄이면 헛경보가 늘어나는** 맞바꿈(trade-off)이고, 공짜는 없습니다. 이번 데이터에서는 반대쪽으로 너무 많이 넘어가서 F1은 오히려 낮아졌습니다(0.40 → 0.24).

## 방법 2: 판정 기준선 내리기 (임계값)

ml-03에서 배운 **임계값**(경보 감도)을 다시 꺼냅니다. `predict()`는 고장 확률이 0.5 이상일 때만 "고장"이라고 답하는데, 불균형 데이터에서는 이 0.5가 너무 높은 경우가 많습니다. 이번에는 "얼마나 낮출까"를 **돈(비용)으로** 정하는 방법을 배웁니다.

`predict_proba()`로 확률을 직접 받아서, 기준선을 바꿔 가며 비교해 봅시다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_tr, y_tr)
proba = model.predict_proba(X_te)[:, 1]
for t in [0.5, 0.3, 0.2, 0.1]:
    pred = (proba >= t).astype(int)
    print(f"threshold {t}: recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}  alarms {pred.sum()}")
```

기준선을 0.5 → 0.2로 내리면 재현율이 0.26 → 0.56으로 오르고, 정밀도는 0.48로 아직 절반 가까이 유지됩니다. `balanced`처럼 한 번에 크게 넘어가지 않고 **원하는 만큼 조금씩 조절**할 수 있다는 것이 임계값의 장점입니다. 그럼 어디가 정답일까요? **비용**으로 정합니다.

::figure{src="content/img/ml/ml08-cost.svg" alt="저울 왼쪽에는 무거운 놓침 1건(라인 정지와 수리비), 오른쪽에는 가벼운 헛경보 1건(점검 10분)" caption="놓침 1건과 헛경보 1건의 비용을 저울에 달아 보고 기준선을 정합니다."}

- 고장 하나를 놓치면 라인이 멈추고 수리비가 크게 든다 → 기준선을 낮춰 재현율을 높인다.
- 헛경보 하나에 사람이 가서 설비를 세우고 점검해야 하고, 그 비용이 크다 → 기준선을 너무 낮추지 않는다.

### 직접 해보기: 총비용이 가장 적은 기준선 찾기

놓침 1건의 비용(`cost_fn`)과 헛경보 1건의 비용(`cost_fp`)을 정해 두면, 기준선마다 **총비용 = 놓침 수 × cost_fn + 헛경보 수 × cost_fp**를 계산할 수 있습니다. 두 비용을 바꿔 가며 가장 싼 기준선이 어떻게 움직이는지 보세요. 놓침이 비쌀수록 기준선이 내려갑니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_tr, y_tr).predict_proba(X_te)[:, 1]

cost_fn = 100   # <- missing one failure (e.g. 100만 원)
cost_fp = 5     # <- one false alarm (e.g. 5만 원)
best = None
for t in [0.5, 0.4, 0.3, 0.2, 0.1, 0.05]:
    pred = (proba >= t).astype(int)
    fn = int(((pred == 0) & (y_te == 1)).sum())
    fp = int(((pred == 1) & (y_te == 0)).sum())
    total = fn * cost_fn + fp * cost_fp
    print(f"threshold {t:<4}: missed {fn:3d}  false alarms {fp:4d}  total cost {total}")
    if best is None or total < best[1]:
        best = (t, total)
print("cheapest threshold:", best[0])
```

처음 값(놓침 100, 헛경보 5)으로 돌리면 기준선 0.05가 가장 쌉니다. 헛경보를 373건이나 울려도, 놓침 한 건이 헛경보 20건 값이라 놓침을 줄이는 쪽이 이득이기 때문입니다. `cost_fp`를 10이나 30으로 올려 보세요. 가장 싼 기준선이 0.2로 올라갑니다. 헛경보가 비싸질수록 경보를 아껴야 하기 때문입니다.

> 기준선을 고를 때는 **테스트 데이터를 보면서 고르면 안 됩니다.** 시험 문제를 보고 답을 맞춰 놓는 것과 같아서 점수가 실제보다 좋게 나옵니다. 학습 데이터를 다시 나눈 검증용 데이터(또는 교차검증)로 고르고, 테스트는 마지막 확인에만 씁니다.

## 방법 3: 드문 쪽 데이터 늘리기 (오버샘플링)

고장 사례가 적으니, 학습 데이터 속 고장 행을 **복사해서 늘려** 정상과 개수를 비슷하게 맞추는 방법입니다. `sklearn.utils.resample`로 복원 추출(같은 행을 여러 번 뽑을 수 있게)을 합니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.utils import resample
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

X_min, X_maj = X_tr[y_tr == 1], X_tr[y_tr == 0]
X_up = resample(X_min, n_samples=len(X_maj), replace=True, random_state=0)
X_bal = np.vstack([X_maj, X_up])
y_bal = np.array([0] * len(X_maj) + [1] * len(X_up))
print("before:", np.bincount(y_tr), " after:", np.bincount(y_bal))

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_bal, y_bal)
pred = model.predict(X_te)
print(f"recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}")
```

고장 행 237개를 6,763개로 늘려 정상과 개수를 맞췄습니다. 결과(재현율 0.85, 정밀도 0.14)는 `class_weight="balanced"`와 거의 같습니다. 사실 둘은 같은 생각("드문 쪽을 더 중요하게")을 다른 방식으로 구현한 것입니다.

::figure{src="content/img/ml/ml08-oversample.svg" alt="올바른 순서는 나누기 다음 학습용 고장 행만 복사, 잘못된 순서는 복사 후 나누기라 같은 행의 복사본이 학습용과 시험용 양쪽에 들어간다" caption="나누기 전에 복사하면 같은 행의 복사본이 시험지에 섞여 점수가 부풀려집니다."}

가장 중요한 규칙은 **반드시 나눈 뒤, 학습 데이터에만** 늘린다는 것입니다. 나누기 전에 복사하면 같은 고장 행의 복사본이 학습용과 테스트용에 동시에 들어갑니다. 그러면 모델은 테스트에서 "이미 본 문제"를 맞히게 되어 점수가 부풀려집니다.

### 다른 리샘플링 방법들

| 방법 | 하는 일 | 장점 | 주의 |
| --- | --- | --- | --- |
| 오버샘플링 | 드문 쪽 행을 복사해 늘림 | 간단 | 같은 행을 반복해 보며 외울 수 있음 |
| 언더샘플링 | 많은 쪽 행을 버려 줄임 | 학습이 빨라짐 | 정상 데이터의 정보를 버림 |
| SMOTE | 드문 쪽 점들 **사이에** 새 점을 만들어 늘림 | 단순 복사보다 덜 외움 | 진짜로는 없을 수도 있는 점을 만듦 |

어떤 방법이든 규칙은 같습니다. **나눈 뒤 학습용에만**, 교차검증을 할 때는 **조각마다 따로** 적용합니다(`imbalanced-learn` 라이브러리의 파이프라인이 이 일을 해 줍니다). 그리고 가장 먼저 할 일은 리샘플링이 아니라, ml-03에서 배운 지표로 **현재 모델이 얼마나 놓치는지 확인하는 것**입니다.

## 정리

| 상황 | 할 일 |
| --- | --- |
| 정답 한쪽이 아주 드물다 | 정확도 대신 재현율 · 정밀도 · F1을 본다 |
| 데이터 나누기 | `stratify=y`로 비율을 맞춰 나눈다 |
| 드문 쪽을 놓친다 | `class_weight="balanced"` 또는 임계값 낮추기 또는 오버샘플링 |
| 기준선 고르기 | 놓침 비용 vs 헛경보 비용으로, 검증 데이터에서 정한다 |
| 오버샘플링 | 반드시 train/test로 나눈 **뒤** 학습 데이터에만 |
