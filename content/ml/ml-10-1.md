## 가까운 이웃에게 묻기

전학 온 친구가 어떤 동아리를 좋아할지 맞혀야 한다고 해 봅시다. 가장 간단한 방법은 **취미와 성격이 가장 비슷한 친구 몇 명**을 찾아, 그 친구들이 많이 든 동아리를 고르는 것입니다.

**KNN(K-Nearest Neighbors, k-최근접 이웃)** 이 바로 이 방법입니다.

1. 새 사례와 학습 데이터 모든 사례 사이의 **거리**를 잽니다.
2. 가장 가까운 **k개**를 고릅니다.
3. 그 k개의 정답으로 **다수결**(회귀면 평균)을 합니다.

::figure{src="content/img/ml/ml10-knn.svg" alt="새 승객 주변의 가장 가까운 5명 중 생존 3명, 사망 2명이라 생존으로 예측" caption="k=5면 가장 가까운 5명의 다수결로 정합니다."}

KNN은 학습 단계에서 하는 일이 거의 없습니다. 규칙을 미리 만들지 않고 데이터를 **그대로 기억**해 두었다가, 예측할 때 이웃을 찾습니다. 그래서 "게으른 학습(lazy learning)"이라고도 부릅니다.

## 실제 이웃을 확인해 보기

1등실 30세 여성, 운임 80파운드인 새 승객의 이웃 5명을 직접 꺼내 봅니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)

model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5)).fit(X_train, y_train)
new = pd.DataFrame({"pclass": [1], "female": [1], "age": [30], "fare": [80.0]})
dist, idx = model[-1].kneighbors(model[0].transform(new))
print(X_train.iloc[idx[0]].assign(survived=y_train.iloc[idx[0]].values))
print("prediction:", model.predict(new))
```

이웃 5명이 모두 1등실 28~32세 여성이고 운임도 76~94파운드로 비슷합니다. 5명 모두 생존했으니 예측도 1(생존)입니다. 모델의 판단 근거를 "비슷한 사람 5명이 이랬다"로 바로 설명할 수 있는 것이 KNN의 장점입니다.

## 거리를 재니까 표준화가 꼭 필요하다

KNN은 거리로 이웃을 고릅니다. 표준화하지 않으면 운임(0~512) 차이가 거리를 독차지해서, 성별(0/1)이나 객실 등급 차이는 거의 무시됩니다. [숫자 크기 맞추기: 표준화와 정규화](#/l/ml-06-2)에서 "거리를 재는 모델은 스케일링이 **꼭** 필요하다"고 한 이유를 직접 확인해 봅니다.

```run
import pandas as pd
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
raw = cross_val_score(KNeighborsClassifier(n_neighbors=9), X, y, cv=cv).mean()
scaled = cross_val_score(make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=9)), X, y, cv=cv).mean()
print("without scaling:", round(raw, 3))
print("with scaling   :", round(scaled, 3))
```

같은 k=9인데 표준화 없이는 0.698, 표준화하면 0.793입니다. 운임만 보고 이웃을 고르면 "운임이 비슷한 남성"이 "운임이 조금 다른 여성"보다 가까운 이웃이 되어 버리기 때문입니다.

## 직접 해보기: k는 몇 명?

`k`를 1, 5, 25, 101, 301로 바꿔 보세요. 교차검증으로 학습 점수와 검증 점수를 함께 봅니다.

```run
import pandas as pd
from sklearn.model_selection import cross_validate, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

k = 1   # <- change me: 1, 5, 25, 101, 301
r = cross_validate(make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=k)), X, y, cv=cv, return_train_score=True)
print(f"k={k}: train {r['train_score'].mean():.3f}   validation {r['test_score'].mean():.3f}")
```

| k | 학습 | 검증 | 상태 |
| --- | --- | --- | --- |
| 1 | 0.976 | 0.762 | 자기 자신이 가장 가까운 이웃이라 학습 데이터는 거의 다 맞힘 → **과적합** |
| 5 | 0.863 | 0.813 | 적당함 |
| 25 | 0.821 | 0.796 | 조금 뭉개짐 |
| 101 | 0.795 | 0.791 | 더 뭉개짐 |
| 301 | 0.746 | 0.738 | 전체의 절반 가까이에게 물어 "다수 의견"만 따름 → **과소적합** |

[깊어질수록 외운다: 과적합과 과소적합](#/l/ml-04-2)의 트리 깊이와 같은 모양입니다. k가 작을수록 복잡하고(외우기 쉬움), 클수록 단순합니다. k는 하이퍼파라미터라 GridSearchCV([하이퍼파라미터와 GridSearchCV](#/l/ml-05-2))로 고릅니다.

## 숫자 예측도: KNN 회귀

KNN은 분류뿐 아니라 회귀에도 씁니다. 이웃 k명의 **다수결 대신 평균**을 내면 됩니다. [특성을 여러 개 쓰면](#/l/ml-02-4)의 당뇨병 데이터로 k를 바꿔 가며 선형회귀와 비교합니다.

```run
from sklearn.datasets import load_diabetes
from sklearn.model_selection import cross_val_score, KFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsRegressor
from sklearn.linear_model import LinearRegression

X, y = load_diabetes(return_X_y=True)
cv = KFold(n_splits=5, shuffle=True, random_state=0)
for k in [1, 5, 15, 30]:
    r2 = cross_val_score(make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=k)), X, y, cv=cv, scoring="r2").mean()
    print(f"KNN k={k:>2}: R^2 {r2:.3f}")
print(f"linear    : R^2 {cross_val_score(LinearRegression(), X, y, cv=cv, scoring='r2').mean():.3f}")
```

- k=1이면 R²가 **−0.125**로, 평균만 찍는 것보다도 못합니다. 가장 비슷한 환자 한 명의 값을 그대로 베끼니 그 사람의 우연한 사정까지 따라갑니다.
- k=15에서 0.451로 가장 좋고, k=30이면 조금 내려갑니다.
- 그래도 선형회귀(0.489)보다는 낮습니다. 이 데이터처럼 관계가 대체로 **직선 모양**이면 직선 모델이 유리합니다.

KNN 회귀는 관계가 직선이 아니고 들쭉날쭉할 때, 그리고 "비슷한 과거 사례 몇 개의 평균"이라는 설명이 필요할 때(예: 비슷한 조건의 과거 배치 5개 평균 수율) 쓸모가 있습니다.

## 장단점

| 장점 | 단점 |
| --- | --- |
| 원리가 직관적, "비슷한 사례"로 설명 가능 | 예측할 때마다 모든 데이터와 거리를 재서 **데이터가 많으면 느림** |
| 학습이 거의 없음, 데이터를 추가하기 쉬움 | **표준화 필수**, 쓸모없는 특성이 섞이면 거리가 흐려짐 |
| 회귀(이웃 평균)에도 쓸 수 있음 | 특성이 아주 많으면 모두가 비슷하게 멀어져 이웃의 의미가 약해짐 |

## 정리

- KNN = 가장 가까운 k개 사례의 다수결(회귀면 평균)
- 거리를 재므로 **표준화가 꼭** 필요합니다(0.698 → 0.793).
- k가 작으면 과적합(k=1), 너무 크면 과소적합(k=301). 교차검증으로 고릅니다.
- 회귀에서는 이웃 평균을 냅니다(당뇨 k=15: R² 0.451). 관계가 직선 모양이면 선형회귀(0.489)가 더 나을 수 있습니다.
