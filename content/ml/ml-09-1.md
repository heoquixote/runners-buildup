## 예측만으로는 부족하다

모델이 "이 설비는 곧 고장 납니다"라고 말했다고 해 봅시다. 현장 담당자는 바로 이렇게 물을 겁니다.

- "왜요? 무엇을 보고 그렇게 판단했죠?"
- "그럼 무엇을 바꾸면 고장을 막을 수 있나요?"

답을 못 하면 담당자는 모델을 믿지 않고, 믿지 않는 모델은 쓰이지 않습니다. 그래서 **모델이 무엇을 보고 판단했는지 들여다보는 일**, 즉 **모델 해석**이 필요합니다. 이 코스([모델 해석](#/l/ml-09-1))에서는 두 레슨에 걸쳐 세 가지 질문에 답하는 방법을 배웁니다. [무엇을 많이 봤나: 피처 중요도와 순열 중요도](#/l/ml-09-1)는 "무엇을 많이 봤나", [어느 방향으로, 어떤 모양으로: 계수와 부분 의존도](#/l/ml-09-2)는 "어느 방향으로, 어떤 모양으로"입니다.

| 질문 | 방법 |
| --- | --- |
| 어떤 열을 가장 많이 봤나? | 피처 중요도, 순열 중요도 |
| 그 열이 커지면 예측이 올라가나 내려가나? | 계수(선형 모델), 부분 의존도 |
| 그 결과를 믿어도 되나? | 가짜 열을 넣어 보는 등 직접 확인 |

## 먼저 모델 하나 만들기

AI4I 설비 데이터로 랜덤포레스트를 학습합니다. 여기에 일부러 **고장과 아무 관계없는 가짜 열** `noise`(무작위 숫자)를 하나 끼워 넣겠습니다. 해석 방법이 이 가짜 열을 제대로 "쓸모없다"고 알아보는지 확인하는 장치입니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import recall_score, precision_score

df = pd.read_csv("ai4i2020.csv")
df["noise"] = np.random.default_rng(0).normal(size=len(df))
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear", "noise"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])

rf = RandomForestClassifier(n_estimators=100, random_state=0, n_jobs=1).fit(X_tr, y_tr)
pred = rf.predict(X_te)
print("recall   :", round(recall_score(y_te, pred), 3))
print("precision:", round(precision_score(y_te, pred), 3))
```

## 방법 1: 피처 중요도 (트리 모델 기본 제공)

결정나무는 질문("토크가 60보다 큰가?")을 던지며 데이터를 나눕니다. 어떤 열로 질문했을 때 정답이 깔끔하게 갈라질수록 그 열은 쓸모 있는 열입니다. 랜덤포레스트의 `feature_importances_`는 **각 열이 이렇게 깔끔하게 나누는 데 기여한 양을 모두 더한 값**이고, 전체 합은 1입니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
df["noise"] = np.random.default_rng(0).normal(size=len(df))
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear", "noise"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
rf = RandomForestClassifier(n_estimators=100, random_state=0, n_jobs=1).fit(X_tr, y_tr)

imp = pd.Series(rf.feature_importances_, index=features).sort_values(ascending=False)
print(imp.round(3))
```

토크(0.29)·회전수(0.22)·공구 마모(0.15)가 위쪽에 옵니다. 그런데 이상한 점이 있습니다. 아무 의미 없는 `noise`도 0.08이나 받았습니다. 전체의 8%를 무작위 숫자가 차지한 셈입니다. 이것이 이 방법의 약점입니다.

- **학습 데이터로 계산**합니다. 모델이 학습 데이터의 우연한 무늬까지 외우면, 그 무늬를 만든 열도 중요하다고 나옵니다.
- 값의 종류가 많은 숫자 열(무작위 숫자처럼)은 나눌 자리가 많아서 **실제보다 중요해 보이기 쉽습니다.**

빠르고 편하지만 "참고용"으로 보는 것이 좋습니다.

## 방법 2: 순열 중요도 (섞어서 망가뜨려 보기)

더 믿을 만한 방법은 이렇습니다. **테스트 데이터에서 한 열만 무작위로 섞어** 그 열의 정보를 망가뜨린 뒤, 점수가 얼마나 떨어지는지 봅니다.

비유하면 요리 맛보기입니다. 찌개에서 소금만 빼고 맛을 봤더니 맛이 확 떨어진다면 소금은 중요한 재료입니다. 파를 뺐는데 맛이 그대로라면 파는 이 찌개에서 별로 중요하지 않은 재료입니다.

::figure{src="content/img/ml/ml09-permutation.svg" alt="테스트 데이터에서 torque 열의 값만 무작위로 섞으면 재현율이 크게 떨어진다" caption="한 열만 섞어 그 열의 정보를 망가뜨리고, 점수가 얼마나 떨어지는지 봅니다."}

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance

df = pd.read_csv("ai4i2020.csv")
df["noise"] = np.random.default_rng(0).normal(size=len(df))
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear", "noise"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
rf = RandomForestClassifier(n_estimators=100, random_state=0, n_jobs=1).fit(X_tr, y_tr)

perm = permutation_importance(rf, X_te, y_te, scoring="recall", n_repeats=5, random_state=0)
result = pd.Series(perm.importances_mean, index=features).sort_values(ascending=False)
print("recall drop when shuffled:")
print(result.round(3))
```

- `scoring="recall"`: 고장을 잡는 능력(재현율)이 얼마나 떨어지는지로 잽니다. 불균형 데이터라 정확도로 재면 차이가 잘 안 보이기 때문입니다.
- `n_repeats=5`: 섞는 것은 우연이 끼므로 5번 섞어 평균을 냅니다.

토크를 섞으면 재현율이 0.33, 회전수를 섞으면 0.22나 떨어집니다. 반면 `noise`는 0.03으로 바닥 근처입니다. 섞어도 성능이 거의 그대로라는 뜻이니, 모델이 실제 예측에 이 열을 거의 쓰지 않는다는 것이 드러났습니다.

그런데 `process_temp`도 0.03으로 `noise`만큼 낮게 나왔습니다. 공정 온도가 쓸모없는 열일까요? 그렇지 않습니다. 바로 아래 주의를 보세요.

> 주의: `process_temp`는 `air_temp`와 함께 움직이는 열입니다([선형 · 로지스틱 회귀](#/l/ml-02-1)에서 본 상관계수 약 0.86). 이렇게 비슷한 두 열은 하나를 섞어도 다른 하나가 정보를 대신해 줍니다. 그래서 **한쪽이나 둘 다 중요도가 낮게 나올 수 있습니다.** "중요도가 낮다 = 쓸모없다"라고 바로 결론 내리지 마세요.

## 정리

| 방법 | 알려 주는 것 | 주의 |
| --- | --- | --- |
| `feature_importances_` | 트리가 나누는 데 많이 쓴 열 (학습 데이터 기준) | 의미 없는 `noise`도 0.08을 받음 |
| 순열 중요도 | 테스트에서 섞었을 때 점수가 떨어지는 양 | 비슷한 열끼리는 서로 가려 줌 |

- 가짜 열(`noise`)을 넣어 보면 해석 방법이 믿을 만한지 직접 확인할 수 있습니다.
- 중요도는 "얼마나"만 알려 주고 **방향**은 알려 주지 않습니다. 다음 레슨에서 방향과 모양을 봅니다.
