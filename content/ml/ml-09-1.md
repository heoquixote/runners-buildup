## 예측만으로는 부족하다

모델이 "이 설비는 곧 고장 납니다"라고 말했다고 해 봅시다. 현장 담당자는 바로 이렇게 물을 겁니다.

- "왜요? 무엇을 보고 그렇게 판단했죠?"
- "그럼 무엇을 바꾸면 고장을 막을 수 있나요?"

답을 못 하면 담당자는 모델을 믿지 않고, 믿지 않는 모델은 쓰이지 않습니다. 그래서 **모델이 무엇을 보고 판단했는지 들여다보는 일**, 즉 **모델 해석**이 필요합니다. 이번 레슨에서는 세 가지 질문에 답하는 방법을 배웁니다.

| 질문 | 방법 |
| --- | --- |
| 어떤 열을 가장 많이 봤나? | 피처 중요도, 순열 중요도 |
| 그 열이 커지면 예측이 올라가나 내려가나? | 계수(선형 모델), 부분 의존도 |
| 그 결과를 믿어도 되나? | 가짜 열을 넣어 보는 등 직접 확인 |

## 먼저 모델 하나 만들기

AI4I 설비 데이터로 랜덤포레스트를 학습합니다. 여기에 일부러 **고장과 아무 관계없는 가짜 열** `noise`(무작위 숫자)를 하나 끼워 넣겠습니다. 해석 방법이 이 가짜 열을 제대로 "쓸모없다"고 알아보는지 확인하는 장치입니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import recall_score, precision_score

df = pd.read_csv("ai4i2020.csv")
df["noise"] = np.random.default_rng(0).normal(size=len(df))
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear", "noise"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])

rf = RandomForestClassifier(n_estimators=100, random_state=0, n_jobs=1).fit(X_tr, y_tr)
pred = rf.predict(X_te)
print("recall   :", round(recall_score(y_te, pred), 3))
print("precision:", round(precision_score(y_te, pred), 3))
```

## 방법 1: 피처 중요도 (트리 모델 기본 제공)

결정나무는 질문("토크가 60보다 큰가?")을 던지며 데이터를 나눕니다. 어떤 열로 질문했을 때 정답이 깔끔하게 갈라질수록 그 열은 쓸모 있는 열입니다. 랜덤포레스트의 `feature_importances_`는 **각 열이 이렇게 깔끔하게 나누는 데 기여한 양을 모두 더한 값**이고, 전체 합은 1입니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
df["noise"] = np.random.default_rng(0).normal(size=len(df))
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear", "noise"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
rf = RandomForestClassifier(n_estimators=100, random_state=0, n_jobs=1).fit(X_tr, y_tr)

imp = pd.Series(rf.feature_importances_, index=features).sort_values(ascending=False)
print(imp.round(3))
```

토크(0.29)·회전수(0.22)·공구 마모(0.15)가 위쪽에 옵니다. 그런데 이상한 점이 있습니다. 아무 의미 없는 `noise`도 0.08이나 받았습니다. 전체의 8%를 무작위 숫자가 차지한 셈입니다. 이것이 이 방법의 약점입니다.

- **학습 데이터로 계산**합니다. 모델이 학습 데이터의 우연한 무늬까지 외우면, 그 무늬를 만든 열도 중요하다고 나옵니다.
- 값의 종류가 많은 숫자 열(무작위 숫자처럼)은 나눌 자리가 많아서 **실제보다 중요해 보이기 쉽습니다.**

빠르고 편하지만 "참고용"으로 보는 것이 좋습니다.

## 방법 2: 순열 중요도 (섞어서 망가뜨려 보기)

더 믿을 만한 방법은 이렇습니다. **테스트 데이터에서 한 열만 무작위로 섞어** 그 열의 정보를 망가뜨린 뒤, 점수가 얼마나 떨어지는지 봅니다.

비유하면 요리 맛보기입니다. 찌개에서 소금만 빼고 맛을 봤더니 맛이 확 떨어진다면 소금은 중요한 재료입니다. 파를 뺐는데 맛이 그대로라면 파는 이 찌개에서 별로 중요하지 않은 재료입니다.

::figure{src="content/img/ml/ml09-permutation.svg" alt="테스트 데이터에서 torque 열의 값만 무작위로 섞으면 재현율이 크게 떨어진다" caption="한 열만 섞어 그 열의 정보를 망가뜨리고, 점수가 얼마나 떨어지는지 봅니다."}

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance

df = pd.read_csv("ai4i2020.csv")
df["noise"] = np.random.default_rng(0).normal(size=len(df))
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear", "noise"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
rf = RandomForestClassifier(n_estimators=100, random_state=0, n_jobs=1).fit(X_tr, y_tr)

perm = permutation_importance(rf, X_te, y_te, scoring="recall", n_repeats=5, random_state=0)
result = pd.Series(perm.importances_mean, index=features).sort_values(ascending=False)
print("recall drop when shuffled:")
print(result.round(3))
```

- `scoring="recall"`: 고장을 잡는 능력(재현율)이 얼마나 떨어지는지로 잽니다. 불균형 데이터라 정확도로 재면 차이가 잘 안 보이기 때문입니다.
- `n_repeats=5`: 섞는 것은 우연이 끼므로 5번 섞어 평균을 냅니다.

토크를 섞으면 재현율이 0.33, 회전수를 섞으면 0.22나 떨어집니다. 반면 `noise`는 0.03으로 바닥 근처입니다. 섞어도 성능이 거의 그대로라는 뜻이니, 모델이 실제 예측에 이 열을 거의 쓰지 않는다는 것이 드러났습니다.

그런데 `process_temp`도 0.03으로 `noise`만큼 낮게 나왔습니다. 공정 온도가 쓸모없는 열일까요? 그렇지 않습니다. 바로 아래 주의를 보세요.

> 주의: `process_temp`는 `air_temp`와 함께 움직이는 열입니다(ml-02에서 본 상관계수 약 0.86). 이렇게 비슷한 두 열은 하나를 섞어도 다른 하나가 정보를 대신해 줍니다. 그래서 **한쪽이나 둘 다 중요도가 낮게 나올 수 있습니다.** "중요도가 낮다 = 쓸모없다"라고 바로 결론 내리지 마세요.

## 방법 3: 선형 모델의 계수 (방향까지 알려 준다)

중요도는 "얼마나 중요한가"만 알려 주고, **방향**(커지면 위험이 오르나 내리나)은 알려 주지 않습니다. 로지스틱 회귀 같은 선형 모델은 계수의 **부호**로 방향을 바로 알 수 있습니다.

- 계수 **+**: 이 값이 커지면 예측 확률이 **올라간다**
- 계수 **−**: 이 값이 커지면 예측 확률이 **내려간다**

다만 열마다 단위가 다르면(나이는 0~80, 운임은 0~512) 계수 크기를 비교할 수 없습니다. 그래서 **표준화한 뒤** 계수를 봅니다. 그러면 계수는 "이 값이 보통 정도(1 표준편차) 커질 때의 효과"가 되어 서로 비교할 수 있습니다. 타이타닉 데이터로 해 봅시다.

```run
import pandas as pd
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
features = ["pclass", "female", "age", "sibsp", "parch", "fare"]

model = make_pipeline(StandardScaler(), LogisticRegression()).fit(df[features], df["survived"])
coef = pd.Series(model[-1].coef_[0], index=features).sort_values()
print(coef.round(2))
```

- `female`이 +1.30으로 가장 큰 **+**: 여성이면 생존 확률이 크게 올라갑니다.
- `pclass`는 −0.89: 숫자가 클수록(1등실 → 3등실) 생존 확률이 내려갑니다.
- `age`도 −0.50: 나이가 많을수록 생존 확률이 내려갑니다.
- `fare`(+0.14)와 `parch`(−0.08)는 0에 가까워 영향이 작습니다. 운임은 객실 등급과 거의 같은 정보라서, 등급이 이미 들어간 뒤에는 더할 게 별로 없기 때문입니다.

"여성과 아이 먼저, 그리고 상급 객실이 구명보트에 가까웠다"는 역사적 사실과 맞아떨어집니다. 모델의 판단 근거가 상식과 맞으면 그만큼 믿을 수 있습니다.

## 방법 4: 부분 의존도 (그래프로 모양 보기)

계수는 "직선 하나의 기울기"라서 복잡한 모양은 못 보여 줍니다. 랜덤포레스트 같은 모델에서 "토크가 커지면 고장 확률이 어떻게 변하나?"를 보려면 **부분 의존도(PDP)**를 그립니다. 방법은 단순합니다.

1. 모든 설비의 토크를 **똑같이 20**으로 바꾸고, 나머지 열은 그대로 둔 채 고장 확률을 예측해 평균을 낸다.
2. 토크를 25, 30, …, 70으로 바꿔 가며 같은 일을 반복한다.
3. 토크 값(가로)과 평균 고장 확률(세로)을 선으로 잇는다.

"다른 조건은 그대로 두고 토크만 바꿨다면?"이라는 가상 실험을 하는 셈입니다.

::figure{src="content/img/ml/ml09-pdp.svg" alt="모든 설비의 torque를 20, 45, 70으로 바꿔 평균 고장 확률을 구하고, 그 값을 이어 곡선을 그린다" caption="토크 값마다 평균 예측을 구해 점으로 찍고 이으면 부분 의존도 곡선이 됩니다."}

```run
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
rf = RandomForestClassifier(n_estimators=100, min_samples_leaf=5, random_state=0, n_jobs=1).fit(df[features], df["failure"])

sample = df[features].sample(1000, random_state=0)
grid = np.arange(20, 71, 5)
avg = []
for t in grid:
    X_new = sample.copy()
    X_new["torque"] = t
    avg.append(float(rf.predict_proba(X_new)[:, 1].mean()))
for t, a in zip(grid, avg):
    print(f"torque {t}: failure prob {a:.3f}")

plt.figure(figsize=(6, 3.5))
plt.plot(grid, avg, marker="o")
plt.xlabel("torque (Nm)")
plt.ylabel("avg predicted failure prob")
plt.title("Partial dependence of torque")
plt.show()
```

토크 20~50에서는 고장 확률이 3% 근처로 평평하다가, 55에서 8%, 60에서 31%, 70에서 87%로 **급격히 올라갑니다.** 이런 "꺾이는 지점(임계점)"은 현장에서 바로 쓸 수 있는 정보입니다. 예를 들어 "토크가 이 값을 넘으면 경고를 띄우자"는 운전 기준을 정할 수 있습니다.

> 부분 의존도는 **상관관계**를 보여 줄 뿐, "토크를 낮추면 반드시 고장이 줄어든다"는 **인과**를 증명하지는 않습니다. 실제 조치는 현장 지식과 실험으로 확인해야 합니다.

### 한 건 한 건 설명하고 싶다면: SHAP

지금까지 본 방법은 "전체적으로 어떤 열이 중요한가"였습니다. 현장에서는 "**이 설비**는 왜 위험하다고 나왔나?"처럼 한 건을 설명해야 할 때도 많습니다. 이때 쓰는 대표 도구가 **SHAP**입니다. 예측 하나를 "기본값 3% + 토크 때문에 +40% + 공구 마모 때문에 +12% …"처럼 열마다 나눠서 보여 줍니다. (SHAP 라이브러리는 이 사이트의 브라우저 파이썬에서는 돌아가지 않아 개념만 소개합니다.)

> 어떤 방법이든 **중요도가 높다 = 원인이다**가 아닙니다. 모델이 그 열을 많이 참고했다는 뜻일 뿐입니다. 그리고 한 모델의 중요도는 그 모델 기준이라, 모델을 바꾸면 순서가 달라질 수 있습니다.

## 정리

| 방법 | 알려 주는 것 | 장점 | 주의 |
| --- | --- | --- | --- |
| `feature_importances_` | 트리가 많이 쓴 열 | 빠름, 바로 나옴 | 학습 데이터 기준, 무의미한 숫자 열도 높게 나올 수 있음 |
| 순열 중요도 | 섞었을 때 점수가 떨어지는 열 | 어떤 모델에도 사용, 테스트 데이터 기준 | 비슷한 열끼리는 서로 가려 줌 |
| 표준화한 계수 | 방향(+/−)과 크기 | 해석이 쉬움 | 선형 모델에서만, 표준화 필수 |
| 부분 의존도 | 값이 바뀔 때 예측이 변하는 모양 | 임계점 같은 모양이 보임 | 인과가 아님 |
