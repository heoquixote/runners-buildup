## 시작하기 전에

지금까지는 모델을 만들고 점수를 확인하면 끝이었습니다. 하지만 현장에서 모델의 일은 그때부터 시작입니다. 매일 들어오는 새 설비 데이터에 예측을 내야 하고, 몇 달이 지나도 그 예측을 믿을 수 있어야 합니다. 이번 레슨에서는 모델을 **파일로 저장하고 다시 불러 쓰는 법**과, 시간이 지나며 모델이 조용히 나빠지는 **드리프트**를 알아차리는 법을 배웁니다.

## 모델을 파일로 저장하기

모델을 매번 새로 학습하면 시간도 걸리고, 학습할 때마다 결과가 조금씩 달라질 수도 있습니다. 그래서 학습이 끝난 모델을 **파일로 저장**해 두고, 예측할 때는 그 파일을 불러서 씁니다. 요리로 치면 매번 새로 레시피를 연구하지 않고, 완성된 레시피를 적어 두고 그대로 따라 하는 것입니다.

파이썬 객체를 파일로 저장하는 기본 도구는 `pickle`입니다. 전처리까지 묶은 **Pipeline 전체**를 저장하는 것이 중요합니다. 모델만 저장하면, 예측할 때 표준화 같은 손질을 다시 똑같이 짜야 하니까요.

```run
import pickle
import pandas as pd
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
pipe = make_pipeline(StandardScaler(), RandomForestClassifier(n_estimators=100, min_samples_leaf=5, random_state=0, n_jobs=1))
pipe.fit(df[features], df["failure"])

with open("failure_model.pkl", "wb") as f:     # wb = write binary
    pickle.dump(pipe, f)
print("saved")

with open("failure_model.pkl", "rb") as f:     # rb = read binary
    loaded = pickle.load(f)

new_machine = pd.DataFrame([{"air_temp": 299.8, "process_temp": 309.3, "rpm": 1299, "torque": 65.1, "tool_wear": 212}])
print("original model:", round(pipe.predict_proba(new_machine)[0, 1], 3))
print("loaded model  :", round(loaded.predict_proba(new_machine)[0, 1], 3))
```

저장했다가 불러온 모델이 원래 모델과 **똑같은 예측**(0.928)을 냅니다. 실무에서는 큰 배열을 더 빠르게 저장하는 `joblib.dump` / `joblib.load`도 많이 씁니다. 사용법은 같습니다.

> pickle 파일은 불러오는 순간 그 안의 코드가 실행될 수 있습니다. **출처를 모르는 pickle 파일은 절대 열지 마세요.**

몇 달 뒤 "이 모델 어떻게 만든 거지?"라는 질문에 답할 수 있어야 합니다. 모델 파일 옆에 꼭 남겨 둡니다.

| 학습 데이터 기간·행 수 | 2026년 1~4월, 4,000행 | 어떤 상황을 배웠는지 |

## 드리프트: 세상이 바뀌면 모델은 낡는다

모델은 **학습한 시기의 세상**을 배웁니다. 그런데 계절이 바뀌고, 원자재가 바뀌고, 설비를 교체하면 데이터의 모습이 달라집니다. 이렇게 시간이 지나며 데이터가 학습 때와 달라지는 것을 **드리프트**(drift)라고 합니다. 겨울 옷 판매 데이터로 배운 모델이 여름에 틀리는 것과 같습니다.

AI4I 데이터는 시간 순서대로 쌓여 있고, 중간에 **기온이 높은 구간**이 있습니다. [K-fold 교차검증](#/l/ml-05-1)에서 순서대로 나눴을 때 세 번째 조각만 점수가 떨어졌던 바로 그 구간입니다. 앞 4,000행(봄)으로 학습하고, 다음 2,000행(더운 구간)과 마지막 2,000행에 써 봅니다.

```run
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.metrics import f1_score, recall_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
train = df.iloc[:4000]
model = RandomForestClassifier(n_estimators=100, min_samples_leaf=5, class_weight="balanced", random_state=0, n_jobs=1)
cv_f1 = cross_val_score(model, train[features], train["failure"], cv=StratifiedKFold(5, shuffle=True, random_state=0), scoring="f1").mean()
print("validation F1 at training time:", round(cv_f1, 3))

model.fit(train[features], train["failure"])
for name, part in [("rows 4000-5999 (hot)", df.iloc[4000:6000]), ("rows 8000-9999", df.iloc[8000:])]:
    pred = model.predict(part[features])
    print(f"{name}: F1 {f1_score(part['failure'], pred):.3f}, recall {recall_score(part['failure'], pred):.3f}, air_temp mean {part['air_temp'].mean():.1f}")
```

- 학습할 때 검증 F1은 **0.633**이었습니다.
- 더운 구간에서는 F1 **0.405**, 재현율 **0.292**로 떨어집니다. 고장 10건 중 7건을 놓칩니다. 공기 온도 평균이 299.1K에서 302.7K로 올라가 있습니다.
- 마지막 구간은 온도가 다시 학습 때와 비슷해져서(298.4K) F1이 0.607로 돌아옵니다.

더운 구간에는 고장률도 2.5% → 7.7%로 뜁니다. 고장 154건 중 108건이 "공정 온도와 공기 온도의 차이가 8.6K보다 작고 회전이 느린" **열 방출 고장** 조건에 해당합니다. 학습 구간에서는 이 조건의 고장이 101건 중 7건뿐이었으니, 모델이 이 유형을 거의 배우지 못한 것입니다.

## 드리프트 알아차리기: 입력 분포 비교

문제는 현장에서는 **정답이 늦게 온다**는 것입니다. 고장이 났는지는 며칠, 몇 주 뒤에나 확정됩니다. 그래서 정답을 기다리지 않고, **입력 데이터의 모습이 학습 때와 달라졌는지**를 먼저 봅니다.

두 분포가 얼마나 다른지 재는 대표 도구가 **KS 통계량**입니다. 두 데이터의 누적 분포 그래프를 겹쳐 그렸을 때 **가장 많이 벌어진 간격**(0~1)입니다. 0이면 같은 모양, 1에 가까우면 완전히 다른 모양입니다.

::figure{src="content/img/ml/ml11-drift.svg" alt="학습 구간과 더운 구간의 air_temp 분포가 오른쪽으로 크게 밀려 있고, 누적 분포 곡선 사이 가장 큰 간격이 KS 통계량 0.76이다" caption="학습 구간(봄)과 더운 구간의 공기 온도. 누적 분포 곡선 사이 가장 큰 간격이 KS 통계량입니다."}

```run
import pandas as pd
from scipy.stats import ks_2samp

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
train, hot = df.iloc[:4000], df.iloc[4000:6000]
for col in features:
    ks = ks_2samp(train[col], hot[col]).statistic
    flag = "  <-- drift!" if ks > 0.1 else ""
    print(f"{col:>12}: KS {ks:.3f}{flag}")
```

공기 온도(0.762)와 공정 온도(0.749)만 크게 벌어졌고, 회전수·토크·공구 마모는 0.02 정도로 그대로입니다. 정답이 오기 **전에** "온도 분포가 학습 때와 다르다, 이 모델의 예측을 그대로 믿으면 안 된다"는 경고를 띄울 수 있습니다.

> 몇 % 차이를 드리프트로 볼지는 정해진 답이 없습니다. 위에서는 0.1을 기준으로 했습니다. 데이터가 아주 많으면 작은 차이도 통계적으로 '유의'하게 나오므로, p-value보다 **KS 값의 크기**를 보는 편이 실용적입니다.

## 모니터링 체크리스트

| 무엇을 | 언제 | 이상하면 |
| --- | --- | --- |
| 입력 분포 (KS, 평균, 빈칸 비율) | 매일·매주 | 원인 확인 (센서 고장? 계절? 공정 변경?) |
| 예측 분포 (경보 비율) | 매일 | 경보가 갑자기 늘거나 0이면 점검 |
| 실제 성능 (재현율, 정밀도) | 정답이 확정될 때마다 | 학습 때 점수와 비교 |
| 재학습 | 드리프트 확인 시 또는 정기적으로 | 최근 데이터를 포함해 다시 학습 → 검증 → 교체 |

## 정리

- 학습이 끝난 **Pipeline 전체**를 `pickle`(또는 `joblib`)로 저장하고, 예측할 때 불러 씁니다. 입력 열, 학습 기간, 검증 점수, 기준선, 버전을 함께 기록합니다.
- **드리프트**: 시간이 지나며 데이터가 학습 때와 달라지는 것. 더운 구간에서 F1이 0.633 → 0.405로 떨어졌습니다.
- 정답은 늦게 오므로 **입력 분포**부터 감시합니다. KS 통계량으로 공기 온도의 변화(0.762)를 바로 잡았습니다.
- 모델은 한 번 만들고 끝이 아니라 **감시하고, 다시 학습하는** 것까지가 일입니다.
