## 시작하기 전에

ml-06-1, 06-2는 이미 있는 열을 **손질**했습니다. 이번에는 데이터에 없는 열을 **새로 만들어** 모델을 돕는 방법, 피처 엔지니어링입니다. 같은 모델이라도 좋은 특성 하나로 성능이 크게 달라집니다.

## 새 특성 만들기: 피처 엔지니어링

데이터에 없는 열을 **아이디어로** 만들어 넣으면 모델이 훨씬 쉽게 배우기도 합니다. 이렇게 만든 열을 **파생변수**라고 합니다. 자주 쓰는 아이디어는 네 가지입니다.

| 종류 | 예 |
| --- | --- |
| 곱하기·나누기 (조합) | 회전수 × 토크 = 동력, 운임 ÷ 가족 수 = 1인당 운임 |
| 차이 | 공정 온도 − 공기 온도 |
| 날짜에서 뽑기 | 요일, 월, 주말 여부 |
| 묶어서 세기 | 가족 수 = 형제자매 + 부모자식 + 1 |

설비 데이터에서 회전수 × 토크는 물리적으로 **동력(힘)**에 해당합니다. 공정 온도 − 공기 온도는 **열이 잘 빠지는지**를 나타냅니다. 이 두 열을 만들어 넣어 봅니다.

```run
import pandas as pd
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.tree import DecisionTreeClassifier

df = pd.read_csv("ai4i2020.csv")
df["power"] = df["rpm"] * df["torque"] * 2 * 3.1416 / 60     # watts
df["temp_gap"] = df["process_temp"] - df["air_temp"]
y = df["failure"]
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
base = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
for cols in [base, base + ["power", "temp_gap"]]:
    f1 = cross_val_score(DecisionTreeClassifier(max_depth=5, random_state=0), df[cols], y, cv=cv, scoring="f1").mean()
    print(len(cols), "features -> F1", round(f1, 3))
```

같은 모델인데 새 특성 두 개만으로 F1이 크게 오릅니다. 좋은 특성 하나가 복잡한 모델보다 효과가 클 때가 많습니다. **현장 지식**이 머신러닝에서 중요한 이유입니다.

> 단, **예측하는 시점에 알 수 없는 정보**로 특성을 만들면 안 됩니다. 예를 들어 "고장 후 수리 시간"은 고장을 예측하는 데 쓸 수 없습니다(누수).

## 타이타닉에서도: 가족 수

타이타닉에는 `sibsp`(함께 탄 형제·배우자 수)와 `parch`(함께 탄 부모·자녀 수)가 따로 있습니다. 둘을 더하고 본인 1명을 더하면 **가족 수**가 됩니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
df["family"] = df["sibsp"] + df["parch"] + 1
groups = pd.cut(df["family"], bins=[0, 1, 4, 11], labels=["alone", "2-4", "5+"])
print(df.groupby(groups, observed=True)["survived"].agg(["mean", "size"]).round(3))
```

혼자 탄 승객(537명)은 생존율 30.4%, 2~4명 가족(292명)은 57.9%, 5명 이상 대가족(62명)은 16.1%입니다. 가족 수가 늘수록 **올라갔다가 다시 떨어지는** 모양입니다. 이런 관계는 직선 하나로는 잡기 어려워서, 위처럼 구간으로 나눈 열(`alone`, `2-4`, `5+`)을 만들어 원-핫으로 넣으면 로지스틱 회귀도 쉽게 배울 수 있습니다. 숫자를 구간으로 나누는 것을 **구간화(binning)** 라고 합니다.

## 구간으로 바꾸면 직선 모델도 잡는다

가족 수와 생존율은 "올라갔다가 떨어지는" 모양이었습니다. 로지스틱 회귀처럼 **직선으로 판단하는 모델**에 가족 수를 숫자 그대로 넣으면 "많을수록 좋다" 또는 "많을수록 나쁘다" 한 방향만 배울 수 있습니다. 구간을 0/1 열로 바꿔 넣으면 어떨까요?

```run
import pandas as pd
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
df["family"] = df["sibsp"] + df["parch"] + 1
df["fam_alone"] = (df["family"] == 1).astype(int)     # traveling alone
df["fam_big"] = (df["family"] >= 5).astype(int)       # big family
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
base = ["pclass", "female", "age"]
for cols in [base, base + ["family"], base + ["fam_alone", "fam_big"]]:
    s = cross_val_score(make_pipeline(StandardScaler(), LogisticRegression()), df[cols], df["survived"], cv=cv).mean()
    print(f"{str(cols[3:]) if len(cols) > 3 else '(base only)':>26}: {s:.3f}")
```

| 넣은 특성 | 교차검증 정확도 |
| --- | --- |
| 기본(등급·성별·나이)만 | 0.784 |
| + 가족 수(숫자 그대로) | 0.792 |
| + 혼자 / 대가족 0·1 열 | **0.807** |

숫자 그대로 넣었을 때보다 "혼자인가", "대가족인가"로 바꿔 넣었을 때 더 좋아졌습니다. 로지스틱 회귀가 "혼자면 −, 대가족이면 −, 그 사이면 +"라는 **꺾인 관계**를 표현할 수 있게 됐기 때문입니다. 트리 모델은 이런 구간을 스스로 찾지만, 직선 모델에는 사람이 구간을 만들어 주는 것이 큰 도움이 됩니다.

### 특성을 만들 때의 순서

1. **아이디어**: 현장 지식이나 데이터 탐색(그룹별 평균)에서 "이게 관련 있지 않을까?"
2. **확인**: 그룹별 평균·그래프로 관계가 보이는지
3. **검증**: 넣기 전·후를 **교차검증 점수**로 비교. 학습 점수만 오르면 소용없음(ml-02-4)
4. **누수 점검**: 예측 시점에 이 값을 정말 알 수 있나

## 정리

| 아이디어 | 예 |
| --- | --- |
| 곱·나눗셈 | 동력 = 회전수 × 토크 |
| 차이 | 온도차 = 공정 온도 − 공기 온도 |
| 합쳐 세기 | 가족 수 = sibsp + parch + 1 |
| 구간화 | 가족 수 → 혼자 / 2~4 / 5+ |

- AI4I에서 새 특성 두 개로 F1이 0.536 → 0.758로 올랐습니다.
- 좋은 특성은 **현장 지식**에서 나옵니다. 예측 시점에 알 수 없는 정보로 만들면 누수입니다.
- 올라갔다 떨어지는 관계는 구간 0/1 열로 바꾸면 직선 모델도 잡습니다(0.792 → 0.807).
- 특성을 넣을지는 넣기 전·후 교차검증 점수로 판단합니다.
