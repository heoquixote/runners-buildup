## 시작하기 전에

[새 특성 만들기](#/l/ml-06-3)에서는 특성을 **늘렸고**, [Pipeline](#/l/ml-06-4)으로 손질과 모델을 한 줄로 묶었습니다. 이번에는 반대로 특성을 **줄이는** 방법, **피처 셀렉션**(특성 선택)을 배웁니다. 그리고 특성 고르기도 Pipeline 안에 넣어야 하는 이유를 실험으로 확인합니다.

## 왜 특성을 골라야 할까

특성이 많을수록 좋을 것 같지만, 그렇지 않을 때가 많습니다.

- **잡음**: 정답과 관계없는 열은 모델을 헷갈리게 해서 과적합을 부릅니다.
- **겹침**: 비슷한 정보를 가진 열이 여러 개면 하나만 있어도 충분합니다.
- **비용**: 현장에서는 센서 하나, 검사 항목 하나가 다 돈입니다. 같은 성능이면 측정할 것이 적은 모델이 낫습니다.
- **설명**: "이 30개를 봤습니다"보다 "이 5개를 봤습니다"가 설명하기 쉽습니다.

사이킷런에 들어 있는 **유방암 진단 데이터**로 연습합니다. 세포 사진에서 잰 크기·모양 수치 30개로 종양이 양성(1)인지 악성(0)인지 맞히는 문제입니다.

```run
from sklearn.datasets import load_breast_cancer

data = load_breast_cancer(as_frame=True)
X, y = data.data, data.target
print(X.shape)
print(list(X.columns[:10]))
print(X[["mean radius", "mean perimeter", "mean area"]].corr().round(3))
```

569명, 특성 30개입니다. 열 이름을 보면 `mean radius`(반지름), `mean perimeter`(둘레), `mean area`(넓이)가 있습니다. 반지름을 알면 둘레와 넓이는 거의 정해지니, 셋의 상관이 0.987~0.998로 **사실상 같은 정보**입니다. 이런 열이 많으면 고를 여지가 큽니다.

## 특성을 고르는 세 가지 방식

::figure{src="content/img/ml/ml06-selection.svg" alt="Filter는 모델 없이 열마다 점수를 매겨 상위만 고르고, Wrapper는 모델을 반복 학습하며 약한 열을 하나씩 빼고, Embedded는 학습하면서 모델이 스스로 골라낸다" caption="특성을 고르는 세 방식. 빠르기와 정확도가 서로 다릅니다."}

| 방식 | 하는 일 | 비유 | 예 |
| --- | --- | --- | --- |
| **Filter** (거르기) | 모델 없이, 열마다 정답과 관련 있는 정도를 점수로 매겨 상위 k개 | 서류 심사 | `SelectKBest` |
| **Wrapper** (감싸기) | 모델을 여러 번 학습하며 약한 열을 하나씩 빼기 | 면접을 여러 번 보며 탈락시키기 | `RFE` |
| **Embedded** (내장) | 모델이 학습하면서 스스로 덜 쓰는 열을 정함 | 일하면서 자연스럽게 역할이 정해짐 | Lasso, 트리 중요도 |

## Filter: 열마다 점수 매겨 상위 k개

`SelectKBest`는 열 하나하나가 정답과 얼마나 관련 있는지 점수(분류에서는 `f_classif`: 두 그룹 평균이 얼마나 다른가)를 매기고 상위 k개만 남깁니다. 표준화 → 고르기 → 로지스틱 회귀를 Pipeline으로 묶어, k를 바꿔 가며 교차검증 정확도를 봅니다. 목록의 숫자를 바꿔 보세요.

```run
from sklearn.datasets import load_breast_cancer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, StratifiedKFold

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
cv = StratifiedKFold(5, shuffle=True, random_state=0)
for k in [1, 3, 10, 20, 30]:   # <- change me
    pipe = make_pipeline(StandardScaler(), SelectKBest(f_classif, k=k), LogisticRegression(max_iter=1000))
    print(f"k={k:>2}: cv accuracy {cross_val_score(pipe, X, y, cv=cv).mean():.3f}")
```

- 특성 **1개**만 써도 0.909, 3개면 0.947입니다. 몇 개의 열이 정보를 대부분 갖고 있습니다.
- **20개**에서 0.984로 가장 높고, 30개 전부 쓰면 0.979로 오히려 조금 낮습니다. 열 10개는 빼도 손해가 없다는 뜻입니다.

어떤 5개를 골랐는지 봅시다.

```run
from sklearn.datasets import load_breast_cancer
from sklearn.feature_selection import SelectKBest, f_classif

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
selector = SelectKBest(f_classif, k=5).fit(X, y)
print(list(X.columns[selector.get_support()]))
```

`mean perimeter`, `worst radius`, `worst perimeter` … 반지름·둘레 계열이 여러 개 뽑혔습니다. Filter는 열을 **하나씩 따로** 보기 때문에, 서로 같은 정보를 가진 열이라도 점수가 높으면 **모두** 뽑습니다. 이것이 Filter의 약점입니다.

## Wrapper: 모델로 직접 시험하며 빼기 (RFE)

`RFE`(재귀적 특성 제거)는 모델을 학습해서 가장 덜 쓰인 열을 하나 빼고, 다시 학습해서 또 빼기를 원하는 개수가 남을 때까지 반복합니다. 열끼리의 **조합**을 보고 판단하니, 겹치는 열은 하나만 남기는 경향이 있습니다.

```run
from sklearn.datasets import load_breast_cancer
from sklearn.preprocessing import StandardScaler
from sklearn.feature_selection import RFE
from sklearn.linear_model import LogisticRegression

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
Xs = StandardScaler().fit_transform(X)
rfe = RFE(LogisticRegression(max_iter=1000), n_features_to_select=5).fit(Xs, y)
print(list(X.columns[rfe.support_]))
```

RFE가 고른 5개는 `radius error`, `worst radius`, `worst texture`(질감), `worst area`, `worst concave points`(오목한 점)입니다. Filter와 달리 **질감** 같은 다른 종류의 정보가 들어왔습니다. 대신 모델을 26번(30 → 5) 학습했으니 Filter보다 훨씬 느립니다. 특성이 수백 개면 시간이 꽤 걸립니다.

## Embedded: 학습하면서 저절로

따로 고르는 단계 없이, 모델이 학습하면서 덜 쓰는 열을 정하는 방식입니다. 이미 두 가지를 배웠습니다.

- [Ridge와 Lasso](#/l/ml-02-6)의 **Lasso**: 쓸모없는 열의 계수를 0으로 만듭니다.
- [부스팅과 피처 중요도](#/l/ml-04-4)의 **트리 중요도**: 중요도가 아주 낮은 열은 빼도 됩니다.

`SelectFromModel(Lasso(...))`처럼 쓰면 이 결과로 열을 골라 다음 모델에 넘길 수도 있습니다.

## 함정: 고르기도 Pipeline 안에서

가장 흔한 실수는 **전체 데이터로 특성을 고른 다음** 교차검증하는 것입니다. 극단적인 실험으로 확인해 봅니다. 정답과 **아무 관계 없는 난수 열 2,000개**와 동전 던지기 정답 100개를 만듭니다. 어떤 방법으로도 맞힐 수 없으니 정확도는 0.5(찍기)가 나와야 정상입니다.

```run
import numpy as np
from sklearn.pipeline import make_pipeline
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

rng = np.random.RandomState(0)
X = rng.normal(size=(100, 2000))   # 2,000 random columns
y = rng.randint(0, 2, 100)         # coin-flip answers

picked = SelectKBest(f_classif, k=10).fit(X, y).transform(X)
print("select on ALL data, then CV:", round(cross_val_score(LogisticRegression(), picked, y, cv=5).mean(), 3))

pipe = make_pipeline(SelectKBest(f_classif, k=10), LogisticRegression())
print("select inside pipeline     :", round(cross_val_score(pipe, X, y, cv=5).mean(), 3))
```

- 전체 데이터로 고른 뒤 교차검증: **0.79**. 맞힐 수 없는 문제인데 79%를 맞힌다고 나옵니다.
- Pipeline 안에서 고르기: **0.50**. 정직한 점수입니다.

난수 열 2,000개 중에는 **우연히** 정답과 비슷하게 움직이는 열이 몇 개쯤 있습니다. 전체 데이터로 고르면 시험 조각의 정답까지 보고 그런 열을 골라 버립니다. 시험 문제를 보고 공부할 범위를 정한 셈입니다. 앞에서 본 **누수**([기준 모델과 누수](#/l/ml-01-5))가 특성 선택에서도 똑같이 생깁니다.

> 특성 선택은 정답(y)을 보는 단계입니다. 그래서 스케일러보다 더 위험합니다. **언제나 Pipeline 안에 넣어서** 교차검증 조각마다 학습용으로만 고르게 합니다.

## 정리

| 방식 | 장점 | 단점 | 도구 |
| --- | --- | --- | --- |
| Filter | 아주 빠름 | 열을 따로 봐서 겹치는 열을 모두 뽑음 | `SelectKBest` |
| Wrapper | 열의 조합을 보고 고름 | 모델을 여러 번 학습해 느림 | `RFE` |
| Embedded | 학습과 동시에, 추가 비용 적음 | 모델 종류에 따라 결과가 다름 | Lasso, 트리 중요도, `SelectFromModel` |

- 30개 중 20개만 써도 정확도가 같거나 더 좋았습니다(0.984 vs 0.979). 특성은 많다고 좋은 게 아닙니다.
- 특성 선택도 정답을 보는 단계라 **반드시 Pipeline 안에서** 합니다(밖에서 고르면 찍기 문제가 0.79로 부풀려짐).
- 현장 지식으로 꼭 필요한 열은 점수가 낮아도 바로 버리지 말고, 왜 낮은지 먼저 확인합니다. 비슷한 열끼리 정보를 나눠 가졌을 수 있습니다. 이 문제는 [다음 레슨](#/l/ml-06-6)에서 다룹니다.
