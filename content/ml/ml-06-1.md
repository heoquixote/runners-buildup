## 모델은 숫자 표만 먹는다

scikit-learn 모델에 넣는 X는 **숫자로만 된 표**여야 합니다. 그런데 실제 데이터에는 이런 것들이 섞여 있습니다.

- 글자: 성별 `male/female`, 객실 `First/Second/Third`, 제품 등급 `L/M/H`
- 빈칸: 나이를 모르는 승객
- 크기가 제각각인 숫자: 나이(0~80)와 운임(0~512), 회전수(1,000단위)와 토크(10단위)

이걸 모델이 먹기 좋게 손질하는 일을 **전처리**, 예측에 도움이 되는 새 열을 만드는 일을 **피처 엔지니어링**이라고 합니다. 요리로 치면 재료 손질입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print(df[["sex", "class", "embarked", "age", "fare"]].head())
print()
print("empty cells per column:")
print(df[["sex", "class", "embarked", "age", "fare"]].isna().sum())
```

## 빈칸 채우기

빈칸이 있으면 대부분의 모델이 에러를 냅니다. 간단한 방법은 중앙값(숫자)이나 가장 많은 값(글자)으로 채우는 것입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print("median age:", df["age"].median())
print("most common port:", df["embarked"].mode()[0])
df["age"] = df["age"].fillna(df["age"].median())
df["embarked"] = df["embarked"].fillna(df["embarked"].mode()[0])
print(df[["age", "embarked"]].isna().sum())
```

> 엄밀하게는 이 중앙값도 **학습용 데이터로만** 계산해야 누수가 없습니다. 아래에서 배울 Pipeline이 이것을 자동으로 처리해 줍니다(`SimpleImputer`).

## 글자는 원-핫 인코딩

`First=1, Second=2, Third=3`처럼 번호를 매기면 모델은 "Third는 First의 3배"처럼 없는 크기 관계를 배울 수 있습니다. 그래서 범주마다 **0/1 열을 하나씩** 만드는 **원-핫 인코딩**을 씁니다. 출석부에 해당 칸에만 동그라미를 치는 것과 같습니다.

::figure{src="content/img/ml/ml06-onehot.svg" alt="class 열의 First, Second, Third 값을 class_First, class_Second, class_Third 세 개의 0/1 열로 바꾼다" caption="글자 열 하나가 범주 수만큼의 0/1 열로 바뀝니다."}

```run
import pandas as pd
from sklearn.preprocessing import OneHotEncoder

df = pd.read_csv("titanic.csv")
print(pd.get_dummies(df[["class"]], dtype=int).head())

enc = OneHotEncoder(handle_unknown="ignore").fit(df[["class"]])
print("categories learned:", enc.categories_)
print(enc.transform(pd.DataFrame({"class": ["Second", "Crew"]})).toarray())
```

- `pd.get_dummies`: 탐색할 때 간편
- `OneHotEncoder`: 학습 때 본 범주를 **기억**해서, 처음 보는 값(`Crew`)이 와도 에러 없이 모두 0으로 처리 → 모델에 쓰기 안전

### 번호 매기기가 괜찮을 때도 있다

모든 글자 열에 원-핫이 정답은 아닙니다. 범주에 **진짜 순서**가 있으면 번호를 매기는 편이 더 자연스럽습니다.

| 열의 성격 | 예 | 방법 |
| --- | --- | --- |
| 순서 없음 | 성별, 탑승 항구, 색깔 | 원-핫 (`OneHotEncoder`) |
| 순서 있음 | 제품 등급 L < M < H, 학년, 만족도 1~5 | 순서대로 번호 (`OrdinalEncoder(categories=[["L", "M", "H"]])`) |
| 범주가 수백 개 | 우편번호, 상품 ID | 원-핫을 하면 열이 너무 많아짐 → 자주 나오는 것만 남기거나 다른 방법 고민 |

AI4I 데이터의 `type`(L·M·H 등급)이 순서 있는 범주의 예입니다.

```run
import pandas as pd
from sklearn.preprocessing import OrdinalEncoder

df = pd.read_csv("ai4i2020.csv")
enc = OrdinalEncoder(categories=[["L", "M", "H"]])
df["type_num"] = enc.fit_transform(df[["type"]]).ravel()
print(df[["type", "type_num"]].drop_duplicates().sort_values("type_num"))
print(df.groupby("type")["failure"].mean().round(4))
```

L → 0, M → 1, H → 2로 순서가 지켜졌습니다. 등급별 고장률도 L이 가장 높습니다.

## 숫자 크기 맞추기: 표준화

키(cm)와 몸무게(kg)로 "비슷한 사람"을 찾는다고 해 봅시다. 키 차이 10은 작은 차이인데 몸무게 차이 10은 큰 차이입니다. 숫자만 보면 둘 다 10이라 공정하지 않습니다.

**표준화**는 각 열을 "평균에서 표준편차 몇 개만큼 떨어졌나"로 바꿔 모든 열을 같은 잣대로 만듭니다. 결과는 평균 0, 표준편차 1 근처가 됩니다.

::figure{src="content/img/ml/ml06-scale.svg" alt="표준화 전에는 운임이 0~500, 나이가 0~80으로 범위가 다르고, 표준화 후에는 둘 다 0을 중심으로 비슷한 범위에 놓인다" caption="표준화 전에는 운임 숫자가 훨씬 커서 거리 계산을 독차지하지만, 표준화 후에는 두 열이 같은 잣대에 놓입니다."}

```run
import pandas as pd
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("ai4i2020.csv")
cols = ["rpm", "torque", "tool_wear"]
print("before:")
print(df[cols].describe().loc[["mean", "std"]].round(1))
scaled = StandardScaler().fit_transform(df[cols])
print("after: mean", scaled.mean(axis=0).round(3), " std", scaled.std(axis=0).round(3))
```

거리나 계수를 쓰는 모델(KNN, 로지스틱 회귀, 신경망)에는 표준화가 중요하고, 트리 모델에는 필요 없습니다.

주의할 점 두 가지:

- **원-핫으로 만든 0/1 열은 표준화하지 않습니다.** 이미 같은 잣대(0 또는 1)이고, 표준화하면 "여성이면 1"처럼 읽기 쉬운 의미가 사라집니다. 그래서 아래 Pipeline에서도 표준화는 숫자 열에만 겁니다.
- **아주 튀는 값(이상치)이 많으면** 평균·표준편차가 그 값에 끌려갑니다. 이럴 때는 중앙값 기준으로 맞추는 `RobustScaler`를 고려합니다.

## 새 특성 만들기: 피처 엔지니어링

데이터에 없는 열을 **아이디어로** 만들어 넣으면 모델이 훨씬 쉽게 배우기도 합니다. 이렇게 만든 열을 **파생변수**라고 합니다. 자주 쓰는 아이디어는 네 가지입니다.

| 종류 | 예 |
| --- | --- |
| 곱하기·나누기 (조합) | 회전수 × 토크 = 동력, 운임 ÷ 가족 수 = 1인당 운임 |
| 차이 | 공정 온도 − 공기 온도 |
| 날짜에서 뽑기 | 요일, 월, 주말 여부 |
| 묶어서 세기 | 가족 수 = 형제자매 + 부모자식 + 1 |

설비 데이터에서 회전수 × 토크는 물리적으로 **동력(힘)**에 해당합니다. 공정 온도 − 공기 온도는 **열이 잘 빠지는지**를 나타냅니다. 이 두 열을 만들어 넣어 봅니다.

```run
import pandas as pd
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.tree import DecisionTreeClassifier

df = pd.read_csv("ai4i2020.csv")
df["power"] = df["rpm"] * df["torque"] * 2 * 3.1416 / 60     # watts
df["temp_gap"] = df["process_temp"] - df["air_temp"]
y = df["failure"]
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
base = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
for cols in [base, base + ["power", "temp_gap"]]:
    f1 = cross_val_score(DecisionTreeClassifier(max_depth=5, random_state=0), df[cols], y, cv=cv, scoring="f1").mean()
    print(len(cols), "features -> F1", round(f1, 3))
```

같은 모델인데 새 특성 두 개만으로 F1이 크게 오릅니다. 좋은 특성 하나가 복잡한 모델보다 효과가 클 때가 많습니다. **현장 지식**이 머신러닝에서 중요한 이유입니다.

> 단, **예측하는 시점에 알 수 없는 정보**로 특성을 만들면 안 됩니다. 예를 들어 "고장 후 수리 시간"은 고장을 예측하는 데 쓸 수 없습니다(누수).

## Pipeline: 손질부터 요리까지 한 줄로

전처리 단계를 따로따로 하면 실수하기 쉽습니다. 특히 시험용 데이터로 기준을 다시 fit 하는 실수가 흔합니다. `ColumnTransformer`로 열마다 할 일을 정하고, `make_pipeline`으로 모델까지 이어 붙이면 **한 덩어리**로 다룰 수 있습니다.

::figure{src="content/img/ml/ml06-pipeline.svg" alt="숫자 열은 빈칸을 중앙값으로 채우고 표준화, 글자 열은 빈칸을 최빈값으로 채우고 원-핫, 두 갈래가 합쳐져 로지스틱 회귀로 들어간다" caption="ColumnTransformer가 열 종류마다 다른 손질을 하고, Pipeline이 그 뒤에 모델을 이어 붙입니다."}

```run
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

df = pd.read_csv("titanic.csv")
num_cols = ["age", "sibsp", "parch", "fare"]
cat_cols = ["sex", "class", "embarked"]
pre = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), num_cols),
    ("cat", make_pipeline(SimpleImputer(strategy="most_frequent"), OneHotEncoder(handle_unknown="ignore")), cat_cols),
])
pipe = make_pipeline(pre, LogisticRegression())
scores = cross_val_score(pipe, df[num_cols + cat_cols], df["survived"], cv=5)
print("cv accuracy:", scores.round(3), "mean", round(scores.mean(), 3))
```

- 숫자 열: 빈칸을 중앙값으로 → 표준화
- 글자 열: 빈칸을 최빈값으로 → 원-핫
- 그 뒤 로지스틱 회귀

파이프라인째 교차검증하면 **조각마다 전처리 기준도 학습용 조각으로만 새로 계산**되어 누수가 없습니다.

## 정리

| 문제 | 해결 | 도구 |
| --- | --- | --- |
| 빈칸 | 중앙값 / 최빈값으로 채우기 | `fillna`, `SimpleImputer` |
| 글자 범주 | 원-핫 인코딩 | `get_dummies`, `OneHotEncoder` |
| 숫자 크기 차이 | 표준화 | `StandardScaler` |
| 좋은 정보가 숨어 있음 | 새 특성 만들기 | 현장 지식 + pandas |
| 단계가 많아 실수 | 한 줄로 묶기 | `ColumnTransformer`, `make_pipeline` |
