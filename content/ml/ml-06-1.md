## 모델이 먹을 수 있는 모양으로

scikit-learn 모델은 **숫자 2차원 배열**을 받습니다. 그래서 실무 데이터는 보통 두 가지 손질이 필요합니다.

- **스케일링**: 온도(200℃대)와 전류밀도(3 A/dm²)처럼 범위가 다르면 거리 · 계수 기반 모델(KNN, 로지스틱, SVM, 신경망)이 큰 값에 끌려갑니다. `StandardScaler`는 (x − 평균) / 표준편차.
- **인코딩**: 라인 A/B/C 같은 문자열 범주는 `OneHotEncoder`로 0/1 열 여러 개로 펼칩니다. A=0, B=1, C=2로 바꾸면 "C가 A보다 크다"는 없는 순서가 생깁니다.

트리 계열(결정트리, 랜덤포레스트)은 값의 순서만 쓰므로 스케일링이 필요 없습니다.

## 전처리도 fit 한다

스케일러의 평균 · 표준편차, 인코더의 범주 목록은 데이터에서 **학습한 값**입니다. 반드시 학습 데이터로만 `fit`하고, 테스트에는 `transform`만 합니다.

```run
import numpy as np
from sklearn.preprocessing import StandardScaler

X_train = np.array([[200.0, 3.0], [204.0, 3.2], [208.0, 2.8], [212.0, 3.4]])
X_test = np.array([[216.0, 3.1]])
sc = StandardScaler().fit(X_train)
print("learned mean", sc.mean_, " std", sc.scale_.round(3))
print("train ->", sc.transform(X_train).round(2).tolist())
print("test  ->", sc.transform(X_test).round(2).tolist(), "(not 0: uses train stats)")
```

## 범주 열은 원-핫

```run
import pandas as pd
from sklearn.preprocessing import OneHotEncoder

train = pd.DataFrame({"line": ["A", "B", "C", "A"]})
enc = OneHotEncoder(handle_unknown="ignore").fit(train)
print(enc.categories_)
print(enc.transform(pd.DataFrame({"line": ["B", "D"]})).toarray())
print(pd.get_dummies(train, columns=["line"], dtype=int))
```

`handle_unknown="ignore"`는 학습 때 없던 범주(D)를 모두 0으로 처리해 운영 중 에러를 막아 줍니다. `pd.get_dummies`는 탐색에는 편하지만 학습 때의 범주를 기억하지 않아 모델 운영에는 인코더가 안전합니다.

## ColumnTransformer + Pipeline

열마다 다른 전처리를 `ColumnTransformer`로 묶고, 모델과 `make_pipeline`으로 잇습니다. 이 파이프라인 하나가 `fit` · `predict` · `cross_val_score`를 모두 받습니다.

```run
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

i = np.arange(120)
df = pd.DataFrame({
    "temp": 52 + 4 * np.sin(i * 0.37) + 1.5 * np.cos(i * 1.91),
    "current": 3.0 + 0.6 * np.cos(i * 0.53) + 0.25 * np.sin(i * 2.71),
    "line": np.array(["A", "B", "C"])[i % 3],
})
score = (df["temp"] - 52) / 4 + (df["current"] - 3) / 0.6 + 0.6 * (df["line"] == "C") + 0.7 * np.sin(i * 3.33)
y = (score > 1).astype(int)

pre = ColumnTransformer([
    ("num", StandardScaler(), ["temp", "current"]),
    ("cat", OneHotEncoder(handle_unknown="ignore"), ["line"]),
])
pipe = make_pipeline(pre, LogisticRegression())
print("cv acc with line   ", round(cross_val_score(pipe, df, y, cv=5).mean(), 3))
print("cv acc numeric only", round(cross_val_score(make_pipeline(StandardScaler(), LogisticRegression()), df[["temp", "current"]], y, cv=5).mean(), 3))
```

> 파이프라인째 교차검증하면 폴드마다 스케일러가 학습 폴드로만 다시 fit 됩니다. 전체 데이터로 스케일링한 다음 교차검증하면 검증 폴드 정보가 새어 들어가(누수) 점수가 부풀려집니다.

## 피처 엔지니어링 아이디어

- 비율 · 차이: 불량 수 / 생산량, 설정 온도 − 실제 온도
- 날짜에서 요일 · 시간대 · 교대조 꺼내기 (`dt.dayofweek`)
- 구간화: 나이 → 연령대 (`pd.cut`)
- 로그 변환: 금액처럼 오른쪽 꼬리가 긴 값 (`np.log1p`)

좋은 피처 하나가 복잡한 모델보다 효과가 큰 경우가 많습니다. 다만 **예측 시점에 알 수 없는 정보**(예: 검사 후에야 나오는 값)를 피처로 쓰면 누수입니다.
