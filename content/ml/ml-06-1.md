## 모델은 숫자 표만 먹는다

scikit-learn 모델에 넣는 X는 **숫자로만 된 표**여야 합니다. 그런데 실제 데이터에는 이런 것들이 섞여 있습니다.

- 글자: 성별 `male/female`, 객실 `First/Second/Third`, 제품 등급 `L/M/H`
- 빈칸: 나이를 모르는 승객
- 크기가 제각각인 숫자: 나이(0~80)와 운임(0~512), 회전수(1,000단위)와 토크(10단위)

이걸 모델이 먹기 좋게 손질하는 일을 **전처리**, 예측에 도움이 되는 새 열을 만드는 일을 **피처 엔지니어링**이라고 합니다. 요리로 치면 재료 손질입니다.

```run
import pandas as pd

df = pd.read_csv("titanic.csv")
print(df[["sex", "class", "embarked", "age", "fare"]].head())
print()
print("empty cells per column:")
print(df[["sex", "class", "embarked", "age", "fare"]].isna().sum())
```

## 빈칸 채우기: 이번에는 도구로

[ML 워크플로와 데이터 준비](#/l/ml-01-0)에서 결측치를 `isna().sum()`으로 세고, 중앙값(숫자)이나 최빈값(글자)으로 `fillna` 하는 법을 배웠습니다. 그때 "중앙값은 **학습용 데이터로만** 계산해야 한다"고 했습니다. 시험용 승객의 나이까지 섞어 중앙값을 내면, 시험지 정보를 미리 본 셈(누수)이기 때문입니다.

이 규칙을 매번 손으로 지키기는 번거롭습니다. scikit-learn의 `SimpleImputer`는 **학습용으로 기준을 배우고(fit), 그 기준으로 어디든 채우는(transform)** 도구입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.impute import SimpleImputer

df = pd.read_csv("titanic.csv")
train, test = train_test_split(df, test_size=0.25, random_state=0)

imp = SimpleImputer(strategy="median").fit(train[["age"]])   # learn the median from train only
print("median learned from train:", imp.statistics_)
filled = imp.transform(test[["age"]])
print("empty ages in test before:", int(test["age"].isna().sum()), " after:", int(pd.isna(filled).sum()))
```

- `strategy="median"`: 중앙값으로, `"mean"`: 평균으로, `"most_frequent"`: 최빈값으로 채웁니다(글자 열도 가능).
- 학습용에서 배운 중앙값(`statistics_`)을 시험용에도 **그대로** 씁니다. 새 승객이 와도 같은 기준을 쓰는 것과 같습니다.

## 글자를 숫자로: 이번에는 도구로

[ML 워크플로와 데이터 준비](#/l/ml-01-0)에서 배운 인코딩을 다시 정리하면 이렇습니다.

- 두 종류(성별): 0/1로
- 여러 종류, **순서 있음**(제품 등급 L<M<H): 순서대로 번호
- 여러 종류, **순서 없음**(탑승 항구): 원-핫. 번호를 매기면 "Q는 C의 두 배" 같은 가짜 크기가 생기기 때문

객실 등급(`class`: First/Second/Third)은 순서가 있어 번호(1, 2, 3)를 써도 되지만, "1등실과 2등실의 차이 = 2등실과 3등실의 차이"라고 장담할 수 없을 때는 원-핫으로 바꾸기도 합니다.

::figure{src="content/img/ml/ml06-onehot.svg" alt="class 열의 First, Second, Third 값을 class_First, class_Second, class_Third 세 개의 0/1 열로 바꾼다" caption="글자 열 하나가 범주 수만큼의 0/1 열로 바뀝니다."}

```run
import pandas as pd
from sklearn.preprocessing import OneHotEncoder

df = pd.read_csv("titanic.csv")
print(pd.get_dummies(df[["class"]], dtype=int).head())

enc = OneHotEncoder(handle_unknown="ignore").fit(df[["class"]])
print("categories learned:", enc.categories_)
print(enc.transform(pd.DataFrame({"class": ["Second", "Crew"]})).toarray())
```

- `pd.get_dummies`: [ML 워크플로와 데이터 준비](#/l/ml-01-0)에서 쓴 방법. 탐색할 때 간편하지만, 학습용과 시험용에 따로 쓰면 범주가 다를 때 열 개수가 달라질 수 있습니다.
- `OneHotEncoder`: 학습 때 본 범주를 **기억**해서, 처음 보는 값(`Crew`)이 와도 에러 없이 모두 0으로 처리 → 모델에 쓰기 안전

### 번호 매기기가 괜찮을 때도 있다

모든 글자 열에 원-핫이 정답은 아닙니다. 범주에 **진짜 순서**가 있으면 번호를 매기는 편이 더 자연스럽습니다.

| 열의 성격 | 예 | 방법 |
| --- | --- | --- |
| 순서 없음 | 성별, 탑승 항구, 색깔 | 원-핫 (`OneHotEncoder`) |
| 순서 있음 | 제품 등급 L < M < H, 학년, 만족도 1~5 | 순서대로 번호 (`OrdinalEncoder(categories=[["L", "M", "H"]])`) |
| 범주가 수백 개 | 우편번호, 상품 ID | 원-핫을 하면 열이 너무 많아짐 → 자주 나오는 것만 남기거나 타깃 인코딩(아래) |

AI4I 데이터의 `type`(L·M·H 등급)이 순서 있는 범주의 예입니다.

```run
import pandas as pd
from sklearn.preprocessing import OrdinalEncoder

df = pd.read_csv("ai4i2020.csv")
enc = OrdinalEncoder(categories=[["L", "M", "H"]])
df["type_num"] = enc.fit_transform(df[["type"]]).ravel()
print(df[["type", "type_num"]].drop_duplicates().sort_values("type_num"))
print(df.groupby("type")["failure"].mean().round(4))
```

L → 0, M → 1, H → 2로 순서가 지켜졌습니다. 등급별 고장률도 L이 가장 높습니다.

### 범주가 아주 많을 때: 타깃 인코딩

위 표의 마지막 줄처럼 범주가 수백 개(설비 번호, 협력사, 상품 코드)면 원-핫은 열이 수백 개로 불어납니다. 이때 쓰는 방법이 **타깃 인코딩**입니다. 각 범주를 **그 범주의 정답 평균**으로 바꿉니다. 예를 들어 타이타닉의 갑판(`deck`) B는 B 갑판 승객의 생존율 0.745로 바꾸는 식입니다. 열이 하나로 끝나고, 숫자 자체가 "생존과 얼마나 관련 있나"를 담고 있습니다.

하지만 정답(y)으로 특성을 만드는 것이라 **누수 위험**이 큽니다. 자기 정답이 자기 특성에 섞이니까요. 특히 G 갑판처럼 4명뿐인 범주는 평균이 그 4명의 정답 그 자체입니다. 사이킷런의 `TargetEncoder`는 이 두 문제를 이렇게 막습니다.

- **교차 적합**: 데이터를 조각으로 나눠, 각 행은 **자기가 빠진 다른 조각**의 평균으로 바꿉니다.
- **작은 범주는 전체 평균 쪽으로 당기기**: 몇 명뿐인 범주는 전체 생존율에 가깝게 조정합니다.

```run
import pandas as pd
from sklearn.preprocessing import TargetEncoder

df = pd.read_csv("titanic.csv")
deck = df[["deck"]].fillna("none")
print(df.assign(deck=deck["deck"]).groupby("deck")["survived"].agg(["mean", "size"]).round(3))

enc = TargetEncoder(random_state=0)
encoded = enc.fit_transform(deck, df["survived"])
print(pd.DataFrame({"deck": deck["deck"], "encoded": encoded[:, 0]}).head(4).round(3))
print("learned:", {c: round(float(v), 3) for c, v in zip(enc.categories_[0], enc.encodings_[0])})
```

- 1번 행과 3번 행은 둘 다 C 갑판인데 0.540과 0.648로 **다르게** 바뀌었습니다. 교차 적합 때문입니다. 각 행은 자기가 속하지 않은 조각들의 평균을 받으므로, 자기 정답을 보지 않습니다.
- G 갑판(4명)의 실제 생존율은 0.500인데 학습된 값은 0.476으로 전체 평균(0.384) 쪽으로 조금 당겨졌습니다. 반면 47명인 B 갑판은 0.745 → 0.739로 거의 그대로입니다.
- 새 데이터(시험용)에는 `transform`으로 전체 학습용에서 배운 값(`learned`)을 씁니다.

> 타깃 인코딩을 `groupby().mean()`으로 직접 만들어 전체 데이터에 붙이면 거의 확실히 누수가 생깁니다. 반드시 `TargetEncoder`를 **Pipeline 안에서** 쓰세요.

## 정리

- `SimpleImputer`: 학습용에서 기준(중앙값 등)을 배우고(fit), 어디든 같은 기준으로 채웁니다(transform).
- `OneHotEncoder`: 학습 때 본 범주를 기억해, 처음 보는 값이 와도 안전합니다.
- `OrdinalEncoder`: 순서 있는 범주를 순서대로 번호 매깁니다.
- fit은 학습용에만, transform은 어디에나. 이 규칙이 누수를 막습니다.
- 범주가 아주 많으면 `TargetEncoder`(범주별 정답 평균, 교차 적합으로 누수 방지)를 Pipeline 안에서 씁니다.
