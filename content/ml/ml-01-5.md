## 시작하기 전에

앞 레슨에서 학습용·시험용으로 나눴습니다. 모델을 만들기 전 마지막 준비 두 가지가 남았습니다. 하나는 "아무 생각 없이 찍어도 나오는 점수"를 먼저 아는 것, 다른 하나는 시험지를 미리 보는 실수(**누수**)를 피하는 것입니다.

## 기준 모델: 넘어야 할 최소선

"아무 생각 없이 찍어도 이 정도는 나온다"는 점수를 먼저 알아야 내 모델이 잘한 건지 알 수 있습니다. 가장 많은 답만 계속 말하는 모델을 **기준 모델(baseline)**이라고 합니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyClassifier
from sklearn.metrics import recall_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]].values
y = df["failure"].values
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
base = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
pred = base.predict(X_test)
print("accuracy:", round(base.score(X_test, y_test), 3))
print("failures caught (recall):", recall_score(y_test, pred))
```

전부 "정상"이라고만 답했는데 정확도가 96.6%입니다. 하지만 고장은 **하나도** 못 잡았습니다(재현율 0). 고장이 드문 데이터에서 "정확도 97%"는 자랑이 아닐 수 있다는 뜻입니다. 이런 지표는 평가지표 코스(ml-03)에서 자세히 다룹니다.

## 누수: 시험지를 미리 본 것

**누수(leakage)**는 **실제로 예측하는 순간에는 알 수 없는 정보**가 학습에 몰래 섞여 들어가는 것입니다. 시험 전에 시험지를 슬쩍 본 것과 같아서 점수는 아주 좋게 나오지만, 실제로 쓰면 그대로 무너집니다. 과적합은 "너무 외운" 문제라면, 누수는 **평가 자체가 무효**가 되는 더 심각한 문제입니다.

대표적인 누수는 세 가지입니다.

1. **정답을 다르게 쓴 열**: 정답과 사실상 같은 열이 특성에 들어간 경우. 예: 생존 예측에 "구조 완료 여부"
2. **미래 정보**: 예측 시점 이후에야 생기는 정보. 예: 고장 예측에 "수리 완료 날짜"
3. **전처리 누수**: 평균·표준편차 같은 기준을 시험용까지 포함한 전체 데이터로 계산한 경우

타이타닉 데이터에는 1번의 좋은 예가 들어 있습니다. `alive` 열은 `survived`를 yes/no로 다시 쓴 열입니다. 이걸 특성으로 넣으면 어떻게 되는지 봅시다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["alive_yes"] = (df["alive"] == "yes").astype(int)
y = df["survived"]
for cols in [["pclass", "female"], ["pclass", "female", "alive_yes"]]:
    X_train, X_test, y_train, y_test = train_test_split(df[cols], y, test_size=0.25, random_state=0, stratify=y)
    acc = DecisionTreeClassifier(max_depth=3, random_state=0).fit(X_train, y_train).score(X_test, y_test)
    print(cols, "-> test accuracy", round(acc, 3))
```

`alive_yes`를 넣자 정확도가 1.0(100%)이 됩니다. 모델이 똑똑해진 게 아니라 **정답을 그대로 읽은** 것입니다. 실제로 새 승객의 생존을 예측하는 순간에는 `alive` 값을 알 수 없으니 이 모델은 쓸모가 없습니다.

> 점수가 갑자기 "너무 좋게" 나오면 먼저 누수를 의심하세요. 열 이름에 `final`, `result`, `completed`, `after`, `status` 같은 말이 들어 있으면 "이 값은 사건이 일어난 뒤에 채워지는가?"를 꼭 확인합니다.

3번 전처리 누수의 흔한 실수는 "평균으로 숫자 크기를 맞추는" 표준화를 **전체 데이터로** 하는 것입니다. 평균·표준편차 같은 기준은 **학습용으로만** 정하고(fit), 시험용에는 그 기준을 적용(transform)만 해야 합니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("titanic.csv")
X = df[["fare"]].values
X_train, X_test = train_test_split(X, test_size=0.25, random_state=0)
scaler = StandardScaler().fit(X_train)          # learn mean/std from train only
print("mean learned from train:", scaler.mean_.round(2))
print("test after transform, mean:", scaler.transform(X_test).mean().round(3), "(not exactly 0 - that's normal)")
```

시험용의 평균이 딱 0이 아닌 것이 정상입니다. 실제 서비스에서 새 데이터가 들어올 때도 학습 때 정한 기준을 그대로 쓰기 때문입니다.

## 정리: 머신러닝 작업 순서

1. **문제 정하기**: 무엇을 예측하나 (생존? 고장?)
2. **데이터 살펴보기**: 표 모양, 빈 값, 정답 비율
3. **특성 점검**: 예측하는 순간에 알 수 있는 정보인가? (누수 확인)
4. **나누기**: 학습용 / (검증용) / 시험용 (드문 정답이면 `stratify=y`)
5. **기준 모델** 점수 확인
6. **학습**: 학습용 데이터로만 (전처리 기준도 학습용으로)
7. **평가**: 시험용으로 딱 한 번
