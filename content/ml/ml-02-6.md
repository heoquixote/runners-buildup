## 시작하기 전에

[특성을 여러 개 쓰면](#/l/ml-02-4)에서 특성을 늘리면 예측이 좋아질 수 있다는 것을 봤습니다. 그런데 특성을 **너무 많이** 넣으면 어떻게 될까요? [깊어질수록 외운다](#/l/ml-04-2)에서 본 것처럼, 모델이 학습 데이터를 외워 버립니다. 이번 레슨에서는 선형회귀가 외우지 못하게 **계수에 벌점을 주는** 두 방법, **Ridge**와 **Lasso**를 배웁니다.

## 특성이 많으면 선형회귀도 외운다

사이킷런에 들어 있는 **당뇨 데이터**를 씁니다. 환자 442명의 나이, 성별, 체질량지수(bmi), 혈압(bp), 혈액검사 수치 6개(s1~s6)로 **1년 뒤 당뇨가 얼마나 진행됐는지**(숫자)를 예측하는 회귀 문제입니다. 열은 10개뿐이라, 일부러 열을 늘려 보겠습니다. `PolynomialFeatures(2)`는 열끼리 곱한 값(나이 × bmi 같은)과 제곱을 모두 만들어 **10개 열을 65개로** 늘립니다.

```run
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LinearRegression

X, y = load_diabetes(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)
model = make_pipeline(PolynomialFeatures(2, include_bias=False), StandardScaler(), LinearRegression())
model.fit(X_train, y_train)
print("features:", model[0].n_output_features_)
print("train R^2:", round(model.score(X_train, y_train), 3))
print("test  R^2:", round(model.score(X_test, y_test), 3))
```

학습 R²는 0.657인데 시험 R²는 **0.225**로 뚝 떨어집니다. 학습 데이터는 309명뿐인데 맞출 계수가 65개나 되니, 모델이 309명의 **우연한 특징까지 외워 버린** 것입니다. 이때 계수들을 보면 서로 크게 +와 −로 튀어 있는 경우가 많습니다. 우연을 맞추려고 계수를 크게 키웠기 때문입니다.

## 벌점(규제): 계수가 커지면 세금을 매긴다

해결책은 간단합니다. 모델이 "오차를 줄이는 것"만 신경 쓰지 말고, **계수를 크게 쓰는 것에도 벌점**을 받게 하는 겁니다.

`줄이려는 값 = 오차 + alpha × (계수 크기)`

용돈 비유로 보면, 오차를 줄이려고 계수를 마음껏 키우던 모델에게 "계수를 크게 쓸 때마다 세금을 내라"고 하는 셈입니다. 그러면 모델은 **정말 효과가 큰 특성에만 계수를 쓰고**, 우연을 맞추려는 자잘한 계수는 줄입니다. 이렇게 모델이 너무 복잡해지지 않게 막는 것을 **규제(regularization)** 라고 합니다. `alpha`는 세율입니다.

- `alpha`가 0이면: 세금 없음 = 보통 선형회귀
- `alpha`가 크면: 세금이 비싸서 계수가 0 쪽으로 쭉 줄어듦 (너무 크면 아무것도 못 배움 = 과소적합)

세금을 매기는 방식이 두 가지라서 이름이 다릅니다.

| | Ridge | Lasso |
| --- | --- | --- |
| 벌점 | 계수의 **제곱** 합 | 계수의 **절댓값** 합 |
| 결과 | 모든 계수를 골고루 **조금씩 줄인다** | 쓸모없는 계수를 **딱 0으로** 만든다 |
| 비유 | 모든 직원 월급을 조금씩 깎기 | 꼭 필요 없는 직원은 내보내기 |

::figure{src="content/img/ml/ml02-ridge-lasso.svg" alt="alpha가 커질수록 Ridge의 계수 막대는 모두 조금씩 짧아지고, Lasso의 계수 막대는 작은 것부터 0이 되어 사라진다" caption="같은 계수 다섯 개에 벌점을 키울 때. Ridge는 모두 줄이고, Lasso는 작은 계수부터 0으로 만듭니다."}

> 벌점은 계수 **크기**에 매기므로, 열마다 단위가 다르면 불공평해집니다(단위가 작은 열은 계수가 크게 나오니까요). 그래서 Ridge·Lasso 앞에는 꼭 **표준화**를 둡니다.

## 직접 해보기: Ridge의 alpha 바꾸기

같은 65개 특성에 `Ridge`를 써 봅니다. `alpha` 목록의 값을 바꿔 가며 학습·시험 R²가 어떻게 변하는지 보세요.

```run
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import Ridge

X, y = load_diabetes(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)
for alpha in [0.01, 1, 10, 100, 1000]:   # <- change me
    model = make_pipeline(PolynomialFeatures(2, include_bias=False), StandardScaler(), Ridge(alpha=alpha))
    model.fit(X_train, y_train)
    print(f"alpha {alpha:>7}: train {model.score(X_train, y_train):.3f} / test {model.score(X_test, y_test):.3f}")
```

| alpha | 학습 R² | 시험 R² | 상태 |
| --- | --- | --- | --- |
| 0.01 | 0.656 | 0.228 | 거의 보통 선형회귀, 외운 상태 |
| 100 | 0.606 | **0.376** | 학습 점수를 조금 내주고 시험 점수가 크게 오름 |
| 1000 | 0.419 | 0.304 | 세금이 너무 비싸서 덜 배움 (과소적합) |

학습 점수는 alpha가 커질수록 계속 떨어지지만, 시험 점수는 **올라갔다가 다시 떨어집니다.** [검증 곡선](#/l/ml-05-3)에서 본 것과 같은 모양입니다. 그래서 alpha도 `GridSearchCV`나 `RidgeCV`로 교차검증해서 고릅니다.

## Lasso: 쓸모없는 특성은 0으로

Lasso는 계수를 줄이다가 **딱 0으로** 만들어 버립니다. 계수가 0인 특성은 예측에 전혀 쓰이지 않으니, Lasso는 **특성을 저절로 골라 주는** 효과가 있습니다. 원래 10개 열에 Lasso를 써서, alpha를 키울 때 몇 개가 살아남는지 봅니다.

```run
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Lasso

X, y = load_diabetes(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)
for alpha in [0.1, 1, 5, 10, 20]:
    model = make_pipeline(StandardScaler(), Lasso(alpha=alpha)).fit(X_train, y_train)
    kept = list(X.columns[model[-1].coef_ != 0])
    print(f"alpha {alpha:>4}: test {model.score(X_test, y_test):.3f}, {len(kept)} kept {kept}")
```

- alpha 0.1: 10개 모두 살아 있고 시험 R² 0.389
- alpha 5: **5개**(sex, bmi, bp, s3, s5)만 남았는데 시험 R²는 0.373으로 거의 그대로
- alpha 20: bmi와 s5 **두 개**만 남고 0.309

절반의 특성을 버려도 성능이 거의 같다는 것은, 버린 특성들이 **다른 특성과 정보가 겹치거나 쓸모가 적었다**는 뜻입니다. 특성이 적으면 설명하기도 쉽고, 측정해야 할 항목도 줄어듭니다. 마지막에 남은 bmi(비만도)와 s5(혈중 지방 관련 수치)가 당뇨 진행과 가장 관련이 큰 정보라는 것도 알 수 있습니다.

> 특성을 고르는 다른 방법들은 [쓸 특성만 고르기](#/l/ml-06-5)에서, s1·s2처럼 서로 겹치는 열이 계수를 흔드는 문제는 [다중공선성과 VIF](#/l/ml-06-6)에서 이어서 봅니다.

## 언제 무엇을 쓸까

| 상황 | 추천 |
| --- | --- |
| 특성이 많고 대부분 조금씩 쓸모 있을 때 | Ridge |
| 쓸모없는 특성이 많이 섞여 있어 골라내고 싶을 때 | Lasso |
| 둘 다 애매할 때 | ElasticNet (Ridge + Lasso 섞기) |
| 분류 문제 (로지스틱 회귀) | `LogisticRegression(C=...)`도 기본으로 Ridge식 벌점이 들어 있음. **C는 alpha의 반대**(작을수록 벌점이 셈) |

## 정리

- 특성이 많고 데이터가 적으면 선형회귀도 외웁니다(65개 특성: 학습 0.657 / 시험 0.225).
- **규제**: 오차 + alpha × 계수 크기를 줄이게 해서 계수가 함부로 커지지 못하게 합니다.
- **Ridge**는 모든 계수를 조금씩 줄이고(alpha 100에서 시험 0.376), **Lasso**는 쓸모없는 계수를 0으로 만들어 특성을 골라 줍니다(10개 → 5개, 성능 거의 그대로).
- 벌점은 계수 크기에 매기므로 **표준화가 먼저**, alpha는 **교차검증으로** 고릅니다.
