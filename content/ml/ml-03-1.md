## 정확도만으로는 부족하다

**정확도(accuracy)**는 "전체 중 맞힌 비율"입니다. 이해하기 쉽지만 함정이 있습니다. 앞 레슨에서 본 것처럼 고장이 3%뿐인 설비 데이터에서는 "전부 정상"이라고만 해도 정확도가 97%입니다.

그래서 "**무엇을** 맞히고 **무엇을** 틀렸는지" 나눠서 봐야 합니다. 그 출발점이 혼동행렬입니다.

## 혼동행렬: 맞힘과 틀림을 네 칸으로

화재경보기를 떠올려 봅시다.

::figure{src="content/img/ml/ml03-confusion.svg" alt="실제와 예측으로 나눈 2×2 표: TP 제대로 울림, FN 놓침, FP 헛경보, TN 조용히 잘 있음" caption="가로는 모델의 예측, 세로는 실제입니다. 초록은 맞힘, 빨강은 놓침, 노랑은 헛경보입니다."}

- T(True)/F(False): 예측이 맞았나 틀렸나
- P(Positive)/N(Negative): 모델이 1이라고 했나 0이라고 했나

타이타닉 생존 예측 모델로 네 칸을 세어 봅니다. 여기서 1은 "생존"입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)
pred = model.predict(X_test)
tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()
print(confusion_matrix(y_test, pred))
print(f"TN={tn} FP={fp} FN={fn} TP={tp}")
print("accuracy:", round((tp + tn) / (tp + tn + fp + fn), 3))
```

`confusion_matrix`의 결과는 행이 실제, 열이 예측이고, `.ravel()`로 펴면 TN, FP, FN, TP 순서입니다.

## 정밀도와 재현율

네 칸으로 두 가지 중요한 점수를 만듭니다.

- **정밀도(precision)** = TP / (TP + FP): "1이라고 한 것 중 진짜 1의 비율". 경보가 울렸을 때 진짜 불일 확률. **헛경보가 적을수록** 높음
- **재현율(recall)** = TP / (TP + FN): "진짜 1 중에서 잡아낸 비율". 실제 불 중 경보가 울린 비율. **놓친 게 적을수록** 높음
- **F1** = 둘의 조화평균. 둘 다 적당히 높아야 높음

::figure{src="content/img/ml/ml03-precision-recall.svg" alt="정밀도는 예측 1 열(TP와 FP) 안에서, 재현율은 실제 1 행(TP와 FN) 안에서 비율을 잰다" caption="두 점수 모두 분자는 TP입니다. 정밀도는 '울린 것' 칸 안에서, 재현율은 '진짜 불' 칸 안에서 셉니다."}

어느 쪽이 더 중요한지는 상황이 정합니다.

| 상황 | 더 아픈 실수 | 중요한 지표 |
| --- | --- | --- |
| 설비 고장 탐지, 암 검진 | 놓침(FN) | 재현율 |
| 스팸 필터 (정상 메일을 스팸함으로) | 헛경보(FP) | 정밀도 |

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, f1_score, accuracy_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
pred = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict(X_test)
print("accuracy :", round(accuracy_score(y_test, pred), 3))
print("precision:", round(precision_score(y_test, pred), 3))
print("recall   :", round(recall_score(y_test, pred), 3))
print("f1       :", round(f1_score(y_test, pred), 3))
```

설비 데이터에서 정확도는 97%로 높지만 재현율은 약 0.28입니다. 실제 고장 10건 중 7건 이상을 놓친다는 뜻이라, 현장에서 쓰기에는 부족한 모델입니다.

## 임계값: 경보 감도 조절

로지스틱 회귀는 확률을 내고, 기본으로 0.5 이상이면 1로 판정합니다. 이 기준선이 **임계값**입니다. 경보기 감도와 같습니다.

- 임계값을 **낮추면**: 조금만 의심돼도 울림 → 재현율↑, 헛경보도↑(정밀도↓)
- 임계값을 **올리면**: 확실할 때만 울림 → 정밀도↑, 놓침도↑(재현율↓)

::video{ref="dl-m11"}

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict_proba(X_test)[:, 1]
for t in [0.5, 0.3, 0.1, 0.05]:
    pred = (proba >= t).astype(int)
    print(f"threshold {t:<4}: recall {recall_score(y_test, pred):.2f}  precision {precision_score(y_test, pred, zero_division=0):.2f}  alarms {pred.sum()}")
```

임계값을 0.1까지 내리면 고장의 대부분을 잡지만 경보 횟수가 크게 늘어납니다. 경보 한 번마다 점검 비용이 들기 때문에, **놓쳤을 때의 손해와 헛경보 비용을 비교해** 임계값을 정합니다.

### 직접 해보기

`threshold` 값을 0.5에서 시작해 0.4, 0.2, 0.08로 낮춰 보세요. 네 칸 숫자가 어떻게 옮겨 가는지 보면, 기준선을 낮출 때 FN(놓침)이 TP로, TN이 FP(헛경보)로 넘어가는 것이 보입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict_proba(X_test)[:, 1]

threshold = 0.5   # <- change me
tn, fp, fn, tp = confusion_matrix(y_test, (proba >= threshold).astype(int)).ravel()
print(f"threshold {threshold}:  TP={tp}  FN={fn}  FP={fp}  TN={tn}")
```

## ROC 곡선과 AUC: 임계값과 상관없는 점수

임계값을 0부터 1까지 바꿔 가며 (헛경보 비율, 재현율)을 점으로 찍어 이은 것이 **ROC 곡선**입니다. 곡선 아래 넓이가 **AUC**입니다.

- AUC 1.0: 완벽하게 구분
- AUC 0.5: 동전 던지기 수준
- 쉽게 말해 "고장 하나와 정상 하나를 무작위로 골랐을 때, 고장 쪽 확률을 더 높게 줄 확률"

```run
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_curve, roc_auc_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict_proba(X_test)[:, 1]
fpr, tpr, _ = roc_curve(y_test, proba)
print("AUC:", round(roc_auc_score(y_test, proba), 3))
fig, ax = plt.subplots(figsize=(4, 4))
ax.plot(fpr, tpr, label="model"); ax.plot([0, 1], [0, 1], "--", color="gray", label="random")
ax.set_xlabel("false alarm rate"); ax.set_ylabel("recall"); ax.legend(); ax.set_title("ROC curve")
plt.tight_layout(); plt.show()
```

AUC가 약 0.9라 "고장 쪽에 더 높은 확률을 주는 능력"은 꽤 좋습니다. 재현율이 낮았던 것은 임계값 0.5가 이 데이터에 너무 높았기 때문입니다.

> `roc_auc_score`에는 0/1 예측이 아니라 **확률**을 넣어야 합니다.

### 고장처럼 드문 것을 찾을 때는 PR-AUC도 함께

ROC 곡선의 가로축(헛경보 비율)은 "정상 전체 중 잘못 울린 비율"입니다. 정상이 9,000건이 넘으면 헛경보가 수십 건 생겨도 비율로는 아주 작게 보여서, AUC가 실제보다 **좋아 보일 수 있습니다.**

그래서 고장·사기처럼 찾는 대상이 아주 드물 때는 **PR-AUC**(정밀도-재현율 곡선 아래 넓이, `average_precision_score`)를 함께 봅니다. 기준선이 "무작위로 찍으면 고장 비율(약 0.03)"이라서, 드문 것을 찾는 실력을 더 정직하게 보여 줍니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score, average_precision_score

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "rpm", "torque", "tool_wear"]]
y = df["failure"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
proba = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train).predict_proba(X_test)[:, 1]
print("ROC-AUC:", round(roc_auc_score(y_test, proba), 3), "  (random = 0.5)")
print("PR-AUC :", round(average_precision_score(y_test, proba), 3), "  (random =", round(y_test.mean(), 3), ")")
```

ROC-AUC는 높아 보이지만 PR-AUC는 훨씬 낮게 나옵니다. "고장이라고 찍은 것 중 진짜 고장"을 높게 유지하면서 고장을 많이 잡기는 아직 어렵다는 뜻입니다. 불균형 데이터 다루는 법은 ml-08에서 더 배웁니다.

## 정리

- 정확도만 보지 말고 혼동행렬의 네 칸을 본다
- 놓침이 무서우면 **재현율**, 헛경보가 무서우면 **정밀도**
- 임계값으로 둘 사이의 균형을 조절한다
- AUC는 임계값과 상관없이 "구분하는 힘"을 잰다. 찾는 대상이 아주 드물면 PR-AUC도 함께 본다
