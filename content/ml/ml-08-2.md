## 시작하기 전에

앞 레슨의 로지스틱 회귀는 실제 고장 102건 중 27건(재현율 0.26)만 잡았습니다. 모델이 정상 쪽으로 기우는 이유는 학습할 때 **정상 하나를 틀리든 고장 하나를 틀리든 벌점이 같기** 때문입니다. 이번 레슨에서는 그 벌점을 바꿔 봅니다.

## 방법 1: 드문 쪽을 틀리면 더 혼내기 (class_weight)

모델은 학습할 때 틀린 만큼 벌점(손실)을 받으며 고쳐 갑니다. 기본 설정에서는 정상 하나를 틀리든 고장 하나를 틀리든 벌점이 같습니다. `class_weight="balanced"`를 주면 **드문 클래스를 틀렸을 때 벌점을 그만큼 크게** 줍니다. 고장이 정상보다 약 28배 드물면, 고장 하나를 틀릴 때 약 28배 벌점을 받는 식입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, f1_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X = df[features].values
y = df["failure"].values
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

for cw in [None, "balanced"]:
    model = make_pipeline(StandardScaler(), LogisticRegression(class_weight=cw)).fit(X_tr, y_tr)
    pred = model.predict(X_te)
    print(f"class_weight={cw}: recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}  f1 {f1_score(y_te, pred):.2f}  alarms {pred.sum()}")
```

`balanced`로 바꾸자 재현율이 0.26 → 0.85로 크게 올랐습니다. 대신 경보(`alarms`, 고장이라고 예측한 건수)가 34건 → 614건으로 늘고 정밀도는 0.14로 떨어졌습니다. 경보 7건 중 6건이 헛경보라는 뜻입니다. **놓침을 줄이면 헛경보가 늘어나는** 맞바꿈(trade-off)이고, 공짜는 없습니다. 이번 데이터에서는 반대쪽으로 너무 많이 넘어가서 F1은 오히려 낮아졌습니다(0.40 → 0.24).

## 직접 해보기: 무게를 손으로 정하기

`"balanced"` 대신 `{0: 1, 1: 무게}`처럼 고장의 벌점 배수를 직접 줄 수도 있습니다. 무게를 1, 3, 10, 28로 바꿔 보세요. 무게가 커질수록 재현율은 오르고 정밀도는 내려갑니다. 그 사이 어딘가에서 F1이 가장 높은 지점이 있습니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import precision_score, recall_score, f1_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])

weight = 3   # <- change me: 1, 3, 10, 28
model = make_pipeline(StandardScaler(), LogisticRegression(class_weight={0: 1, 1: weight})).fit(X_tr, y_tr)
pred = model.predict(X_te)
print(f"weight {weight}: recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}  f1 {f1_score(y_te, pred):.2f}  alarms {pred.sum()}")
```

| 무게 | 재현율 | 정밀도 | F1 | 경보 수 |
| --- | --- | --- | --- | --- |
| 1 (기본) | 0.26 | 0.79 | 0.40 | 34 |
| 3 | 0.46 | 0.56 | **0.51** | 84 |
| 5 | 0.56 | 0.40 | 0.47 | 143 |
| 10 | 0.64 | 0.25 | 0.36 | 263 |
| 28 (≈ balanced) | 0.85 | 0.14 | 0.25 | 605 |

무게 3에서 F1이 0.51로 가장 높습니다. 재현율과 정밀도가 둘 다 절반 정도인 지점입니다. 하지만 "F1이 가장 높은 곳"이 언제나 정답은 아닙니다. 놓침이 아주 비싸다면 무게 10이 더 나을 수도 있습니다. 이 판단을 비용으로 하는 방법이 다음 레슨입니다.

> 무게도 하이퍼파라미터입니다. 고를 때는 테스트 대신 교차검증([교차검증과 하이퍼파라미터](#/l/ml-05-1))을 씁니다.

## 트리 모델에도, 그리고 확률에 생기는 일

`class_weight`는 로지스틱 회귀 말고도 트리·랜덤포레스트·SVM 등 대부분의 분류 모델에 있습니다. 랜덤포레스트에 적용하고, 함께 **확률의 평균**이 어떻게 변하는지도 봅니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import recall_score, precision_score

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X_tr, X_te, y_tr, y_te = train_test_split(df[features], df["failure"], test_size=0.3, random_state=0, stratify=df["failure"])
for cw in [None, "balanced"]:
    rf = RandomForestClassifier(n_estimators=100, class_weight=cw, random_state=0).fit(X_tr, y_tr)
    pred = rf.predict(X_te)
    print(f"forest class_weight={cw}: recall {recall_score(y_te, pred):.2f}  precision {precision_score(y_te, pred):.2f}  alarms {pred.sum()}")
print("actual failure rate in test:", round(y_te.mean(), 3))
for cw in [None, "balanced"]:
    lr = make_pipeline(StandardScaler(), LogisticRegression(class_weight=cw)).fit(X_tr, y_tr)
    print(f"logistic class_weight={cw}: average predicted probability {lr.predict_proba(X_te)[:, 1].mean():.3f}")
```

- 랜덤포레스트는 `balanced`를 줘도 재현율이 0.64 → 0.65로 거의 그대로이고 정밀도만 0.88 → 0.69로 떨어졌습니다. 숲은 원래 고장 구석을 잘 찾고 있어서, 벌점만 바꾸는 것으로는 크게 달라지지 않습니다. **어떤 방법이 효과적인지는 모델마다 다르니** 직접 비교해 봐야 합니다.
- 로지스틱 회귀의 평균 예측 확률은 기본일 때 0.035로 실제 고장률(0.034)과 거의 같습니다. 그런데 `balanced`로 학습하면 **0.271**로 부풀려집니다. 고장을 28배로 크게 보며 배웠기 때문입니다.

그래서 `class_weight`로 학습한 모델의 확률은 "고장 날 확률 27%"처럼 **그대로 읽으면 안 됩니다.** 순위(어느 설비가 더 위험한가)나 판정에는 쓸 수 있지만, 확률 값 자체를 보고서에 쓰려면 가중치 없이 학습하고 임계값을 조절하는(ml-08-3) 편이 낫습니다.

## 정리

- `class_weight="balanced"`: 드문 클래스를 틀렸을 때 벌점을 그만큼(약 28배) 크게 줍니다.
- 재현율 0.26 → 0.85, 대신 경보가 34 → 614건으로 늘고 정밀도 0.14. **놓침과 헛경보는 맞바꿈**입니다.
- `{0: 1, 1: w}`로 무게를 직접 정하면 중간 지점을 고를 수 있습니다.
- 효과는 모델마다 다릅니다(랜덤포레스트는 재현율 0.64 → 0.65로 거의 그대로).
- 가중치로 학습하면 확률이 부풀려집니다(평균 0.035 → 0.271). 확률 값 자체를 쓸 때는 주의합니다.
