## 결정트리: 스무고개로 예측하기

스무고개 놀이를 떠올려 봅시다. "동물인가요?" → "네 발인가요?" → … 질문을 이어 가며 답을 좁혀 갑니다.

**결정트리**도 똑같이 예/아니오 질문을 이어 붙여 예측합니다. 다른 점은 **어떤 질문을 어떤 순서로 할지 데이터를 보고 스스로 정한다**는 것입니다. 매 단계에서 "이 질문으로 나누면 두 그룹이 가장 깔끔하게 갈린다"는 질문을 고릅니다.

- 맨 위 질문: **뿌리(root)**
- 질문으로 갈라지는 갈래: **가지(branch)**
- 더 이상 나누지 않는 끝: **잎(leaf)**, 여기서 최종 답을 냄

::figure{src="content/img/ml/ml04-tree.svg" alt="여성인가로 먼저 나누고, 여성은 3등실인가, 남성은 나이 6.5세 이하인가로 다시 나누는 결정트리" caption="깊이 2인 타이타닉 트리. 아래 코드가 만드는 트리를 그림으로 옮긴 것입니다."}

## 타이타닉 트리를 직접 읽어 보기

깊이(질문 단계 수)를 2로 제한한 작은 트리를 만들고 규칙을 글로 출력해 봅니다.

```run
import pandas as pd
from sklearn.tree import DecisionTreeClassifier, export_text

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
features = ["pclass", "female", "age", "fare"]
tree = DecisionTreeClassifier(max_depth=2, random_state=0).fit(df[features], df["survived"])
print(export_text(tree, feature_names=features))
```

읽는 법:

- 첫 질문은 `female <= 0.5`(남성인가?)입니다. 성별이 생존을 가장 잘 가르는 질문이라는 뜻입니다.
- 남성 쪽에서는 나이(`age`)로 한 번 더 나눠 6.5세 이하 어린이면 생존으로 봅니다. "여성과 어린이 먼저"가 그대로 보입니다.
- 여성 쪽에서는 객실 등급(`pclass`)으로 나눠 1·2등실이면 생존, 3등실이면 사망으로 봅니다.
- `class: 1`이면 생존, `class: 0`이면 사망으로 예측합니다.

사람이 그대로 읽을 수 있는 규칙이 나온다는 것이 결정트리의 가장 큰 장점입니다.

## 깊어질수록 외운다: 과적합

질문을 계속 늘리면(깊이를 키우면) 학습 데이터는 결국 전부 맞힐 수 있습니다. 승객 한 명 한 명에게 맞춘 질문까지 만들어 버리기 때문입니다. 하지만 그건 **이해가 아니라 암기**라서 새 승객에게는 오히려 틀립니다. 이것을 **과적합(overfitting)**이라고 합니다.

::figure{src="content/img/ml/ml04-overfit.svg" alt="트리가 깊어질수록 학습 점수는 계속 오르지만 시험 점수는 어느 지점부터 떨어진다" caption="학습 점수와 시험 점수의 차이가 벌어지기 시작하는 곳부터가 과적합입니다."}

::video{ref="dl-m10"}

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
for d in [1, 2, 3, 4, 6, 10, None]:
    m = DecisionTreeClassifier(max_depth=d, random_state=0).fit(X_train, y_train)
    print(f"depth {str(d):>4}:  train {m.score(X_train, y_train):.3f}   test {m.score(X_test, y_test):.3f}")
```

깊이 제한이 없으면(None) 학습 점수는 0.98 이상인데 시험 점수는 오히려 떨어집니다. 학습 점수와 시험 점수의 차이가 크게 벌어지면 과적합을 의심합니다. 그래서 `max_depth`를 적당히 제한합니다.

### 직접 해보기

`max_depth`를 1부터 하나씩 올려 보고, `None`(제한 없음)도 넣어 보세요. 그리고 `min_samples_leaf`(잎 하나에 최소 몇 명이 있어야 하는지)를 1에서 10으로 바꿔 보세요. 잎을 너무 잘게 쪼개지 못하게 막는 것도 과적합을 줄이는 방법입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)

max_depth = 3          # <- change me (1, 2, ..., None)
min_samples_leaf = 1   # <- change me (1, 5, 10)
m = DecisionTreeClassifier(max_depth=max_depth, min_samples_leaf=min_samples_leaf, random_state=0).fit(X_train, y_train)
print(f"train {m.score(X_train, y_train):.3f}   test {m.score(X_test, y_test):.3f}   gap {m.score(X_train, y_train) - m.score(X_test, y_test):.3f}")
```

## 랜덤포레스트: 여러 트리의 투표

한 사람의 판단보다 여러 사람의 다수결이 더 안정적일 때가 많습니다. **랜덤포레스트**는 트리를 수십~수백 개 만들고 투표로 예측합니다.

트리마다 일부러 조금씩 다르게 만듭니다.

1. 데이터를 무작위로 다시 뽑아서(중복 허용) 트리마다 다른 데이터로 학습
2. 질문 후보도 매번 일부 특성만 무작위로 골라서 사용

그러면 트리 하나하나는 조금씩 틀려도, 그 실수가 서로 다른 방향이라 투표하면 상쇄됩니다.

::figure{src="content/img/ml/ml04-forest.svg" alt="트리 다섯 그루가 각각 생존 또는 사망에 투표하고 다수결로 생존을 고른다" caption="트리 하나하나는 조금씩 틀려도, 다수결을 하면 실수가 상쇄됩니다."}

::video{ref="dl-m23"}

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
tree = DecisionTreeClassifier(random_state=0).fit(X_train, y_train)
forest = RandomForestClassifier(n_estimators=100, random_state=0).fit(X_train, y_train)
print("one tree    test:", round(tree.score(X_test, y_test), 3))
print("100 trees   test:", round(forest.score(X_test, y_test), 3))
```

### 또 다른 숲: 부스팅

트리를 여러 개 쓰는 방법은 하나 더 있습니다. 랜덤포레스트가 트리들을 **따로따로 만들어 투표**한다면, **부스팅(Gradient Boosting)**은 트리를 **하나씩 차례로** 만듭니다. 새 트리는 앞 트리들이 **틀린 부분을 고치는 데** 집중합니다. 오답 노트를 보며 틀린 문제만 다시 공부하는 학생과 비슷합니다.

| | 랜덤포레스트 (배깅) | 부스팅 |
| --- | --- | --- |
| 트리 만드는 순서 | 동시에, 서로 독립 | 차례로, 앞 트리의 실수를 보완 |
| 합치는 방법 | 다수결 | 차례로 더하기 |
| 특징 | 설정을 대충 해도 안정적 | 잘 맞추면 성능이 더 좋지만 설정에 민감 |

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

df = pd.read_csv("titanic.csv")
df["female"] = (df["sex"] == "female").astype(int)
df["age"] = df["age"].fillna(df["age"].median())
X = df[["pclass", "female", "age", "sibsp", "parch", "fare"]]
y = df["survived"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
for name, m in [("random forest", RandomForestClassifier(n_estimators=100, random_state=0)),
                ("boosting", GradientBoostingClassifier(n_estimators=100, learning_rate=0.1, max_depth=3, random_state=0))]:
    m.fit(X_train, y_train)
    print(f"{name:>13}: test {m.score(X_test, y_test):.3f}")
```

부스팅이 0.834로 랜덤포레스트(0.807)보다 조금 높게 나왔습니다. 다만 이 정도 차이는 데이터를 어떻게 나누느냐에 따라 뒤집히기도 해서, ml-05에서 배울 교차검증으로 여러 번 확인해야 믿을 수 있습니다. 성능이 비슷하면 더 단순하고 안정적인 쪽을 고르는 것도 좋은 판단입니다. 실무에서 많이 쓰는 XGBoost, LightGBM, CatBoost가 모두 이 부스팅 계열입니다.

## 피처 중요도 맛보기: 어떤 정보를 많이 썼나

트리 모델은 각 특성이 예측에 얼마나 쓰였는지를 `feature_importances_`로 알려 줍니다. 합은 1입니다. 설비 데이터로 고장 예측에 중요한 센서를 찾아봅니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

df = pd.read_csv("ai4i2020.csv")
features = ["air_temp", "process_temp", "rpm", "torque", "tool_wear"]
X_train, X_test, y_train, y_test = train_test_split(df[features], df["failure"], test_size=0.25, random_state=0, stratify=df["failure"])
forest = RandomForestClassifier(n_estimators=50, random_state=0).fit(X_train, y_train)
print(pd.Series(forest.feature_importances_, index=features).sort_values(ascending=False).round(3))
```

토크와 회전수가 가장 중요하게 쓰였습니다. 실제로 이 데이터의 고장 원인에는 "힘(토크 × 회전수)이 너무 크거나 작음", "토크가 큰데 공구가 많이 닳음" 같은 조건이 들어 있습니다.

> 트리는 "값이 어떤 기준보다 큰가?"만 묻기 때문에 숫자 크기를 맞추는 표준화가 필요 없습니다. 대신 `random_state`를 고정해야 매번 같은 결과가 나옵니다.

## 정리

- 결정트리 = 데이터가 스스로 고른 스무고개, 규칙을 사람이 읽을 수 있음
- 너무 깊으면 외워 버림(과적합) → `max_depth`로 제한
- 랜덤포레스트 = 조금씩 다른 트리 여러 개의 투표 → 더 안정적
- 부스팅 = 앞 트리의 실수를 차례로 고쳐 가는 트리들 (XGBoost·LightGBM의 바탕)
- `feature_importances_`로 중요한 특성 확인 (약점과 더 믿을 만한 방법은 ml-09 모델 해석에서)
