## 그래디언트 부스팅의 한 걸음: 잔차를 맞힌다

회귀용 그래디언트 부스팅은 아래 과정을 반복합니다.

1. 처음 예측은 정답들의 **평균** 하나로 시작한다.
2. **잔차** = 정답 − 지금까지의 예측을 계산한다. "아직 얼마나 틀렸나"입니다.
3. 작은 회귀 트리 하나가 **잔차를 맞히도록** 학습한다. 정답 y가 아니라 잔차가 이 트리의 정답입니다.
4. 그 트리의 예측에 작은 수 η(**학습률**, `learning_rate`)를 곱해 지금까지의 예측에 더한다.
5. 2로 돌아간다.

`새 예측 = 이전 예측 + η × (잔차를 맞힌 트리의 예측)`

::figure{src="content/img/ml/ml04-gboost.svg" alt="트리 1은 y를 대충 맞히고, 트리 2는 트리 1의 잔차를, 트리 3은 트리 1과 2의 잔차를 맞혀 남은 잔차가 점점 줄어든다" caption="각 트리는 '지금까지 틀린 만큼'을 맞힙니다. 최종 예측은 기준값에 트리들의 예측을 학습률만큼씩 더한 것입니다."}

골프에 비유하면, 첫 샷(평균)으로 그린 근처까지 보내고, 두 번째 샷은 **남은 거리(잔차)** 만큼을 노리고, 세 번째 샷은 또 남은 거리를 노리는 것입니다. 학습률은 "남은 거리를 한 번에 다 치지 말고 10%씩만 쳐라"는 규칙입니다. 한 번에 다 치면 트리 하나의 실수까지 그대로 따라가기 때문입니다.

## 직접 구현하기: for 문 하나로

[회귀 트리](#/l/ml-04-5) 실무 예제와 같은 문제(온도 · 토크 · 공구 마모로 회전수 예측)를 부스팅으로 풉니다. 깊이 3짜리 회귀 트리를 200번 쌓습니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeRegressor
from sklearn.metrics import mean_absolute_error

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "torque", "tool_wear"]]
y = df["rpm"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0)

lr = 0.1
pred_train = np.full(len(y_train), y_train.mean())   # step 1: start from the mean
pred_test = np.full(len(y_test), y_train.mean())
for m in range(1, 201):
    residual = y_train - pred_train                                       # step 2
    tree = DecisionTreeRegressor(max_depth=3, random_state=0).fit(X_train, residual)  # step 3
    pred_train += lr * tree.predict(X_train)                              # step 4
    pred_test += lr * tree.predict(X_test)
    if m in (1, 2, 3, 10, 50, 200):
        print(f"after {m:>3} trees: train MAE {mean_absolute_error(y_train, pred_train):6.1f}, test MAE {mean_absolute_error(y_test, pred_test):6.1f}")
```

| 트리 수 | 학습 MAE | 시험 MAE |
| --- | --- | --- |
| 1 | 116.5 | 117.6 |
| 3 | 97.8 | 98.9 |
| 10 | 59.9 | 61.0 |
| 50 | 39.5 | 40.1 |
| 200 | 38.3 | 40.3 |

트리 하나로는 평균에서 10%밖에 움직이지 않아 거의 그대로입니다. 트리를 쌓을수록 오차가 꾸준히 줄어 50그루에서 시험 MAE 40.1이 되고, 그 뒤로는 거의 변하지 않습니다. 사이킷런의 `GradientBoostingRegressor`도 정확히 이 계산을 합니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.metrics import mean_absolute_error

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "torque", "tool_wear"]]
y = df["rpm"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0)
gb = GradientBoostingRegressor(n_estimators=200, learning_rate=0.1, max_depth=3, random_state=0).fit(X_train, y_train)
print("sklearn test MAE:", round(mean_absolute_error(y_test, gb.predict(X_test)), 1))
```

직접 만든 것과 같은 40.3이 나옵니다. 라이브러리 안에 마법은 없고, 잔차를 맞히는 트리를 차례로 더할 뿐입니다.

## 왜 '그래디언트'일까

잔차는 사실 **손실 함수의 기울기(gradient)를 뒤집은 것**입니다. 제곱 오차 손실 L = ½(y − ŷ)²을 예측 ŷ로 미분하면 −(y − ŷ)이고, 그 반대 방향이 바로 잔차 y − ŷ입니다. 그래서 "잔차를 맞힌 트리를 더한다"는 것은 [경사하강법](#/l/ml-02-3)에서 "기울기 반대 방향으로 한 걸음 간다"와 같은 일입니다. 다른 점은 계수 하나를 움직이는 대신 **예측값 전체를 트리 하나만큼** 움직인다는 것입니다. 학습률이 곧 경사하강법의 보폭입니다.

이렇게 보면 손실만 바꿔서 같은 틀로 여러 문제를 풀 수 있습니다.

| 문제 | 손실 | 다음 트리가 맞히는 것 (음의 기울기) |
| --- | --- | --- |
| 회귀 (제곱 오차) | ½(y − ŷ)² | 잔차 y − ŷ |
| 회귀 (절대 오차) | abs(y − ŷ) | 잔차의 부호 (+1 또는 −1) |
| 이진 분류 (로그 손실) | −[y log p + (1 − y) log(1 − p)] | y − p (정답 − 예측 확률) |

분류에서도 "정답(0/1)과 지금 예측한 확률의 차이"를 다음 트리가 맞힙니다. 고장(y = 1)인데 확률을 0.2로 본 설비는 +0.8만큼, 정상(y = 0)인데 0.3으로 본 설비는 −0.3만큼 고쳐야 할 대상이 됩니다.

## 학습률과 트리 수: 함께 움직이는 두 손잡이

학습률을 바꾸면 시험 오차가 가장 낮아지는 트리 수가 달라집니다. `staged_predict`는 트리를 하나 더할 때마다의 예측을 차례로 돌려줘서, 모든 트리 수의 점수를 한 번에 볼 수 있습니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.metrics import mean_absolute_error

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "torque", "tool_wear"]]
y = df["rpm"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0)
for lr in [1.0, 0.3, 0.1, 0.03]:
    gb = GradientBoostingRegressor(n_estimators=300, learning_rate=lr, max_depth=3, random_state=0).fit(X_train, y_train)
    scores = [mean_absolute_error(y_test, p) for p in gb.staged_predict(X_test)]
    print(f"learning_rate {lr:<4}: best at {int(np.argmin(scores)) + 1:>3} trees (MAE {min(scores):.1f}), at 300 trees MAE {scores[-1]:.1f}")
```

| 학습률 | 가장 좋은 트리 수 | 그때 MAE | 300그루 MAE |
| --- | --- | --- | --- |
| 1.0 | 13 | 40.6 | 46.4 (과적합) |
| 0.3 | 17 | 40.4 | 41.8 |
| 0.1 | 93 | 40.0 | 40.5 |
| 0.03 | 253 | 40.1 | 40.1 |

- 학습률이 크면 몇 그루 만에 좋아지지만, 그 뒤로 트리를 더하면 금방 외우기 시작합니다(1.0에서 46.4까지 나빠짐).
- 학습률이 작으면 트리가 훨씬 많이 필요하지만, 최고점이 비슷하거나 조금 낫고 트리 수를 넘겨도 덜 망가집니다.
- 실무 규칙: **학습률은 0.05 ~ 0.1 정도로 낮게 두고, 트리 수는 조기 종료로 정한다.**

**조기 종료(early stopping)** 는 학습용 일부를 검증용으로 떼어 두고, 검증 점수가 몇 번 연속 나아지지 않으면 트리 쌓기를 멈추는 방법입니다. 트리 수를 GridSearch로 찾는 수고를 덜어 줍니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error

df = pd.read_csv("ai4i2020.csv")
X = df[["air_temp", "process_temp", "torque", "tool_wear"]]
y = df["rpm"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0)
hgb = HistGradientBoostingRegressor(max_iter=1000, learning_rate=0.1, early_stopping=True,
                                    validation_fraction=0.1, n_iter_no_change=20, random_state=0).fit(X_train, y_train)
print("trees actually built:", hgb.n_iter_, "of max 1000")
print("test MAE:", round(mean_absolute_error(y_test, hgb.predict(X_test)), 1))
```

최대 1,000그루를 허락했지만 76그루에서 스스로 멈췄고, 시험 MAE는 41.2입니다. 시험용은 한 번도 보지 않고 정한 트리 수라서 정직한 점수입니다.

## XGBoost · LightGBM · CatBoost: 무엇이 다른가

세 라이브러리 모두 위의 그래디언트 부스팅을 **더 빠르고, 더 잘 규제되게** 만든 것입니다. 핵심 원리는 같고, 트리를 키우는 방식과 기본 설정이 다릅니다.

| | XGBoost | LightGBM | CatBoost |
| --- | --- | --- | --- |
| 트리 키우는 방식 | 깊이별로 고르게 (level-wise) | 손실이 가장 많이 주는 잎부터 (leaf-wise), 빠르지만 깊어지기 쉬움 | 같은 질문을 한 층 전체에 (대칭 트리) |
| 속도의 비결 | 2차 기울기까지 써서 한 번에 정확히 이동, 병렬화 | 숫자를 구간(히스토그램)으로 묶음 | 범주형 열 처리를 내장 |
| 손실에 붙는 규제 | 잎 수 · 잎 값 크기에 벌점 (`gamma`, `lambda`) | `num_leaves`, `min_child_samples`로 조절 | 기본값이 무난함 |
| 사이킷런에서 비슷한 것 | `GradientBoosting...` | `HistGradientBoosting...` | (없음) |

설정값 이름은 라이브러리마다 다르지만, 모두 아래 네 가지 손잡이 중 하나입니다.

| 손잡이 | XGBoost | LightGBM | 사이킷런 Hist | 올리면 |
| --- | --- | --- | --- | --- |
| 한 걸음 크기 | `learning_rate` (`eta`) | `learning_rate` | `learning_rate` | 빨리 배우고 과적합 쉬움 |
| 트리 수 | `n_estimators` | `n_estimators` | `max_iter` | 더 배움 (조기 종료로 정함) |
| 트리 하나의 복잡도 | `max_depth` | `num_leaves` | `max_leaf_nodes` | 상호작용을 더 잡고 과적합 쉬움 |
| 무작위성 · 규제 | `subsample`, `colsample_bytree`, `reg_lambda` | `bagging_fraction`, `feature_fraction`, `lambda_l2` | `l2_regularization` | 분산 감소 (랜덤포레스트처럼) |

:::tip 알아 두면 좋아요 · 내 컴퓨터에서 XGBoost · LightGBM 쓰기
브라우저 실습 환경에서는 사이킷런의 `HistGradientBoosting...`으로 충분합니다(LightGBM과 같은 히스토그램 방식). 내 컴퓨터(아나콘다 · 코랩)에서는 `pip install xgboost lightgbm` 후 사이킷런과 똑같은 모양으로 씁니다.

```python
from xgboost import XGBRegressor
from lightgbm import LGBMRegressor

xgb = XGBRegressor(n_estimators=500, learning_rate=0.05, max_depth=4, subsample=0.8, colsample_bytree=0.8)
lgbm = LGBMRegressor(n_estimators=500, learning_rate=0.05, num_leaves=31, subsample=0.8, colsample_bytree=0.8)
xgb.fit(X_train, y_train)
lgbm.fit(X_train, y_train)
```
:::

## 자주 하는 실수

| 실수 | 무슨 일이 생기나 | 바로잡기 |
| --- | --- | --- |
| 학습률 1.0 + 트리 수백 그루 | 몇 그루 만에 외우기 시작 (MAE 40.6 → 46.4) | 학습률 0.05 ~ 0.1 + 조기 종료 |
| 시험용으로 트리 수를 고름 | 시험 점수가 낙관적으로 부풀려짐 | 검증용(`validation_fraction`)이나 교차검증으로 |
| `max_depth`를 랜덤포레스트처럼 크게 | 트리 하나가 이미 외워서 부스팅할 게 없음 | 부스팅 트리는 얕게 (깊이 3 ~ 6) |
| 라이브러리를 바꾸면 성능이 확 오를 거라 기대 | 원리가 같아서 차이는 대개 작음 | 특성 · 데이터 품질부터 손본다 |

## 정리

- 그래디언트 부스팅 = 평균에서 시작해 **잔차를 맞히는 작은 트리**를 학습률만큼씩 더해 가는 것. 직접 구현한 결과(MAE 40.3)가 사이킷런과 같았습니다.
- 잔차는 손실의 **음의 기울기**입니다. 그래서 부스팅은 "예측값 공간에서 하는 경사하강법"이고, 손실만 바꾸면 분류(y − p)에도 그대로 쓰입니다.
- 학습률을 낮추면 트리가 더 필요하지만 덜 망가집니다. 트리 수는 **조기 종료**로 정합니다(1,000그루 허용 → 76그루에서 멈춤).
- XGBoost · LightGBM · CatBoost는 같은 원리를 빠르게 · 규제를 강하게 만든 구현입니다. 손잡이는 학습률 · 트리 수 · 트리 복잡도 · 무작위성 네 가지입니다.
