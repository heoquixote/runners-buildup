## 시작하기 전에

[K-fold 교차검증](#/l/ml-05-1)에서는 데이터를 섞어서 조각을 나눴습니다. 그런데 레슨 끝에서 "시간 순서가 있는 데이터는 섞는 것이 항상 정답은 아니다"라는 말이 나왔습니다. 이번 레슨에서는 그 이유를 직접 확인하고, 시간 데이터를 나누는 법과 시간 데이터용 특성(래그·이동평균)을 만드는 법을 배웁니다.

## 미래로 과거를 맞히면 반칙

일기예보를 만든다고 해 봅시다. 수요일 날씨를 맞히는 시험을 보는데, 학습 자료에 **목요일·금요일 날씨**가 섞여 있다면 어떨까요? 앞뒤 날씨를 보고 가운데를 메우는 건 쉽습니다. 하지만 진짜 예보할 때는 **내일 이후 날씨를 절대 알 수 없습니다.** 시험이 실전보다 쉬워진 셈이라, 점수가 실제보다 좋게 나옵니다.

데이터를 섞어서 K-fold로 나누면 정확히 이 일이 생깁니다. 1958년을 시험할 때 1959년, 1960년 데이터로 학습하게 되니까요.

## 데이터 보기: 월별 비행기 승객 수

1949~1960년 12년 동안 매달 국제선 승객 수(천 명)를 기록한 실제 데이터입니다.

```run
import pandas as pd

df = pd.read_csv("flights.csv")
print(df.head(3))
print("rows:", len(df))
print("first year:", df["passengers"][:12].tolist())
print("last year :", df["passengers"][-12:].tolist())
```

144개월(12년)입니다. 1949년엔 한 달에 104~148천 명이던 승객이 1960년엔 390~622천 명으로 늘었습니다. 해마다 **커지는 추세**가 있고, 매년 **여름(7·8월)에 가장 많은** 계절 패턴도 있습니다.

## 시간 데이터용 특성: 래그와 이동평균

이 표에는 "연도, 월, 승객 수"뿐이라 예측에 쓸 특성이 마땅치 않습니다. 시간 데이터에서는 **과거 값 자체**를 특성으로 만듭니다.

- **래그(lag) 특성**: 몇 칸 전의 값. `lag1` = 지난달 승객 수, `lag12` = 작년 같은 달 승객 수
- **이동평균(rolling mean)**: 최근 몇 달 값의 평균. 들쭉날쭉한 값을 부드럽게 만든 추세

pandas의 `shift(1)`은 값을 한 칸 아래로 밀어서 "지난달 값"을 옆에 붙여 줍니다. 이동평균도 반드시 `shift(1)`로 한 칸 민 뒤에 계산해야 합니다. 안 그러면 **이번 달 값이 평균에 섞여** 정답을 미리 보는 누수가 됩니다.

```run
import pandas as pd

df = pd.read_csv("flights.csv")
df["lag1"] = df["passengers"].shift(1)
df["lag12"] = df["passengers"].shift(12)
df["roll3"] = df["passengers"].shift(1).rolling(3).mean()
print(df.iloc[10:15].round(1))
```

- 1950년 1월(12번 행)의 `lag1`은 118(1949년 12월), `lag12`는 112(1949년 1월)입니다.
- 처음 12개월은 `lag12`가 비어 있습니다(NaN). 1년 전 기록이 없으니까요. 이런 행은 학습에서 뺍니다.
- `roll3`은 지난 3개월 평균입니다. 1950년 1월의 `roll3`은 1949년 10~12월 값으로 (119 + 104 + 118) / 3 = 113.7이고, **이번 달 값 115는 들어가지 않았습니다.**

## 섞어서 나누기 vs 시간 순서대로 나누기

이제 `lag1`, `lag12`로 이번 달 승객 수를 예측하면서 두 가지 방법으로 교차검증해 봅니다.

- **섞은 K-fold**: 132개월을 섞어서 5조각
- **TimeSeriesSplit**: 언제나 **앞부분으로 학습하고 바로 뒤 구간으로 시험**. 학습 구간이 점점 길어집니다.

::figure{src="content/img/ml/ml05-timesplit.svg" alt="섞은 K-fold는 시험 칸이 시간 축 여기저기 흩어져 있고, TimeSeriesSplit은 언제나 학습 구간 바로 뒤가 시험 구간이며 학습 구간이 점점 길어진다" caption="TimeSeriesSplit은 '과거로 배우고 그다음을 맞히는' 실전 상황을 그대로 흉내 냅니다."}

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import KFold, TimeSeriesSplit, cross_val_score
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression

df = pd.read_csv("flights.csv")
df["lag1"] = df["passengers"].shift(1)
df["lag12"] = df["passengers"].shift(12)
df = df.dropna().reset_index(drop=True)
X, y = df[["lag1", "lag12"]], df["passengers"]

splits = {"shuffled KFold": KFold(5, shuffle=True, random_state=0), "TimeSeriesSplit": TimeSeriesSplit(5)}
models = {"forest": RandomForestRegressor(n_estimators=200, random_state=0, n_jobs=1), "linear": LinearRegression()}
for sname, cv in splits.items():
    for mname, m in models.items():
        mae = -cross_val_score(m, X, y, cv=cv, scoring="neg_mean_absolute_error")
        print(f"{sname:>16} | {mname:>6}: MAE {mae.mean():.1f}  {mae.round(1)}")
```

| | 섞은 K-fold | TimeSeriesSplit |
| --- | --- | --- |
| 랜덤포레스트 | MAE **13.8** | MAE **28.6** |
| 선형회귀 | MAE 12.0 | MAE 15.0 |

섞어서 나누면 랜덤포레스트도 평균 13.8천 명 정도만 틀리는 좋은 모델처럼 보입니다. 그런데 실전처럼 시간 순서대로 시험하면 **두 배 넘게**(28.6) 틀립니다. 특히 뒤쪽 세 조각(1955년 이후)에서 오차가 34~35로 커집니다. 섞은 K-fold 점수는 "앞뒤를 보고 가운데 메우기" 시험이었던 것입니다.

## 왜 숲만 크게 무너질까

랜덤포레스트는 학습 데이터의 값들을 **평균 내서** 예측합니다. 그래서 학습 때 본 적 없는 큰 값은 **절대 예측하지 못합니다.** 마지막 24개월을 시험으로 남겨서 확인해 봅니다.

```run
import pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression

df = pd.read_csv("flights.csv")
df["lag1"] = df["passengers"].shift(1)
df["lag12"] = df["passengers"].shift(12)
df = df.dropna().reset_index(drop=True)
train, test = df.iloc[:-24], df.iloc[-24:]
features = ["lag1", "lag12"]
print("train max:", train["passengers"].max(), "/ test max:", test["passengers"].max())
for name, m in [("forest", RandomForestRegressor(n_estimators=200, random_state=0, n_jobs=1)), ("linear", LinearRegression())]:
    pred = m.fit(train[features], train["passengers"]).predict(test[features])
    print(f"{name:>6}: max prediction {pred.max():.0f}, MAE {abs(pred - test['passengers']).mean():.1f}")
```

학습 기간의 최대 승객 수는 505인데, 시험 기간(1959~1960년)에는 622까지 올라갑니다. 랜덤포레스트의 예측은 **495에서 멈춥니다.** 배운 범위 밖은 그리지 못하는 겁니다. 반면 선형회귀는 "작년 같은 달보다 이만큼 많다"는 관계를 직선으로 배워서 608까지 따라갑니다(MAE 32.0 vs 14.5).

> 추세가 있는 데이터에서 트리 모델을 쓰려면, 승객 수 자체 대신 **작년 대비 증가율**처럼 범위가 일정한 값을 예측하게 바꾸는 방법을 씁니다. 설비 센서처럼 정해진 범위 안에서 움직이는 데이터에서는 이 문제가 덜합니다.

## 정리

- 시간 순서가 있는 데이터를 섞어서 나누면 **미래 정보로 과거를 맞히는** 셈이라 점수가 부풀려집니다(숲 MAE 13.8 → 실제 28.6).
- `TimeSeriesSplit`은 언제나 앞부분으로 학습하고 바로 뒤로 시험합니다. 마지막 시험용도 **가장 최근 구간**으로 남깁니다.
- 시간 데이터 특성: **래그**(`shift`), **이동평균**(`shift(1).rolling(n).mean()`). 이번 값이 섞이지 않게 꼭 한 칸 밀고 계산합니다.
- 트리 모델은 학습 범위 밖의 값을 예측하지 못합니다. 추세가 있으면 증가율처럼 범위가 일정한 값을 예측하게 바꿉니다.
