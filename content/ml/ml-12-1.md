## 시작하기 전에

[로지스틱 회귀: 확률로 분류하기](#/l/ml-02-5)는 정답이 **두 종류**(생존/사망, 고장/정상)인 이진 분류였습니다. 그런데 펭귄 종(3종), 손글씨 숫자(10종), 불량 유형(5종)처럼 **셋 이상** 중 하나를 고르는 문제도 많습니다. 이것을 **다중 분류**라고 합니다. 이번 레슨에서는 이진 분류기를 다중 분류로 넓히는 두 방법(OvR, 소프트맥스)과, 다중 분류의 점수를 읽는 법(macro · weighted 평균)을 배웁니다.

## 데이터: 펭귄 세 종

## 방법 1: OvR, "너 대 나머지 전부"

가장 단순한 방법은 이진 분류기를 **클래스 수만큼** 만드는 것입니다.

1. "Adelie인가 아닌가" 분류기
2. "Chinstrap인가 아닌가" 분류기
3. "Gentoo인가 아닌가" 분류기

새 펭귄이 오면 세 분류기에 모두 물어 **"맞다"는 확률이 가장 높은 쪽**을 답으로 고릅니다. 이것을 **OvR(One-vs-Rest)** 이라고 합니다. 어떤 이진 분류기에도 쓸 수 있다는 것이 장점입니다. 단점은 세 분류기가 따로 학습돼서 세 확률의 합이 1이 아니라는 점입니다.

## 방법 2: 소프트맥스, 확률을 나눠 갖기

로지스틱 회귀를 다중 분류로 넓힌 모델이 **소프트맥스 회귀**(다항 로지스틱 회귀)입니다. 클래스마다 직선 점수 z를 하나씩 계산한 뒤, 세 점수를 **합이 1인 확률**로 바꿉니다.

`p(클래스 k) = e^(z_k) / (e^(z_1) + e^(z_2) + e^(z_3))`

- **e^z**(지수)는 점수가 음수여도 항상 양수로 바꿔 줍니다. 점수가 1 크면 e^z는 약 2.7배가 됩니다.
- **합으로 나누면** 세 값의 합이 정확히 1이 됩니다. 그래서 "이 펭귄이 Adelie일 확률 61%"처럼 읽을 수 있습니다.

::figure{src="content/img/ml/ml12-softmax.svg" alt="세 클래스의 점수 2.0, 0.5, -1.0을 지수로 바꾸면 7.39, 1.65, 0.37이 되고, 합 9.41로 나누면 확률 0.79, 0.18, 0.04가 된다" caption="소프트맥스는 점수를 지수로 바꾼 뒤 합으로 나눠 확률로 만듭니다. 이름처럼 가장 큰 점수를 '부드럽게(soft)' 골라 줍니다."}

클래스가 둘뿐이면 소프트맥스는 [로지스틱 회귀](#/l/ml-02-5)의 시그모이드와 똑같아집니다. 시그모이드는 소프트맥스의 두 클래스 버전입니다. 사이킷런의 `LogisticRegression`은 정답이 셋 이상이면 **자동으로 소프트맥스**로 학습합니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.multiclass import OneVsRestClassifier

df = pd.read_csv("penguins.csv").dropna()
X = df[["flipper_length_mm", "body_mass_g"]]
y = df["species"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
softmax = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)
ovr = make_pipeline(StandardScaler(), OneVsRestClassifier(LogisticRegression())).fit(X_train, y_train)
print("classes:", softmax.classes_)
print("softmax accuracy:", round(softmax.score(X_test, y_test), 3))
print("OvR accuracy:    ", round(ovr.score(X_test, y_test), 3))
```

정확도는 소프트맥스 0.82, OvR 0.81로 거의 같습니다. 보통 큰 차이는 나지 않고, 확률을 해석해야 한다면 합이 1로 맞춰진 소프트맥스가 편합니다.

## 소프트맥스를 손으로 계산해 보기

모델이 낸 점수(`decision_function`)에 위 공식을 직접 적용해서, 모델의 확률(`predict_proba`)과 같은지 확인합니다.

```run
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("penguins.csv").dropna()
X = df[["flipper_length_mm", "body_mass_g"]]
y = df["species"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)
one = X_test.iloc[[0]]
z = model.decision_function(one)[0]
print("penguin:", one.values[0], "-> true species:", y_test.iloc[0])
print("scores z:      ", z.round(3))
print("softmax by hand:", (np.exp(z) / np.exp(z).sum()).round(3))
print("predict_proba:  ", model.predict_proba(one)[0].round(3))
```

날개 194mm · 몸무게 3,550g인 펭귄의 점수는 Adelie 1.817, Chinstrap 1.361, Gentoo −3.179입니다. 손으로 계산한 확률(0.609, 0.386, 0.004)이 모델의 확률과 똑같습니다. Adelie와 Chinstrap의 점수 차이가 0.46밖에 안 돼서 확률도 61% 대 39%로 팽팽합니다. 실제로 이 펭귄은 Adelie라 맞혔지만, 이 두 종은 이 두 특성만으로는 헷갈리기 쉽다는 신호입니다.

## 다중 분류의 손실: 크로스 엔트로피

학습할 때 줄이는 손실은 이진 분류의 로그 손실을 그대로 넓힌 **크로스 엔트로피**입니다.

`손실 = 평균( −log p(정답 클래스) )`

정답 클래스에 준 확률만 봅니다. 정답에 0.9를 줬으면 −log 0.9 = 0.105로 작고, 0.1을 줬으면 −log 0.1 = 2.303으로 큽니다. 확신하며 틀릴수록 크게 혼나는 구조라서, 모델은 정답 쪽 확률을 높이는 방향으로 계수를 고칩니다. 아무것도 모르고 세 종에 1/3씩 주면 손실은 −log(1/3) = 1.099입니다. 이 값이 다중 분류 로그 손실의 기준선입니다.

## 다중 분류의 혼동행렬과 평균 두 가지

이진 분류의 혼동행렬은 2 × 2였지만, 3종이면 **3 × 3** 표가 됩니다. 행이 정답, 열이 예측입니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, classification_report, log_loss

df = pd.read_csv("penguins.csv").dropna()
X = df[["flipper_length_mm", "body_mass_g"]]
y = df["species"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)
pred = model.predict(X_test)
print(pd.DataFrame(confusion_matrix(y_test, pred, labels=model.classes_), index=model.classes_, columns=model.classes_))
print(classification_report(y_test, pred, digits=3))
print("log loss:", round(log_loss(y_test, model.predict_proba(X_test)), 3))
```

| 정답 \ 예측 | Adelie | Chinstrap | Gentoo |
| --- | --- | --- | --- |
| Adelie (44) | **41** | 3 | 0 |
| Chinstrap (20) | 14 | **6** | 0 |
| Gentoo (36) | 0 | 1 | **35** |

- 대각선(굵은 칸)이 맞힌 수입니다. Gentoo는 36마리 중 35마리를 맞혔습니다(재현율 0.972).
- **Chinstrap 20마리 중 14마리를 Adelie로** 잘못 봤습니다. 재현율이 0.300에 그칩니다. 처음에 짐작한 대로 두 종이 헷갈렸습니다.
- 로그 손실 0.405는 기준선 1.099보다 훨씬 작으니, 확률 자체는 꽤 쓸 만합니다.

클래스가 셋이면 정밀도 · 재현율 · F1도 클래스마다 하나씩 셋 나옵니다. 하나의 숫자로 요약하는 방법이 두 가지입니다.

| 평균 | 계산 | 이 모델의 F1 | 언제 쓰나 |
| --- | --- | --- | --- |
| **macro** | 클래스별 점수를 **똑같은 무게로** 평균 | 0.738 | 작은 클래스도 큰 클래스만큼 중요할 때 |
| **weighted** | 클래스별 점수를 **개수만큼 가중** 평균 | 0.799 | 전체 개체 기준 성능을 보고 싶을 때 |

macro F1 = (0.828 + 0.400 + 0.986) / 3 = 0.738입니다. 수가 적은 Chinstrap(20마리)의 낮은 점수 0.400이 3분의 1 무게로 반영돼서 weighted(0.799)보다 낮습니다. **작은 클래스를 못 맞히는 약점을 드러내려면 macro**를 봅니다. 불량 유형 분류처럼 드문 유형이 중요한 현장 문제라면 macro 평균과 클래스별 재현율을 함께 보고해야 합니다.

## 직접 해보기: 특성을 하나 더 넣으면

Adelie와 Chinstrap을 가르는 데 무엇이 도움이 될까요? 부리 길이(`bill_length_mm`)를 특성에 더해 보세요. 리스트에 열 이름 하나만 추가하면 됩니다.

```run
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

df = pd.read_csv("penguins.csv").dropna()
features = ["flipper_length_mm", "body_mass_g"]   # <- add "bill_length_mm"
X_train, X_test, y_train, y_test = train_test_split(df[features], df["species"], test_size=0.3, random_state=0, stratify=df["species"])
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)

```

부리 길이를 넣으면 정확도가 0.82에서 0.95로 오르고, Chinstrap의 재현율이 0.300에서 0.900으로, macro F1이 0.738에서 0.940으로 오릅니다. Chinstrap은 Adelie보다 부리가 훨씬 길기 때문입니다. 모델을 바꾸기 전에 **헷갈리는 두 클래스를 가르는 특성이 있는지** 먼저 찾아보는 것이 다중 분류에서 가장 효과적인 개선입니다.

## 자주 하는 실수

| 실수 | 무슨 일이 생기나 | 바로잡기 |
| --- | --- | --- |
| 정확도 하나만 보고함 | 작은 클래스를 거의 못 맞혀도 0.82처럼 괜찮아 보임 | 혼동행렬 + 클래스별 재현율 + macro 평균 |

## 정리

- 정답이 셋 이상이면 **다중 분류**입니다. 이진 분류기를 클래스마다 하나씩 두는 **OvR**, 점수를 확률로 나눠 갖는 **소프트맥스**가 있습니다.
- 소프트맥스 = e^(z_k) / Σ e^(z_j). 확률의 합이 1이고, 두 클래스일 때는 시그모이드와 같습니다. 손실은 −log p(정답)의 평균(크로스 엔트로피)입니다.
- 혼동행렬은 클래스 수만큼 커집니다. 펭귄에서는 Chinstrap 20마리 중 14마리를 Adelie로 봤습니다(재현율 0.300).
- **macro 평균**(0.738)은 작은 클래스의 약점을 드러내고, **weighted 평균**(0.799)은 개수 기준 성능을 보여 줍니다.
