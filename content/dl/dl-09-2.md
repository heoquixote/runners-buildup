- 실제 도구(PyTorch · Keras)와 코드 맛보기

## 단계별 점검 질문

| 단계 | 점검 질문 | 관련 레슨 |
| --- | --- | --- |
| 문제 정의 | 정말 딥러닝이 필요한가? 표 데이터라면 부스팅이 먼저 아닌가? 무엇을 맞히면 성공인가(지표)? | [딥러닝의 역사와 쓸 때 · 안 쓸 때](#/l/dl-00-2), [평가지표](#/l/ml-03-1) |
| 데이터 | 라벨은 믿을 만한가? 학습 · 검증 · 테스트를 **사람·설비·기간 단위로** 겹치지 않게 나눴나? 증강은 정답을 바꾸지 않나? | [학습용과 시험용 나누기](#/l/ml-01-4), [과적합을 막는 도구들](#/l/dl-04-3) |
| 모델 | 데이터 모양에 맞는 구조인가(표 → MLP, 사진 → CNN, 순서 → RNN/Transformer)? 사전학습 모델을 쓸 수 있나? 출력층과 손실은 짝이 맞나? | [신경망 설계도: 층 · 노드 · 출력층](#/l/dl-04-1), [CNN](#/l/dl-05-1) · [RNN과 시퀀스](#/l/dl-06-1) · [임베딩과 어텐션](#/l/dl-07-1), [처음부터 만들지 않는다: 전이 학습](#/l/dl-09-1) |
| 학습 | 학습률은 적당한가? 학습 곡선에 과적합이 보이나? 조기 종료를 걸었나? | [내리막으로 걷기: 경사하강법과 학습률](#/l/dl-02-2), [학습 곡선으로 과적합 알아보기](#/l/dl-04-2) |
| 평가 | 테스트 데이터로 한 번만 쟀나? **기준 모델**(찍기, 간단한 모델)보다 정말 나은가? 틀린 사례를 직접 들여다봤나? | [기준 모델과 누수](#/l/ml-01-5), [평가지표](#/l/ml-03-1) |
| 배포 · 관찰 | 예측 속도는 충분한가? 시간이 지나며 데이터가 바뀌어 성능이 떨어지지 않나? 언제 다시 학습하나? | |

"틀린 사례를 직접 들여다봤나?"가 특히 중요합니다. 불량 검사 모델이 틀린 사진 50장을 모아 보면 "조명이 어두운 사진에서 다 틀렸다", "라벨 자체가 잘못된 사진이 섞여 있었다" 같은 원인이 바로 보입니다. 모델을 바꾸는 것보다 데이터를 고치는 게 더 큰 효과를 내는 경우가 많습니다.

## 코드 맛보기 (읽기만)

이 트랙은 실습을 하지 않지만, 실제 코드가 어떻게 생겼는지 한 번 보겠습니다. 특성 4개로 3종류를 분류하는 [신경망 설계도: 층 · 노드 · 출력층](#/l/dl-04-1)의 신경망을 Keras로 쓰면 이렇습니다.

```python
from tensorflow import keras

model = keras.Sequential([
    keras.layers.Input(shape=(4,)),
    keras.layers.Dense(8, activation="relu"),
    keras.layers.Dropout(0.2),
    keras.layers.Dense(3, activation="softmax"),
])
model.compile(optimizer=keras.optimizers.Adam(learning_rate=0.001), loss="categorical_crossentropy", metrics=["accuracy"])
model.fit(X_train, y_train, epochs=50, batch_size=32, validation_data=(X_val, y_val),
          callbacks=[keras.callbacks.EarlyStopping(patience=5, restore_best_weights=True)])
```

처음 보는 코드인데도 단어들이 낯익지 않나요? 이 트랙에서 배운 개념이 그대로 이름으로 들어 있습니다.

| 코드 속 단어 | 뜻 | 배운 곳 |
| --- | --- | --- |
| `Input(shape=(4,))` | 입력층, 특성 4개 | [신경망 설계도: 층 · 노드 · 출력층](#/l/dl-04-1) |
| `Dense(8, activation="relu")` | 완전연결 은닉층, 노드 8개, ReLU | [활성화 함수: 신호를 다듬는 스위치](#/l/dl-01-2), [신경망 설계도: 층 · 노드 · 출력층](#/l/dl-04-1) |
| `Dropout(0.2)` | 학습 때 노드 20%를 무작위로 끄기 | [과적합을 막는 도구들](#/l/dl-04-3) |
| `Dense(3, activation="softmax")` | 출력층, 3종류, 소프트맥스 | [활성화 함수: 신호를 다듬는 스위치](#/l/dl-01-2) |
| `Adam(learning_rate=0.001)` | 옵티마이저 Adam, 학습률 0.001 | [내리막으로 걷기: 경사하강법과 학습률](#/l/dl-02-2), [더 똑똑하게 내려가기: 옵티마이저](#/l/dl-02-4) |
| `categorical_crossentropy` | 다중 분류 교차엔트로피 손실 | [틀린 정도 재기: 손실 함수](#/l/dl-02-1) |
| `epochs=50, batch_size=32` | 최대 50에폭, 미니배치 32개 | [조금씩 보고 고치기: 배치 · 미니배치 · 에폭](#/l/dl-02-3) |
| `EarlyStopping(patience=5, restore_best_weights=True)` | 조기 종료, 인내 5, 가장 좋았던 가중치로 되돌리기 | [학습 곡선으로 과적합 알아보기](#/l/dl-04-2) |

순전파·역전파·업데이트([순전파와 역전파](#/l/dl-03-1))는 `fit` 안에서 자동으로 일어납니다.

## 설정값 체크리스트

처음 학습이 잘 안 될 때 하나씩 확인할 목록입니다.

| 증상 | 먼저 볼 설정 |
| --- | --- |
| 손실이 안 줄어든다 | 학습률(너무 작거나 큼), 입력 표준화, 출력층·손실 짝 |
| 손실이 튀거나 NaN | 학습률 낮추기, 기울기 클리핑 ([기울기 소실과 폭주](#/l/dl-03-3)) |
| 학습 손실만 줄고 검증 손실은 오른다 | 조기 종료, 드롭아웃, 증강, 모델 줄이기 ([과적합을 막는 도구들](#/l/dl-04-3)) |
| 둘 다 높게 멈춘다 | 모델 키우기, 더 오래 학습 |
| 메모리 부족 오류 | 배치 크기 줄이기 |

한 번에 **하나씩만** 바꾸고 결과를 기록합니다. 여러 개를 한꺼번에 바꾸면 무엇이 효과였는지 알 수 없습니다.

## 해석과 책임

딥러닝은 정확하지만 **왜 그렇게 판단했는지 설명하기 어렵습니다.** 현장에서 이게 문제가 되는 경우가 있습니다.

- **설명이 필요한 결정**: 불량 판정으로 출하를 막거나, 대출을 거절할 때는 근거가 필요합니다. 어텐션 맵([어텐션: 어디를 볼지 스스로 정하기](#/l/dl-07-2))이나 사진에서 모델이 주목한 영역을 표시하는 방법으로 근거를 보완하고, 필요하면 해석 쉬운 모델을 함께 씁니다.
- **데이터 편향**: 특정 라인·특정 조명의 사진만으로 학습하면 다른 조건에서 성능이 떨어집니다. 사람 데이터라면 특정 집단에 불리한 판단을 배울 수 있습니다.
- **개인정보**: 얼굴·음성·글에는 개인정보가 담깁니다. 수집과 사용에 동의와 관리가 필요합니다.
- **사람의 확인**: 모델은 도구입니다. 중요한 결정에는 사람이 최종 확인하는 절차를 둡니다.

## 트랙 정리

- **DAY 01**: 딥러닝 = 층을 쌓아 **특징까지 스스로 배우는** 머신러닝. 사진·소리·글에 강하고, 표 데이터는 부스팅부터.
- **DAY 02**: 뉴런 = 가중합 + 활성화. 비선형 활성화와 은닉층이 있어야 XOR 같은 문제를 푼다.
- **DAY 03**: 손실로 틀린 정도를 재고, 경사하강법(학습률 · 미니배치 · Adam)으로 줄인다.
- **DAY 04**: 순전파 → 손실 → 역전파(연쇄법칙) → 업데이트. 기울기 소실은 ReLU · 잔차 연결 등으로 막는다.
- **DAY 05**: 출력층·손실은 문제에 맞춘 세트. 학습 곡선으로 과적합을 보고, 조기 종료 · 드롭아웃 · 증강으로 막는다.
- **DAY 06~08**: 사진은 CNN(필터 · 풀링), 순서는 RNN · LSTM(메모 · 게이트), 글은 임베딩 · 어텐션 · Transformer.
- **DAY 09**: 오토인코더(복원 오차로 이상 탐지), GAN · 확산 모델(새로 만들기).
- **DAY 10**: 사전학습 모델 + 전이 학습이 실무의 기본. 프로젝트는 문제 정의부터 배포 후 관찰까지 계속 돈다.

딥러닝 트랙을 모두 마쳤습니다. 수고 많으셨습니다.
