## 반 평균 키를 맞혀 보세요

새 학교에 전학 온 첫날, 누군가 "우리 반 평균 키가 얼마쯤일까?" 하고 묻습니다. 반 친구 30명을 모두 재 볼 수는 없으니, 옆자리 친구 몇 명의 키를 보고 짐작하겠지요. 그런데 마침 옆자리에 농구부 친구들만 앉아 있었다면요? 짐작이 크게 빗나갈 겁니다.

통계는 바로 이런 상황을 다루는 학문입니다. **일부만 보고, 매번 조금씩 흔들리는 숫자로, 그래도 믿을 만한 결론을 내리는 방법**이지요.

## 데이터가 가진 두 가지 한계

현실의 데이터 문제는 대부분 두 가지 한계를 갖고 있습니다.

1. **전체를 다 볼 수 없다.** 전국 고등학생 키를 다 잴 수도, 공장에서 만든 과자를 다 먹어 볼 수도 없습니다. 우리가 보는 것은 언제나 일부입니다.
2. **숫자는 언제나 흔들린다.** 같은 식당, 같은 요일이라도 손님이 남기는 팁은 날마다 다릅니다. 이런 우연한 흔들림을 **노이즈(noise)**라고 부릅니다.

그래서 숫자를 계산하는 것만으로는 부족합니다. "이 숫자를 **어디까지 믿어도 되나**"를 판단해야 하는데, 통계가 그 판단 기준을 줍니다.

## 직접 보기: 토요일과 일요일 팁

**데이터 소개 · 식당 팁 기록** (`tips.csv`)

미국 한 식당에서 웨이터 한 명이 몇 달 동안 받은 계산서 **244장**을 적은 데이터입니다. 통계 교재(Bryant & Smith, 1995)에 실린 뒤 데이터 분석 입문 예제로 널리 쓰입니다. **한 행 = 계산서 한 장**이고, 금액 단위는 달러입니다.

| 컬럼 | 뜻 | 자료형 | 예시 |
| --- | --- | --- | --- |
| `total_bill` | 계산 금액(달러) | 소수 | 16.99 |
| `tip` | 팁(달러) | 소수 | 1.01 |
| `sex` | 계산한 손님의 성별 | 글자 | Female, Male |
| `smoker` | 일행 중 흡연자가 있었나 | 글자 | No, Yes |
| `day` | 요일 | 글자 | Thur, Fri, Sat, Sun |
| `time` | 식사 시간대 | 글자 | Lunch, Dinner |
| `size` | 일행 수(명) | 정수 | 2 |

빈칸은 없습니다. 영업일이 목 ~ 일요일이라 월 ~ 수요일 기록은 없습니다.

이 트랙에서는 이처럼 실제 데이터를 많이 씁니다. 첫 데이터인 `tips.csv`로 먼저 팁의 평균을 구해 봅니다.

```run
import pandas as pd

df = pd.read_csv("tips.csv")
print("계산서 수:", len(df))
print("평균 팁:", round(df["tip"].mean(), 2), "달러")
```

계산서 244장의 평균 팁은 약 3.00달러입니다. 이번에는 토요일과 일요일만 따로 평균을 내 봅니다.

```run
import pandas as pd

df = pd.read_csv("tips.csv")
print(df.groupby("day")["tip"].mean().round(2)[["Sat", "Sun"]])
```

토요일은 2.99달러, 일요일은 3.26달러입니다. 일요일 손님이 팁을 약 0.26달러 더 줬네요. 그렇다면 "일요일 손님이 팁을 더 후하게 준다"고 말해도 될까요?

## 같은 데이터에서 뽑아도 평균은 흔들린다

이 질문에 답하기 전에 작은 실험을 해 봅시다. 요일을 무시하고 **같은 244장 안에서** 무작위로 40장씩 두 번 뽑아 평균을 비교합니다. 같은 식당, 같은 손님들 안에서 뽑았으니 원래는 차이가 없어야 합니다.

```run
import pandas as pd

df = pd.read_csv("tips.csv")
a = df["tip"].sample(40, random_state=7).mean()
b = df["tip"].sample(40, random_state=2).mean()
print("첫 번째 40장:", round(a, 2), "/ 두 번째 40장:", round(b, 2))
```

같은 데이터에서 뽑았는데도 첫 번째는 2.80달러, 두 번째는 3.28달러로 0.48달러나 차이가 납니다. 토요일과 일요일의 차이(0.26달러)보다도 큽니다. **아무 이유 없이도 이 정도 차이는 생긴다**는 뜻입니다.

직접 해 보세요: `random_state` 숫자를 바꿔 가며 실행해 보세요. 뽑을 때마다 평균이 달라지고, 차이도 커졌다 작아졌다 합니다.

```run
import pandas as pd

df = pd.read_csv("tips.csv")
for seed in [3, 4, 5, 6, 7]:
    print(seed, round(df["tip"].sample(40, random_state=seed).mean(), 2))
```

다섯 번 뽑았더니 평균이 2.80달러에서 3.27달러까지 오르내립니다. 그러니 토요일과 일요일의 0.26달러 차이가 "진짜 요일 차이"인지 "그냥 흔들림"인지는 눈으로 봐서는 알 수 없습니다. 이것을 판단하는 방법(가설검정)을 [가설검정의 논리와 p-value](#/l/st-05-1)에서 배웁니다.

## 통계가 하는 두 가지 일

통계가 하는 일은 크게 두 가지입니다.

::figure{src="content/img/stats/st00-desc-infer.svg" alt="손에 든 표본 데이터를 요약하는 기술통계와, 그 표본으로 모집단 전체에 대해 말하는 추론통계의 흐름" caption="기술통계는 손에 든 데이터를 설명하고, 추론통계는 그 데이터로 더 넓은 전체에 대해 조심스럽게 말합니다."}

**1. 기술통계 (요약하기)**
지금 손에 있는 데이터를 정리해서 보여 줍니다. 평균, 중앙값, 표준편차, 비율, 그래프가 여기에 속합니다. "이번 달 평균 팁은 3.00달러입니다"는 기술통계 문장입니다.

**2. 추론통계 (넓혀서 말하기)**
지금 가진 일부 데이터로 더 넓은 전체나 앞으로의 일에 대해 말하려고 합니다. 신뢰구간, 가설검정, 회귀분석이 여기에 속합니다. "이 식당 손님 전체로 봐도 일요일 팁이 더 많을 것 같습니다"는 추론통계 문장입니다.

| 문장 | 종류 | 이유 |
| --- | --- | --- |
| 계산서 244장의 평균 팁은 3.00달러다 | 기술 | 가진 데이터를 그대로 요약 |
| 일요일 계산서의 팁 평균이 토요일보다 0.26달러 높다 | 기술 | 관측한 차이를 그대로 말함 |
| 이 차이는 우연으로 보기 어렵다 | 추론 | 데이터 밖(전체 손님)으로 판단을 넓힘 |
| 다음 달에도 일요일 팁이 더 많을 것이다 | 추론 | 아직 오지 않은 일에 대해 말함 |

두 가지는 경쟁 관계가 아니라 **순서**입니다. 먼저 기술통계로 데이터 모양을 잘 이해하고, 그다음 추론통계로 결론을 어디까지 말할 수 있는지 따집니다. 이 순서를 거꾸로 하면 숫자는 그럴듯한데 현실과 맞지 않는 결론이 나옵니다.

## 통계 없이 숫자를 보면 생기는 실수

**① 평균 하나만 보고 판단한다**
반 친구 10명의 한 달 용돈이 대부분 5만 원인데 한 명이 100만 원이라면, 평균은 14만 원이 넘습니다. 평균만 보면 "우리 반은 용돈이 넉넉하다"는 틀린 결론이 나옵니다. ([대표값: 평균 · 중앙값 · 최빈값](#/l/st-01-1)에서 직접 계산해 봅니다.)

**② 한쪽으로 쏠린 일부만 본다**
학원가 앞에서만 "하루에 몇 시간 공부하나요?"를 물어보면 전체 학생보다 높게 나올 수밖에 없습니다. 데이터가 아무리 많아도, **뽑는 방법이 쏠려 있으면** 결론도 쏠립니다. ([표본 뽑기와 편향](#/l/st-03-1))

**③ "통계적으로 의미 있다"를 "중요하다"로 착각한다**
데이터가 아주 많으면 아주 작은 차이도 "우연이 아니다"라고 나옵니다. 하지만 하루 0.01달러 차이는 우연이 아니어도 신경 쓸 만큼 중요하지 않을 수 있습니다. ([표본 수 설계와 실무 판단](#/l/st-08-2))

## 좋은 분석가가 하는 세 문장

통계를 배운다는 것은 복잡한 수식을 외우는 일이 아닙니다. **데이터가 말해 주는 범위와 말해 주지 못하는 범위를 구분하는 태도**를 익히는 일입니다. 이 트랙을 마치면 다음 세 문장을 자연스럽게 말할 수 있게 됩니다.

> "지금 데이터에서는 이런 패턴이 보입니다."
> "다만 표본이 이렇게 모였기 때문에 이런 한계가 있습니다."
> "그래서 이 결론은 여기까지는 말할 수 있고, 그 이상은 더 확인이 필요합니다."

## 공장 데이터에서도 똑같다

**데이터 소개 · 설비 고장 기록 (AI4I 2020)** (`ai4i2020.csv`)

공작 기계 설비의 작동 조건과 고장 여부를 기록한 데이터 **10,000건**입니다. 실제 공장 데이터를 본떠 만든 공개 데이터(UCI 머신러닝 저장소, CC BY 4.0)로, 예지 보전(고장 나기 전에 미리 알아채기) 연습에 많이 씁니다. **한 행 = 작업 한 건**입니다.

| 컬럼 | 뜻 | 자료형 | 예시 |
| --- | --- | --- | --- |
| `type` | 제품 품질 등급(L < M < H) | 글자 | L, M, H |
| `air_temp` | 주변 공기 온도(K, 켈빈) | 소수 | 298.1 |
| `process_temp` | 공정 온도(K) | 소수 | 308.6 |
| `rpm` | 분당 회전 수 | 정수 | 1551 |
| `torque` | 토크(Nm, 돌리는 힘) | 소수 | 42.8 |
| `tool_wear` | 공구를 쓴 시간(분) | 정수 | 0 |
| `failure` | 고장 여부(1 = 고장, 0 = 정상) | 정수 | 0, 1 |

빈칸은 없습니다. 고장(`failure` = 1)은 339건(3.4%)뿐이라 아주 드뭅니다. 켈빈 온도에서 273.15를 빼면 섭씨입니다(298K ≈ 25℃).

식당 팁만의 이야기가 아닙니다. 이 트랙에서 자주 쓸 공장 설비 데이터(`ai4i2020.csv`)를 열어 봅니다. 위 표의 `failure`(1 = 고장)가 이번에 볼 열입니다.

```run
import pandas as pd

df = pd.read_csv("ai4i2020.csv")
print("설비 수:", len(df), "/ 전체 고장률:", round(df["failure"].mean() * 100, 2), "%")
```

10,000대 전체의 고장률은 3.39%입니다. 현실에서는 10,000대를 다 점검할 시간이 없어서 100대만 골라 점검한다고 해 봅시다. 100대씩 다섯 번 뽑아 고장률을 구합니다.

```run
import pandas as pd

df = pd.read_csv("ai4i2020.csv")
for seed in [1, 2, 3, 4, 5]:
    print(f"{seed}번째 100대 고장률: {df['failure'].sample(100, random_state=seed).mean() * 100:.0f}%")
```

1%, 1%, 9%, 3%, 7%로 크게 오르내립니다. 전체는 3.39%인데, 운이 나쁘면 100대 점검 결과가 9%로 나와 "공장에 큰 문제가 생겼다"고 착각할 수 있고, 운이 좋으면 1%로 나와 문제를 놓칠 수도 있습니다. 이번 달 점검 결과가 지난달보다 2%p 높다고 바로 원인 찾기에 나서기 전에 **"이 정도 차이는 우연히도 생기나?"**를 먼저 물어야 하는 이유입니다.

## 기술 문장과 추론 문장 구분 연습

분석 보고서를 쓸 때 가장 흔한 실수는 기술 문장과 추론 문장을 섞어서, 관측한 사실처럼 추측을 쓰는 것입니다. 앞의 설비 결과로 연습해 봅니다.

| 문장 | 종류 | 고쳐 쓸 점 |
| --- | --- | --- |
| "점검한 100대 중 9대가 고장이었다" | 기술 | 그대로 좋음 |
| "우리 공장 고장률은 9%다" | 추론 | 100대로 10,000대 전체를 말함. 흔들림 범위를 함께 적어야 함 |
| "지난달보다 고장률이 올랐다" | 추론 | 표본 차이가 우연인지 검정이 필요 ([가설검정의 논리와 p-value](#/l/st-05-1)) |
| "10,000대 전체 기록상 고장률은 3.39%였다" | 기술 | 전체를 다 봤으니 기술통계로 충분 |

마지막 줄처럼 **전체를 다 가지고 있으면** 추론이 필요 없습니다. 추론통계는 "일부만 봤을 때" 필요한 도구입니다.

## 정리

- 데이터의 두 한계: **일부만 본다**, **숫자는 흔들린다**.
- **기술통계**는 손에 든 데이터를 요약하고, **추론통계**는 그것으로 더 넓은 전체에 대해 조심스럽게 말한다.
- 기술통계는 지도이고, 추론통계는 그 지도를 보고 내리는 판단입니다. 지도가 부정확하면 판단도 흔들립니다.
