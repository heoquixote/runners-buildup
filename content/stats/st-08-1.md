## 급식 메뉴 두 개 중 무엇이 인기 있을까

학교 급식실에서 새 메뉴 B가 기존 메뉴 A보다 인기가 있는지 알고 싶습니다. 이번 주는 A, 다음 주는 B를 내고 남긴 양을 비교하면 될까요? 그런데 다음 주에 시험 기간이 겹쳐서 학생들이 입맛이 없었다면요? 날씨가 더웠다면요? **메뉴 말고 다른 것도 함께 바뀌어서** 무엇 때문에 차이가 났는지 알 수 없습니다.

공정하게 비교하려면 **같은 기간에, 학생들을 무작위로 두 그룹으로 나눠서**, 한 그룹에는 A, 다른 그룹에는 B를 주고 비교해야 합니다. 이렇게 하나만 다르게 하고 나머지 조건은 모두 같게 만든 비교 실험을 웹 · 앱 업계에서는 **A/B 테스트**라고 부릅니다. 버튼 색, 광고 문구, 추천 방식처럼 무언가를 바꿨을 때 정말 효과가 있는지 확인하는 가장 기본적인 방법입니다.

::figure{src="content/img/stats/st08-ab-flow.svg" alt="A/B 테스트 흐름: 사용자들이 동전 던지기(무작위 배정)로 A 그룹(기존)과 B 그룹(새 버전)으로 나뉘고, 각 그룹의 전환율을 측정해 비교한 뒤 검정과 신뢰구간으로 판단하는 흐름도" caption="A/B 테스트는 무작위 배정 → 같은 기간 동안 두 버전 노출 → 주 지표 비교 → 검정 · 신뢰구간으로 판단하는 순서로 진행됩니다."}

## 무작위 배정이 공정한 이유

A/B 테스트의 핵심은 **무작위 배정**(random assignment)입니다. 동전을 던져 앞면이면 A, 뒷면이면 B로 보내는 것처럼, 누가 어느 그룹에 갈지를 우연에 맡깁니다. 그러면 나이, 성별, 관심사, 그날의 기분 같은 **다른 모든 차이가 두 그룹에 고르게 섞입니다.** 그래서 두 그룹의 결과가 다르다면, 남은 차이는 우리가 바꾼 것(B 버전) 하나뿐입니다.

정말 고르게 섞이는지 확인해 봅니다. 사용자 1,000명(나이는 평균 35세쯤)을 무작위로 500명씩 나누고 두 그룹의 평균 나이를 비교합니다.

```run
import numpy as np

rng = np.random.default_rng(0)
age = rng.normal(35, 10, 1000).round()
group = rng.permutation(np.repeat(["A", "B"], 500))
print("A 평균 나이:", age[group == "A"].mean(), "/ B 평균 나이:", age[group == "B"].mean())
```

A 그룹 34.0세, B 그룹 35.0세로 거의 같습니다. 나이 말고도 우리가 재지 못한 모든 특성이 이렇게 비슷하게 나뉩니다. 이것이 [DAY 05의 편향](#/l/st-03-1)과 [DAY 11의 교란변수](#/l/st-10-1) 문제를 한 번에 해결하는 가장 강력한 방법입니다.

반대로 "원하는 사람만 새 버전을 써 보게" 하면 무작위가 아닙니다. 새 기능을 직접 고른 사람들은 원래 더 적극적인 사용자일 가능성이 높아서, 결과가 좋게 나와도 기능 덕분인지 사람 덕분인지 알 수 없습니다.

## 실험 전에 정해 둘 것

A/B 테스트는 결과를 보기 **전에** 다음을 정해 두어야 합니다. 결과를 보고 나서 기준을 바꾸면 [p-value의 의미](#/l/st-05-1)가 무너집니다.

1. **주 지표 하나**: 무엇으로 이겼다고 판단할지 (예: 구매 전환율). 지표를 여러 개 보다가 좋게 나온 것만 고르면 안 됩니다.
2. **최소 의미 있는 차이**: 이 정도는 올라야 바꿀 가치가 있다 (예: 1%p)
3. **표본 수와 기간**: 차이를 잡아낼 만큼 충분히 ([다음 레슨](#/l/st-08-2)에서 계산)
4. **유의수준**: 보통 α = 0.05

## 결과 데이터: 두 전환율

온라인 쇼핑몰이 "구매하기" 버튼 디자인을 바꾸는 A/B 테스트를 했습니다. 각 그룹 2,000명씩 방문했고, 구매한 사람 수는 이렇습니다.

| 그룹 | 방문자 | 구매 | 구매 안 함 |
| --- | --- | --- | --- |
| A (기존) | 2,000 | 80 | 1,920 |
| B (새 디자인) | 2,000 | 110 | 1,890 |

방문자 중 구매한 비율을 **전환율**(conversion rate)이라고 합니다.

```run
a_buy, a_n, b_buy, b_n = 80, 2000, 110, 2000
pa, pb = a_buy / a_n, b_buy / b_n
print(f"A 전환율 {pa:.2%} / B 전환율 {pb:.2%} / 차이 {pb - pa:.2%}p")
```

A는 4.00%, B는 5.50%로 B가 1.5%p 높습니다. 이 차이가 우연인지 검정해야 합니다.

## 두 비율 검정: 카이제곱으로

2 × 2 표(그룹 × 구매 여부)이니 [카이제곱 독립성 검정](#/l/st-06-1)을 그대로 쓸 수 있습니다. "그룹과 구매가 관련 없다" = "두 전환율이 같다"는 귀무가설입니다.

```run
from scipy import stats

table = [[80, 1920], [110, 1890]]
res = stats.chi2_contingency(table)
print("χ² =", round(res.statistic, 2), "/ p-value =", round(res.pvalue, 4))
```

p-value = 0.031로 0.05보다 작습니다. **귀무가설을 기각**하고, 새 디자인의 전환율이 기존과 다르다고(더 높다고) 볼 근거가 있다고 판단합니다.

## 차이의 신뢰구간

p-value는 "차이가 있다"까지만 말해 줍니다. 실무에서 더 궁금한 것은 "**얼마나** 오를까?"입니다. 그래서 두 비율 차이의 [신뢰구간](#/l/st-04-2)을 함께 보고합니다. 차이의 표준오차는 각 비율의 분산을 더한 뒤 제곱근을 씌워 구합니다.

```run
import numpy as np

pa, pb, n = 80 / 2000, 110 / 2000, 2000
se = np.sqrt(pa * (1 - pa) / n + pb * (1 - pb) / n)
diff = pb - pa
print(f"차이 {diff:.2%}p, 95% CI {diff - 1.96 * se:.2%}p ~ {diff + 1.96 * se:.2%}p")
```

차이의 95% 신뢰구간은 0.18%p ~ 2.82%p입니다. 구간이 0을 포함하지 않으니 검정 결과와 같은 결론이지만, 훨씬 많은 것을 알려 줍니다. **효과는 거의 없을(0.2%p) 수도, 꽤 클(2.8%p) 수도 있다**는 것입니다. 이 정도 불확실성이라면 바로 전면 적용할지, 더 오래 실험할지 판단할 재료가 됩니다.

## 상대 차이와 절대 차이

전환율 4.0% → 5.5%를 말하는 방법은 두 가지입니다.

| 방식 | 계산 | 값 | 주의 |
| --- | --- | --- | --- |
| **절대 차이** | 5.5% − 4.0% | **+1.5%p** (퍼센트포인트) | 실제로 늘어난 구매자 비율 |
| **상대 차이** | (5.5 − 4.0) ÷ 4.0 | **+37.5%** | 기준이 작으면 숫자가 커 보임 |

"전환율 37.5% 상승!"과 "전환율 1.5%p 상승"은 같은 결과입니다. 상대 차이는 기준값이 작을수록 크게 부풀어 보이므로, 보고할 때는 **두 가지를 함께** 쓰거나 최소한 %와 %p를 정확히 구분하세요. "4%에서 5.5%로 1.5% 올랐다"는 틀린 표현입니다.

## 몰래 들여다보기(peeking)의 위험

실험을 20일 동안 하기로 해 놓고, **매일** 결과를 확인하다가 p < 0.05가 나오는 날 바로 멈추면 어떻게 될까요? 실제로는 A와 B가 **똑같은**(전환율 5%) 실험 500개로 시뮬레이션해 봅니다. 하루에 그룹당 100명씩 들어옵니다.

```run
import numpy as np

rng = np.random.default_rng(0)
a = (rng.random((500, 20, 100)) < 0.05).sum(axis=2).cumsum(axis=1)   # 실험 500개 × 20일, 누적 구매 수
b = (rng.random((500, 20, 100)) < 0.05).sum(axis=2).cumsum(axis=1)
n = np.arange(1, 21) * 100; p = (a + b) / (2 * n); z = (b - a) / n / np.sqrt(p * (1 - p) * 2 / n)
print("매일 보다가 유의하면 멈춤:", (abs(z) > 1.96).any(axis=1).mean(), "/ 마지막 날 한 번만:", (abs(z[:, -1]) > 1.96).mean())
```

차이가 전혀 없는데도 매일 들여다보다 멈추면 23.6%의 실험이 "유의한 차이 발견"으로 끝납니다. 정해진 날에 한 번만 보면 약속대로 5%입니다. 매일 보는 것은 [검정을 20번 하는 것](#/l/st-05-2)과 같아서 헛경보가 쌓이기 때문입니다. **실험 기간과 표본 수는 미리 정하고, 끝날 때 한 번 판단**하세요.

## 실무 예제: 결과 판정 함수 만들기

실험을 여러 번 하다 보면 같은 계산을 반복합니다. 두 그룹의 구매 수와 방문자 수를 넣으면 차이, 95% 신뢰구간, p-value를 돌려주는 함수를 만들어 둡니다.

```run
import numpy as np
from scipy import stats

def ab(a_buy, a_n, b_buy, b_n):
    pa, pb = a_buy / a_n, b_buy / b_n; se = np.sqrt(pa * (1 - pa) / a_n + pb * (1 - pb) / b_n)
    p = stats.chi2_contingency([[a_buy, a_n - a_buy], [b_buy, b_n - b_buy]]).pvalue
    return f"차이 {(pb - pa) * 100:+.2f}%p (95% CI {(pb - pa - 1.96 * se) * 100:+.2f} ~ {(pb - pa + 1.96 * se) * 100:+.2f}), p = {p:.3f}"

print("버튼 실험:", ab(80, 2000, 110, 2000))
print("문구 실험:", ab(400, 10000, 430, 10000))
print("작은 실험:", ab(12, 300, 20, 300))
```

세 실험의 결과를 읽어 봅니다.

- **버튼 실험**: +1.50%p, 구간 전체가 0보다 큼 → 효과가 있다고 볼 근거가 있음.
- **문구 실험**: 방문자가 10,000명씩이나 되는데 +0.30%p, 구간이 −0.25 ~ +0.85로 0을 포함 → 효과가 있다 해도 1%p 미만일 가능성이 큼.
- **작은 실험**: 차이는 +2.67%p로 가장 크지만 구간이 −0.92 ~ +6.26으로 아주 넓음 → 300명씩으로는 판단할 수 없음. "효과 없음"이 아니라 **"아직 모름"**.

같은 "유의하지 않음"(문구 실험, 작은 실험)이라도 신뢰구간을 보면 의미가 전혀 다릅니다. 문구 실험은 "효과가 있어도 작다", 작은 실험은 "더 모아야 안다"입니다.

## 자주 하는 실수

1. **실험 도중 사용자를 다시 배정한다.** 같은 사람이 A와 B를 오가면 두 그룹이 섞여 차이가 흐려집니다. 한 번 배정한 사람은 끝까지 같은 그룹에 둡니다.
2. **주말만, 이벤트 기간만 실험한다.** 특정 기간의 사용자는 평소와 다를 수 있습니다. 최소 1주일(요일 효과)은 돌리는 것이 일반적입니다.
3. **그룹 크기가 계획과 크게 다른데 확인하지 않는다.** 50 : 50으로 나눴는데 52 : 48로 나왔다면 배정 과정에 버그가 있을 수 있습니다(표본 비율 불일치, SRM).

## 정리

- **A/B 테스트**: 하나만 바꾸고 **무작위 배정**으로 두 그룹을 나눠 같은 기간에 비교한다. 무작위 배정은 다른 모든 차이를 고르게 섞어 준다.
- 실험 전에 **주 지표 · 최소 의미 있는 차이 · 표본 수 · 유의수준**을 정한다.
- 두 전환율 비교는 2 × 2 표의 카이제곱 검정(`stats.chi2_contingency`), 그리고 **차이의 신뢰구간**을 함께 보고한다.
- 절대 차이(%p)와 상대 차이(%)를 구분한다.
- 결과를 매일 들여다보다 멈추면 헛경보가 크게 늘어난다.
