## 학습 목표

- 결정트리가 어떻게 분할 기준을 찾는지 직관적으로 설명할 수 있습니다.
- 앙상블을 `Bagging`, `Boosting`, `Stacking`, `Voting`으로 나눠 이해할 수 있습니다.
- 랜덤포레스트와 부스팅 계열 모델의 차이를 큰 그림에서 이해할 수 있습니다.
- XGBoost, LightGBM, CatBoost가 왜 따로 자주 언급되는지 설명할 수 있습니다.
- 선형모델과 트리모델의 장단점을 비교할 수 있습니다.
- 트리 기반 모델을 실무에서 쓸 때 주의할 점을 말할 수 있습니다.

## 초심자용 한 줄 요약

트리 기반 모델은 `질문을 계속 나누며 데이터를 분기하는 방식`으로 예측하며, 비선형 패턴을 잘 잡는 것이 큰 강점입니다.

## 오늘의 목표

오늘은 입문 이후 가장 자주 만나는 모델군인 트리 계열을 정리합니다.

- 결정트리의 기본 동작을 이해합니다.
- 앙상블을 어떤 방식으로 묶는지 큰 구조를 먼저 봅니다.
- 랜덤포레스트와 여러 부스팅 계열을 비교합니다.
- 언제 선형모델보다 유리한지 판단합니다.

## 결정트리는 어떻게 생각하면 될까

결정트리는 데이터를 계속 질문으로 나누는 모델입니다.

예:

1. 최근 30일 방문 수가 3회 이하인가
2. 평균 주문 금액이 2만 원 이하인가
3. 고객 등급이 VIP인가

이런 질문을 순서대로 따라가면서 최종 예측을 만듭니다.

즉, 선형회귀가 `가중합` 중심이라면, 결정트리는 `조건 분기` 중심입니다.

## 왜 트리가 직관적인가

트리 구조는 사람이 읽기에 비교적 자연스럽습니다.

- 어떤 조건에서 분기되는지 보이기 때문
- 비선형 관계를 잘 잡기 때문
- 변수 간 상호작용을 자동으로 반영하기 때문

예를 들어 “방문 수가 적고, 주문 금액도 낮은 고객”처럼  
여러 조건이 결합된 패턴을 선형모델보다 자연스럽게 표현할 수 있습니다.

## 하지만 단일 결정트리의 한계

결정트리는 해석은 쉽지만 흔들리기 쉽습니다.

- 데이터가 조금만 바뀌어도 트리 구조가 달라질 수 있음
- 깊어질수록 과적합되기 쉬움
- 일반화 성능이 불안정할 수 있음

그래서 실무에서는 단일 트리보다 `앙상블`을 더 자주 씁니다.

## 앙상블을 구조로 먼저 나누면

앙상블은 여러 모델을 결합해 더 안정적이거나 더 강한 예측을 만들려는 접근입니다.

입문 단계에서는 아래 4가지로 나누면 가장 이해하기 쉽습니다.

- `Bagging`: 비슷한 모델을 여러 번 학습해 평균이나 투표로 합침
- `Boosting`: 앞 모델의 오차를 뒤 모델이 순차적으로 보완
- `Voting`: 서로 다른 여러 모델의 최종 예측을 단순 투표 또는 평균으로 합침
- `Stacking`: 여러 모델의 예측을 다시 다른 모델이 입력으로 받아 최종 판단

즉, 앙상블은 단순히 `트리를 많이 쓰는 것`이 아니라  
`어떻게 결합하느냐`의 설계 문제이기도 합니다.

## 트리 모델 종류를 어떻게 나눠 보면 좋을까

입문 단계에서는 아래 흐름으로 이해하시면 좋습니다.

- `결정트리`: 한 개 트리로 분기 규칙을 만드는 출발점
- `랜덤포레스트`: 여러 트리를 평균 내서 흔들림을 줄이는 bagging 계열
- `Gradient Boosting`: 이전 오차를 순차적으로 줄이는 boosting 계열
- `XGBoost`, `LightGBM`, `CatBoost`: boosting을 더 빠르고 강하게 만든 실무형 구현체
- `Voting`, `Stacking`: 트리뿐 아니라 서로 다른 모델들을 결합하는 일반 앙상블 전략

즉, 트리 모델은 이름이 많아 보여도  
`단일 트리 -> 여러 트리 평균 -> 여러 트리 순차 보정` 흐름으로 잡으면 구조가 단순해집니다.

`Voting`, `Stacking`처럼 여러 모델을 조합하는 방식은  
이후 실무에서 `로지스틱 + 랜덤포레스트 + boosting`을 함께 묶는 설계로 자주 이어집니다.

## 랜덤포레스트

랜덤포레스트는 여러 개의 트리를 만들어 평균 또는 투표로 예측합니다.

핵심 아이디어:

- 데이터 샘플을 여러 번 다르게 뽑음
- 각 트리마다 일부 feature만 사용
- 결과를 합쳐 안정성을 높임

장점:

- 단일 트리보다 과적합이 덜함
- 성능이 안정적임
- 비선형성과 상호작용을 잘 잡음

단점:

- 해석이 단일 트리보다 어려움
- 모델 크기가 커짐

## Gradient Boosting

부스팅은 여러 모델을 순차적으로 학습시키며  
이전 모델이 틀린 부분을 다음 모델이 보완하는 방식입니다.

대표 예:

- Gradient Boosting
- XGBoost
- LightGBM
- CatBoost

직관적으로는:

- 랜덤포레스트: 여러 사람 의견을 평균 내는 느낌
- 부스팅: 틀린 문제를 복습하며 점점 보완하는 느낌

부스팅은 강력한 성능을 내는 경우가 많지만,  
튜닝과 학습 설정에 조금 더 신경을 써야 합니다.

## XGBoost, LightGBM, CatBoost는 왜 자주 따로 부를까

세 모델은 모두 부스팅 계열이지만 실무에서 성능과 편의성 차이 때문에 따로 많이 언급됩니다.

- `XGBoost`: 규제가 잘 잡혀 있고 문서와 예제가 많아 안정적인 선택지
- `LightGBM`: 큰 데이터에서 빠르고 메모리 효율이 좋은 편
- `CatBoost`: 범주형 변수를 다루기 편하고 전처리 부담을 줄여주는 편

즉, 같은 부스팅이라도  
`어떤 데이터인가`, `범주형이 많은가`, `속도가 중요한가`에 따라 선택이 갈립니다.

## 선형모델과 트리모델 비교

| 기준 | 선형모델 | 트리 기반 모델 |
| --- | --- | --- |
| 해석 가능성 | 높음 | 중간 |
| 비선형 패턴 | 약함 | 강함 |
| 전처리 부담 | 스케일링 등 신경 씀 | 비교적 적음 |
| 범주/상호작용 처리 | 수동 설계가 많음 | 자동으로 일부 반영 |
| baseline 적합성 | 매우 좋음 | 좋음 |

즉, 선형모델은 `빠르고 설명이 쉽고`, 트리모델은 `유연하고 성능이 강한` 편입니다.

## 상황별 빠른 모델 선택 가이드

입문 단계에서는 아래처럼 `첫 후보`를 잡으면 방향을 빠르게 정할 수 있습니다.

| 상황 | 먼저 볼 모델 | 왜 그렇게 보나 | 같이 주의할 점 |
| --- | --- | --- | --- |
| 데이터가 상대적으로 적다 | Logistic Regression | 구조가 단순하고 과하게 흔들릴 가능성이 비교적 낮아 baseline으로 안정적 | 비선형 관계가 강하면 한계가 있음 |
| 데이터가 크고 tabular 성능이 중요하다 | XGBoost | 비선형성과 상호작용을 잘 잡고 boosting 계열 성능이 강한 편 | 아주 큰 데이터에서는 LightGBM이 속도상 더 유리할 수도 있음 |
| 범주형 변수가 많다 | CatBoost | 범주형 처리 부담을 줄이며 강한 성능을 내기 쉬움 | 의미 없는 ID 컬럼까지 좋은 변수처럼 넣으면 위험 |
| 설명력이 중요하다 | Logistic Regression | 계수 방향, odds, threshold 설명이 비교적 명확 | 스케일링, 인코딩, 다중공선성 점검이 필요 |
| 정확도가 중요하다 | Boosting 계열 | tabular 분류에서 높은 성능을 내는 경우가 많음 | 해석과 운영 복잡도가 같이 올라갈 수 있음 |

이 표는 절대 규칙이 아니라 `처음 무엇부터 시도할지 정하는 빠른 기준`입니다.

실무에서는 보통 아래처럼 생각하면 좋습니다.

1. 먼저 로지스틱 회귀로 baseline과 설명 구조를 만든다
2. 성능이 더 필요하면 랜덤포레스트나 boosting으로 확장한다
3. 범주형이 많으면 CatBoost를 일찍 후보에 넣는다
4. 데이터가 크고 성능 경쟁이 중요하면 XGBoost 같은 boosting을 강하게 검토한다

## feature importance는 어떻게 봐야 할까

트리 모델을 쓰면 feature importance를 쉽게 볼 수 있습니다.  
하지만 이것을 바로 “원인”으로 해석하면 위험합니다.

주의할 점:

- 중요도가 높다고 인과관계는 아님
- 상관된 변수끼리는 중요도가 분산될 수 있음
- 데이터 분포가 바뀌면 중요도도 달라질 수 있음

즉, importance는 `모델이 많이 참고한 변수` 정도로 먼저 읽는 것이 안전합니다.

## 실무에서 언제 문제가 되는가

### 1. 표본 수가 매우 적은데 트리 깊이가 큰 경우

쉽게 과적합됩니다.

### 2. 범주 수가 너무 많은 고카디널리티 변수

ID 성격이 강한 컬럼은 트리도 잘못 학습할 수 있습니다.

### 3. 설명 책임이 큰 프로젝트

성능은 좋지만 의사결정 근거를 매우 명확히 요구하는 환경에서는  
단순 선형모델이 더 적합할 수 있습니다.

### 4. 데이터 분포 변화

트리모델도 학습 시점 패턴에 의존하므로 drift가 생기면 성능이 떨어집니다.

## 대안은 무엇인가

상황에 따라 아래 선택지가 있습니다.

- 해석이 최우선 -> 선형모델, 특히 로지스틱 회귀
- 빠른 baseline -> 로지스틱 회귀, 얕은 트리
- 성능 중심 tabular data -> 랜덤포레스트, Gradient Boosting, XGBoost, LightGBM, CatBoost
- 규칙이 명확 -> 룰 기반

결국 좋은 모델은 `무조건 가장 복잡한 모델`이 아니라  
`지금 문제에서 성능, 해석, 운영 비용 균형이 가장 좋은 모델`입니다.

추가로 `Bagging`, `Boosting`, `Stacking`, `Voting`을 구조적으로 비교하고 싶다면  
`10-7. 앙상블 전략: Bagging, Boosting, Stacking, Voting` 페이지를 이어서 보시면 좋습니다.
