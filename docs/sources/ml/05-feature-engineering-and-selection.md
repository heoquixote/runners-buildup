## 학습 목표

- Feature Engineering이 왜 모델링 성능과 해석에 큰 영향을 주는지 설명할 수 있습니다.
- 파생변수, Feature Selection, Feature Importance, SHAP, PDP, 다중공선성을 하나의 흐름으로 연결해 이해할 수 있습니다.
- 좋은 변수를 추가하는 일과 불필요한 변수를 줄이는 일이 왜 동시에 중요한지 말할 수 있습니다.
- Feature Engineering이 누수와 과적합을 만들 수 있는 지점도 구분할 수 있습니다.

## 초심자용 한 줄 요약

Feature Engineering은 `모델을 바꾸기 전에 데이터 표현 자체를 더 예측하기 좋은 형태로 바꾸는 작업`입니다.

## 오늘의 목표

이번 장에서는 모델 앞단에서 성능을 좌우하는 변수 설계를 다룹니다.

- 파생변수가 무엇인지 이해합니다.
- 너무 많은 변수 중 무엇을 남길지 감각을 잡습니다.
- 변수 중요도와 모델 해석 도구를 읽을 때의 함정도 봅니다.
- 다중공선성이 왜 계수 해석을 흔드는지 연결합니다.

## 왜 Feature Engineering이 중요한가

같은 모델이라도 어떤 feature를 넣느냐에 따라 성능 차이가 크게 날 수 있습니다.

예:

- 단순 `총 구매금액`보다 `최근 30일 구매금액`
- 단순 `로그인 수`보다 `최근 7일 / 30일 로그인 비율`
- 단순 `나이`보다 `연령대 구간`

즉, 모델 성능은 알고리즘만이 아니라  
`데이터를 어떤 관점으로 다시 표현했는가`에 크게 좌우됩니다.

현업에서는 오히려 모델 교체보다 feature 개선이 더 큰 차이를 만드는 경우가 많습니다.

## Feature Engineering은 무엇을 포함하나

넓게 보면 아래가 모두 feature engineering에 들어갑니다.

- 파생변수 만들기
- 구간화(binning)
- 날짜/시간 변수 분해
- 로그 변환
- interaction feature
- 집계 feature
- feature selection
- 다중공선성 점검과 제거

즉, 단순히 “새 컬럼 하나 만들기”가 아니라  
`모델이 더 잘 읽을 수 있는 표현을 설계하는 작업`입니다.

## 파생변수는 왜 자주 쓰나

원본 컬럼만으로는 패턴이 잘 안 보일 때가 많습니다.

예:

- `last_login_date`만 있는 것보다 `days_since_last_login`
- `birth_year`만 있는 것보다 `age`
- `total_amount`만 있는 것보다 `avg_amount_per_order`

이런 파생변수는 모델이 직접 찾아내기 어려운 구조를  
사람이 먼저 힌트로 제공하는 역할을 합니다.

## 하지만 많이 만들수록 항상 좋은가

그렇지는 않습니다.

feature를 무작정 늘리면 아래 문제가 생길 수 있습니다.

- 과적합 위험 증가
- 해석 어려움 증가
- 운영 파이프라인 복잡도 증가
- 누수 컬럼 유입 가능성 증가
- 다중공선성 심화

즉, `더 많이`보다 `더 의미 있게`가 중요합니다.

## Feature Selection은 왜 필요한가

변수가 너무 많으면 모델이 잡음까지 배우기 쉬워집니다.

그래서 아래 질문이 필요합니다.

- 정말 예측에 도움이 되는가
- 중복 정보가 너무 많은가
- 비용 대비 유지 가치가 있는가
- 운영 환경에서도 계산 가능한가

특히 표본 수가 적은데 feature 수가 많으면  
선형모델이나 로지스틱 회귀에서 불안정성이 커질 수 있습니다.

## Feature Importance는 무엇을 도와주나

변수 중요도는 모델이 어떤 feature에 상대적으로 많이 의존하는지 보는 출발점입니다.

하지만 중요도는 아래와 다릅니다.

- 인과관계
- 반드시 유지해야 하는 변수
- 비즈니스 절대 영향도

즉, 중요도는 해석의 출발점이지 최종 결론은 아닙니다.

최근에는 여기에 더해 아래 해석 도구도 자주 함께 봅니다.

- `Permutation Importance`
- `SHAP`
- `PDP(Partial Dependence Plot)`

## 다중공선성은 왜 따로 봐야 하나

비슷한 변수가 여러 개 함께 들어가면  
선형계수 해석이 흔들릴 수 있습니다.

예:

- `월매출`, `주매출`, `일평균매출`
- `age`, `birth_year`
- `visits_last_30d`, `visits_last_7d`, `visits_ratio_7_to_30`

이때 모델 성능은 비슷해 보여도  
각 변수 계수는 매우 불안정하게 흔들릴 수 있습니다.

## 실무에서 언제 문제가 되는가

### 1. 미래 정보를 파생변수에 섞는 경우

예측 시점 이후 데이터가 들어가면  
파생변수도 곧 데이터 누수입니다.

### 2. 좋은 뜻으로 만든 변수가 실제로는 중복만 늘리는 경우

정보량은 거의 같은데 컬럼만 많아질 수 있습니다.

### 3. 변수 중요도나 SHAP 값을 그대로 의사결정 근거로 쓰는 경우

값이 커 보인다고 해서 반드시 액션 우선순위도 높은 것은 아닙니다.

## 정리

- Feature Engineering은 모델이 데이터를 더 잘 읽도록 표현을 바꾸는 작업입니다.
- 좋은 feature를 추가하는 것과 불필요한 feature를 줄이는 것은 같이 가야 합니다.
- 파생변수, 중요도, SHAP/PDP, selection, 다중공선성은 따로 떨어진 주제가 아니라 하나의 설계 흐름입니다.
