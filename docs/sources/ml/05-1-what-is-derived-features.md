## 학습 목표

- 파생변수가 무엇인지 설명할 수 있습니다.
- 원본 변수보다 파생변수가 더 유용해지는 상황을 이해할 수 있습니다.
- 날짜, 비율, 집계, interaction 기반 파생변수 예시를 말할 수 있습니다.
- 파생변수가 누수나 과적합을 만들 수 있는 지점도 구분할 수 있습니다.

## 초심자용 한 줄 요약

파생변수는 `원본 데이터를 더 예측하기 좋은 형태로 다시 표현한 변수`입니다.

## 파생변수란 무엇인가

파생변수는 기존 컬럼을 조합, 변환, 집계해서 새로 만든 변수입니다.

예:

- `birth_year` -> `age`
- `last_login_date` -> `days_since_last_login`
- `total_amount / total_orders` -> `avg_amount_per_order`
- `weekday`, `month`, `hour` 분해

즉, 원본 데이터를 그대로 넣는 대신  
모델이 읽기 쉬운 힌트를 사람이 먼저 만들어 주는 것입니다.

## 왜 원본 변수만으로는 부족할까

모델이 자동으로 다 찾아내지 못하는 구조가 많기 때문입니다.

예를 들어 고객 이탈 예측에서

- `last_login_date` 자체보다
- `오늘 기준 마지막 로그인 후 며칠이 지났는가`

가 훨씬 직접적인 신호일 수 있습니다.

즉, 파생변수는 `사람의 도메인 이해`를 데이터에 반영하는 수단입니다.

## 파생변수의 대표 유형

### 1. 날짜/시간 기반

- `요일`
- `월`
- `분기`
- `최근 접속 후 경과일`
- `주말 여부`

### 2. 비율 기반

- `구매 전환율`
- `클릭 수 / 노출 수`
- `최근 7일 로그인 수 / 최근 30일 로그인 수`

### 3. 집계 기반

- 고객별 평균 주문금액
- 최근 30일 총 결제금액
- 카테고리별 평균 체류시간

### 4. interaction 기반

- `price * quantity`
- `discount_rate * visits`
- `membership_grade x recent_activity`

즉, 파생변수는 하나의 정답이 아니라  
문제를 어떻게 바라보느냐에 따라 여러 방식이 가능합니다.

## 작은 예시

고객 이탈 예측을 생각해보겠습니다.

원본 변수:

- `last_login_date`
- `total_orders`
- `total_amount`

파생변수:

- `days_since_last_login`
- `avg_amount_per_order`
- `recent_30d_orders`
- `recent_7d_orders / recent_30d_orders`

이렇게 바꾸면 “오랫동안 안 들어온 고객”,  
“최근 활동이 급격히 줄어든 고객” 같은 패턴을 더 직접적으로 표현할 수 있습니다.

## 작은 코드 예시

```python
import pandas as pd

df = pd.DataFrame(
    {
        "birth_year": [1995, 1988, 2001],
        "total_amount": [120000, 450000, 90000],
        "total_orders": [3, 10, 2],
    }
)

current_year = 2026

df["age"] = current_year - df["birth_year"]
df["avg_amount_per_order"] = df["total_amount"] / df["total_orders"]

print(df)
```

핵심은 계산 자체보다  
`이 변수가 실제 의사결정 신호를 더 잘 담는가`입니다.

## 언제 특히 유용한가

- 원본 컬럼이 너무 원시적이다
- 시간 흐름을 직접 표현해야 한다
- 비율이나 변화량이 더 중요하다
- 도메인 지식을 반영할 수 있다

예를 들어 매출 예측에서는 절대값보다  
전주 대비 증가율이 더 의미 있을 수 있습니다.

## 실무에서 자주 생기는 문제

### 1. 미래 정보를 섞는 경우

예측 시점 이후 데이터를 사용해 만든 파생변수는 누수입니다.

예:

- `다음 달 구매 여부`
- `예측 후 7일 클릭 수`

### 2. 너무 많은 파생변수를 만드는 경우

컬럼 수만 늘고 잡음이 많아질 수 있습니다.

### 3. 운영에서 계산 불가능한 변수를 만드는 경우

학습 때는 있었지만 실제 추론 시점에는 바로 계산할 수 없는 feature가 있습니다.

### 4. 의미 없는 산술 조합을 남발하는 경우

곱셈, 나눗셈을 많이 했다고 좋은 feature engineering은 아닙니다.

## 대안은 무엇인가

- 원본 변수로도 충분히 설명된다 -> 굳이 복잡한 파생변수 추가를 줄인다
- 시간 흐름이 중요하다 -> 날짜/시점 feature 중심으로 설계
- 도메인 지식이 강하다 -> 비율, 변화량, 집계 feature 우선 검토
- 과적합이 걱정된다 -> selection과 검증을 함께 본다

## 정리

- 파생변수는 원본 데이터를 더 직접적인 예측 신호로 바꾸는 작업입니다.
- 좋은 파생변수는 모델이 아니라 문제 구조에서 나옵니다.
- 다만 파생변수는 누수, 과적합, 운영 복잡도도 같이 만들 수 있으므로 검증이 필요합니다.
