## 학습 목표

- 혼동행렬의 네 칸을 설명할 수 있습니다.
- threshold 변화가 precision과 recall에 어떤 영향을 주는지 이해할 수 있습니다.
- 분류 문제에서 어떤 오류를 더 줄일지 비용 관점으로 판단할 수 있습니다.

## 초심자용 한 줄 요약

분류 문제의 핵심은 `몇 개를 맞혔는가`보다 `어떤 종류의 오답을 얼마나 냈는가`를 보는 것입니다.

## 혼동행렬 다시 보기

| 실제 / 예측 | 양성 예측 | 음성 예측 |
| --- | --- | --- |
| 실제 양성 | TP | FN |
| 실제 음성 | FP | TN |

- TP: 실제 양성을 양성으로 맞춤
- FP: 실제 음성을 양성으로 잘못 예측
- FN: 실제 양성을 놓침
- TN: 실제 음성을 음성으로 맞춤

분류 지표 대부분은 이 네 칸에서 나옵니다.

## threshold는 무엇인가

모델이 `양성 확률 0.63`을 냈다고 해보겠습니다.

- threshold `0.5` -> 양성
- threshold `0.7` -> 음성

즉, threshold는 확률 점수를 실제 액션으로 바꾸는 경계선입니다.

## threshold를 낮추면 무슨 일이 생길까

threshold를 낮추면 더 많은 샘플이 양성으로 분류됩니다.

보통 일어나는 변화:

- recall 상승 가능
- precision 하락 가능
- FP 증가 가능

즉, 놓침은 줄지만 헛경보는 늘 수 있습니다.

## threshold를 높이면 무슨 일이 생길까

- precision 상승 가능
- recall 하락 가능
- FN 증가 가능

즉, 더 엄격해지지만 실제 양성을 놓칠 위험이 커질 수 있습니다.

## 작은 예시: 고객 이탈 캠페인

이탈 확률 상위 고객에게만 쿠폰을 주는 상황을 생각해보겠습니다.

### threshold를 낮게 잡는 경우

- 더 많은 고객에게 쿠폰 발송
- 실제 이탈 고객을 더 많이 잡을 수 있음
- 하지만 불필요한 쿠폰 비용도 증가

### threshold를 높게 잡는 경우

- 캠페인 대상은 줄어듦
- 비용은 줄 수 있음
- 실제 이탈 고객 일부를 놓칠 수 있음

즉, threshold는 기술 매개변수이면서 동시에 `비용 정책`입니다.

## accuracy만 보면 왜 위험한가

양성 비율이 5%인 문제에서 전부 음성이라고 예측해도 accuracy는 95%가 나올 수 있습니다.

하지만 이 모델은 실제 양성을 하나도 못 잡습니다.

즉, accuracy는 불균형 데이터에서 매우 낙관적으로 보일 수 있습니다.

## 실무 판단 질문

분류 문제를 풀 때는 아래를 먼저 적어보면 좋습니다.

1. FP가 더 비싼가, FN이 더 비싼가
2. 양성 비율이 얼마나 희귀한가
3. 운영팀이 감당 가능한 양성 예측 수는 얼마나 되는가
4. 확률 점수 자체가 필요한가, 최종 클래스만 필요한가

## 실무에서 자주 생기는 문제

### 1. default threshold 0.5를 그대로 쓴다

이 값은 편의상 많이 쓰일 뿐, 항상 최적은 아닙니다.

### 2. 혼동행렬을 보지 않고 accuracy만 보고 끝낸다

실패 비용 구조를 전혀 반영하지 못할 수 있습니다.

### 3. threshold를 조정했는데 운영 수용량을 안 본다

모델은 좋아 보여도 실제 캠페인 대상 수가 너무 많을 수 있습니다.

## 정리

- 혼동행렬은 분류 문제를 읽는 기본 표입니다.
- threshold는 precision과 recall의 균형을 바꾸는 의사결정 레버입니다.
- 결국 어떤 threshold가 좋은지는 기술보다 비즈니스 비용 구조가 결정합니다.
