## 학습 목표

- 규칙 기반 접근과 머신러닝 접근의 차이를 설명할 수 있습니다.
- 어떤 문제가 머신러닝에 적합하고 어떤 문제는 규칙 기반이 더 나은지 구분할 수 있습니다.
- 모델 성능 외에 운영 복잡도와 설명 가능성도 함께 고려할 수 있습니다.

## 초심자용 한 줄 요약

규칙 기반은 `사람이 직접 기준을 적는 방식`, 머신러닝은 `데이터로 기준을 학습하는 방식`입니다.

## 규칙 기반과 머신러닝은 무엇이 다를까

규칙 기반 시스템은 사람이 직접 조건을 설계합니다.

예:

- 최근 30일 미접속이면 휴면 후보
- 주문 금액이 10만 원 이상이면 VIP
- 제목에 `"광고"`가 있으면 프로모션 메일

머신러닝은 반대로, 과거 데이터에서 패턴을 찾아 스스로 예측 규칙을 만듭니다.

예:

- 어떤 고객이 이탈할 가능성이 높은지
- 어떤 거래가 사기에 가까운지
- 어떤 집의 가격이 비쌀지

즉, 둘의 차이는 `누가 규칙을 만들고 있느냐`입니다.

## 언제 규칙 기반이 더 좋은가

아래 조건에서는 머신러닝보다 규칙 기반이 더 안정적일 수 있습니다.

- 규칙이 명확하고 거의 변하지 않는다
- 실수했을 때 설명 책임이 매우 크다
- 정답 데이터(label)가 충분하지 않다
- 문제 구조가 단순하고 해석이 더 중요하다

예를 들어 세금 계산, 배송비 정책, 권한 분기처럼 기준이 명확한 문제는  
굳이 모델을 쓰지 않아도 됩니다.

## 언제 머신러닝이 더 유리한가

아래와 같은 문제는 사람이 규칙을 모두 쓰기 어렵습니다.

- 변수(feature)가 많다
- 패턴이 자주 변한다
- 여러 조건이 복합적으로 작용한다
- 정확도를 데이터와 함께 점진적으로 개선하고 싶다

예:

- 고객 이탈 예측
- 수요 예측
- 사기 거래 탐지
- 추천 시스템

공통점은 `복잡한 패턴을 사람이 손으로 모두 적기 어렵다`는 점입니다.

## 실무 판단 기준 4가지

머신러닝 도입 여부를 고민할 때는 아래 네 가지를 같이 봐야 합니다.

### 1. 정답 데이터가 있는가

지도학습은 과거 정답 데이터가 있어야 학습할 수 있습니다.  
정답이 애매하거나 수집이 불가능하면 모델링보다 문제 재정의가 먼저입니다.

### 2. 성능이 조금 좋아지는 것이 운영 복잡도를 감수할 만큼 가치가 있는가

모델을 넣으면 보통 아래 부담이 함께 생깁니다.

- 재학습
- 데이터 파이프라인 유지
- 성능 모니터링
- 설명 요청 대응

즉, `정확도 2% 향상`이 실제 운영 가치로 이어지는지 같이 봐야 합니다.

### 3. 설명 가능성이 얼마나 중요한가

신용 심사, 보험 심사, 인사 평가 같은 영역에서는  
정확도만큼 `왜 그렇게 판단했는가`가 중요합니다.

이 경우는 복잡한 블랙박스 모델보다

- 규칙 기반
- 로지스틱 회귀
- 얕은 결정트리

같은 해석 가능한 접근이 더 적합할 수 있습니다.

### 4. 데이터가 계속 바뀌는가

머신러닝은 과거 패턴을 학습합니다.  
그래서 운영 데이터 분포가 바뀌면 성능이 급격히 무너질 수 있습니다.

예:

- 프로모션 정책 변경
- 서비스 가격 개편
- 신규 유입 채널 변화

이런 경우는 모델 도입보다 먼저 `데이터 drift를 감지할 체계`가 필요합니다.

## 작은 예시: 고객 이탈 예측

고객 이탈 고위험군을 찾는다고 가정해보겠습니다.

### 규칙 기반 접근

- 최근 30일 미접속
- 최근 결제 금액 급감
- 최근 문의 수 증가

장점:

- 바로 설명 가능
- 빠르게 배포 가능

단점:

- 기준값을 사람이 계속 손봐야 함
- 복합 패턴을 잘 못 잡음

### 머신러닝 접근

- 최근 방문 수
- 결제 금액 변화율
- 고객 등급
- 문의 빈도
- 마지막 접속 이후 경과일

장점:

- 여러 변수의 조합 패턴을 학습 가능
- 지속적으로 개선 가능

단점:

- label 정의가 필요
- 누수와 검증 설계가 어려움

## 실무에서 자주 생기는 오해

### 오해 1. 데이터가 많으면 무조건 머신러닝이 낫다

데이터가 많아도 label 품질이 나쁘면 모델은 잘못 학습합니다.

### 오해 2. 모델이 복잡할수록 더 좋다

baseline보다 조금만 좋아도 운영 비용 때문에 단순 모델이 더 나을 수 있습니다.

### 오해 3. 머신러닝은 규칙 기반을 완전히 대체한다

실제 현업에서는 `규칙 기반 + 모델` 조합이 많습니다.

예:

- 명백한 이상값은 규칙으로 차단
- 애매한 케이스만 모델 점수로 분류

## 정리

- 규칙 기반은 `명확한 문제`, 머신러닝은 `복잡한 패턴`에 강합니다.
- 모델 성능만이 아니라 label, 설명 가능성, 운영 비용을 함께 봐야 합니다.
- 좋은 시작은 `작은 규칙 기반 baseline`과 `단순 모델 baseline`을 같이 비교하는 것입니다.
