## 학습 목표

- 회귀와 분류에서 대표적인 평가 지표를 구분할 수 있습니다.
- `accuracy`, `precision`, `recall`, `F1`, `F2`, `F0.5`의 차이를 설명할 수 있습니다.
- `MAE`, `RMSE`, `R2`를 어떤 상황에서 중시할지 판단할 수 있습니다.
- 지표 선택이 결국 비즈니스 비용 구조와 연결된다는 점을 이해할 수 있습니다.

## 초심자용 한 줄 요약

모델 평가는 `점수 숫자 하나`를 보는 일이 아니라, `어떤 종류의 실패를 더 싫어하는가`를 지표로 표현하는 일입니다.

## 오늘의 목표

오늘은 모델 성능을 읽는 언어를 정리합니다.

- 회귀 지표와 분류 지표를 구분합니다.
- precision과 recall을 헷갈리지 않게 정리합니다.
- `F1` 외에 `F2`, `F0.5`처럼 가중치를 다르게 둔 지표가 왜 필요한지도 봅니다.
- 실무에서 어떤 지표를 우선 볼지 판단 기준을 잡습니다.

## 왜 지표가 중요한가

같은 모델도 지표를 어떻게 잡느냐에 따라 전혀 다르게 해석될 수 있습니다.

예:

- 의료 판별: 양성을 놓치면 위험 -> `recall` 중요
- 광고 타기팅: 잘못 보내는 비용 큼 -> `precision` 중요
- 재고 예측: 큰 오차가 치명적 -> `RMSE` 중요
- 일반 매출 예측: 평균적인 빗나감 정도 -> `MAE` 중요

즉, `좋은 모델`은 절대적 개념이 아니라 `무엇을 잘해야 하는가`에 따라 달라집니다.

## 회귀 지표 다시 정리

### MAE

`MAE = 평균 절대 오차`

- 해석이 쉬움
- 원래 단위 그대로 읽힘
- 이상치에 상대적으로 덜 민감

### RMSE

`RMSE = 평균 제곱 오차의 제곱근`

- 큰 오차를 더 강하게 벌줌
- 큰 실패를 줄이고 싶을 때 유용

### R2

`R2 = 설명력`

- 평균만 예측하는 기준 대비 얼마나 나은지
- 모델 비교 시 참고 가능
- 절대 오차 단위를 직접 보여주지는 않음

## 분류 지표의 핵심

혼동행렬 기준으로 네 가지 수를 기억합니다.

- TP: 실제 양성을 양성으로 맞춤
- FP: 실제 음성을 양성으로 잘못 예측
- FN: 실제 양성을 놓침
- TN: 실제 음성을 음성으로 맞춤

여기서 대표 지표가 나옵니다.

### Accuracy

`(TP + TN) / 전체`

- 전체 중 맞힌 비율
- 직관적이지만 클래스 불균형에 약함

### Precision

`TP / (TP + FP)`

- 양성이라고 예측한 것 중 실제 양성 비율
- `헛경보를 얼마나 줄였는가`

예:

- 사기 탐지에서 정상 거래를 너무 많이 사기로 잡으면 운영 비용이 큼
- 마케팅 캠페인 타기팅에서 잘못 쏘는 비용이 큼

### Recall

`TP / (TP + FN)`

- 실제 양성 중 놓치지 않고 잡은 비율
- `중요한 양성을 얼마나 놓치지 않았는가`

예:

- 암 진단 보조
- 사기 거래 탐지
- 고객 이탈 사전 대응

### F1 Score

`2 * (precision * recall) / (precision + recall)`

- precision과 recall의 균형을 보는 지표
- 둘 중 하나가 매우 낮으면 F1도 낮아짐

### F2, F0.5는 언제 볼까

`F1`은 precision과 recall을 같은 비중으로 봅니다.  
하지만 실무에서는 둘 중 하나를 더 중요하게 봐야 하는 경우가 많습니다.

- recall을 더 중시하면 `F2`
- precision을 더 중시하면 `F0.5`

즉, F 계열 지표는 `precision과 recall 사이 우선순위를 숫자로 반영하는 방법`이라고 생각하시면 됩니다.

## precision vs recall, 어떻게 구분할까

아래 질문으로 기억하면 쉽습니다.

- precision: `양성이라고 말한 것들이 얼마나 믿을 만한가`
- recall: `실제 양성을 얼마나 놓치지 않았는가`

예를 들어 이탈 고객 캠페인에서:

- precision이 높다 -> 타기팅한 고객 중 실제 이탈 위험 고객 비율이 높다
- recall이 높다 -> 실제 이탈 위험 고객을 많이 놓치지 않았다

하지만 둘은 종종 trade-off 관계입니다.  
더 많이 잡으려 하면(recall 증가) 잘못 잡는 경우도 늘어 precision이 낮아질 수 있습니다.

## threshold가 왜 중요한가

모델이 확률을 내놓을 때, threshold를 바꾸면 precision과 recall이 함께 움직입니다.

- threshold를 낮춤 -> 더 쉽게 양성 판정 -> recall 상승 가능, precision 하락 가능
- threshold를 높임 -> 더 엄격하게 양성 판정 -> precision 상승 가능, recall 하락 가능

즉, threshold tuning은 기술 문제가 아니라 `비즈니스 비용 조정`에 가깝습니다.

## ROC-AUC와 PR-AUC

### ROC-AUC

- 다양한 threshold에서 TPR과 FPR의 관계를 본다
- 전반적인 분리 능력을 볼 때 유용
- 클래스 불균형이 심할 때는 낙관적으로 보일 수 있음

### PR-AUC

- precision-recall 관계를 본다
- 양성 클래스가 희귀한 문제에서 더 민감하게 볼 수 있음

처음에는 아래 정도로 기억하시면 충분합니다.

- 클래스가 비교적 균형적 -> ROC-AUC도 유용
- 양성이 매우 희귀 -> PR-AUC를 더 주의 깊게 보기

## 작은 코드 예시

```python
from sklearn.metrics import (
    accuracy_score,
    f1_score,
    precision_score,
    recall_score,
    roc_auc_score,
)

acc = accuracy_score(y_test, pred)
precision = precision_score(y_test, pred)
recall = recall_score(y_test, pred)
f1 = f1_score(y_test, pred)
auc = roc_auc_score(y_test, proba)

print(acc, precision, recall, f1, auc)
```

이때 점수를 줄줄 외우는 것보다 아래처럼 해석하는 것이 중요합니다.

- accuracy는 높지만 recall이 낮은가
- precision이 높지만 너무 적게 잡는가
- AUC는 괜찮은데 threshold 설정이 아쉬운가

## 실무에서 언제 문제가 되는가

### 1. 정확도 하나만 보고 보고서를 끝내는 경우

불균형 데이터에서는 매우 위험합니다.

### 2. 모델 점수는 좋은데 threshold 선택 근거가 없는 경우

예측 확률이 있어도 운영 정책이 없으면 실제 액션으로 이어지기 어렵습니다.

### 3. 회귀에서 R2만 강조하는 경우

설명력이 높아 보여도 실제 오차 단위가 크면 운영에는 쓸 수 없을 수 있습니다.

### 4. 지표가 비즈니스 비용을 반영하지 못하는 경우

예를 들어 FN이 훨씬 비싼 문제에서 accuracy만 보면 의사결정이 왜곡될 수 있습니다.

## 대안은 무엇인가

상황에 따라 다음도 고려할 수 있습니다.

- 비용 기반 custom metric
- top-k precision
- calibration curve
- MAPE, SMAPE 같은 비율 오차 지표

즉, 대표 지표는 출발점일 뿐이고 최종 판단은 문제 구조에 맞게 조정해야 합니다.

## 처음엔 이렇게 정리하면 됩니다

- 회귀: `MAE`, `RMSE`, `R2`
- 분류: `accuracy`, `precision`, `recall`, `F1`, `F2`, `F0.5`, `AUC`
- 중요한 양성을 놓치면 안 됨 -> recall
- 양성이라고 말한 대상의 정확성이 중요 -> precision
- 큰 오차가 치명적 -> RMSE
- 평균적인 오차 해석이 중요 -> MAE
