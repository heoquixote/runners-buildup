## 학습 목표

- 프로젝트에서 모델 비교를 어떻게 정리할지 설명할 수 있습니다.
- threshold와 지표를 운영 액션과 연결할 수 있습니다.
- 결과 보고서에 꼭 들어가야 할 항목을 정리할 수 있습니다.

## 초심자용 한 줄 요약

좋은 프로젝트 마무리는 `모델이 최고였다`가 아니라 `왜 이 모델을 선택했고, 어떤 조건에서 어떻게 쓸지`를 보고할 수 있는 상태입니다.

## 모델 비교는 어떻게 할까

첫 프로젝트에서는 너무 많은 모델보다 아래 정도면 충분합니다.

- baseline
- 해석 가능한 단순 모델
- 성능 확장용 대안 모델

예:

- Majority class baseline
- Logistic Regression
- Random Forest
- Gradient Boosting

## 상황별 1차 후보를 어떻게 고를까

모델 비교를 시작할 때는 아래처럼 첫 후보를 잡으면 됩니다.

| 상황 | 먼저 볼 모델 | 실무적 이유 |
| --- | --- | --- |
| 데이터가 적다 | Logistic Regression | 단순하고 baseline으로 안정적이며 설명도 쉽기 때문 |
| 데이터가 크다 | XGBoost | tabular 데이터에서 정확도 경쟁력이 강한 대표 boosting이기 때문 |
| 범주형이 많다 | CatBoost | 전처리 부담을 줄이면서 범주형을 다루기 편하기 때문 |
| 설명력이 중요하다 | Logistic Regression | 계수 방향과 threshold 해석을 설명하기 쉽기 때문 |
| 정확도가 중요하다 | Boosting 계열 | 비선형성과 상호작용을 잘 잡아 높은 성능을 내기 쉽기 때문 |

이 표를 절대 규칙으로 외우기보다  
`첫 후보를 빨리 좁히는 출발점`으로 쓰는 편이 좋습니다.

예를 들어 실무에서는 아래처럼 말할 수 있습니다.

- 데이터 건수가 많지 않고 설명 책임이 커서 `Logistic Regression`을 baseline이자 주요 후보로 선택했습니다.
- 정확도 개선 여지가 커 보여 `XGBoost`를 성능 확장용 후보로 비교했습니다.
- 범주형 비중이 높아 one-hot encoding 부담을 줄이기 위해 `CatBoost`를 후보에 포함했습니다.
- 최종적으로는 설명용 baseline과 정확도 중심 boosting 모델을 함께 비교해 의사결정했습니다.

## 비교 표에 넣을 것

모델 비교는 표로 정리하면 좋습니다.

예:

| 모델 | Precision | Recall | F1 | ROC-AUC | 해석성 | 운영 복잡도 |
| --- | --- | --- | --- | --- | --- | --- |
| Logistic Regression | 0.62 | 0.71 | 0.66 | 0.79 | 높음 | 낮음 |
| Random Forest | 0.68 | 0.69 | 0.68 | 0.82 | 중간 | 중간 |

이렇게 보면 단순 점수 외에도 선택 이유가 보입니다.

## threshold는 보고서에 어떻게 쓸까

예:

`threshold 0.55에서는 recall이 높아 실제 이탈 고객을 더 많이 잡지만, 캠페인 대상 수가 운영 한도를 넘습니다. threshold 0.65에서는 precision이 올라 운영 효율이 좋아집니다.`

즉, threshold는 지표 조정이 아니라  
`예산`, `인력`, `쿠폰 수량`, `조사 가능 건수`와 연결해 써야 합니다.

## 결과 보고서 기본 구조

1. 문제 정의
2. 데이터 범위와 예측 시점
3. label 정의
4. feature 구성
5. split 방식
6. baseline 결과
7. 비교 모델 결과
8. 최종 선택 이유
9. 한계와 다음 액션

이 구조만 지켜도 초보 프로젝트가 훨씬 실무형으로 보입니다.

## 꼭 써야 하는 한계

첫 프로젝트에서 아래를 솔직하게 적는 것이 중요합니다.

- 데이터 양 부족
- label 정의의 애매함
- 특정 세그먼트 오차
- threshold 민감도
- drift 가능성

완벽한 모델인 척하는 것보다  
어디서 깨질 수 있는지 말하는 편이 더 실무적입니다.

## 정리

- 모델 비교는 점수뿐 아니라 해석성, 운영 복잡도까지 함께 봐야 합니다.
- `데이터 크기`, `범주형 비중`, `설명 가능성`, `정확도 우선 여부`로 첫 후보를 좁히면 비교가 쉬워집니다.
- threshold는 액션 수용량과 함께 보고해야 합니다.
- 좋은 보고서는 `무엇을 했는가`보다 `왜 그렇게 결정했는가`가 보입니다.
