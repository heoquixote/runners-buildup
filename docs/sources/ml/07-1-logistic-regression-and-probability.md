## 학습 목표

- 로지스틱 회귀가 분류 문제에서 확률을 어떻게 다루는지 설명할 수 있습니다.
- sigmoid 함수의 역할을 이해할 수 있습니다.
- 분류 확률과 최종 클래스 예측의 차이를 구분할 수 있습니다.

## 초심자용 한 줄 요약

로지스틱 회귀는 `선형 점수`를 만든 뒤 이를 `0과 1 사이 확률`로 바꾸어 분류 문제를 다루는 모델입니다.

## 왜 선형회귀로는 분류가 어렵나

분류에서는 결과를 확률처럼 해석하고 싶은 경우가 많습니다.

예:

- 이탈 확률 `0.82`
- 사기 확률 `0.13`

그런데 선형회귀는 예측값이 0보다 작거나 1보다 커질 수 있어  
확률 해석에 바로 쓰기 어렵습니다.

## 로지스틱 회귀의 핵심 아이디어

로지스틱 회귀는 아래 두 단계를 거칩니다.

1. feature를 선형 결합해 점수 `z`를 만듭니다.
2. sigmoid 함수로 점수를 확률 `p`로 바꿉니다.

식으로 쓰면:

`z = b0 + b1x1 + ... + bpxp`

`p = 1 / (1 + e^(-z))`

## sigmoid를 직관적으로 이해하기

sigmoid 함수는 아무 점수나 받아서 `0 ~ 1` 사이 값으로 바꿉니다.

- 점수가 아주 크다 -> 확률이 1에 가까움
- 점수가 아주 작다 -> 확률이 0에 가까움
- 점수가 0 근처다 -> 확률이 0.5 근처

즉, 로지스틱 회귀는  
`이 샘플이 양성일 가능성이 얼마나 큰가`를 다루는 모델입니다.

## 계수는 어떻게 해석하나

입문 단계에서는 우선 아래 정도로 읽으면 충분합니다.

- 계수가 양수면 해당 feature가 양성 확률을 높이는 방향
- 계수가 음수면 양성 확률을 낮추는 방향

조금 더 엄밀하게는 로지스틱 회귀 계수는 `log-odds`에 영향을 줍니다.  
즉, 선형회귀처럼 “1 증가할 때 결과가 얼마 증가”로 바로 읽기보다  
`방향성과 상대적 영향`을 먼저 보는 편이 안전합니다.

## 확률 예측과 클래스 예측은 다르다

예를 들어 어떤 고객의 이탈 확률이 `0.73`이라고 해보겠습니다.

- 확률 예측: `0.73`
- 최종 클래스: threshold가 `0.5`면 이탈

threshold를 `0.8`로 바꾸면 같은 고객도 유지가 될 수 있습니다.

즉, 로지스틱 회귀가 만드는 핵심 결과물은 종종 `확률 점수`입니다.

## 왜 로지스틱 회귀가 좋은 baseline인가

- 빠르다
- 해석이 비교적 쉽다
- 확률 예측이 가능하다
- 다양한 분류 문제에서 출발점으로 안정적이다

그래서 분류 문제를 시작할 때는  
복잡한 모델 전에 로지스틱 회귀 baseline을 잡는 경우가 많습니다.

## 언제 먼저 로지스틱 회귀를 떠올리면 좋을까

아래 상황에서는 로지스틱 회귀를 첫 후보로 두는 것이 실무적으로 자연스럽습니다.

- 데이터가 아주 크지 않다
- 설명력이 중요하다
- baseline을 빠르게 잡아야 한다
- 확률과 threshold를 현업에 설명해야 한다

예를 들어 고객 이탈 프로젝트에서  
데이터 건수가 아주 많지 않고, 마케팅팀에 “어떤 변수가 이탈 확률을 올리는 방향인가”를 설명해야 한다면  
로지스틱 회귀는 좋은 출발점이 됩니다.

즉, `작은 데이터 + 설명 가능성 + 빠른 baseline` 조합에서는  
로지스틱 회귀를 먼저 보는 편이 안전합니다.

물론 이것이 항상 최종 모델이라는 뜻은 아닙니다.  
비선형 관계와 변수 상호작용이 강하면 boosting 계열이 더 높은 성능을 낼 수도 있습니다.

## 실무에서 자주 생기는 문제

### 1. 확률을 바로 사실처럼 해석한다

`0.8`은 “무조건 80% 확률로 일어난다”가 아니라  
모델이 현재 데이터와 구조에서 그렇게 평가한 점수입니다.

### 2. coefficient를 인과효과처럼 읽는다

계수는 상관 구조와 feature 설계 영향을 받으므로  
바로 원인 해석으로 뛰면 위험합니다.

### 3. 범주형 변수 인코딩과 스케일링을 대충 처리한다

로지스틱 회귀는 전처리 품질에 민감할 수 있습니다.

## 정리

- 로지스틱 회귀는 선형 점수를 sigmoid로 확률화하는 분류 모델입니다.
- 모델의 본질적 출력은 확률이고, 최종 클래스는 threshold로 정해집니다.
- 해석 가능성과 baseline 가치 때문에 실무 입문에서 매우 유용합니다.
