## 학습 목표

- 머신러닝이 무엇인지 자기 말로 설명할 수 있습니다.
- 규칙 기반 접근과 머신러닝 접근의 차이를 이해할 수 있습니다.
- 회귀, 분류, 비지도학습의 차이를 큰 그림에서 구분할 수 있습니다.
- 머신러닝이 잘 맞는 문제와 오히려 비효율적인 문제를 구분할 수 있습니다.

## 초심자용 한 줄 요약

머신러닝은 `사람이 규칙을 하나씩 적는 대신, 데이터로부터 패턴을 학습해 예측 규칙을 만드는 방법`입니다.

## 오늘의 목표

오늘은 머신러닝의 출발점을 정리합니다.

- 머신러닝이 왜 필요한지 이해합니다.
- 어떤 문제를 머신러닝 문제로 바꿔 볼 수 있는지 익힙니다.
- 모델 이름보다 먼저 `문제 구조`를 보는 습관을 시작합니다.

## 비유로 이해하기

- 규칙 기반 시스템: `체크리스트를 직접 쓰는 방식`
- 머신러닝: `예시를 많이 보여주고 스스로 기준을 익히게 하는 방식`

예를 들어 스팸 메일을 걸러낸다고 생각해보겠습니다.

- 규칙 기반: 제목에 `"무료"`가 있으면 스팸, `"광고"`가 있으면 스팸
- 머신러닝: 과거 스팸/정상 메일 데이터를 보고 어떤 패턴이 스팸에 가까운지 학습

규칙이 단순하고 안정적이면 직접 규칙을 쓰는 편이 낫습니다.  
반대로 패턴이 복잡하고 자주 바뀌면 머신러닝이 더 유리할 수 있습니다.

## 왜 머신러닝이 필요한가

머신러닝은 특히 아래 상황에서 힘을 발휘합니다.

- 규칙을 사람이 전부 정의하기 어렵다
- 입력 변수(feature)가 많다
- 데이터가 쌓일수록 패턴이 보인다
- 예측 정확도를 계속 개선하고 싶다

예:

- 부동산 가격 예측
- 고객 이탈 가능성 예측
- 카드 거래 사기 탐지
- 상품 추천
- 이미지 분류

공통점은 `정답을 손으로 모두 규칙화하기 어렵다`는 점입니다.

## 머신러닝은 무엇을 학습하는가

머신러닝 모델은 보통 아래 관계를 학습합니다.

`입력(feature) -> 출력(label 또는 target)`

예를 들어 집값 예측에서는:

- feature: 평수, 방 개수, 위치, 준공연도
- label: 실제 매매가

고객 이탈 예측에서는:

- feature: 최근 로그인 수, 결제 횟수, 고객 등급, 문의 수
- label: 다음 달 이탈 여부

즉, 머신러닝은 본질적으로 `입력과 출력의 관계를 근사하는 함수`를 찾는 과정입니다.

## 대표적인 문제 유형

### 1. 회귀

숫자를 예측하는 문제입니다.

- 매출 예측
- 배송 시간 예측
- 주택 가격 예측

예측 결과가 `23.7`, `152000`, `4.8일`처럼 연속형 숫자입니다.

### 2. 분류

범주를 예측하는 문제입니다.

- 스팸/정상 메일 구분
- 이탈/유지 고객 분류
- 불량/정상 제품 판별

결과는 `예/아니오`, `A/B/C`, `고위험/저위험`처럼 클래스입니다.

### 3. 비지도학습

정답(label) 없이 데이터 구조를 찾는 문제입니다.

- 고객 세그먼트 나누기
- 유사 사용자 묶기
- 이상 패턴 탐색

처음 배우실 때는 `회귀`와 `분류`가 가장 중요합니다.  
실무에서도 머신러닝 입문의 대부분은 이 두 축에서 시작합니다.

## 머신러닝 프로젝트의 기본 흐름

아주 단순화하면 아래 순서로 생각하시면 됩니다.

1. 해결할 문제를 정의합니다.
2. 예측할 대상(label)을 정합니다.
3. 사용할 입력(feature)을 모읍니다.
4. 데이터를 학습용과 평가용으로 나눕니다.
5. 모델을 학습시킵니다.
6. 예측 결과를 지표로 평가합니다.
7. 성능과 해석 가능성을 보고 개선합니다.

초심자는 종종 5번 `모델`만 머신러닝이라고 생각하지만, 실제 실무에서는 1번부터 4번이 더 어렵고 더 중요할 때가 많습니다.

## 머신러닝이 만능은 아닙니다

아래 경우에는 머신러닝이 꼭 정답은 아닐 수 있습니다.

- 규칙이 명확하고 거의 변하지 않는다
- 데이터가 너무 적다
- 라벨 품질이 나쁘다
- 모델이 틀렸을 때 비용이 매우 큰데 설명 가능성이 낮다

예를 들어 세금 계산, 배송비 표준 정책, 단순 등급 분기처럼 규칙이 명확한 문제는  
SQL, 룰 엔진, 일반 코드가 더 안정적이고 운영도 쉽습니다.

## 실무에서 언제 문제가 되는가

### 1. 데이터는 있는데 정답(label)이 없는 경우

머신러닝을 하고 싶어도 `무엇을 맞힐 것인가`가 없으면 지도학습이 바로 되지 않습니다.  
이 경우는 먼저 문제 정의를 다시 하거나 비지도학습 관점으로 바꿔야 합니다.

### 2. 훈련 데이터와 실제 운영 데이터가 다른 경우

모델은 과거 데이터에서 배운 패턴으로 예측합니다.  
그래서 운영 환경이 바뀌면 성능이 급격히 떨어질 수 있습니다. 이를 흔히 `data drift`라고 부릅니다.

### 3. 성능보다 설명이 더 중요한 경우

예를 들어 신용 심사나 의료 판별처럼 설명 책임이 큰 문제에서는  
조금 더 복잡한 고성능 모델보다 해석 가능한 모델이 선호될 수 있습니다.

## 대안은 무엇인가

머신러닝을 고려할 때는 항상 다른 선택지도 같이 봐야 합니다.

- 단순 규칙 기반 접근
- SQL 집계와 임계값 조건
- 통계 모델과 가설검정
- 도메인 룰 + 휴리스틱

예를 들어 고객 이탈 고위험군을 찾는 문제에서:

- 빠른 시작이 목적이면: 최근 30일 미접속 + 결제 감소 규칙
- 해석력이 중요하면: 로지스틱 회귀
- 최고 성능이 중요하면: 트리 기반 앙상블

즉, `머신러닝을 쓸 수 있는가`보다 `왜 이 접근이 지금 가장 적절한가`가 더 중요합니다.

## 처음엔 이렇게 생각하면 됩니다

- 정답이 있는가
- 예측 결과가 숫자인가, 범주인가
- 단순 규칙으로 충분한가
- 예측 오류 비용이 어떤 형태인가
- 설명 가능성과 운영 복잡도 중 무엇이 더 중요한가
