## 학습 목표

- 첫 머신러닝 프로젝트에서 문제 정의를 어떻게 시작할지 알 수 있습니다.
- label, 예측 시점, feature 범위를 설계할 수 있습니다.
- 기술 문제와 비즈니스 문제를 함께 정리할 수 있습니다.

## 초심자용 한 줄 요약

첫 프로젝트의 성패는 모델 선택보다 `무엇을 언제 어떤 기준으로 예측할지`를 선명하게 적는 데서 갈립니다.

## 프로젝트를 시작할 때 가장 먼저 적을 것

아래 네 줄을 먼저 문장으로 적어보면 좋습니다.

1. 무엇을 예측할 것인가
2. 언제 시점에서 예측할 것인가
3. 예측 결과를 어디에 쓸 것인가
4. 어떤 오류가 더 비싼가

이 네 줄이 없으면 모델링이 아니라 실험 놀음이 되기 쉽습니다.

## 예시: 고객 이탈 예측

좋은 문제 정의 예:

`매주 월요일 기준으로, 다음 30일 안에 이탈할 가능성이 높은 고객을 찾아 리텐션 캠페인 대상으로 쓰고 싶다.`

이 문장에는 이미 아래가 들어 있습니다.

- 예측 대상: 고객 이탈
- 예측 시점: 매주 월요일
- 예측 기간: 다음 30일
- 활용 액션: 리텐션 캠페인

## label 정의

label은 가능한 한 명확해야 합니다.

예:

- 30일 미접속
- 30일 무결제
- 구독 해지 완료

무엇을 이탈로 볼지는 팀마다 다를 수 있으므로  
분석가가 먼저 문장으로 정리해야 합니다.

## feature 범위 설계

feature는 예측 시점 이전 정보만 사용해야 합니다.

예:

- 최근 7일 로그인 수
- 최근 30일 결제 금액
- 최근 문의 수
- 마지막 로그인 이후 경과일

배제해야 할 것:

- 예측 시점 이후 결제 정보
- 해지 완료 처리 상태

## split 전략

첫 프로젝트라고 해도 split을 대충 하면 안 됩니다.

- 시간 의미가 약하면 random split
- 시간 의미가 크면 time-based split

특히 이탈, 수요, 매출 예측은 시계열 관점을 꼭 점검해야 합니다.

## 성공 기준 정하기

프로젝트 성공 기준은 단순히 모델 점수 하나가 아닐 수 있습니다.

예:

- recall 70% 이상
- 상위 10% 고객군에서 precision 30% 이상
- baseline 대비 ROC-AUC 0.05 이상 개선
- 캠페인 대상 수용량 5,000명 이내

즉, 모델 점수와 운영 제약을 같이 적어야 합니다.

## 정리

- 첫 프로젝트의 절반은 문제 정의 문장을 잘 쓰는 일입니다.
- label, 예측 시점, feature 범위, 활용 액션을 먼저 정해야 합니다.
- 좋은 프로젝트는 `모델 파일`보다 `문제 설계 문서`가 먼저 나옵니다.
