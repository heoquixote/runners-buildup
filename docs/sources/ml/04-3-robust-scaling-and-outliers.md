## 학습 목표

- RobustScaler가 어떤 통계를 기준으로 동작하는지 설명할 수 있습니다.
- 평균/표준편차 대신 중앙값과 IQR을 쓰는 이유를 이해할 수 있습니다.
- 이상치가 많은 데이터에서 왜 RobustScaler가 유용할 수 있는지 말할 수 있습니다.

## 초심자용 한 줄 요약

RobustScaler는 `이상치에 덜 흔들리도록 중앙값과 사분위 범위(IQR)를 기준으로 스케일링하는 방식`입니다.

## 왜 RobustScaler가 필요한가

StandardScaler는 평균과 표준편차를 씁니다.  
그런데 이 값들은 이상치에 민감합니다.

예를 들어 거래 금액 데이터에서  
대부분은 `1만~10만 원`인데 일부가 `500만 원`이라면  
평균과 표준편차가 크게 흔들릴 수 있습니다.

이럴 때 중앙값과 IQR을 쓰면  
중심과 퍼짐을 더 안정적으로 잡을 수 있습니다.

## IQR은 무엇인가

IQR은 `Q3 - Q1`입니다.

- `Q1`: 하위 25%
- `Q3`: 상위 75%
- `IQR`: 가운데 50% 구간 폭

즉, 매우 큰 값이나 매우 작은 값보다는  
중간 부분의 구조를 기준으로 스케일을 맞추는 셈입니다.

## 언제 유용한가

- 이상치가 자주 등장한다
- 금융 금액, 거래 규모, 체류 시간처럼 긴 꼬리 분포가 많다
- 평균 기반 스케일링이 불안정하다

## 이상치를 실제로 어떻게 볼까

RobustScaler는 이상치 영향을 줄이는 도구이지  
이상치를 자동으로 찾아 없애는 도구는 아닙니다.

실무에서는 보통 아래 질문을 먼저 합니다.

- 이 값이 측정 오류인가
- 정상적이지만 드문 이벤트인가
- 제거보다 변환이나 clipping이 더 자연스러운가

즉, 스케일러 선택과 이상치 처리 판단은 완전히 같은 문제가 아닙니다.

## IQR 기준으로 이상치 보기

IQR 방식은 사분위수를 이용해 이상치를 판단합니다.

- `Q1`: 하위 25%
- `Q3`: 상위 75%
- `IQR = Q3 - Q1`

자주 쓰는 규칙은 아래와 같습니다.

- 하한: `Q1 - 1.5 * IQR`
- 상한: `Q3 + 1.5 * IQR`

이 범위를 크게 벗어나면 이상치 후보로 봅니다.

장점:

- 평균보다 이상치 영향이 작음
- 오른쪽 꼬리가 긴 데이터에서 비교적 안정적

주의:

- 비즈니스적으로 중요한 큰 거래도 함께 잡힐 수 있음
- 무조건 제거 기준으로 쓰기보다 `후보 탐지 규칙`으로 보는 편이 안전함

## Z-score 기준으로 이상치 보기

Z-score는 평균에서 몇 표준편차 떨어져 있는지를 보는 방식입니다.

공식은 아래와 같습니다.

`z = (x - mean) / std`

자주 쓰는 기준:

- `|z| > 3`

장점:

- 계산이 단순함
- 정규분포에 가까운 데이터에서 직관적임

주의:

- 평균과 표준편차 자체가 이상치에 민감함
- 왜도가 큰 데이터에서는 해석이 흔들릴 수 있음

즉, 긴 꼬리 분포에서는 IQR 쪽이 더 안정적으로 느껴질 때가 많습니다.

## 작은 코드 예시

```python
import pandas as pd
from sklearn.preprocessing import RobustScaler, StandardScaler

df = pd.DataFrame(
    {
        "amount": [10, 12, 11, 13, 12, 500],
        "visits": [1, 2, 1, 3, 2, 2],
    }
)

standard = StandardScaler()
robust = RobustScaler()

print(standard.fit_transform(df))
print(robust.fit_transform(df))
```

이 예시에서는 `500` 같은 극단값 때문에  
StandardScaler와 RobustScaler 결과 차이가 눈에 띌 수 있습니다.

## 작은 코드 예시: IQR과 Z-score

```python
import pandas as pd

df = pd.DataFrame({"amount": [10, 12, 11, 13, 12, 500]})

q1 = df["amount"].quantile(0.25)
q3 = df["amount"].quantile(0.75)
iqr = q3 - q1

lower = q1 - 1.5 * iqr
upper = q3 + 1.5 * iqr

df["iqr_outlier"] = (df["amount"] < lower) | (df["amount"] > upper)

mean = df["amount"].mean()
std = df["amount"].std()
df["z_score"] = (df["amount"] - mean) / std
df["z_outlier"] = df["z_score"].abs() > 3

print(df)
```

핵심은 `탐지 기준`과 `처리 의사결정`을 구분하는 것입니다.

## RobustScaler의 장점

- 이상치 영향이 상대적으로 작다
- 긴 꼬리 분포에서 더 안정적일 수 있다
- 계수 기반 모델 전처리로 꽤 실용적이다

## RobustScaler의 한계

### 1. 이상치를 제거해주는 것은 아니다

영향을 줄일 뿐, 이상치 자체가 사라지는 것은 아닙니다.

### 2. 분포 왜도가 큰 문제를 완전히 해결하지는 못한다

로그 변환이나 power transform이 더 자연스러운 경우도 있습니다.

### 3. 이상치가 비즈니스적으로 중요한 신호일 수 있다

무조건 줄이는 것이 항상 좋은 것은 아닙니다.

## 제거할까, 유지할까

이상치 처리는 보통 아래 셋 중 하나를 고르는 문제입니다.

- 제거
- 유지
- 유지하되 변환 또는 clipping

### 제거가 자연스러운 경우

- 센서 오류, 입력 오류, 중복 적재처럼 명백한 데이터 오류다
- 도메인상 불가능한 값이다
- 운영 환경에서도 다시 나오기 어려운 비정상 데이터다

### 유지가 자연스러운 경우

- 실제로 발생한 대형 거래, VIP 행동, 사고 이벤트다
- 우리가 예측해야 하는 중요한 극단 케이스다
- 제거하면 비즈니스 현실을 더 크게 왜곡한다

### 중간 대안이 더 좋은 경우

- 로그 변환
- clipping / winsorizing
- RobustScaler
- 이상치 indicator 추가

즉, `이상치 = 삭제`로 바로 연결하면 안 되고  
`오류인가, 희귀하지만 중요한 신호인가`를 먼저 봐야 합니다.

## StandardScaler와 언제 다르게 볼까

### StandardScaler가 더 무난한 경우

- 이상치가 심하지 않다
- 정규분포에 가까운 연속형 수치가 많다

### RobustScaler가 더 자연스러운 경우

- 극단값이 자주 나온다
- 긴 꼬리 분포가 많다
- 평균 기준 스케일링이 자주 흔들린다

## 실무에서 자주 생기는 문제

### 1. 이상치가 많은데 StandardScaler만 반복하는 경우

스케일러보다 데이터 구조 문제가 더 클 수 있습니다.

### 2. RobustScaler를 썼다고 이상치 처리가 끝났다고 생각하는 경우

여전히 로그 변환, clipping, 도메인 검토가 더 필요할 수 있습니다.

### 3. 이상치가 오류인지 실제 중요한 이벤트인지 구분하지 않는 경우

이상치가 VIP 고객, 대형 거래, 사고 이벤트일 수 있습니다.

## 대안은 무엇인가

- 이상치가 거의 없다 -> `StandardScaler`
- 범위를 맞추고 싶다 -> `MinMaxScaler`
- 분포 왜도가 심하다 -> 로그 변환, `PowerTransformer`, `QuantileTransformer`
- 먼저 이상치 후보를 탐지하고 싶다 -> `IQR`, `Z-score`

## 정리

- RobustScaler는 중앙값과 IQR 기준으로 스케일링합니다.
- 이상치가 많은 데이터에서 StandardScaler보다 더 안정적일 수 있습니다.
- IQR과 Z-score는 이상치 후보를 찾는 규칙이고, RobustScaler는 스케일링 도구입니다.
- 이상치는 제거할지 유지할지보다 먼저 `왜 생겼는지`를 해석해야 합니다.
- 다만 이상치 문제 전체를 해결하는 것은 아니므로 분포 자체도 함께 봐야 합니다.
