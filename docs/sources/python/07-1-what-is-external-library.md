## 학습 목표

- 외부 라이브러리가 무엇인지 설명할 수 있습니다.
- 표준 라이브러리와 외부 라이브러리의 차이를 구분할 수 있습니다.
- `pip install`과 가상환경이 왜 함께 따라오는지 이해할 수 있습니다.

## 사용 라이브러리

- 표준 라이브러리: `venv`
- 외부 라이브러리: 예시로 `requests`, `numpy`, `pandas`, `matplotlib`, `seaborn`, `plotly`

## 왜 외부 라이브러리를 배워야 하는가

Python이 강력한 가장 큰 이유 중 하나는 문법 자체보다 `생태계`에 있습니다. 즉, 이미 많은 사람들이 만들어 둔 도구를 필요에 맞게 가져다 쓸 수 있다는 점이 큽니다.

실무에서는 다음 작업이 자주 필요합니다.

- 웹 API 호출
- 대규모 테이블 데이터 처리
- 수치 계산 최적화
- 시각화
- 통계 분석

이런 작업을 매번 처음부터 구현하기보다, 검증된 라이브러리를 가져다 쓰는 것이 훨씬 효율적입니다.

## 외부 라이브러리란 무엇인가

외부 라이브러리는 Python 설치만으로는 제공되지 않지만, 특정 문제를 더 편하게 해결하도록 만든 추가 도구입니다.

예:

- `requests`: HTTP 요청
- `numpy`: 배열 계산
- `pandas`: 테이블 데이터 처리
- `matplotlib`, `seaborn`, `plotly`: 시각화

즉, Python 언어 위에 올라가는 `추가 기능 묶음`이라고 이해하면 좋습니다.

## 표준 라이브러리와의 차이

### 표준 라이브러리

Python 설치와 함께 기본 제공됩니다.

예:

- `math`
- `random`
- `datetime`
- `json`
- `pathlib`

### 외부 라이브러리

별도 설치가 필요합니다.

예:

- `requests`
- `numpy`
- `pandas`

이 구분은 입문자에게 중요합니다. 왜냐하면 `import가 안 되는 이유`가 설치 문제인지, 이름 오타인지, 환경 문제인지 구분하는 출발점이 되기 때문입니다.

## 왜 외부 라이브러리를 쓰는가

표준 라이브러리만으로도 많은 일을 할 수 있지만, 어떤 문제는 외부 라이브러리가 훨씬 효율적입니다.

예를 들어:

- 리스트만으로 대량 수치 계산 -> 가능하지만 비효율적
- `numpy` 사용 -> 더 빠르고 더 풍부한 연산 가능

또는:

- `urllib`로 HTTP 요청 -> 가능하지만 상대적으로 복잡
- `requests` 사용 -> 더 읽기 쉽고 편리

즉, 외부 라이브러리는 `문제를 더 짧고 안정적으로 해결하기 위한 도구`입니다.

## 설치가 필요한 이유

외부 라이브러리는 Python 언어 자체가 아니라 `별도 배포되는 패키지`이기 때문에 설치가 필요합니다.

```bash
pip install pandas
```

설치 후에는 코드에서 import해서 사용할 수 있습니다.

```python
import pandas as pd
```

## `pip`는 무엇인가

`pip`는 Python 패키지 설치 도구입니다.

쉽게 말하면:

- 패키지를 다운로드하고
- 현재 Python 환경에 설치해 주는 도구

입니다.

실무에서는 다음 명령을 자주 사용합니다.

```bash
pip install requests
pip install pandas
pip list
```

## 버전이 중요한 이유

외부 라이브러리는 계속 업데이트됩니다. 따라서 같은 코드라도 버전에 따라 동작이 달라질 수 있습니다.

예:

- 어떤 함수가 deprecated 되었을 수 있음
- 기본 옵션이 바뀌었을 수 있음
- 예전 튜토리얼 코드가 최신 버전에서는 그대로 안 될 수 있음

그래서 실무에서는 단순 설치보다:

- 가상환경
- 버전 고정
- `requirements.txt`

가 함께 중요해집니다.

## 가상환경과 외부 라이브러리

외부 라이브러리를 배울 때 가상환경이 같이 따라오는 이유는 프로젝트마다 필요한 패키지와 버전이 다르기 때문입니다.

예:

- 프로젝트 A는 `pandas 2.x`
- 프로젝트 B는 `pandas 1.x`

이 둘을 한 환경에 마구 설치하면 충돌이 날 수 있습니다. 그래서 프로젝트별로 환경을 분리합니다.

## 언제 외부 라이브러리를 도입하면 좋은가

### 바로 쓰는 것이 좋은 경우

- HTTP 요청 -> `requests`
- 배열 계산 -> `numpy`
- 테이블 데이터 -> `pandas`
- 시각화 -> `matplotlib`, `seaborn`, `plotly`

### 표준 라이브러리로 먼저 해보는 것이 좋은 경우

- 파일 입출력
- 날짜 계산
- JSON 처리
- 경로 조작

입문 단계에서는 `표준 라이브러리로 가능한 범위`를 먼저 익히고, 그 한계를 느낄 때 외부 라이브러리를 붙이는 방식이 학습에 도움이 됩니다.

## 실무에서 자주 하는 실수

### 1. 표준 라이브러리와 외부 라이브러리 구분을 못함

그래서 설치가 필요한지 아닌지 헷갈립니다.

### 2. 설치는 했지만 다른 환경에 설치함

터미널과 Notebook이 다른 환경을 보고 있을 수 있습니다.

### 3. 버전을 전혀 신경 쓰지 않음

튜토리얼 코드를 그대로 실행했는데 왜 안 되는지 이해하지 못할 수 있습니다.

### 4. 작은 작업에도 무조건 외부 라이브러리를 가져옴

때로는 표준 라이브러리만으로 충분한데 의존성만 늘어날 수 있습니다.
