## 학습 목표

- Python 실습 환경을 스스로 만들 수 있습니다.
- 스크립트 실행과 Notebook 실행 환경을 구분할 수 있습니다.
- 패키지 설치 문제를 줄이기 위한 기본 원칙을 이해할 수 있습니다.

## 사용 라이브러리

- 표준 라이브러리: `venv`
- 외부 라이브러리: 상황에 따라 `jupyter`, `ipykernel`

## 왜 개발 환경이 중요한가

Python 초보자가 가장 자주 겪는 문제는 문법이 아니라 `설치는 했는데 실행이 안 되는 상황`입니다.

대표적인 원인은 다음과 같습니다.

- 여러 Python 버전이 섞여 있음
- 패키지가 다른 환경에 설치됨
- Notebook 커널과 터미널 환경이 다름

즉, 개발 환경은 부가 지식이 아니라 `코드가 실제로 돌아가게 만드는 기반`입니다.

## 권장 환경

입문 단계에서는 다음 구성을 추천합니다.

- Python `3.11+`
- VS Code 같은 편집기
- 프로젝트별 가상환경
- 필요할 때만 Jupyter Notebook 추가

핵심은 `프로젝트마다 독립된 환경`을 갖는 것입니다.

## Python 설치 후 먼저 확인할 것

터미널에서 다음 명령으로 현재 환경을 확인합니다.

```bash
python --version
pip --version
```

macOS나 일부 환경에서는 `python3`를 사용해야 할 수도 있습니다.

```bash
python3 --version
pip3 --version
```

실무 팁:

- Python 버전
- pip가 연결된 위치
- 현재 실행 중인 인터프리터

이 세 가지를 확인하는 습관이 매우 중요합니다.

## 가상환경이 왜 필요한가

프로젝트마다 필요한 패키지와 버전이 다를 수 있습니다.

예:

- 프로젝트 A는 `pandas 2.2`
- 프로젝트 B는 `pandas 1.5`

이 상태에서 하나의 환경만 쓰면 충돌이 나기 쉽습니다. 그래서 프로젝트별로 가상환경을 분리합니다.

## `venv` 만들기

```bash
python -m venv .venv
```

이 명령은 현재 폴더 안에 `.venv`라는 가상환경을 만듭니다.

## 가상환경 활성화

### macOS / Linux

```bash
source .venv/bin/activate
```

### Windows PowerShell

```powershell
.venv\Scripts\Activate.ps1
```

활성화되면 보통 터미널 프롬프트 앞에 `(.venv)`가 보입니다.

## 패키지 설치

가상환경을 활성화한 뒤 설치합니다.

```bash
pip install pandas matplotlib
```

이렇게 해야 현재 프로젝트 환경에만 패키지가 설치됩니다.

## Notebook 환경은 왜 더 헷갈릴까

Notebook은 화면상으로는 편하지만, 실제로는 `현재 커널이 어떤 Python 환경을 보고 있는지`가 중요합니다.

터미널에서는 설치가 되었는데 Notebook에서 import가 안 되는 경우는 대부분:

- 터미널 Python과
- Notebook 커널 Python

이 다르기 때문입니다.

그래서 Notebook을 쓸 때도 가능하면 현재 가상환경을 커널로 연결하는 습관이 좋습니다.

## VS Code를 활용한 기본 흐름

VS Code에서는 보통 다음 순서로 환경을 맞춥니다.

1. 프로젝트 폴더 열기
2. 가상환경 생성
3. Python 인터프리터 선택
4. 터미널에서 실행 확인
5. 필요하면 Notebook 커널도 같은 환경으로 설정

이 흐름만 지켜도 초반 환경 오류가 크게 줄어듭니다.

## `.py`와 Notebook을 어떻게 구분해 쓸까

### `.py`가 좋은 경우

- 재현 가능성이 중요할 때
- 협업 코드
- 자동화 스크립트
- 배포 전 검증

### Notebook이 좋은 경우

- 실험
- 데이터 탐색
- 시각화 확인
- 교육용 설명

입문 단계에서는:

- 처음에는 `.py` 기준으로 동작 확인
- 탐색과 시각화는 Notebook 활용

이 흐름이 가장 안정적입니다.

## 설치 문제를 줄이는 기본 원칙

### 1. 프로젝트마다 가상환경 분리

가장 중요합니다.

### 2. 설치 후 바로 import 테스트

```bash
python -c "import pandas; print(pandas.__version__)"
```

이렇게 하면 실제 실행 환경 기준으로 설치가 잘 되었는지 빠르게 확인할 수 있습니다.

### 3. 환경 정보부터 확인

문제가 생기면 먼저:

- `python --version`
- `pip --version`
- 어떤 인터프리터를 선택했는지

를 봐야 합니다.

### 4. Notebook 커널과 터미널 환경을 구분

이 차이를 놓치면 같은 컴퓨터에서 `되기도 하고 안 되기도 하는` 상황이 반복됩니다.

## 실무에서 자주 하는 실수

- 전역 환경에 계속 설치해서 프로젝트 간 충돌이 나는 것
- `pip`는 한 환경인데 `python`은 다른 환경인 상태
- Notebook이 다른 커널을 보고 있다는 사실을 모르는 것
- 설치 문제를 코드 문제로 착각하는 것

## 추천 시작 루틴

새 프로젝트를 시작할 때는 다음 순서를 추천합니다.

1. 새 폴더 생성
2. `python -m venv .venv`
3. 가상환경 활성화
4. 필요한 패키지 설치
5. `.py` 파일 하나로 실행 확인

이 루틴이 익숙해지면 환경 문제로 막히는 일이 훨씬 줄어듭니다.

## 정리

이번 페이지의 핵심은 다음입니다.

- Python 개발 환경은 설치보다 `어떤 환경에서 실행 중인지`를 아는 것이 중요합니다.
- 가상환경은 프로젝트별 패키지 충돌을 막는 가장 기본적인 도구입니다.
- Notebook과 스크립트는 편의성뿐 아니라 실행 환경도 다를 수 있습니다.

환경 구성이 안정되면 이후 라이브러리 학습, 데이터 분석, 자동화 실습이 훨씬 매끄럽게 이어집니다.
