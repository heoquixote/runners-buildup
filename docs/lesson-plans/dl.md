# 딥러닝 트랙 레슨 기획안

작성 기준은 [README.md](README.md). 이 트랙은 **실습 없이 개념만** 다룹니다(2026-11-03 결정). 그래서 기호를 이렇게 씁니다.

- `S` 설명 (비유 → 정의 → 왜 필요한지)
- `F` 그림·도식 (자체 SVG, `scripts/figures_dl.py` → `content/img/dl/`)
- `E` 손으로 따라 하는 작은 계산 예 (숫자 2~4개짜리 표 · 단계 목록. 코드 셀 대신 이 역할을 맡는다)
- `V` 모션 영상 (`::video{ref="dl-mNN"}`, 관련 설명 바로 뒤)
- `R` 정리 표 (비교 · 선택 기준)

원본은 진성 님의 빅데이터분석기사 2-1-4 인공신경망 · 2-2-5 딥러닝 분석(`docs/sources/dl/raw-*.md`)과 위키 개념 노트(`docs/sources/dl/*.md`)입니다. 자격증 교재라 설명이 압축돼 있어서, 원고의 표·논리 순서(문제 → 해법 → 남은 문제)를 뼈대로 가져오고 **비유 · 그림 · 손 계산**을 보태 풀어 씁니다.

## 왜 개편하나

기존 트랙은 코스 7개 × 레슨 1개였고,

1. 레슨마다 numpy **실행 셀**이 2~3개 있었습니다. 프로젝트 결정(딥러닝은 개념만)과 맞지 않고, 행렬 곱 코드를 읽는 부담이 개념 이해를 가렸습니다.
2. 한 레슨에 개념이 4~6개씩 몰려 있었습니다(예: dl-02-1에 MSE · 교차엔트로피 · 경사하강법 · 학습률 · 미니배치 · 옵티마이저).
3. "딥러닝은 머신러닝과 무엇이 다른가", "언제 딥러닝을 쓰지 말아야 하나", 옵티마이저, 기울기 소실의 처방, 생성 모델(오토인코더 · GAN · 확산), 전이 학습, 대규모 언어 모델이 빠져 있었습니다.

개편 후에는 **코스 10개 · 레슨 27개**, 레슨 하나에 큰 개념 하나(10~15분)를 둡니다. 머신러닝 트랙(ml-02 로지스틱 회귀 · ml-02-3 경사하강법 · ml-04-2 과적합 · ml-05 검증)의 다음 단계로 이어지도록, 앞에서 배운 개념은 "ml-02-5에서 배운 시그모이드"처럼 한 줄로 연결합니다.

## 공통 규칙

- **실행 셀(```run) 없음.** 코드 대신 `E` 손 계산(숫자 2~4개)과 그림으로 원리를 보입니다. 꼭 보여 줄 코드가 있으면 읽기 전용 ```python 펜스로 3~5줄만(dl-09-2의 Keras 맛보기 하나).
- 각 레슨은 "시작하기 전에"(앞 레슨 한 줄 복습 + 이번에 배울 것)로 시작하고, "자주 하는 오해"와 "정리"로 끝냅니다.
- 수식은 한 줄, 그것도 말로 먼저 설명한 뒤에. 기호(w, b, η)는 처음 나올 때 우리말 이름을 붙입니다.
- 그림은 레슨마다 1~2개. 글자는 한글(SVG는 시스템 글꼴로 렌더).
- 퀴즈는 판단 · 오개념 확인용으로 레슨당 2~3문항(choice · ox · short). "출력 결과를 쓰세요"와 코드 작성(write) 문항은 만들지 않습니다.
- 개념 퀴즈 유닛 40~46에 남아 있던 코드 작성(write) 문항은 같은 내용을 묻는 short · choice 문항으로 바꿉니다.

## dl-00-1 딥러닝은 무엇이 다를까 (트랙 소개)

- **목표**: "딥러닝 = 특징을 사람이 만들지 않고, 층을 깊게 쌓아 데이터에서 스스로 배우는 머신러닝"을 자기 말로 설명할 수 있다.
- **전제 개념**: ml-00-1(AI ⊃ ML ⊃ DL, fit/predict). 없으면 한 줄로 다시 짚는다.
- **알아야 할 개념**
  1. AI · ML · DL 포함 관계 복습 (한 줄)
  2. 머신러닝이 잘하는 것: 표 데이터, 사람이 고른 특성(나이·등급·온도)
  3. 사진·소리·글은 표가 아니다 — "고양이 귀 모양"을 사람이 숫자로 정의하기 어렵다
  4. 딥러닝의 차이: **특징 만들기를 모델 안으로** 가져왔다 (사람이 만든 특징 vs 학습된 특징)
  5. 층이 쌓이며 표현이 추상화된다: 점·선 → 모양 → 부품 → 물체
  6. "깊다(deep)"의 뜻 = 층이 많다
  7. 우리 주변의 딥러닝: 얼굴 인식, 번역, 음성 비서, 챗봇, 불량 사진 검사
- **배치**: S(시작하기 전에) → S(ML 복습: 타이타닉 표) → S(사진을 표로 만들 수 있을까? 사람이 특징 정의하는 어려움) → **F1** 전통 ML vs DL 파이프라인 → S(딥러닝의 정의) → **F2** 층별 표현(선 → 모양 → 물체) → S(deep의 뜻) → R(생활·제조 사례 표) → S(자주 하는 오해: 딥러닝 = 뇌 복제? / 딥러닝이 항상 더 좋다?) → S(정리)
- **퀴즈 vs 코드**: 퀴즈 2. 개념 구분이 목표.
  - choice: 딥러닝과 전통 머신러닝의 가장 큰 차이는? (특징을 누가 만드나) / ox: 딥러닝은 사람 뇌를 그대로 본떠 만든 것이다(X)
- **그림**: F1 dl00-ml-vs-dl(입력 → 사람이 특징 설계 → 모델 vs 입력 → 신경망(특징+판단)), F2 dl00-hierarchy(층 1 선 · 층 2 모양 · 층 3 부품 · 출력 고양이)
- **영상**: 없음
- **원본**: raw-2-2-5 "깊이가 바꾼 것" 표(특징 추출 · 데이터량 · 정형/비정형 · 연산 · 해석), 고양이 귀 예. raw-2-1-4 "특징 설계를 모델에 맡기기로 한 하나의 선택" 문장. figures/ai-ml-dl-taxonomy.svg는 ml00-ai-ml-dl로 이미 다시 그렸으므로 링크만.

## dl-00-2 딥러닝의 역사와 쓸 때 · 안 쓸 때

- **목표**: 두 번의 침체와 지금 딥러닝을 가능하게 한 세 조건을 말하고, 주어진 문제에 딥러닝이 맞는지 판단할 수 있다.
- **전제**: dl-00-1.
- **개념**: 1) 퍼셉트론(1958) 2) 첫 겨울: XOR 3) 다층 퍼셉트론 + 역전파(1986) 4) 두 번째 겨울: 깊으면 학습 안 됨 5) 딥러닝의 부활(2006~2012): 데이터 · GPU · 학습 기법(ReLU · 드롭아웃 · 배치 정규화) 6) 2017 Transformer → LLM 7) 쓸 때 · 안 쓸 때 표 8) 트랙 지도
- **배치**: S(시작하기 전에) → S(역사를 왜 보나: 각 단계가 앞 문제를 푸는 이야기) → **F1** 연표 → S(겨울 두 번 · 해결 각각 한 문단, 뒤 코스 링크) → S(세 조건: 요리 비유 — 재료(데이터) · 화력(GPU) · 레시피(기법)) → R(세 조건 표) → S(쓸 때 · 안 쓸 때) → R(판단 표) → S(표 데이터는 부스팅이 강한 이유 한 문단, ml-04-4 링크) → **F2** 트랙 지도 → S(정리)
- **퀴즈**: 2. 상황 판단.
  - choice: 다음 중 딥러닝보다 그래디언트 부스팅이 먼저 고려될 문제는? (설비 센서 요약 표 1,000행) / ox: 딥러닝 아이디어는 2010년대에 처음 나왔다(X)
- **그림**: F1 dl00-timeline(1958 퍼셉트론 → XOR 겨울 → 1986 역전파 → 깊이 겨울 → 2012 이미지 대회 → 2017 Transformer → LLM), F2 dl00-track-map(DAY 01~10)
- **원본**: raw-2-1-4 "인공신경망의 발전" 표, raw-2-2-5 "왜 최근에야 가능해졌는가" · "딥러닝을 쓸지 판단하기".

## dl-01-1 뉴런 하나가 하는 일

- **목표**: 입력 · 가중치 · 편향으로 가중합을 구하고 활성화 함수를 적용하는 두 단계를 손으로 계산할 수 있다.
- **전제**: ml-02-5의 "점수 → 확률" 흐름을 알면 좋다. 곱하고 더하기만 할 줄 알면 된다.
- **개념**: 1) 생물 뉴런 비유(입력 신호를 모아 일정 이상이면 신호를 보냄)와 한계 2) 입력 x · 가중치 w(중요도) · 편향 b(기준선 조정) 3) 가중합 z = w₁x₁ + w₂x₂ + b 4) 활성화(일단 계단 함수: 0보다 크면 1) 5) 소풍 갈까 결정 예(날씨 · 친구 · 거리) 6) 학습 = w, b를 데이터로 정하는 일 7) 로지스틱 회귀 = 뉴런 하나 + 시그모이드
- **배치**: S(시작하기 전에) → S(투표·결정 비유: 소풍) → **F1** 뉴런 도식 → S(가중치 · 편향의 뜻) → E(소풍 손 계산 2가지 경우) → S(편향을 바꾸면 결정이 바뀐다) → E(편향 바꾸기) → S(학습 = 숫자 맞추기, 구조는 사람 · 숫자는 데이터) → S(로지스틱 회귀와의 관계) → S(자주 하는 오해: 편향 빠뜨림, 활성화 건너뜀) → S(정리)
- **퀴즈**: 2. 계산 원리 → short, 오해 → ox.
  - short: x=[1,2], w=[0.5,−1], b=1이면 z? (−0.5) / ox: 학습은 뉴런 개수를 바꾸는 일이다(X)

## dl-01-2 활성화 함수: 신호를 다듬는 스위치

- **목표**: 계단 · 시그모이드 · tanh · ReLU · Leaky ReLU · 소프트맥스의 모양과 쓰임을 구분하고 위치에 맞는 것을 고를 수 있다.
- **전제**: dl-01-1 가중합 z.
- **개념**: 1) 활성화의 두 역할: 비선형 만들기 · 출력 모양 맞추기 2) 계단 → 시그모이드(부드러운 계단, 0~1) 3) tanh(−1~1, 평균 0) 4) 양 끝이 평평 = 기울기 0 (dl-03-3 예고) 5) ReLU(음수 0, 양수 그대로) — 은닉층 표준 6) Dying ReLU와 Leaky ReLU 7) 소프트맥스(여러 점수 → 합 1 확률) 8) 어디에 무엇을 쓰나 표
- **배치**: S(시작하기 전에) → S(스위치·조광기 비유) → **F1** 함수 4개 그래프 → S(각 함수 한 문단) → E(z=−2, 0, 3에서 각 함수 값 표) → S(Dying ReLU) → S(소프트맥스: 반 회장 선거 득표 비유) → E(점수 2, 1, 0 → 0.67, 0.24, 0.09) → **F2** 소프트맥스 막대 → R(어디에 무엇 표) → S(오해: 출력층에도 ReLU? 회귀 출력엔 활성화 없음) → S(정리)
- **퀴즈**: 3. 상황 판단.
  - choice: 사진을 고양이·개·새 중 하나로 분류하는 출력층 활성화? (소프트맥스) / short: ReLU(−3)? (0) / ox: 시그모이드 출력은 항상 0과 1 사이다(O)
- **그림**: F1 dl01-activations(계단 · 시그모이드 · tanh · ReLU 4칸), F2 dl01-softmax(점수 → 확률 막대)

## dl-01-3 왜 층을 쌓을까: XOR과 비선형

- **목표**: 직선 하나로 나눌 수 없는 문제(XOR)를 은닉층이 푸는 원리와, 비선형 활성화가 없으면 층을 쌓아도 소용없는 이유를 설명할 수 있다.
- **전제**: dl-01-1 뉴런 = 직선 하나로 나누기, dl-01-2 비선형 활성화.
- **개념**: 1) 뉴런 하나 = 평면 위 직선 하나 2) AND · OR는 직선으로 나뉜다 3) XOR(둘이 다를 때만 1)은 안 된다 → 첫 번째 겨울 4) 해법: 은닉층 — OR 뉴런 · NAND 뉴런을 만들고 둘을 AND로 합친다 5) 은닉층이 점들을 새 공간으로 옮긴다 6) 선형만 쌓으면 결국 직선 하나(2배 하고 3배 = 6배 한 번) 7) 은닉층 = 특징을 만드는 층, 다층 퍼셉트론(MLP)
- **배치**: S(시작하기 전에) → S(직선 하나 = 칼질 한 번 비유) → **F1** AND · OR · XOR 점 4개 그림 → S(XOR이 왜 안 되나) → S(해법: 칼질 두 번 후 합치기) → E(XOR 진리표: x1 x2 → OR · NAND → AND) → **F2** 은닉층이 공간을 바꾸는 그림 → S(선형만 쌓으면? 2배·3배 비유) → S(MLP 정의) → S(오해: 층이 많을수록 항상 좋다) → S(정리)
- **퀴즈**: 2.
  - choice: 활성화 함수 없이 선형 층 3개를 쌓으면? (선형 층 1개와 같다) / ox: 단층 퍼셉트론으로 XOR을 풀 수 있다(X)
- **그림**: F1 dl01-xor(AND · OR · XOR 세 칸, 직선 그어짐/안 그어짐), F2 dl01-xor-hidden(입력 공간 → 은닉 공간(h1, h2)에서 직선 하나로 나뉨)
- **원본**: raw-2-1-4 "XOR 문제가 중요한 이유"(은닉층이 입력을 다른 공간으로 옮김), "활성화 함수가 없으면 층을 쌓는 의미가 사라집니다". 기존 dl-01-1의 XOR 코드(OR · NAND · AND 가중치)를 손 계산 표로 바꿈.

## dl-02-1 틀린 정도 재기: 손실 함수

- **목표**: 손실 함수가 하는 일을 설명하고, 회귀엔 MSE · 분류엔 교차엔트로피를 쓰는 이유를 말할 수 있다.
- **전제**: ml-02-2 MAE · RMSE, ml-02-5 로그 손실(있으면 연결).
- **개념**: 1) 학습하려면 "얼마나 틀렸나"를 숫자 하나로 2) 손실 = 채점표 3) MSE(오차 제곱 평균): 크게 틀린 것에 큰 벌점 4) 분류에서 MSE가 아쉬운 이유 5) 교차엔트로피: 정답에 준 확률의 −log, 자신 있게 틀리면 벌점 폭발 6) 다중 분류도 정답 칸 확률만 본다 7) 손실 vs 평가 지표(정확도)는 다르다

- **그림**: F1 dl02-crossentropy(정답에 준 확률 p → −log p 곡선, 0.9 · 0.5 · 0.1 표시)

## dl-02-2 내리막으로 걷기: 경사하강법과 학습률

- **목표**: 경사하강법 규칙(w ← w − 학습률 × 기울기)으로 한 걸음을 계산하고, 학습률이 크거나 작을 때 생기는 일을 말할 수 있다.

## dl-02-3 조금씩 보고 고치기: 배치 · 미니배치 · 에폭

- **목표**: 에폭 · 배치 크기 · 반복(iteration)의 관계를 계산하고, 배치 · SGD · 미니배치의 장단점을 비교할 수 있다.

## dl-03-2 역전파: 책임을 거꾸로 나누기

- **목표**: 계산 그래프에서 덧셈 · 곱셈 노드를 따라 기울기를 거꾸로 전달하고, 연쇄법칙을 "영향의 곱"으로 설명할 수 있다.
- **전제**: dl-02-2 기울기, dl-03-1 순전파.
- **개념**: 1) 문제: 가중치가 수천 개, 각각 얼마나 책임 있나 2) 단체 과제 책임 나누기 비유 3) 계산 그래프 4) 연쇄법칙: 톱니바퀴(A가 1 돌면 B 2, B가 1 돌면 C 3 → A가 1 돌면 C 6) 5) 덧셈 노드: 그대로 나눠줌 6) 곱셈 노드: 상대편 값을 곱해줌 7) 장보기 예 (사과 2개 × 100원 × 세금 1.1) 8) 역전파가 빠른 이유: 한 번 거꾸로 가며 모두 계산

## dl-03-3 기울기 소실과 폭주

- **목표**: 깊은 층에서 기울기가 사라지거나(소실) 터지는(폭주) 이유를 곱셈으로 설명하고, ReLU · 초기화 · 배치 정규화 · 잔차 연결 · 클리핑 처방을 연결할 수 있다.
- **전제**: dl-03-2 연쇄법칙 = 곱, dl-01-2 시그모이드 양 끝 평평.
- **개념**: 1) 전화 게임(말 전달) 비유 2) 시그모이드 기울기 최대 0.25 → 0.25¹⁰ ≈ 0.000001 3) 앞쪽 층이 안 배움 = 두 번째 겨울 4) 반대로 1보다 큰 수가 곱해지면 폭주 5) 처방: ReLU(기울기 1), 좋은 초기화(He · Xavier, 이름만), 배치 정규화(dl-04-3), 잔차 연결(지름길), 기울기 클리핑(폭주) 6) RNN에서도 같은 문제(dl-06-2 예고)
- **배치**: S(시작하기 전에) → S(전화 게임) → E(0.25를 층 수만큼 곱하기 표: 1, 2, 5, 10층) → **F1** 층별 기울기 크기 막대(시그모이드 vs ReLU) → S(폭주) → R(처방 표) → **F2** 잔차 연결 지름길 → S(오해) → S(정리)

- **그림**: F1 dl03-vanishing, F2 dl03-residual

## dl-06-2 긴 기억의 문제와 LSTM · GRU

- **목표**: 긴 시퀀스에서 RNN이 앞부분을 잊는 이유를 기울기 소실로 설명하고, LSTM의 세 게이트가 하는 일을 비유로 말할 수 있다.
- **전제**: dl-03-3 기울기 소실, dl-06-1.
- **개념**: 1) 긴 문장 예("어제 산 … 그것은") 2) 시점을 거슬러 갈 때마다 곱 → 소실 3) LSTM: 셀 상태(컨베이어 벨트) + 게이트 3개(잊기 · 입력 · 출력) 4) 게이트 = 0~1 밸브(시그모이드) 5) 덧셈으로 흐르는 셀 상태 → 기울기가 덜 사라짐 6) GRU: 게이트 2개로 단순화 7) 그래도 남는 한계: 순차 처리라 느림 · 아주 긴 거리 → 어텐션(dl-07)
- **배치**: S(시작하기 전에) → S(긴 문장 예) → S(왜 잊나) → **F1** LSTM 셀(벨트 + 밸브 3개) → R(게이트 표: 질문 · 비유) → S(왜 덜 잊나) → S(GRU) → R(RNN · LSTM · GRU 비교 표) → S(남은 한계 → 어텐션) → S(오해) → S(정리)

  - ox: LSTM은 게이트를 써서 기울기 소실 문제를 줄인다(O) / choice: 지난 정보 중 무엇을 버릴지 정하는 게이트? (잊기 게이트)

## dl-07-1 단어를 숫자로: 토큰과 임베딩

- **목표**: 글을 토큰으로 나누는 이유, 원-핫의 한계, 임베딩이 의미를 거리로 담는 방식을 설명할 수 있다.
- **전제**: ml-01-3 원-핫 인코딩.
- **개념**: 1) 모델은 숫자만 2) 토큰화: 단어 · 조각(subword) 단위 3) 원-핫: 어휘 5만 → 5만 칸, 모든 단어 사이 거리 같음 4) 임베딩: 수백 칸짜리 촘촘한 벡터, 비슷한 뜻은 가까이 5) 지도 위 좌표 비유 6) 코사인 유사도 = 방향이 얼마나 같은가 7) 유명한 예: 왕 − 남자 + 여자 ≈ 여왕 8) 임베딩도 학습된다 · 쓰임(검색, 추천, RAG)
- **배치**: S(시작하기 전에) → S(토큰화) → **F1** 문장 → 토큰 → 번호 → S(원-핫의 한계) → S(지도 좌표 비유) → **F2** 2차원 임베딩 지도(불량 · 결함 · 흠집 가깝고, 송장 · 견적 멀리) → E(2차원 벡터 3개로 거리 비교) → S(왕 − 남자 + 여자) → S(쓰임) → S(오해) → S(정리)
- **퀴즈**: 2.
  - choice: 원-핫 표현의 문제? (모든 단어 사이 거리가 같아 의미 유사성을 못 담음) / ox: 임베딩 벡터의 숫자는 사람이 하나하나 정해 준다(X)
- **그림**: F1 dl07-tokenize, F2 dl07-embedding-map
- **원본**: embedding.md (임베딩 정의 · 같은 모델 공간), 기존 dl-07-1의 defect/flaw/invoice 예를 지도 그림으로.

## dl-07-2 어텐션: 어디를 볼지 스스로 정하기

- **목표**: Q · K · V로 관련도 → softmax 가중치 → 가중합을 만드는 과정을 작은 예로 따라가고, RNN과 달리 먼 단어를 바로 볼 수 있음을 설명할 수 있다.
- **전제**: dl-07-1 임베딩, dl-01-2 소프트맥스, dl-06-2 RNN의 한계.
- **개념**: 1) "그것"이 무엇을 가리키나 2) 사람은 문장 전체를 훑고 관련 단어에 집중 3) 도서관 검색 비유: Q(내가 찾는 것) · K(책 제목표) · V(책 내용) 4) 단계: Q·K 점수 → √d로 나눔 → softmax → V 가중합 5) 손 계산: 점수 [2, 0, 1] → 가중치 [0.67, 0.09, 0.24] 6) 결과 = 문맥이 섞인 새 표현 7) 어텐션 가중치 시각화로 해석 8) √d로 나누는 이유 한 문단
- **배치**: S(시작하기 전에) → S("그것" 예) → S(도서관 비유) → **F1** Q · K · V 흐름 → E(점수 → softmax → 가중합) → V dl-m28 → **F2** 어텐션 가중치 히트맵(문장 내 단어끼리) → S(√d) → S(RNN과 비교) → S(오해) → S(정리)
- **퀴즈**: 2.
  - choice: 어텐션 가중치를 만들 때 Q와 K의 유사도에 적용하는 함수? (softmax) / ox: 어텐션은 가까이 있는 단어만 참고할 수 있다(X)
- **그림**: F1 dl07-qkv, F2 dl07-attention-map
- **영상**: dl-m28
- **원본**: transformer.md, raw-2-2-5 "트랜스포머"(어텐션 · '그것' 예).

## dl-07-3 Transformer와 대규모 언어 모델

- **목표**: 셀프 어텐션 · 멀티헤드 · 위치 정보로 이루어진 Transformer 블록과, LLM이 다음 토큰을 예측하며 글을 만드는 큰 그림을 설명할 수 있다.
- **전제**: dl-07-2.
- **개념**: 1) RNN의 두 한계(순차 처리 · 먼 거리) 2) 셀프 어텐션: 같은 문장에서 Q · K · V 3) 멀티헤드: 여러 관점(문법 · 지시어 …) 4) 위치 정보 더하기 5) Transformer 블록 = 어텐션 + 작은 MLP + 잔차 · 정규화, 여러 번 쌓기 6) 인코더(BERT, 이해) · 디코더(GPT, 생성) 7) LLM: 다음 토큰 맞히기를 엄청난 글로 사전학습 → 지시 따르기 미세 조정 8) 한계: 그럴듯한 틀린 말(환각), 계산량은 길이의 제곱 9) 이미지(ViT) · 음성에도
- **배치**: S(시작하기 전에) → S(두 한계) → **F1** Transformer 블록 도식 → S(셀프 · 멀티헤드 · 위치) → R(인코더 vs 디코더 표) → S(LLM: 다음 토큰 예측) → **F2** 다음 토큰 예측(“오늘 날씨가” → 좋다 0.41 · 맑다 0.22 …) → E(한 토큰씩 이어 쓰기) → S(사전학습 → 미세 조정) → S(한계) → S(오해: LLM은 사실을 검색해서 답한다?) → S(정리)
- **퀴즈**: 3.
  - ox: 셀프 어텐션에서 Q, K, V는 같은 입력에서 각각 다른 가중치로 만든다(O) / choice: Transformer가 순서 정보를 얻는 방법? (위치 정보를 더함) / choice: GPT 같은 LLM의 기본 학습 과제? (다음 토큰 예측)
- **그림**: F1 dl07-transformer-block, F2 dl07-next-token
- **원본**: transformer.md, raw-2-2-5 "트랜스포머" 한계 표.
