# 머신러닝 트랙 레슨 기획안

작성 기준은 [README.md](README.md). 기호: `S` 설명, `F` 그림, `C` 실행 셀, `T` 직접 해보기, `R` 결과 해석.

원본은 진성 님의 머신러닝 기초 원고(`docs/sources/ml/`, 매핑은 `docs/sources/README.md`)입니다. 원고는 실무자 기준이라, 레슨에서는 전제 개념을 보태고 고등학생~대학 초년생 눈높이로 풀어 씁니다. 모션 영상은 트랙 페이지에 따로 모으지 않고 본문 흐름 속 위치에 넣습니다(아직 제작 전이면 '영상 준비 중' 자리로 보이고, 영상 주소가 들어오면 바로 재생).

## 트랙 전체 흐름

| 레슨 | 한 문장 목표 | 데이터 | 마무리 방식 |
| --- | --- | --- | --- |
| ml-01 워크플로 | 데이터를 X·y로 나누고, 학습용·시험용으로 나눠 기준 점수를 잴 수 있다 | 타이타닉, AI4I | 퀴즈 3 |
| ml-02 회귀 | 직선으로 숫자를 예측해 오차를 재고, 확률로 분류할 수 있다 | AI4I, 타이타닉 | 퀴즈 2 |
| ml-03 평가지표 | 상황에 맞는 지표(정밀도·재현율)를 고를 수 있다 | 타이타닉 | 퀴즈 3 |
| ml-04 트리 | 깊이를 바꾸며 과적합을 확인하고, 배깅·부스팅을 구분할 수 있다 | 타이타닉, AI4I | 레슨 완료 (T 셀) |
| ml-05 교차검증 | 점수를 여러 번 재서 평균 내고, 설정값을 고를 수 있다 | 타이타닉 | 퀴즈 2 |
| ml-06 전처리·Pipeline | 빈칸·글자·크기 차이를 손질해 모델 하나로 묶을 수 있다 | 타이타닉, AI4I | 레슨 완료 (실습 문제) |
| ml-07 비지도 | 정답 없이 묶고(K-means) 요약(PCA)할 수 있다 | AI4I, 와인 | 퀴즈 3 |
| ml-08 불균형 | 드문 고장을 놓치지 않게 모델을 조정할 수 있다 | AI4I | 퀴즈 2 |
| ml-09 해석 | 모델이 무엇을 보고 판단했는지 설명할 수 있다 | AI4I, 타이타닉 | 퀴즈 2 |

**중복 정리**: 정확도의 함정은 ml-01(기준 모델)에서 처음, ml-03에서 지표로 정식으로 배운다. 임계값 개념은 ml-03이 맡고, ml-08은 "비용으로 기준선 정하기"에 집중한다. `feature_importances_`는 ml-04에서 처음 보고, ml-09에서 약점과 대안(순열 중요도)을 배운다.

## ml-01 모델보다 먼저: 나누고, 기준을 세우고, 새지 않게

- **목표**: 표를 X·y로 나누고, 학습용·시험용으로 나눈 뒤, 기준 모델 점수를 잴 수 있다.
- **전제 개념**: pandas로 CSV 읽기, 열 선택 (데이터분석 트랙). 그 외는 없음.
- **알아야 할 개념**
  1. 머신러닝 = 예전 기록에서 규칙을 스스로 찾게 하는 것 (규칙을 사람이 쓰는 프로그래밍과 비교)
  2. 행 = 사례, 특성 X, 정답 y
  3. 모델은 숫자만 받는다 (sex → female 0/1, 빈칸 채우기)
  4. 학습용 / 시험용 나누기 (문제집 vs 시험지)
  5. stratify (정답 비율 맞추기)
  6. 기준 모델 (찍기 점수)
  7. 누수 (시험지 미리 보기), fit은 학습용으로만
- **배치**: S(머신러닝이란) → **F1** → S(X·y) → **F2** → C(타이타닉 불러오기) → R → C(성별·객실별 생존율) → R → S(숫자로 바꾸기) → C(X, y 만들기) → S(나누기 비유) → **F3** → C(train_test_split) → **T**(test_size 바꿔 보기) → S(stratify) → C(AI4I 비교) → R → S(기준 모델) → C(Dummy) → R → S(누수) → C(scaler fit) → S(정리: 작업 순서)
- **퀴즈 vs 코드**: **퀴즈 3문항**. 이 레슨의 핵심은 코드보다 "순서와 판단"(언제 나누나, 무엇이 누수인가)이다. 코드 실습은 유닛 17 문제(분할·기준 모델)가 맡는다.
  - choice: stratify 인자 / ox: 스케일러를 전체로 fit하는 게 정석이다(X) / choice: 누수 상황 고르기(새로 추가)
- **그림**: F1 프로그래밍 vs 머신러닝(규칙→답 / 데이터+답→규칙), F2 표에서 행·X·y 색칠, F3 학습용 75% / 시험용 25% 막대
- **연결 실습**: 유닛 17 (17-1~17-4)
- **영상 위치**: 없음 (이 레슨에 맞는 모션 영상 없음)
- **원본 원고**: docs/sources/ml/01-1-ml-vs-rule-based, 01-2, 02-1-dataset-feature-label, 02-2-train-validation-test-split, 02-3-data-leakage
- **원고 반영**: 원고에서 가져온 것: 규칙 기반 vs 머신러닝 판단 표, train/validation/test 세 덩어리(문제집·모의고사·수능), 시간·그룹 단위 분할 주의, 누수 3유형(정답을 다르게 쓴 열·미래 정보·전처리 누수)과 `final·completed·after` 열 이름 경고. 타이타닉 `alive` 열로 target leakage 실습(정확도 0.76 → 1.0).

## ml-02 직선 하나로 예측하고, 확률로 분류하기

- **목표**: LinearRegression으로 숫자를 예측하고, LogisticRegression으로 확률을 출력할 수 있다.
- **전제 개념**: ml-01의 X·y, fit/predict
- **알아야 할 개념**
  1. 회귀(숫자 예측) vs 분류(범주 예측)
  2. 직선 = 기울기 × x + 절편. "자를 대고 점들 사이로 선 긋기"
  3. 오차를 가장 작게 만드는 선을 찾는다 (최소제곱, 수식 없이)
  4. 특성 여러 개 = 각 특성마다 기울기
  5. 로지스틱 회귀: 직선 결과를 0~1 확률로 눌러 담는 S자 곡선
  6. predict_proba와 기준선 0.5
  7. 계수 부호로 방향 읽기
- **배치**: S(두 종류 예측) → **F1** → S(직선 비유) → C(1등실 운임 vs 나이 산점도…기존) → R → C(LinearRegression) → R(기울기 해석) → **T**(특성 하나 추가해 R² 비교) → S(분류로 넘어가기) → **F2** → C(LogisticRegression, predict_proba) → R → S(계수 해석) → C → R → S(정리)
- **퀴즈 vs 코드**: **퀴즈 2문항** (coef_ 속성, 0.5 기준). 회귀식 사용은 T 셀과 유닛 18 문제가 맡는다.
- **그림**: F1 회귀(숫자) vs 분류(범주) 비교 카드, F2 직선 → S자 곡선(시그모이드) 변환
- **연결 실습**: 유닛 18
- **영상 위치**: dl-m09 경사하강법: '오차가 가장 작은 선을 찾는다' 설명 바로 뒤
- **원본 원고**: docs/sources/ml/06-1-linear-regression-and-loss, 06-2-regression-metrics-and-interpretation, 07-1-logistic-regression-and-probability
- **원고 반영**: 원고에서 가져온 것: MAE·RMSE·R² 함께 보기(시험용으로 평가, MAE 0.59 K), 확률 예측과 클래스 판정은 다르다, 계수를 원인으로 읽지 않기. 회귀는 AI4I 온도, 분류는 타이타닉.

## ml-03 정확도 말고 무엇을 볼까

- **목표**: 혼동행렬 네 칸을 읽고, 상황에 맞는 지표를 고를 수 있다.
- **전제 개념**: ml-01 기준 모델(정확도의 함정), ml-02 predict_proba
- **알아야 할 개념**
  1. 정확도의 한계 (ml-01 연결, 한 줄)
  2. 혼동행렬 TP·FP·FN·TN (화재경보기 비유)
  3. 정밀도 = 헛경보가 적은가, 재현율 = 놓침이 적은가, F1
  4. 상황별로 더 아픈 실수가 다르다
  5. 임계값: 경보 감도 (이 트랙에서 임계값을 정식으로 배우는 곳)
  6. ROC·AUC: 기준선과 상관없는 점수
- **배치**: S → **F1**(혼동행렬 네 칸) → C(confusion_matrix) → R(네 칸 숫자 짚기) → S(정밀도·재현율) → **F2**(정밀도 vs 재현율 분모 비교) → C(classification 지표) → R → S(상황표) → S(임계값) → C(임계값별 지표) → **T**(임계값 직접 바꾸기) → R → S(ROC) → C(roc_auc) → S(정리)
- **퀴즈 vs 코드**: **퀴즈 3문항**. 이 레슨의 핵심은 "어떤 실수가 더 아픈가"라는 **판단**이라 퀴즈가 가장 효과적이다. 계산 원리는 short 1문항으로.
  - short: TP=6, FN=2 → 재현율 / choice: 임계값을 낮추면 / choice(새로): "암 검진 1차 선별에서 더 중요한 지표는?"
- **그림**: F1 혼동행렬 2×2 (색: 맞힘 초록, 놓침 빨강, 헛경보 노랑), F2 정밀도는 "울린 것 중", 재현율은 "진짜 불 중" 분모를 동그라미로 강조
- **연결 실습**: 유닛 19
- **영상 위치**: dl-m11 임계값과 precision/recall/ROC: '임계값을 낮추면/올리면' 설명 바로 뒤
- **원본 원고**: docs/sources/ml/07-2-threshold-confusion-matrix, 08-1-precision-recall-f1, 08-2-roc-auc-pr-auc
- **원고 반영**: 원고에서 가져온 것: 기본 0.5를 그대로 쓰지 않기, 드문 대상에서는 PR-AUC 함께 보기(ROC-AUC 0.90 vs PR-AUC 0.49). F-beta는 범위 밖이라 뺌.

## ml-04 질문을 쌓는 결정트리, 투표하는 숲

- **목표**: 결정트리를 읽고, 깊이를 바꿔 과적합을 확인하고, 랜덤포레스트로 개선할 수 있다.
- **전제 개념**: ml-01 학습용/시험용 점수
- **알아야 할 개념**
  1. 결정트리 = 스무고개 (예/아니오 질문을 쌓기)
  2. 트리 읽는 법 (조건, 왼쪽=예)
  3. 과적합 = 문제집 답을 외움 (학습 점수↑ 시험 점수↓)
  4. max_depth로 막기
  5. 랜덤포레스트 = 여러 트리의 다수결
  6. feature_importances_ 맛보기 (자세한 것은 ml-09)
- **배치**: S(스무고개) → **F1**(타이타닉 트리 그림) → C(export_text) → R(트리 읽기) → S(과적합) → **F2**(깊이별 학습/시험 점수 곡선 개념도) → C(깊이별 점수) → **T**(max_depth 바꿔 보기) → R → S(숲) → **F3**(트리 여러 그루 → 투표) → C(RandomForest) → R → S(중요도 맛보기) → C → S(정리)
- **퀴즈 vs 코드**: **퀴즈 없음, 레슨 완료**. 과적합은 T 셀에서 깊이를 직접 바꿔 학습·시험 점수 차이가 벌어지는 걸 보는 게 퀴즈보다 훨씬 강하게 남는다. 유닛 20 문제가 코드 실습을 맡는다.
- **그림**: F1 깊이 2 트리 (성별 → 나이/객실), F2 과적합 곡선, F3 숲 투표
- **연결 실습**: 유닛 20
- **영상 위치**: dl-m10 과적합: 과적합 그림 뒤 / dl-m23 결정트리와 앙상블: 숲 투표 그림 뒤
- **원본 원고**: docs/sources/ml/10-1-decision-tree-basics, 10-2-random-forest-classifier, 10-3-gradient-boosting-classifier
- **원고 반영**: 원고에서 가져온 것: 부스팅(앞 트리의 실수를 차례로 보완) vs 배깅 비교표와 실습, min_samples_leaf, 중요도를 원인처럼 과장하지 않기(ml-09로 연결). XGBoost 등은 이름만 소개.

## ml-05 한 번 나눈 점수를 믿지 말자

- **목표**: 교차검증으로 점수를 평균 내고, GridSearchCV로 설정값을 고를 수 있다.
- **전제 개념**: ml-01 분할, ml-04 max_depth
- **알아야 할 개념**
  1. 한 번 나눈 점수에는 운이 섞인다 (random_state만 바꿔도 달라짐)
  2. K-fold: 돌아가며 시험 보기
  3. 섞지 않으면 조각이 치우칠 수 있다 (shuffle)
  4. 하이퍼파라미터 = 사람이 정하는 설정값
  5. GridSearchCV = 후보 전부 교차검증
  6. 시험용은 맨 마지막에 한 번
- **배치**: S → C(random_state별 점수) → R → S(K-fold) → **F1**(5-fold 그림) → C(cross_val_score) → R → S(조각 치우침) → C → R → S(하이퍼파라미터) → S(GridSearch) → **F2**(후보 × 폴드 표) → C → **T**(후보 목록 바꾸기) → R → S(정리)
- **퀴즈 vs 코드**: **퀴즈 2문항** (write: cross_val_score 점수 개수 / ox: 시험용은 마지막에 한 번). "시험용을 언제 쓰나"는 판단 문제라 퀴즈로 확인한다.
- **그림**: F1 5줄 막대(각 줄에서 시험 조각 위치가 이동), F2 그리드 서치 표(깊이 후보 × 평균 점수, 최고 칸 강조)
- **연결 실습**: 유닛 35
- **영상 위치**: dl-m24 K-fold 교차검증: K-fold 단계 설명 뒤 (dl-m10은 ml-04에서 이미 보므로 여기서는 뺌)
- **원본 원고**: docs/sources/ml/09-1-overfitting-underfitting, 09-2-cross-validation-and-regularization, 09-4-hyperparameter-tuning-grid-random-optuna
- **원고 반영**: 원고에서 가져온 것: 과소적합·적당함·과적합 3단 표, 시계열에는 일반 K-fold 주의, RandomizedSearch·Optuna 소개. 정규화(Ridge·Lasso)는 이 눈높이에서 범위 밖이라 뺌.

## ml-06 전처리와 모델을 한 줄로 잇기

- **목표**: 빈칸·글자·크기 차이를 손질하고, Pipeline으로 전처리와 모델을 묶을 수 있다.
- **전제 개념**: ml-01 누수(fit은 학습용으로만), ml-05 교차검증
- **알아야 할 개념**: 빈칸 채우기 / 원-핫 인코딩 / 표준화 / 새 특성 만들기 / ColumnTransformer + Pipeline
- **배치**: S(재료 손질 비유) → C(빈칸·글자 확인) → S(빈칸) → C → S(원-핫) → **F1**(class 열 → 0/1 세 열) → C → S(표준화) → **F2**(키·몸무게 비유: 단위 맞추기 전후) → C → S(새 특성) → C(power, temp_gap) → R → S(Pipeline) → **F3**(숫자 열 / 글자 열 갈래 → 모델) → C → R → S(정리 표)
- **퀴즈 vs 코드**: **퀴즈 없음, 레슨 완료**. 이 레슨은 전부 "쓸 줄 아는가"의 문제라 이름 맞히기 퀴즈는 효과가 낮다. 유닛 36 문제(전처리·Pipeline 빈칸 채우기)가 실습을 맡는다.
- **그림**: F1 원-핫, F2 표준화 전후 막대, F3 ColumnTransformer 흐름도
- **연결 실습**: 유닛 36
- **영상 위치**: 없음
- **원본 원고**: docs/sources/ml/03-2-baseline-and-pipeline, 03-4-categorical-encoding-and-preprocessing-order, 04-1-standard-scaling, 05-1-what-is-derived-features

## ml-07 정답 없이 묶고, 줄이기

- **목표**: K-means로 비슷한 것끼리 묶고, PCA로 열 여러 개를 2개로 요약해 그릴 수 있다.
- **전제 개념**: ml-06 표준화
- **알아야 할 개념**: 지도 vs 비지도 / K-means 4단계 / 표준화 먼저 / 군집 해석(평균 보고 이름 붙이기) / k 고르기(엘보·실루엣) / PCA 비유 / 설명된 분산
- **배치**: S(정답 없는 데이터) → **F1**(지도 vs 비지도) → C(AI4I 보기) → S(K-means 깃발 비유) → **F2**(4단계 그림) → C(KMeans) → R → C(산점도) → R → C(군집별 고장률) → R → S(k 고르기) → C(엘보·실루엣) → **T**(k 바꿔 그리기) → R → S(PCA 비유) → **F3**(점구름 위 PC1·PC2 화살표) → C(PCA) → R → C(와인 2D 그림) → R → S(정리)
- **퀴즈 vs 코드**: **퀴즈 3문항**. K-means 코드는 짧아서 실습보다 "왜 표준화가 먼저인가", "K-means는 그룹이 없어도 나눈다" 같은 오개념 확인이 중요하다.
  - ox(새로): 표준화 없이 K-means를 돌리면 큰 단위 열이 거리를 독차지한다 / ox(새로): K-means는 그룹이 없으면 나누지 않는다(X) / ox: PCA 첫 주성분은 분산이 가장 큰 방향
- **그림**: F1 정답 있는 점(색) vs 없는 점(회색), F2 깃발 꽂기 → 배정 → 이동 → 반복, F3 PCA 화살표
- **연결 실습**: 유닛 37
- **영상 위치**: dl-m25 K-means: 4단계 그림 뒤 / dl-m26 PCA: 주성분 그림 뒤
- **원본 원고**: docs/sources/ml/11-1-clustering-basics, 11-2-pca-and-dimensionality-reduction
- **원고 반영**: 원고에서 가져온 것: K-means가 약한 경우(둥글지 않은 모양·밀도 차이·이상치), 군집 이름은 사람이 붙인다, 누적 설명 분산으로 축 개수 고르기(와인 5개 80%, 7개 89%).

## ml-08 드문 고장을 놓치지 않으려면

- **목표**: 불균형 데이터에서 class_weight·임계값·오버샘플링으로 재현율을 올리고, 기준선을 비용으로 정할 수 있다.
- **전제 개념**: ml-03 정밀도·재현율·임계값 (짧게 다시 짚기만)
- **알아야 할 개념**: 불균형이란 / 정확도의 함정 다시 보기(한 단락) / 모델이 "애매하면 정상"이라 답하는 이유 / class_weight / 임계값을 비용으로 정하기 / 오버샘플링과 "나눈 뒤 학습용에만" 규칙
- **배치**: S → C(고장 비율) → R → **F1**(정상 966 vs 고장 34 점 그림) → S(정확도의 함정, ml-03 연결) → C(Dummy) → R → C(로지스틱) → R → S(벌점 비유) → C(class_weight) → R → S(기준선=경보 감도, ml-03 연결) → **F2**(놓침 비용 vs 헛경보 비용 저울) → C(임계값별) → **T**(비용을 넣어 총비용 최소 기준선 찾기) → R → S(오버샘플링) → **F3**(나눈 뒤 학습용에만 복사 / 나누기 전 복사 = 누수) → C → R → S(정리)
- **퀴즈 vs 코드**: **퀴즈 2문항**. 핵심은 "어느 기준선이 맞나"라는 비용 판단과 "오버샘플링 순서"라서 상황형 퀴즈가 효과적이다.
  - choice(새로): 놓침 1건 비용 100만 원, 헛경보 1건 1만 원이면 기준선을? / ox(새로): 오버샘플링은 train/test로 나누기 전에 해야 한다(X)
- **그림**: F1 불균형 점 그림, F2 비용 저울, F3 오버샘플링 순서 비교
- **연결 실습**: 유닛 38
- **영상 위치**: 없음 (임계값 영상 dl-m11은 ml-03에서 봄)
- **원본 원고**: docs/sources/ml/09-3-imbalanced-data-and-smote
- **원고 반영**: 원고에서 가져온 것: 가장 먼저 할 일은 현재 모델이 얼마나 놓치는지 확인, 오버·언더샘플링·SMOTE 비교표, 리샘플링은 나눈 뒤 학습용에만·교차검증 조각마다. 직접 해보기는 총비용 최소 기준선 찾기(놓침 100 : 헛경보 5 → 0.05, 헛경보 10~30 → 0.2).

## ml-09 모델이 무엇을 보고 판단했나

- **목표**: 순열 중요도·계수·부분 의존도로 모델의 판단 근거를 설명할 수 있다.
- **전제 개념**: ml-04 feature_importances_ 맛보기, ml-02 계수 부호
- **알아야 할 개념**: 해석이 필요한 이유 / 가짜 열(noise)로 방법 검증하기 / feature_importances_의 약점 / 순열 중요도(재료 빼고 맛보기) / 비슷한 열끼리 가려 주기 / 표준화 계수로 방향 / 부분 의존도와 임계점 / 상관 ≠ 인과
- **배치**: S → C(RF + noise) → R → S(중요도) → C → R(noise도 0.08) → S(순열 비유) → **F1**(한 열만 섞기 그림) → C → R(noise 0.03, process_temp도 낮음 → 비슷한 열) → S(계수) → C(타이타닉) → R → S(PDP 가상실험) → **F2**(모든 행의 토크를 20, 25…로 바꿔 평균) → C → R(55~60에서 급상승) → S(인과 주의) → S(정리)
- **퀴즈 vs 코드**: **퀴즈 2문항**. 해석 결과를 읽고 판단하는 능력이 목표라 퀴즈가 맞다.
  - choice: 섞어서 점수 하락을 보는 방법 / ox: 비슷한 두 열은 둘 다 중요도가 낮게 나올 수 있다
- **그림**: F1 열 섞기 전후 표, F2 PDP 계산 과정
- **연결 실습**: 유닛 39
- **영상 위치**: 없음
- **원본 원고**: docs/sources/ml/05-3-feature-importance, 05-5-shap-and-pdp, 05-4-multicollinearity-and-feature-removal
- **원고 반영**: 원고에서 가져온 것: 중요도 ≠ 원인, 중요도 낮음 ≠ 제거해도 됨, 상관 높은 열(air_temp·process_temp)끼리 중요도 나눠 갖기, SHAP 개념(브라우저에서 실행 불가라 개념만).
